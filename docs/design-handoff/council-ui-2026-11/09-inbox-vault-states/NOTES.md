## Accessibility and interaction handoff

**Reading order.** Gallery: title/explanation → sources/scoring/error-reference links → Screen, State, Platform, Theme, Text selectors → named Before evidence → named After frame/full-size link → keeps-decision sibling when applicable → limits. Selector changes keep focus. Desktop product drawing: sidebar navigation → page heading/intro → error/loading or group heading/count → row title, reason, source/time, assistant summary → existing actions → next group → Settled → toast. Native Inbox: heading → groups/row's combined title/reason/source-time → Settled → tabs → toast. Native Vault: Back to Settings/Vault → page identity and caveat → Add/entry section or local recovery → existing network context. Opened entry: identity → connection/secret/access/use in that platform's established order. Skeletons and decorative icons are hidden; loading has one named status.

**Names and announcements.** Rows retain a meaningful title; native row opener's name includes its complete reason/time even where the visible description is limited to three lines (AP-7415); the sheet shows all text. Web More is “More for {title}”; Settle is “Settle {title}”. Vault entry buttons expose name/kind/address or reason/time plus existing check/set state; native uses `vaultEntryRows.accessibilityLabel`. Expanded/collapsed is on the entry/fold button. Recovery is named “Try reading the Inbox again” or “Try reading this Vault entry again”, with visible Try again. More detail is a real summary. Native back is “Back to Vault”/“Back to Settings”; Close item and iOS toast Dismiss are named buttons.

A read failure is a polite local status, not a repeated alert. Retry leaves focus on the button and says it is reading again; the static fixture remains in error. On real read success, if the retry disappears, focus should move to the recovered section heading. The toast says **“Settled. It comes back if it happens again.”** and exposes Undo; it is the single status for that event in the HTML. Native implementation must keep its explicit VoiceOver announcement from `ui/Toast.tsx` instead of relying on an HTML live region. Avoid double-speaking a toast and a separate live announcement. Undo's proposed confirmation is “It’s back.” Entry close returns to the row and exposes its collapsed/check state. Full native speech remains a GAP.

**Focus and return.** Web Settle moves to the next row's first button (here the restart approval's Yes, now), previous at end, heading if none. Native Settle returns screen-reader focus to the next/previous row, preserving AP-7413; HTML uses that row's opener. Undo restores the removed row in its original place and focuses its Settle button (web) or row opener (phone): this explicit Undo restoration is a proposed refinement, not a claim that the current web callback already focuses it. The screenshot's focus outline is a held marker; clicking the controls exercises actual DOM focus.

Heads-ups/Settled open in place; focus stays on the expander and expanded state changes. Close a web Vault entry by its own header or the error's Close entry; focus returns to Grafana's header at the retained scroll position. Phone Back to Vault returns to Grafana's list row, not the top of Settings. Browser Escape closes the illustrative native item dialog and returns to its opener; its real Close item button does the same. The dialog traps focus. The HTML's native sheet is a review interaction: real iOS menus/swipes and Android predictive back remain unchanged and require native verification. Closing a sheet precedes leaving the screen.

**Toast duration.** Keep shipped UIR-36: 8 seconds, paused on pointer hover or focus in the toast. Keep AP-7414: Android at least recommended accessibility timeout, doubled with a screen reader; iOS VoiceOver Undo remains until Dismiss. The iOS drawing shows Dismiss for this accessibility scenario; native automatic timeout/dismissal is not simulated. Toasts sit above the pinned Settled/tab area and must avoid keyboard/control coverage. Copy retains focus on Copy; Android 13+ owns its system feedback, so no second app toast. Copy failure should keep existing browser/OS permission feedback, never claim success.

**Targets.** HTML phone actions, summaries, back, row openers and tabs are ≥44 CSS px (iOS drawing) /48 CSS px (Android). Handoff units are 44pt/48dp; actual OS layout needs measurement. Full native rows remain tappable in implementation. New web recovery/fold/Undo controls are ≥44px; the shipped compact desktop Inbox 36px and Vault's smaller inline controls are preserved rather than redesigned in this step. Review selectors/links are ≥44px. Decorative marks have no tap target. Icons use token focus rings; native system focus is a GAP.

**Expanded behavior.** Heads-ups starts closed except its explicit opened state; expands two existing calm rows with unchanged actions. Settled starts closed, always opens, and has its own scroll at ≤45% viewport; when empty it reveals its existing explanatory sentence. Entry click expands web details inline; phone opens its existing destination. No secret is ever expanded. Advanced, Danger and More detail start folded (Technical details is explicitly opened for the public-key-copy case). More detail wraps the diagnostic below the controls without shifting them sideways. Expanded groups remain in the document's established order.

**Largest text and stable positions.** All 102 state/platform/theme combinations were additionally inspected for horizontal overflow at **200% HTML text**. Words and action rows wrap, inline details stack, the illustrative phone tab area grows, and the toast becomes part of layout. Existing native three-line row summary retains complete text in its accessible name/sheet; web keeps its shipped two-line summary with the source destination. This does not claim that native maximum Dynamic Type/font scale, keyboard avoidance or browser zoom are certified. The fixed-size gallery frame scrolls locally to preserve 1440/390 drawing width.

There is no polling, timer-driven dismissal, auto-sort or background reorder in this document. Only a deliberate selector/fold/Settle/Undo/open/close changes content. Implementation must keep server/stable order while a finger/focus is on a row, restore Undo at its prior position, and retain scroll on return. Loading/error never masquerades as an empty Inbox. New data arriving during an interaction must not move a control under the finger.
