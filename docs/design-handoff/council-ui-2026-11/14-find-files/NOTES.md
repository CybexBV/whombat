## Accessibility and behavior

- **Screen-reader order:** web navigation → page heading → query → named type buttons with pressed state → result count status → grouped results → coverage. Native stack Back precedes title. File row names combine conversation, count/size and date once; decorative icons/chevrons are hidden. Loading announces “Loading your files” once and skeletons are hidden; read failure offers “Try loading your files again”. Usage: heading → provider coverage → generated time → Today/7/30-day articles → caveat/More. Phone Inbox/Vault preserve step 09’s names and order. Drawer is named Whombat navigation (native More places); links follow visual order.
- **Focus:** visible brand rings; real links/buttons/forms/details/dialogs. Dialog focus is contained by native HTML dialog; Escape and Close return to opener. Search result Back returns to Search, preserving query and stored initiating-link focus/scroll in the prototype. Utility Back names Chat/Settings as origin. In a built app use existing origin handling and native stack focus restoration. Step 09 retains entry-close, Settle-next-row and Undo focus logic. No actual assistive-technology certification is implied.
- **Touch:** phone web/iOS minimum **44px/pt**, Android **48dp**, including back, filters, dialog rows, retry and tab targets. File list rows are full-width links rather than small title-only links. Wrapped controls grow. These CSS drawings specify minimums; actual native hit slop/system frames remain unverified.
- **Expanded:** More places is a modal navigation list; Chat overflow retains displaced actions. Search coverage and Usage More expand in place. Files read failure’s More detail stays local, and retry only announces another read; the static scenario does not fake success. Inbox heads-ups/Settled, Settle/Undo, Vault closed detail/recovery are step 09’s existing prototype behaviors. Vault remains write-only: no reveal or separate-lock feature is proposed.
- **Largest text:** PNGs include 200% content text at 390 for Search, Files, Usage, Inbox and Vault; controls and prose wrap and the body scrolls. Search types take more vertical space and fewer results fit. The gallery can apply 200% to native designs too. This is CSS reflow evidence, not proof of iOS AX5/Android font-scale behavior; today’s native 1.6× cap remains a separate limitation.
- **Stable order:** no live refresh or matching runs while a pointer is down; results change only on explicit submit/filter. Conversation rows keep the current snapshot order; refreshed built lists should apply the new snapshot after interaction, restore focus by stable ID and never move a row under a finger. Retry keeps its target and announces progress. No actual write is submitted.

`render.json` retains measured nominal DOM text/background WCAG ratios in both themes from step 01’s `measureContrast()`. Target ≥4.5:1 even for large text. Retained image text, system chrome, gradients/non-text icons and search-input values are outside that DOM scan. Input ink on sf uses the same ink/sf pair measured in the result text; placeholder mut/sf uses the measured meta pair. Native current Files nominal pairs are recorded above. The desktop selected shortcut uses ink2 (not low-contrast mut on sel), and active native tab text uses ink2. Final sampled minima over 76 rendered viewports: **light 4.942:1 / dark 5.515:1**, with no sampled text pair below 4.5:1. There are 24 before images and 24 after contact-sheet/desktop images; lossless RGB PNG compression is applied. This is not a complete contrast or screen-reader audit.
