# Final Automations · compact rows · round four

[Before/after and every state](index.html) · [static list](mockup.html) · [binding story](../STORY.md). Shared shell/source rules, Dusty labels, focus/target policy, render inventory, contrast method and gaps are in [Overview’s common handoff](../overview/NOTES.md). Applies to **desktop web, phone web, iOS and Android**, light and dark. Mockups only; NO CI/lint/typecheck/notices/tests or check waiting.

Round four compacts the existing final design in place. Each row is **one full-width link**: the real source mark and complete name first, then one continuous **On / Off / Not on yet · last result and date · next run** line. It wraps naturally, including at the kept text cap. A waiting plan remains an independent clause in that line; “On” never claims a previous run worked. One chevron occupies the same trailing column on every row. There are no nested run-link targets or separate button heights inside a row.

Normal drawings fit **8 complete rows on desktop at 1440 × 900**, **5 on phone web at 390 × 844**, and **4 on iOS and Android at 390 × 844**, in both themes. Desktop rows are about 73px; phone rows grow with their actual names and facts rather than using a fixed tall card. The full trigger wording and small history bars live on the existing automation detail page, with every run still reachable there. This is the interpretation of “keep the facts but tight”: no trigger or run data is discarded.

GitHub’s Octocat and the tracker’s own mark are the exact shipped SVG paths, rather than the generic lightning mark. The selected fixture has no owner-avatar image, so GitHub uses the shipped logo fallback; it does not fetch or invent an owner picture. Messages and schedules keep their appropriate source glyphs. No server-provider mark is invented for an automation that is not tied to that provider.

The composer uses a shrinking text column plus three fixed tool columns. Attach, mic and send stay on the same row at normal and largest text. On phones its visible hint is “Tell {assistant}…”; the complete purpose remains its accessible label and the introductory sentence. Entered text grows vertically. iOS keeps chevron-with-previous-title back; Android keeps its arrow.

## Reading, focus and interaction

List order: shared shell → Automations heading/intro → labelled composer → eight source-order rows → Only tells you schedules → native tabs. Each row reads source → complete title → On/Off/not-on state → last result and finish/start date → next trigger → independent plan-wait clause. The single link’s accessible name contains those visible facts; its chevron is decorative. The full trigger and secondary bars are on detail, followed by the existing run links. Draft/off text is not group-faded. Stable identities retain this order during refresh; no outcome-based resort occurs under a finger.

The whole automation row opens its existing detail destination, which exposes its full trigger and recent runs. A run link there opens the named run page. Back to Automation / Back to Automations restores its origin/scroll anchor; native detail/run are pushed pages without invented tabs. The page-level list keeps the binding five tabs. Run facts read result, automation name, Started, Finished only if known, timezone, then More detail. Result is never conveyed only by colour.

Tell/Send opens a modal containing the unsent request; nothing is created/enabled. In the app, web keeps the shared composer and native uses its existing Chat creation path. Attach/voice and schedule actions are local destination previews here; no fictional successful receipt is shown. Remove retains the real app’s confirmation, rather than a promise of new undo. An uncertain command follows command-safety (may have happened, check first); read retries never run/pause/remove an automation.

All interaction targets are **44×44 web/iOS and 48×48 Android**, including the whole row, detail-page run links, back links, composer tools, disclosures and schedule actions. Focus follows DOM/reading order; modal question field first, Close/Escape returns to exact opener. Details expands in place. Largest text keeps 200% web / 1.6× native, complete titles and statuses, a composer whose tools stay together, and vertically flowing facts. Large text is retained when moving between list, detail and run pages. The proposed HTML does not certify native return-stack, VoiceOver/TalkBack, keyboard/safe-area or live receipt handling.

Loading uses compact two-line automation-row placeholders without a claimed result count. Empty is a successful zero **automation + schedule** result and explains what will appear/how to ask for one. First-read failure has no fake zero or empty list. Failed refresh keeps the eight saved rows/schedules with one local read error and actual saved-list time; Try again only rereads the relevant list, Ask prepares an unsent help question, diagnostics stay folded. Separately loaded schedules must remain if only automations.list fails in implementation; these full-page failure scenes model the composite page read, not a mandate to clear successful subqueries.

Normal PNGs feed the final gallery. Every scene also has its own `<platform>-<theme>-<state>.png`: loading, empty, failed, saved-failed, lower, largest, largest-lower, worked, run-failed, skipped, waiting, history and schedules. The local gallery links to these individual PNGs, including largest text; it does not borrow a stale largest-text atlas from Overview. Existing `png/runs-{theme}.png` and `png/states-{theme}.png` are re-rendered for older gallery links. Built-app references remain the original step 01 web / step 08 native fixtures, clearly labelled as different source moments. Round-four matching before/after captures of all 112 scenes are saved under `.whombat/shots/automations-round-four/` (locally excluded). Native drawings are HTML geometry specimens, not captured native app accessibility evidence.

## Recorded design measurements and delivery

`render.mjs` renders this screen only with the current shared shell and fixture story. The main-branch shell finish is included unchanged: real service logos in sidebar/Places, the dedicated Search destination and Back first on native detail/run pages. All 112 Automations scenes were re-rendered after merging that shell, retaining the compact rows and composer. `renders.json` records 112 after scenes: four platforms × two themes × fourteen scenes, with fonts loaded, frozen story time, normal/kept-largest text, row geometry, composer-tool geometry, token contrast pairs, target sizes and page errors. Reproduce with Node 24 and the repository’s existing Playwright/pngjs dependencies: `node docs/design-handoff/council-ui-2026-11/16-final/automations/render.mjs`; `--before` writes matching local before pictures without changing the review PNGs. These are rendering observations, not app tests.

Minimum sampled visible text contrast is **4.942:1 light / 5.515:1 dark**, above 4.5:1 in both themes. All row links and controls meet **44px web/iOS or 48px Android** in the drawing. There is no horizontal page/content overflow and no page error. Large-text drawings show complete names and facts through scrolling; no text cap was raised. Native safe areas, VoiceOver/TalkBack, system return-stack and keyboard handling remain implementation verification, outside these static mockups.

No successful image response or numbered changed area was returned, so there were no numbers to annotate. All requested captures remain local.
