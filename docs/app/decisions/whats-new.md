# What’s new in the apps (AP-10060…AP-10065)

A customer on the web app noticed Whombat updates itself, but nothing readable said what changed. The apps showed
only a technical line under “Updated to …” (control's release summary), and the plain-language changelog
(`docs/changelog.md`, legal-texts.md LGL-05) lived only in the repository. This first step shows that changelog in
the apps and says once that an update happened. Release notes per release are a later step (below).

| Id | Decision | Why |
| --- | --- | --- |
| AP-10060 | **What’s new is a page of the web app, `/whats-new`, built from `docs/changelog.md`** (without its note for those who keep it, after the first `---`), drawn like the legal pages. Inside the app it is a screen in the shell; on the hosted app it also opens without signing in when it is the page first opened (a link, the phone), never when going back and forward inside the app. On the page a box serves, the notice and About open it as a fresh page load, since a page left open across an update still runs the version from before it while the box serves the new one with its changelog. The box's web build copies the changelog for it (`appliance/nix/lib/sources.nix` and the runtime's fetched web source). | One source for the words people read, served by Whombat itself; a box shows the changelog its version came with. Back and forward must never close an open app. |
| AP-10061 | **This Whombat → About's UPDATES has “What’s new”** (“What changed in Whombat lately, in plain words.”, Read) under the update rows, on the web; the phone's About has the same row, opening the hosted page in the in-app browser. | Where people look after an update. |
| AP-10062 | **“Whombat updated · See what’s new · Dismiss” shows once per update** (`whatsNewNotice` in `@whombat/client/managed`), in the web shell's notice slot and in the phone's strip under the status bar (under the passkey nudge when that shows too, never waiting for it). It compares the Whombat's last update (`update.lastUpdate`) with the release the device saw last, kept per Whombat with when it was installed (web: this browser's storage; phone: the secure store); an answer older than what is kept (a page still holding a status from before the update) neither tells nor replaces it. The release is kept as soon as the notice shows (or What’s new is open); the notice stays on screen until See what’s new or Dismiss. | Said once, where the person already is, and never again for the same update, also when the app is closed before anyone taps it. |
| AP-10063 | **The first look only remembers**: a device that never saw a release stores the current one (or `none` before the first update) without a notice, so the next update is the first it tells about. No notice after an update that can't go back (forward repair) or where storage can't be read or written. | Nothing to compare with on a first look; a notice at every start would be worse than none. |
| AP-10064 | **Both apps read the status they already read** (web: the version line's `appliance.status` query; phone: the Settings list's query, once the session is open); no poll while nothing happens. Both ask again each time the box's session opens after a drop (`onSessionReopen`), every 5 s while an update is being installed and not waiting, through its last checks even while updates are paused, and for a minute after the box is back (or after the app starts on an open session) while it hasn't said how its updates stand or its answer failed (`whatsNewPollMs`), since the last update changes only once the box has checked it. Pages of one browser claim the release in turn (the browser's lock where it has one), deciding again from what is kept when their turn comes, so only one tells; a page closed before its turn keeps nothing. Without the lock (a browser older than Web Locks; a page not served over HTTPS can't open a Whombat's session at all) two pages reading at the same moment may both tell, which is harmless. The phone checks one Whombat's release one after another, so a slow write can't bring an update back, and a refreshed answer never cancels the notice an earlier one is about to show. | An update restarts the box, so a page left open hears of it when the box is back and done, without polling the rest of the time. |
| AP-10065 | **Later, not here**: notes per release from the release build (the changelog lines added between two releases, kept with the release and shown under “Updated to …” in place of the technical summary), and a check that a change people can notice adds its changelog line. Until then the hosted app's page is the changelog of the hosted app's build, which can be ahead of a Production Whombat. | The first step needed no contract or control change. |
