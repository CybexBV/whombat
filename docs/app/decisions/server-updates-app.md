# A server's updates on the web and the phone (AP-2860…AP-2899)

John, 2026-10-19: “I want to be able to install software updates via Whombat on, for example, Proxmox or Debian, etc.”
The product decisions are Whombat's `docs/decisions/server-updates.md` (SWU-01…SWU-15); this is stream U of
`docs/implementation/server-updates/assignment.md` there: SWU-10…SWU-14 on the web's System tab and the phone's server
screen. Contracts 0.98.0 (CT-500…CT-503: `packages.check`, `packages.install`, `HostSystem.packageTask` /
`packageLast`, `HostTask.packages` / `code`, platform `host`, feature `hosts.package_updates`). Not in the mocks (B-05):
the System tab's Health card and the phone's server screen as they are.

The rules and words are `@whombat/client/hosts` `updates.ts` (tested); the web's parts
`apps/web/src/features/things/tabs/ServerUpdates.tsx` and `manage/ServerPowerDialog.tsx`; the phone's
`apps/mobile/src/screens/ServerUpdatesScreen.tsx` and `screens/server/Updates.tsx`; the fixtures
`packages/client/src/hosts/fixtures-swu.ts` and `apps/mobile/src/fixtures/hostsUpdates.ts`.

| ID | Decision | Why |
|---|---|---|
| AP-2860 | **One view model for both clients** (`serverUpdatesView`): what the Updates and Restart lines say and which buttons show, from the server's report, its switches, the viewer and the runtime. Nothing new shows without `hosts.package_updates`, on Unraid (its Plugins and OS update their own way, SWU-01) or where the agent reads no package manager (“This server doesn’t report updates.”); the lines are then as they were. | The web and the phone say the same thing for the same state; the brief puts shared words and state logic in `packages/client`. |
| AP-2861 | **Who may**: owners (`hosts.status` `canManage`, as every server change) on a server whose `remoteControl.manage` is on (the hub's and the agent's “Full control” switch, SWU-07), with its agent connected. An owner without it reads SWU-07's sentence under the line, only while updates wait; a member sees the lines without buttons or sentence (as the other owner-only parts of the tab). | SWU-07; the agent and hub gate both ops on `manage`, so the clients do too (not on the head's “Full control” chip, which also needs the shell and power switches). An agent that isn't there can't be asked. |
| AP-2862 | **The Updates line keeps its words** (“4 updates waiting, 1 for security”, “Up to date”, “Couldn’t check: …”) and “checked 3 h ago”. While the server reports a package task it says “Installing updates…” or “Checking for updates…” with a quiet dot. Buttons: **Install updates** (primary) while updates wait, **Check now** whenever the owner may (also on Up to date and Couldn’t check, where a fresh read can help), and while a task runs **Show log** instead. | SWU-10. A check is the way out of a stale list or a failed read. |
| AP-2863 | **How the last one ended**, from `packageLast`, a line under the Updates line for a week: “Installed 23 updates · 12 min ago”, “Nothing to install · …”, “Installing updates stopped: {its first line} · …”. The sentence's full stop gives way to the `·` and the time (as the tab's other lines, “Failed 5 h ago”); toasts and dialogs keep it. A good Install's note (SWU-06's enterprise repository) follows its sentence and makes it amber. A good Check says nothing: “checked just now” says it. | SWU-10's words with when; a result from weeks ago is history, not news. |
| AP-2864 | **Why it stopped**: `code: busy` is SWU-04's sentence (“Another program is installing packages on {server} right now. Try again in a few minutes.”); `code: timeout` is “Installing updates stopped: it took longer than 2 hours.” / “Checking for updates stopped: it took longer than 10 minutes.” (SWU-04's limits); any other code or none, the task's message. | The lead's note on 0.98.0: the lock wait happens inside the task. The limit is the plain fact. |
| AP-2865 | **Install asks first** with SWU-10's question (“Install 23 updates on pve-02?”, its body, Install updates) and sends `platform: host` and `confirm: true`; Check doesn't ask. Started: “Installing updates on pve-02.” / “Checking pve-02 for updates.” with Show progress; ended well: “Installed the updates on pve-02.” / “Checked pve-02 for updates.” (the Done-recently words); failed: “Updates on pve-02 failed: …” (the task's name in its dialog: “Updates on pve-02”, “Update check on pve-02”). A refusal (busy, Full control, an agent too old) stays in the question. | SWU-10; the toast at the end can't know the count (the `hosts.task` frame doesn't carry it), the line says it a moment later. |
| AP-2866 | **Restart now** on the Restart line when a restart is needed, for an owner, with the server's power switch on and its agent there: the head's Power question (“Restart pve-02?”, `hostPowerBody`, This Whombat goes down too) — moved into `ServerPowerDialog`, which the Power menu uses as well. | SWU-05, SWU-10: the existing server action and its existing confirm. |
| AP-2867 | **The task dialog** shows a package task's live log as any task's, but offers Stop the task only when the task can be stopped (`cancellable`, false for an Install, SWU-04), and once ended says what it did: “Installed 4 updates.”, the packages kept back (five, then “and 2 more”), the warning; or SWU-04's busy sentence. | SWU-04 forbids stopping an Install; the hub says so per task. |
| AP-2868 | **A package task started elsewhere** (another device, an agent, before a reload) is followed as one started here as soon as the System tab sees it in `packageTask`: Show log opens its dialog, its end refreshes the page and toasts. After a package task the tracker also refreshes Look inside's lists. | SWU-10: “also after a reload and on another device”. |
| AP-2869 | **Look inside → Updates** gets the same Install updates under its table (the same question). It stays gated on read-only checks, as the web already was. | SWU-10, SWU-11. |
| AP-2870 | **The System tab's waiting-updates hint stays words**: no button of its own, the Updates line right under it installs them (the lead, 2026-10-19; AP-1752's precedent: what a card below does isn't repeated above). SWU-13's “Install them on the System tab” would point at the page it is on. | One Install updates per place; the notice still says why. |
| AP-2871 | **Worth a look's waiting-updates hint** (`system.updates`), with `hosts.package_updates`: on the web “Install them on the System tab” (the System tab); on the phone it opens the Updates screen (`?tab=updates`, AP-2887's words) — `serverDashboard`'s and `useServerDashboard`'s `updates: 'web' \| 'phone'`. Without the feature, and on Unraid, “Open System” as before. A button's words carry no full stop. | SWU-13; the panels are shared, the way out isn't. |
| AP-2872 | **`?tab=updates`** on a server's web page opens System (Unraid's tabs are its own). | One link for the updates on both clients. |
| AP-2873 | **The fixtures' updates hint is the hub's** `system.updates` (it was `updates.available`, a kind the hub doesn't send), and the updates world adds the hub's `system.reboot`. | The way out matches what a real hub sends. |
| AP-2874 | `FEATURE_NAMES['hosts.package_updates']` = “installing a server’s updates” (“Update your Whombat to use …”). | Every runtime feature has its words. |
| AP-2878 | **The fixture world** (`fixtures-swu.ts`, web's `createHostsFixtureLayer` and the phone's demo world): pve-02 with 4 updates waiting (one for security, a kernel among them, so it needs a restart after them), pve-01 with 6, thetitan installing since the world started (a line every 4.5 s, about two minutes), the-falcon installed 12 updates 40 minutes ago and waits for its restart. `packages.check` / `packages.install` start `pkg:<16 hex>` tasks whose log grows with the clock; a second one is refused as busy, an Install can't be stopped, a Check can; at the end the list and the restart need are read again; Restart clears it. | The three states the brief asks for, playable without a server. |
| AP-2880 | **The phone's Updates screen** `ServerUpdates` at `things/:serverId/updates` (the server's thing id in the address, as a guest's), the web's `/things/server%3Apve-02?tab=updates` opening it; restored after a killed process and watched on `hosts.getServer`. | SWU-12; one address scheme. |
| AP-2881 | **The Summary's Updates card** after Worth a look (else after the figures): the Updates line with a dot and when it was read, and “Restart” over “Needed: …” when one is needed; both rows open the screen. `SummaryPanels` takes an `extra` card for it. | AP-2882 | **The phone's way out** of Worth a look's updates and restart hints opens the Updates screen (`ServerScreen` reads `?tab=updates` before the tabs; Unraid's `updates` stays its Plugins). | SWU-13 on the phone, where System isn't a tab. |
| AP-2883 | **The Updates screen**: “Updates” and the server's name, the line with when, the result, SWU-07's sentence; Install updates, Check now or Show log (44dp, wrapping); RESTART with its reason and Restart now when needed; WAITING · n with the packages, security first (a “security” pill), now → new in the mono face — Look inside's list, so with read-only checks off it says why. Install asks in the one-Whombat sheet with SWU-10's words; a refusal stays in the sheet. The page is read every 5 s while a task runs. | SWU-12, the web's words; the sheet is the phone's question. |
