# Settings → Connections: what you have, and Add a connection (AP-1157…AP-1166)

John, 2026-10-11: “What is better UI / UX for the Connections page at settings? Currently I see a long list of connected
devices, then Found on your network and then a long list of add a connection. How would you redesign this?” With the
fixture world the page was 4,213 px at 1440 × 900, almost five screens, ~70 % of it the catalog's 31 tall tiles with a
primary button each. A connection that needed connecting again was row 6 of 7, in the same weight as the healthy
ones; Proxmox showed under Found on your network and again under Infrastructure. I proposed splitting what you have from
what you can add (a mockup with both pages) and he said “yes please”. Android's half is
`connections-redesign-android.md` (AP-1170…). No contracts change.

| ID | Decision | Why |
|---|---|---|
| AP-1157 | **Superseded in part by settings-groups.md STG-06 (Add a connection is the Connections page’s).** **Two places.** Settings → Connections is the overview: what you have. **Add a connection** is its own page at `?tab=connections&connection=add` (`connection=add` is accepted beside a builtin's or a catalog entry's page; `id` and `url` are dropped with it), with “← All connections” back. Reached from the overview's button, the found strip's “See all”, and the back link of a new connection's page. | Checking on what you have and browsing to add something are different jobs; the catalog needs room, and a page (not a dialog) keeps the browser's back button and a link to it. |
| AP-1158 | **The overview's head:** the intro, shortened to “Services your agents can use, for you or for everyone here.”, beside a primary `md` **Add a connection** with lucide `Plus`. | The old intro listed what the catalog now shows; the one action of the page sits where the eye starts. |
| AP-1159 | **NEEDS YOU · 2** first, only when a connection isn't fine: a builtin whose `ok` is false (Google or Microsoft needing connecting again, GitHub or Website feedback needing attention) or a catalog connection whose tone isn't `ok`. A warm card (`--warn` 30 % border, 6 % fill, mixed with the tokens); each row is one link to its page: the 40px logo, name · detail, the state with its dot in `--warn` (`--bad` for an error), the reason line in `--ink2`, and on the right what looks like a `sm` button — primary **Connect again** for “Needs connecting again”, secondary **Open** for the rest. It isn't a button inside a link: the whole row is the link, so there is one tab stop. The count after the label is `aria-hidden` (the region is “NEEDS YOU”). | Problems first, each with its fix in reach. The page of the connection is where reconnecting happens already, so the row goes there rather than starting a flow from the overview. Android also asks whether the viewer may reconnect it (AP-1171); the web sends everyone to the page, which says who can. |
| AP-1160 | **CONNECTED · 5** in one-line rows (min 52px): a 32px logo, the name (· the account in mono, as before), its line in `--mut` cut with an ellipsis (`title` has it whole), the scope word (“Shared” / “Only you”, `CONNECTION_SCOPE_TAGS`, quiet text instead of a tag), a green dot and the chevron. “Connected” is no longer written on each row; the link still carries it for screen readers. The builtins first (GitHub, Google, Microsoft, Website feedback), then the catalog's, shared before personal. From 8 rows, when both scopes are there, a `soft` `sm` segmented **All · Shared · Only you** filters them. `CatalogRow` gains `scope`. | Healthy rows are glanced at, not read: one line each makes the list a third as tall. The repeated green “Connected” and the loud SHARED tag were the noise on every row. |
| AP-1161 | **On your network** on the overview is a strip under CONNECTED: a dashed card with the title, a chip per new found service (20px round logo + name, at most four, then “+2 more”), and **See all ›** to Add a connection. A chip is a link to that entry's connect page with the address filled in (`aria-label` “Connect Proxmox VE at https://192.168.1.10:8006”). Nothing shows while the first scan looks, when nothing new turned up, or when the viewer can't scan. `FoundOnNetwork`'s scan moved into `useFoundScan(burrow \| null)` (the ask, the 1.5 s polling, the shared request count of AP-873 as `begin`/`accept`), used by the strip and the section. | A suggestion, not a section: one line keeps the overview about what you have, and the one click that matters (Connect) is still there. Hide, scanning and other networks are management, on the Add page. |
| AP-1162 | **Add a connection:** “Add a connection” (22/700) and “For you, or for everyone here. Your agents use it as soon as it’s connected.”; a full-width search box (16px `Search` icon, 15px text, focused on opening) with the placeholder “Search 31 services” (every offered entry, Custom ones included); **chips** (`Chip`, in a `fieldset` legend “Show”): All, **On your network 3** (where the viewer can scan; the count is the new ones), then each category that has services, Custom left out. All shows ON YOUR NETWORK (the full section, as before: Look in another network, Scan again, Hide, Show 2 hidden) and then the categories; On your network shows only the section; a category only its tiles. The search box narrows the tiles (name, line or category, any word in any order: `matchesWords`) and the found rows by name; a section with no match steps aside. No match: “No connection matches “zzz”.” in a card. | Search first is how people look for one service among thirty; chips replace headings that left half-empty rows. The found section keeps every control it had (AP-871…AP-875). |
| AP-1163 | **Small tiles** (`minmax(240px, 1fr)`, 10px gaps, 14px radius): each is one link with a 32px logo, the name, a tag — **CONNECTED** (`--ok`) when you have one, **SET UP** when it must be set up first — its line clamped to two lines, and the note under it when it can't be connected yet (“Set up a Microsoft Entra application to connect.”). Its accessible name says what pressing does: “Connect Notion”, “Set up Google”, “View Google”, “Open GitHub”. A builtin you have stays listed (Connected, opening its page); a catalog entry you have stays too (Connected, a second one can be added, CX-05). No button per tile. | Thirty-one primary buttons were the loudest thing on the page. A whole tile as the target is bigger and quieter; the tag says the state without a second line. |
| AP-1164 | **Custom MCP server and API** leave the grid: under the tiles, “Not in the list? Connect any MCP server or any HTTP API.” with the two as underlined links to their connect pages; shown also when nothing matches the search. | They are the way out when the service isn't there, which is exactly when someone reaches the end of the list or searches in vain. |
| AP-1165 | **A new connection's page goes back to Add a connection** (“← Add a connection”, `CatalogHeader back="add"` on `ConnectPage`); a connection's own page and the builtins' pages keep “← All connections”. | Where you came from: a connect page is opened from the catalog (or a found chip). |
| AP-1166 | **Nothing connected:** the overview shows CONNECTED with “Nothing connected yet.” and then ADD A CONNECTION with the catalog itself (search not focused), without the header button. | A first visit shouldn't need a click to see what can be connected. |
| AP-1167 | **Tests and checks.** `ConnectionsTab.test.tsx` (one-line rows, NEEDS YOU with Connect again, the Add page's tiles and tags for admins and others, search and chips, Not in the list, nothing connected); `foundOnNetwork.test.tsx` (the section on the Add page; the strip's chips, its link and the back link; search narrowing the found rows); the tracker and gateway tests find their tiles on the Add page; `catalogRow` has `scope`. Verified in the browser with the fixtures at 1440 × 900, light and dark: the overview is one screen (≈ 830 px), Add a connection 2,346 px with every service and the found section. Not in the mocks (B-05), so no `pnpm visual` comparison. | DEV is fast; the risky parts (the scan shared by two views, the routing) are covered by fixture-app tests. |
| AP-1168 | **Released as whombat-app 0.72.0** with the Android half: version bump, tag `app-v0.72.0`, `pnpm release:dist` from the tag, APK on DEV. | A visible redesign on both clients; no contracts change, so the API level stays. |

## Rows that say only where it is (AP-1177…AP-1180)

John, the same day, on the overview: “We do not need to see “Connected by” and “Looked after by” and tool, so let's
clean that up as well. IP address is useful, but I think we can improve the UI how that's shown.”

| ID | Decision | Why |
|---|---|---|
| AP-1177 | **A CONNECTED row says its name, where it is, “Look only” when agents may only look, whose it is and its state — nothing else.** Gone from the overview: “Connected by …”, “Looked after by …” (OW-10's row line, AP-864), “6 tools”, “Used by automations” (TA-02's row line), a gateway's “Claude Code turns go through it” (AP-1117), Google's “Gmail, Google Calendar and Google Drive”, GitHub's “3 repositories on” and Website feedback's report count. All of it stays on each connection's page (and the agent's profile for what it looks after). NEEDS YOU keeps a second line, but only the reason (“Nextcloud signed Whombat out. Connect again to keep using it.”). `CatalogRow` loses `meta` and its options (`lookedAfter`, `gateway`) and gains `name`, `address`, `lookOnly`, `reason`; the overview no longer reads the bootstrap or `connections.looked_after`. | The overview is for glancing at what you have and spotting what's wrong; those lines were about how each connection works. |
| AP-1178 | **Where it is, as an address pill.** `connectionAddress`: the host and port from the entry's address field (no scheme: `10.100.0.5:8123`, `homeassistant.local:8123`), else the server's detail (the account: `mara@burrowhq.example`); the builtins' account or login (`mara@…`, `@acme`) and a feedback integration's name the same way (that one in the sans font). It sits in a quiet pill: `--sf2`, 6px radius, DM Mono 12.5px in `--ink2`, cut with an ellipsis and whole in `title`. The default label's address is taken off the name (`labelName`: “Home Assistant · home.lan:8123” → “Home Assistant”); a label of its own keeps its words. | An address read inside a bold name (“Home Assistant · 10.100.0.5:8123”) or at the start of a grey sentence is hard to find; a mono pill reads as an address at a glance. |
| AP-1179 | **The addresses line up.** The row is a grid: 32px logo, the name in a column of up to 220px (cut with an ellipsis), the pill and “Look only” tag, then Shared / Only you, the dot and the chevron. On NEEDS YOU the pill follows the name on its first line. | Scanning a list of addresses is easier in a column. |
| AP-1180 | **Released as whombat-app 0.72.1** with Android's AP-1177 (connections-redesign-android.md). | A patch: the same screens, less on them. |
