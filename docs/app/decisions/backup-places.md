# Backup places in the apps: ON YOUR NETWORK, the place in use, Backups kept here (AP-6700…AP-6729)

John, 2026-11-03: a NAS Whombat knows keeps this Whombat's backups (Whombat `docs/decisions/backup-places.md`
BPL-01…BPL-12). These are the web's and the phone's parts (stream W of the backup places build). There is no mock for
any of it: it follows the existing BACKUPS section's components, spacing and type. Contracts: core
`domain/backup-places.ts` and the session ops `backup.places`, `backup.usePlace`, `backup.placeByHand`,
`backup.placeCheck` (`backup.forgetPlace` has no button yet).

| ID | Decision | Why |
|---|---|---|
| AP-6700 | **One read, shared:** `useBackupPlaces(session)` (`@whombat/client/react`) keeps `backup.places` in the query cache under `backup.places`, not retried, 30 s fresh; Settings, the server page and a NAS connection's page read the same answer, and a place that was set reads it again. No session, a box from before (`unknown_op`) or a person who isn't an owner: no data, and nothing new shows anywhere. | One answer for three places, and the old box's silence is the rule BPL's rollout needs. |

| AP-6704 | **The one line** is the place's `reason` when it has one, else the state's words (`BACKUP_PLACE_TEXT.state`), with “· 3.1 TB free” for a ready place whose free space is known. | One line, and the reason already says what to do. |
| AP-6705 | **The one action:** Ready → **Back up here**; a place offering by hand (`byHand`) that isn't ready → **Set it up by hand**; a NAS the scan found → **Connect it first**, linking to the entry's connect form with the address (`/settings?tab=connections&connection=<kind>&url=<address>`; phone `Connect`) or, for an Unraid or Linux computer, Add a server with the address (`/connections?add=1&address=`; phone `AddServer`); Look only → **Turn on Manage first**, linking to the server's System tab (`?tab=system`, where What Whombat may do is) or the connection's Settings tab (`?tab=settings`; phone: the server's page or the Connection screen). | AP-6706 | **Moving asks first** (BPL-06): when `currentPlaceId` is another place, Back up here opens a confirm before any call — title `moveTitle(name)`, body `moveBody(<the place in use>)`, Cancel / Back up here — and sends `move: true`. Otherwise the app calls without `move`; when the box refuses because backups go somewhere else already, the same confirm opens with the place the refusal names. **The refusal the apps read:** `conflict` with `details.code: 'move_needed'` and, when the box knows it, `details.from` (the destination's name); without `from` the body says “the place they go now”. A move to this Whombat's own disk or from nothing never asks. | The app can't tell the box's own disk from another destination (`appliance.status` has no destination kind), the box can; asking up front where the app knows avoids a needless round trip. |
| AP-6707 | **While a place is set up, its row says so plainly:** the line becomes “Setting up <name>. This can take a minute or two.” (`role=status` / a polite live region), its button “Setting up…”, and every other place's button waits. The call's deadline is 6 minutes (`BACKUP_PLACE_DEADLINE_MS`; the hosts hub waits up to 5 for the image pull); a deadline that passes says “This is taking longer than usual. Whombat carries on; look again in a few minutes.” — the op isn't retried on its own. | BPL-05: the person's yes is the request; pulling and starting the app on the NAS isn't instant. |
| AP-6708 | **After it is set,** the row says “Done. Backups go to <destination> now.”, the append-only sentence only when deleting wasn't verified as blocked, and “The first backup has started.”; BACKUPS reads its state again, the places are read again, and “Your recovery kit now needs the backup password: save a new kit.” with Save a new kit follows the list (a new destination, a new kit, as the destination form does). A failed step shows the box's own sentence under the line (`placeErrorText`: `conflict`, `unavailable`, `bad_request`, `not_allowed` and the destination refusals), in `bad`, as an alert. | The same outcome words as the destination form, and the box's sentence names the step that failed. |
| AP-6709 | **Set it up by hand is a dialog (web, `lg`) or a sheet (phone)**: “Set up <name> by hand”, one lead line, the box's steps numbered, the compose file in the key block's look (mono 12.5, scrolling within 280 px on the web, selectable on the phone) with **Copy**, then Close and **Check it**. The compose is asked for when it opens (`backup.placeByHand`, a query: its bcrypt line never lands in a receipt). Check it calls `backup.placeCheck` with the same move rule and progress words as Back up here; the dialog closes when it worked, and shows the box's sentence when it didn't. | BPL-09, in the components the backup form's SFTP key already uses for “paste this there”. |
| AP-6710 | **“Backups kept here” on the web** is a card on the Summary of a server (after the panels, before Technical details) and of a Synology, TrueNAS or QNAP connection (after the panels; the read only happens on those three kinds' pages).
