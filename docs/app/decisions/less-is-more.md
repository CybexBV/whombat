# Less is more: the crew gone everywhere, calmer pages, a guest list that fits (2026-10-18)

John, 2026-10-18 (main checkout): “In this project I still see references to other agents, for example in Settings
and tab AI (retired agents). I want to make sure we clean up completely. Regarding the UI / UX there are pages that
contain WAY to much information, for example the AI page. Consider how to clean up and embrace the "Less is more"
philosophy while keeping the functionality. Also consider how we can improve UI / UX on other pages, like guests page
… We need to keep this page responsive and I would like to see icons of Docker / Incus / VMs instead of the name full
out written. So basically polish the UI / UX globally.”

Since the one-Whombat pivot (one-whombat-shell.md, assistant-name-web.md) a person has one assistant; the crew (Dusty,
Pippa, Banjo, Hazel, Ace and the team roles) is retired on every box (Whombat assistant-name.md AN-S*), but the web
app and the phone still list retired agents (Spend by agent, skills “On Banjo”, “Attach to” pickers) and still speak
of “agents”, “team agents”, handoffs and plans where only the assistant is left. Pages grew a section per feature, each
with its own paragraph, so the AI tab is four screens long.

## The rules every page follows

| # | Rule | Why |
|---|---|---|
| AP-1749 | **Only active agents are shown.** Every list, picker, count, column and chip that names agents keeps the active ones only (`isActivePrincipal` / `listsAgent`); a retired agent keeps its name only where history is read (a message's author, an old run, the audit log). | John: “clean up completely”; a retired agent can't be asked, picked or paid. |
| AP-1750 | **In the assistant shell the assistant is called by its name**, never “agents”, “your agents”, “team agents” or a role (“Associate”, “Developer”, “Operator”, “Lead”). One assistant: no agent pickers, no per-agent columns, no role labels; handoffs and plan budgets are not shown. The crew shell (fixtures, older servers) keeps its words. | One assistant per person (ONE-02); a picker with one choice is noise. |
| AP-1751 | **One sentence of help, at most, per page or section**; the rest goes behind a “More” disclosure or into the row it explains. Mechanics (how often something is read, which version was tested, what's billed where) are folded unless something needs the person. | “Less is more”: the AI tab had nine help paragraphs before its first number. |
| AP-1752 | **Empty sections are not drawn** (“No open handoffs.”, “No plan used tokens”, “Incus has no warnings.”), unless the section is the place to add the first one (Vault, Members, Connections). | An empty box says nothing and pushes what matters down. |
| AP-1753 | **Healthy technical detail is folded, trouble is open.** A block that only says all is well (AI clients installed and current, the agent connected) becomes one summary line with “Details”; it opens by itself when something needs attention. | The person reads the page for what needs them. |
| AP-1754 | **Tables fit their container.** Wide tables use container queries: low-value columns drop first at narrow widths, names ellipsise with the full name in a tooltip, nothing is clipped or scrolls sideways; the row's actions stay reachable at every width. | John's screenshot: the guests table clipped its last columns. |
| AP-1755 | **Icons for kinds, words in tooltips.** Where a row says what kind of thing it is (Docker, Incus, a VM), an icon says it and the words move to the icon's tooltip and accessible label. | John: “icons of Docker / Incus / VMs instead of the name full out written”. |
