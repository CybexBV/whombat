# Automations by talking to the agent: web (AP-6200…AP-6224)

John, 2026-10-28 (main checkout): “make automations only be configurable by talking to the agent … when I talk about an
automation it should give its thoughts on how to build the automation and we can simply accept, deny or change it by
talking to the agent.” He approved a concept (a plan card in Chat, a change card that lists what changes, an Automations
page without an editor) and said “Yes, implement this fully.” The runtime and contracts side (contracts 3.9: the
`automation_plan` card, `AutomationPlanView`, `Automation.talk` and `waitingPlanId`, `automations.acceptPlan` and
`declinePlan`) is Whombat `docs/decisions/automation-chat.md` (AT-01…AT-20).

Supersedes the web's form and editor: automation-recipes.md AP-966…AP-971, AP-974 and AP-977, automation-list.md
AP-1080's chips and tags and AP-1086's “…” menu, and chat-polish.md AP-6142's form and subtitle.

| # | Decision | Why |
|---|---|---|
| AP-6200 | **No form or editor.** New automation's modal (the trigger choices, the simple form, templates, describe, import, blank), Edit, the Steps editor, the JSON view, Keys and webhook, Publish, Save and Discard draft, Export and `?tab=` are gone (`NewAutomationModal`, `EditRecipeModal`, `DefinitionForm`, `RecipeFields`, `recipeForm` and their tests). The run page and its tracker report stay. | AT-01: the agent writes automations; the person agrees on a card. |
| AP-6201 | **The plan card** (`AutomationPlanCard`, `automation_plan`): the shared card frame with a `line2` border; a mono status label with its dot, `NEW AUTOMATION · WAITING FOR YOU` or `CHANGE · …` (core's state labels, upper case), warn while it waits, ok once on, muted otherwise; the plan's name as the card title and the agent's sentence under it. | The approved concept, in the app's card language. |
| AP-6202 | **The rows are the server's** (`plan.sections`): a `dl` with a 112px label column in mono small caps (`section.label`, so the agent's name for its steps) and each line with its detail muted under it. The web never writes or reorders them. | AT-06: the card says exactly what will run. |
| AP-6203 | **WHAT CHANGES** on the `hi` ground for a change: `+` added in ok, `−` (the minus sign) dropped in bad, `~` the agent's instructions changed, muted; a screen reader hears “Adds:”, “Drops:”, “Changes:” instead of the mark. | AT-07; the concept's change card. |
| AP-6204 | **A change shows what changes, then ASKS YOU and LIMIT**, with the whole automation folded under “The whole automation”; a new automation shows every row. | A fixing chain is a dozen lines; what changes is what to decide on, and what still asks first and the limits are what keep it safe. Everything else is one click away. |
| AP-6205 | **Folds**: “How I thought about it” open while the plan waits, folded once decided; “What <agent> is asked” always folded, each step's name over its words in pre-wrap. Native `details`/`summary` on `sf2`. | The agent's reasoning is read when deciding; the prompts are for whoever wants to check. |
| AP-6206 | **While it waits**: Turn it on (Use this version for a change), Try it on #N (Try it now), Not now (Keep the old one), then “or reply to change it”. | The concept's buttons; replying is how a plan changes (AT-05). |
| AP-6207 | **Turn it on** (`automations.acceptPlan`): the answer goes into the automation's list and page, the card settles at once (accepted, now, by the viewer, its version) until the runtime's `message.updated` says the same, and the toast says ““Name” is on.”. A refusal shows the server's words and reads the thread again. | AT-08; a card that was replaced or decided elsewhere shows what it is now. |
| AP-6208 | **Not now** (`automations.declinePlan`): the card settles to “Not now”, the automations are read again (a never-on one is gone) and the toast says “Set aside. Nothing was turned on.”, or for a change “The old version keeps running.”. | AT-09. |
| AP-6209 | **Try it on the card**: the samples are asked only while the plan waits and something like an issue starts it (`automations.samples` on the plan's automation, no retry); the newest by `openedAt`; no button until there is one. It sends `runNow {test: true, sample}` (`{number}`, or `{reportId}` for a tracker report) and the toast “Test run started.” has Open for the run page, so the person stays in the thread. | AT-13. |
| AP-6210 | **The settled line** (card-settle.md AP-731): “You turned on “Name” · Mon 14:02” (ok; “this change to “Name”” for a change; another decider by their short name), “Not now: “Name””, “Replaced by a newer plan · Name”, ““Name” was deleted” (muted). It opens the card without buttons. A card whose plan didn't resolve adds nothing to the message's text. The time: the clock today, the weekday this week, else the date. | The concept's “You turned on … · Mon 14:02”. |
| AP-6211 | **The web decides card or line itself**: `MessageCard` hands `automation_plan` to its container before `cardDisplay`; `packages/client` is unchanged. | The phone's work runs alongside; the words can move into the shared client when the phone draws the same card. |
| AP-6212 | **The overview** (`/automations`): “Automations”, “What <agent> does on its own. To make one or change one, tell <agent>.”, Home's Ask box with “Tell <agent> what should happen on its own…” and three examples that fill it (“Every Monday, sum up last week’s issues”, “Tell me when a disk is nearly full”, “Each morning, what’s on my calendar”). Sending starts a Chat thread with the words (`chats.start`) and opens it. | AT-01; the box already does voice typing, Enter to send and opening the thread. |
| AP-6213 | **New automation** (the sidebar's menu, `?new=1`) puts the focus in that field; the address forgets `new` at once. | Making one starts with saying what you want. |
| AP-6214 | **Superseded by automation-page.md AP-6380:** **A row** keeps the tile, the name as its link, one sentence (the `description` the person agreed to, else Whombat's `summary`), the run history with the last and next run on one mono line, “Run #N is waiting for a yes. Open”, and the switch on the right. The trigger → agent → room chips and the reach tags go, and so does the row's “…”. | The concept's row; the details are on the page and the plan. |
| AP-6215 | **Superseded by automation-page.md AP-6380:** **“Waiting for you to turn it on”** / **“Waiting for you: a change to look at”** (warn, a link to the plan's thread, `talk`) when `waitingPlanId` is set. | AT-12. |
| AP-6216 | **Superseded by automation-page.md AP-6380:** **Row actions**, small secondary buttons named for the automation (“Talk about it: Name”): Talk about it, Run now where the live version starts by hand (else Try it), Details, Delete (the existing dialog). | The concept's actions; AT-18. |
