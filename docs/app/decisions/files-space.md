# Files: a shared file space per conversation, on web and Android (AP-772…AP-784, AP-834…AP-841)

John, 2026-10-05, after Pippa couldn't open a SketchUp file he had attached in #private: “why not create a shared Files
space where people in the same channel can see the files … Files / General, Files / Private … when I share a file with
an agent, Files / <agent name>”, “I also want Files in the sidebar, but only when there are actually files saved.
Restrictions apply, so I can only see files that I actually have access to”, and “Implement this fully”. The spec is
Whombat `docs/decisions/files-space.md` (FS-01…FS-13); contracts 0.49.0 (CT-274…CT-279: `files.summary`, `files.list`,
`files.save`, `files.update`, `files.remove`, the `files.changed` event, feature `files.space`, uploads up to 250 MiB by
default). There is no mock (B-05): the screens reuse the Work view's page and rows, the composer's chips, the context
menus and the dialogs, so they look native to the app. Decided by the implementer (feedback-decide-yourself).

## Save to Files on a message's files (AP-834…AP-841)

John, 2026-10-08: “When an agent creates an images or any other file, it shouldn't automatically store this in /files
unless we click on "Save to Files" and we should also create a "Download" button. Consider how we can make this look
nice in the chat, the UI / UX for this should be subtle.” Contracts 0.59.0 (CT-312): `Attachment.inFiles` on messages'
files, `files.save` takes a file of a live message (people only), `message.updated` after a save or a removal, feature
`files.save_from_messages`; agents no longer save into Files themselves. No mock (B-05): the actions borrow the message
toolbar's frame and the attachment chip's own icons. Decided by the implementer (feedback-decide-yourself).

| ID | Decision | Why |
|---|---|---|
| AP-834 | **Nothing goes into Files unless someone asks; every message's file has Download and, where the Whombat says, “Save to Files” or “In Files”.** `saveActionOf(attachment, saves)` (`packages/client/src/files.ts`, shared): `inFiles: false` → Save to Files, `true` → In Files, absent (an older server) or no `files.save_from_messages` → Download only. Copy: “Save to Files”, “In Files”, “Download”, “Saved to Files”, “Open”; names for assistive technology “Save plan.pdf to Files”, “plan.pdf is in Files. Open Files”, “Download plan.pdf”. | John's request; the server decides what is in Files, the client only shows it. |
| AP-835 | **Web: quiet icons where the file is, words where there is room.** 28px icon buttons (24px is too small to hit), `--mut` at rest, `--sf2` and `--ink` on hover, the global focus ring, tooltips “Save to Files”, “In Files”, “Download”. A chip ends with Save to Files then Download (its padding drops to 4px so it stays 38px tall); a picture (single or a gallery tile) gets the same pair in the message toolbar's frame (`--bg`, `--line2` border, `--radius-button`; no small shadow token exists, so none) over its top right corner, fading in over 120 ms on hover or focus inside and always shown under `(hover: none)`; the thumbnail button and that frame are siblings in a positioned box, so a click never opens the lightbox. The lightbox's bar has “Save to Files” / “In Files” before “Download” in its text style; HTML and Mermaid cards have it before Download as an `ActionLabel` (icon only when the card is narrow). Icons: Lucide `FolderPlus` and `FolderCheck` (the `folder` slot's set and stroke). Names: icon buttons “Save <name> to Files” / “<name> is in Files. Open Files”; worded ones keep their words first (“Save to Files: <name>”, “In Files: <name>”) so voice control finds what it sees. | Subtle in the chat, as asked: nothing new at rest on a picture, the chip's existing icon place on files. |
| AP-836 | **“In Files” is quiet and goes to the conversation's Files.** `FolderCheck` in `--ok` (the icon only; words stay `--ink2`). It is the same `<button>` as Save to Files, so focus stays on it after a click; it opens the conversation's Files (`conversationFilesPath`: its `/files/…` address from the sidebar, `/files` when the sidebar doesn't list it). | One element for both states keeps keyboard users in place; the Files page is where the file now lives. |
| AP-837 | **The click is instant; a refusal says why.** `useSaveMessageFile` marks the file `inFiles: true` in every cached message (lists, threads, single messages) at once and back to `false` on a refusal; the button shows In Files with `aria-busy` (no layout shift) until the answer. Then the toast “Saved to Files” with “Open” (the Toast's action), or the Whombat's words (`filesErrorText`, fallback “Couldn’t save it to Files. Try again.”). The server's `message.updated` brings the same to everyone; a removal in Files (`useFileRemove`) marks the message's file `false` at once too. One promise per click (`mutateAsync`), so two saves at once each end their own busy state. | Feels done the moment it is clicked, as reactions do; the state never lies for long. |
| AP-838 | **Where it shows.** `MessageFilesProvider` sits in the burrow shell (the conversation, the thread pane and a report's details all show messages); `MessageAttachments` takes the message's `conversationId`. Outside a message — Files' own viewer (`AttachmentViewer`), tests, stories — there is Download only. | The thread pane lives outside the conversation room; one provider covers every place a message is drawn without threading props through the room. |
| AP-839 | **Fixtures.** The files layer marks every message it reads (`inFiles` from the Files world) and `files.save` takes a file of a message it read. With `VITE_FIXTURE_FILES=1` the seeded messages carry their files (Priya's brief, Pippa's screenshot and moodboard, the release notes: in Files) and Waffle's 11:20 in #billing-v2 a screenshot and `invoice-fonts.zip` nobody saved; with `VITE_FIXTURE_RICH=1` Pretzel's gallery, PDF, chime and page are unsaved agent files. The fake managed world keeps people's sent files in Files and sends `message.updated` and `files.changed` after a save or a removal. | Every state can be seen and tried without a runtime. |
