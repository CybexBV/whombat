# Better hardware support on Android (AP-3250…AP-3299)

John, 2026-10-20: “I installed a whombat appliance and the mic is not working, also WiFi is not working by default. Is
there a way to implement better hardware support, including WiFi? … we should support other devices as well.” The
product decisions are Whombat's `docs/decisions/hardware-support.md` (HD-01…HD-11); this is stream M of
`docs/implementation/hardware-support/assignment.md` there: on the phone, This Whombat's NETWORK card with the Wi-Fi
sheet and About's HARDWARE card with Share report. The shared models, every word and the fake machines are the web
stream's (`hardware-support-web.md`, AP-3200…AP-3221: `@whombat/client` `host/network.ts`, `host/hardware.ts`,
`@whombat/client/host/fake`), on contracts 0.102.0. No mockup: This Whombat's own cards and sheets (SCREEN, DIAGNOSTICS).

The parts: `apps/mobile/src/managed/NetworkSection.tsx` (NETWORK), `WifiSheet.tsx` (the sheet), `MachineParts.tsx` (the
bars and a change's mark), `HardwareSection.tsx` (HARDWARE), `useMachine.ts` (which machine, the poller, scrolling to
HARDWARE), `machine.ts` (the pure part, tested), the demo world's machine `fixtures/machine.ts`. This Whombat's screens
only gain insertion lines (`WhombatScreen.tsx`, `WhombatAboutScreen.tsx`, the demo's `SettingsPages.tsx`), so the desk
auto-pair work on the SCREEN card merged without touching them.

| AP-3254 | **Join a Wi-Fi network is the card's last row, across its width** (secondary while connected, primary when not, waiting while a change runs; none without a Wi-Fi card), and opens **the Wi-Fi sheet** (the settings bottom sheet): the networks nearby as 52 dp rows — bars, the name over “Connected” (green), “Saved” or why it can't be joined (company and WEP networks dimmed and not tappable), a lock when secured; the one in use not tappable — then **Other network…** (name, Security Password · None); **Look again** · **Cancel**. | AP-3256 | **After Join the sheet follows the change** NETWORK's poller reads: “Joining…” until it is known, then the shared line (“Joining Home…”, “Joined Home” · “Checking that Cybex reaches the internet there…”, “Couldn’t switch to Café Wombat” over HD-11's sentence) in a small panel, with **Close** while it runs and **Done** after. | AP-3257 | **A refusal goes back to the form** (`wifiAfterChange`): a wrong password under the password, red-bordered and emptied; not found or failed above the buttons. **Show** makes the password Android's visible-password field, which the keyboard neither suggests for nor learns from: React Native applies `keyboardType` before `secureTextEntry`, and `secureTextEntry={false}` clears the visible-password flags (checked on the emulator: `0x80091` became `0x80001`, with suggestions), so Show and Hide make a new field — focused again, the typed text kept — that gets `secureTextEntry` only while hidden. Closing the sheet forgets everything typed. | A secret never reaches the keyboard's dictionary, logs or notices (§1 Copy). |
| AP-3258 | **Accessibility**: every control is the 44 dp `Button` (Show/Hide 48 dp to match the field) or the sheet's 52 dp rows; network rows are read as the shared label (“Neighbours, secured, good signal”); the bars, locks and change marks are hidden from TalkBack; Forget says which network (“Forget Office”). The touch-target audit counts the new files (`WifiSheet.tsx` 1, the others 0) and the reading-order audit includes them. | README “Accessibility”; the audits catch a control added later without its size. |
| AP-3259 | **HARDWARE in About, right before DIAGNOSTICS** (AP-3228), read once when About opens (a skeleton, then “The hardware couldn’t be read right now.” with Try again): the machine's name over CPU, cores, memory and kernel (mono), **Share report** under them; the parts that don't work, one row each in HD-11's words, or “Every part has a driver.” (green) when none; then the groups under small mono labels, each part compact (not a control): a dot only when it doesn't work, its name (14/500) over vendor, what it does and its driver on one mono line, “No driver” in red. | The web's section (AP-3229); the driver moves onto the line under the name because a column at the end squeezes long names at phone width. “Every part has a driver.” (the shared `allWork`) answers “is it fine” at a glance. |
