# Agents' computers (AP-617…AP-627)

John, 2026-10-02: “Give each agent a real computer and let it do what it's asked. Keep a person in the loop only for
consequential actions, and keep the walls that protect the team.” The spec is Whombat `docs/decisions/agent-computer.md`
(AC-00…AC-52: an unprivileged container per agent inside the appliance, keys on the computer during their owner's
turns, production servers closed until a person says yes, the guard that asks in the same turn, learned skills active
at once); the shapes are contracts 0.36.0 (CT-217…CT-227, vendored in `63b2e47`). Not mocked (B-05): every screen below
is in the existing language (the Vault's choosers and notices, the settings page's rows, the approval card and modal,
the skill card). All copy is core's unless listed as ours.

**Gating.** Everything new needs the runtime feature `agent.computer` (older runtimes look as before). Where the host
answers `HostInfo.computers.available: false` (a development stack, AC-23) only the Computer tab shows, with the reason;
the Vault's delivery choice, Production, “Destructive commands on other machines”, ALWAYS ALLOWED COMMANDS and the
profile pane's line need computers to run (`useComputers`: `feature`, `host`, `available`). Push to main needs only the
feature (an agent's push to the default branch is decided by it with or without a computer). The fixture world's host
has no `computers`, so the mock's screens and the visual baselines stay as drawn; `VITE_FIXTURE_COMPUTERS=1` adds them
(AP-626).
