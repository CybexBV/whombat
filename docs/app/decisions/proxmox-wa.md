# Full Proxmox support — guest editing on the web (stream WA, 2026-10-17)

Stream WA of the Proxmox build (Whombat `docs/decisions/proxmox.md` PX-01, PX-08; brief
`docs/implementation/proxmox/assignment.md`): everything Rackoon's Hardware, Options and Cloud-Init tabs edited, ported
from `hosts/web/src/features/guest/` and restyled to Whombat's tokens. Builds on the one-Whombat port
(`one-whombat-things.md` AP-1312, AP-1319). Contracts 0.80.3 are enough: `config.set`, `disk.resize`, `disk.move`,
`ha.set` and `ha.remove` and the `HostGuestConfig` fields (`pending`, `pendingDelete`, `restricted`, `ha`) were there.

| # | Decision | Why |
|---|---|---|
| AP-1385 | **Property strings move to `packages/client/src/hosts/props.ts`** (re-exported by `config.ts`, so imports stay `@whombat/client/hosts`). Every dialog's value comes from a pure reader/writer pair in `config.ts` (disk options, NICs, mount points, CPU type, display and machine type, start order, hotplug, guest agent, features, HA) that writes only the sub-keys that changed. Tests: a fuzzed round trip and a table of real Proxmox values that every writer gives back byte for byte when nothing changed. | MANAGE.md 2.4: round trips must be lossless; options Whombat has no field for (`aio=`, `queues=`, `mount=nfs`) must survive an edit. |
| AP-1386 | **Every row says what it becomes at the next restart**: “→ 8 GiB (after restart)” in the warning colour, “→ removed (after restart)” for a pending removal, “New” for a device that exists only after the restart. Rows over several keys (processors, start order) compare their words before and after. | The banner lists keys; the row is where people look. |
| AP-1387 | **Hardware keeps Whombat's cards** (Hardware/Resources, Disks and drives, Network, Boot order, Other settings) instead of Rackoon's one card; the **Add** menu sits in the first card's head and lists only what can be added now (no Cloud-Init drive, EFI disk or TPM when there is one). | Whombat's earlier layout (AP-1312); the shared row menu has no disabled state, and a choice that can't be made is noise. |
| AP-1388 | Row actions: **Change** as a text link plus a **“…” menu** (the shell's `useRowMenu`: portal, arrow keys, Esc) for Grow, Move to another storage, Detach and Remove; unused disks get **Attach…** and **Delete…** inline. | A menu inside a card would be clipped by its rounded corners; one menu component everywhere. |
| AP-1389 | **Moving is blocked, and said why,** for a running container's disks and a running VM's TPM state (“Stop it first: Proxmox moves a container’s disks only while it’s stopped.”): the menu item says when, the dialog says why with Move off. The EFI disk moves live. | Proxmox refuses both; saying it before the task beats a failed task. |
| AP-1390 | **Detach** (a disk or mount point → `unusedN`, “nothing is deleted”), **Remove** (NIC, CD/DVD, cloud-init drive) and **Delete** (an unused disk: destroyed) are separate words. Delete is a serious review sent with `confirm: true`, without the “it’s running” note. | MANAGE.md: deleting an unused disk needs confirm; the words must match what happens to the data. |
| AP-1391 | A **container's unused volume attaches as a mount point** (folder asked, first free `mpN`); a VM's on a bus (first free slot shown). | Rackoon had no Attach for containers; the hub accepts an unused volume on `mpN`. |
| AP-1392 | **New mount points are in backups by default** (Proxmox leaves them out); the tick is visible. New disks: IO thread on, in backups and replication. VM NICs: VirtIO, firewall on; container NICs: next `ethN`, DHCP. | A homelab's data volume is what people expect to be backed up. |
| AP-1393 | **ISO images from any ISO storage**: the storage first, then its images — from `choices.isos` when the host sends them, else that storage's `content.list`. “No disc” always. | Rackoon's dialog listed only the first ISO storage's images. |
| AP-1394 | **Other settings** (last card on Hardware): every key no tab has a row for (PCI/USB passthrough, serial ports, `args`, SMBIOS, `lxc.*` …), raw and read-only; restricted ones with the lock and “Change this in Proxmox” (“in Incus” for Incus). Restricted keys that do have a row (a bind mount, locked features) show the lock in place of the actions. | PX-01's restricted keys and the brief's rare keys in one place, without pretending Whombat can change them. |
| AP-1395 | **The guest agent dialog** edits on/off, trim after move or clone, freezing file systems for backups and the channel, and keeps every other sub-key; only “off” with nothing else deletes the key. | PX-08: the old flag dialog wrote `agent=0`, dropping the rest. |
| AP-1396 | Flags with Proxmox's defaults: tablet, ACPI and KVM default on, local time defaults on for Windows OS types; a value equal to the default is written by removing the key. | As Proxmox stores them; the row reads the same either way. |
| AP-1397 | **High availability** is a card under Options, shown on a cluster (`choices.cluster`, or the guest already has `ha`): state, “1 restart there, then 1 move to another server”, the note; owners (`hosts.status.canManage`) get Set up / Change (through a `key  old → new` review) and Remove (asked). The card sends `ha.set` / `ha.remove` with its own done words (“Saved high availability for web.”) instead of `manageDoneText`, which is stream WC's file. | Rackoon's HA row; one review for every change. The lead may fold the two words into `manageDoneText` at merge. |
| AP-1398 | **Tags are chips**: Enter, “,” or “;” adds, × or Backspace removes, text still in the field counts at Review, duplicates ignoring case drop; stored as Proxmox's `a;b`. | The brief; Proxmox's own list format. |
| AP-1399 | **Cloud-Init**: the password typed twice and removable (the review opens at the removal), SSH keys checked line by line and stored URL-encoded as typed, DNS domain and servers in one dialog (the same one containers use), package upgrades (default on), IPv4 and IPv6 per network device with address and gateway checks (`cidr6Error`, `ip6Error`). | Rackoon's tab plus the gaps the review found. |
| AP-1400 | **Fixtures** in `packages/client/src/hosts/fixtures-wa.ts`, hooked by one line in `fixtures.ts` (`handle: withWaFixtures(world, handle)`, plus its import): seeds for VM 118 (data disk, unused disk, VLAN NIC, GPU passthrough, HA), VM 123 (Windows, TPM, two ISO storages, USB passthrough, agent settings, a pending core change), VM 124 (stopped, two unused disks), CT 132 (mount point, bind mount, unused volume, fixed address, DNS, HA), CT 134 (locked device and features), CT 144 (stopped); Proxmox's rules (detach to `unusedN`, delete needs confirm, attach, new volume names, locked keys refused, unknown network as a field error, removals waiting for a restart, grow, move refused for a running container) and `ha.set` / `ha.remove`; a second ISO storage (`nas-iso`) and disk storage (`tank`) in the choices. | Brief: new handlers in the stream's own file. |
| AP-1401 | The tabs' own styles are a CSS module of their own (`guest/GuestEdit.module.css`, classes `wa…`), not appended to `Things.module.css`. | Same prefix rule, no merge conflict at the end of a shared file. |
| AP-1402 | `HardwareTab`, `OptionsTab`, `CloudInitTab`, `EditDialog` and `PendingBanner` keep their props, so `GuestPage` (stream WB) is untouched; `Row` and `EditBtn` moved to `guest/editParts.tsx` and are re-exported from `HardwareTab`. A container's tab is still labelled “Hardware” (`GUEST_TAB_WORDS`, WB's); its card says “Resources”. | No edits to other streams' files. |
