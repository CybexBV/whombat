# Waiting for T3 Code in a thread (AP-6610…AP-6617)

John, 2026-11-03: Dusty hands a lot of work to T3 Code, and while it waits nothing in Chat says so: “In the Chat thread
list and in the chat itself I would like to see some kind of subtle indicator what is happening.” A mockup first, then
“Implement this fully.” The box's side: Whombat `docs/decisions/t3code.md` T3-24…T3-28.

| # | Decision | Why |
|---|---|---|
| AP-6610 | **One read per conversation**: `useHandoffs(burrow, conversationId)` (`conversations.handoffs`), kept current by the `conversation.handoffs` frame, which replaces the cached list; a missed frame is caught up on the `conv` topic's resync. Empty while loading and from a box without the read. | Every place that shows it (reply rows, the thread's end, Settle) asks the same small list. |
| AP-6611 | *Superseded in part by AP-9304 (chat-inbox-web.md): on the web Chat's rows say “Working”; the thread's head keeps T3 Code's line.* **The reply row**: T3 Code's mark (its letters on an 18px ink tile, as its own white on black logo, in both themes) and “**T3 Code** is working on it · 6m”, “is finishing up”, “asked a question”, “needs your OK” (warn, with the waiting dot), “is waiting for the checks on #342” (muted: nothing to do), “· 2 jobs · 6m” for more than one. While it works the tile breathes a slow halo in the run line's green (still with reduced motion). Ended work leaves the row to the agent's answer. | The row already says “Dusty is looking into it” while Dusty works; the same spot says where the work went once Dusty's turn ended, so a thread never looks finished while work goes on. |
| AP-6612 | **Superseded in part by chat-threads-cards.md CTC-02: a Chat or Feedback row says {assistant} is working or Handed over.** **The agent's own turn comes first**: while it thinks in the thread (or the server says its turn is on it) the row is its own, “Dusty is answering T3 Code” with the dots when T3 Code asked it something. | One line per row; what Dusty does now is the most current. |
| AP-6613 | **Web, the thread's end**: above the thinking line, not a message: a quiet box with the 26px mark, “T3 Code is working on it” and a seconds clock, “Now: running the tests” under it, “Open in T3 Code” (a new tab) and a chevron that folds out its title, program and steps (✓ done, a green dot for the current one, the command in mono). Amber border and a solid Open while it needs the person's OK. Ended: one muted line, “T3 Code finished in 14m · Open in T3 Code”, until a reply comes after it. | The mockup John approved. |
| AP-6614 | **Phone, the thread**: the same line just above the reply box, in sight while scrolling back; the line itself is the button that folds out the steps (52dp), Open is a 44dp icon button that opens T3 Code's page in the browser. | Thumb reach and 44dp targets; the composer is where the eye ends. |
| AP-6615 | **No Settle while T3 Code works on it**: the room's Settle, the thread's head and the phone's swipe and menu offer none (the box refuses it too, T3-27). | A settled thread would leave the room while its line still says something. |
| AP-6616 | **Fixtures**: `VITE_FIXTURE_T3=working\|asked\|needs_ok\|checks\|ended` adds Mara's Settle bug that Neo handed to T3 Code six minutes ago, in that state (`chatChannelFixtures.ts`). Off, Chat is as drawn. | To compare each state in both themes. |
| AP-6617 | **Shared words** in `packages/client/src/handoff.ts` (`handoffRow`, `handoffLine`, `threadHandoffs`, `endedWords`), folded into `threadWork` (`by: 't3code'`, `since`, tone `calm`) so web and phone say the same. | One rule, unit-tested. |
