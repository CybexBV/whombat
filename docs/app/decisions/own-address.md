# The own address in the apps (AP-9480…AP-9494)

2026-11-18, phase 1 of Whombat [own-address.md](../../decisions/own-address.md) (OWA-01…OWA-20), the browser route only
(design §7.1 “Phones”): a phone makes the box's passkey in its browser at the address and joins the app with a device
link. Android's in-app box passkeys and the iPhone's sign-in sheet wait for their device tests. Shared code:
`@whombat/client/managed` (`own-address.ts`, `box-passkeys.ts`); the box page: `apps/web/src/managed/BoxSetup.tsx` (the one setup, whombat-link-app.md) and
`BoxRoot.tsx`; Settings: `apps/web/src/features/machine/OwnAddressSection.tsx`; the account's side:
`apps/web/src/managed/LinkWhombat.tsx`.

| ID | Decision | Why |
|---|---|---|
| AP-9480 | **The page learns that a box is set up at its own address by asking it to start a claim** (`probeOwnClaim`: `enroll.claim.local.start`, with the claim link's secret from `/c/<secret>` when the page has it). An unclaimed commercial box that takes it is one; `claim_link` means “open the link on its screen”; `claim_local_unavailable` or `claim_here_unavailable` means a box with the shared route, which gets today's page. The page is at the address when its host is an own-address host (`ownAddressOfPage`). | No answer the apps read carries the A3 flag, and contracts are frozen at 4.3.0. The start keeps only a claim id in the box's memory and costs no guess. |
| AP-9481 | Superseded by AP-9500, AP-9501 (whombat-link-app.md). **The setup at the address is claim → link → the box's passkey**, in onboarding's frame like the community setup. The claim asks the four letters, then name and email. On a local-network or Tailscale page the passkey step is left out (another RP ID). Link and passkey each have **Later**; Settings → This Whombat → About links later (“Link to your Whombat account”). | Design §7.1's order. Nobody is stuck on a step that needs the account at hand. |
| AP-9482 | **Making the box's passkey takes two touches** (`createBoxPasskey`): the first makes it and gives the box its backup key from PRF at creation with a fresh random salt (`newKitPrfSalt`); the second opens the saved envelope (`backup.passkeyKey.verifyBegin`/`Confirm`). Without PRF at creation the first touch splits in two. The page says what came of it: backups unlocked, backups take it once saved, or no PRF (the paper copy then). The options are refused unless the challenge is the box's own for the pinned PeerId and RP ID. | Design §7.5; SPK-03's check kept apart from the arming. |
| AP-9483 | **At the address, a browser the box doesn't know signs in with the box's passkey first** (“Sign in with this Whombat's passkey”, `boxPasskey.enroll*` bound to its key); pairing is a click away. It comes before the development sign-in. LAN and Tailscale pages never offer a box passkey. | Design §7.3: a box passkey works on any session, but browsers elsewhere are on another RP ID. |
| AP-9484 | **A device link opened on a box with an own address says “Only continue if you started this at <address> or in your Whombat app.”** (the address from the link's `o=`, else the page's). | Design §7.3's words, where a link is used. |
| AP-9485 | **§7.5's words show in one place each**: the box passkey's in the setup's passkey step, which only a claim the box took at its address reaches, so never on Home or a box with the shared route; the account passkey's on “Link a Whombat”, which exists only for boxes set up at their address. Both link “Why?” to the privacy page until its sentence exists. | The plan's “only when the account's Whombats include an A3 one” would hide the words at the first link, when they matter most. |
| AP-9486 | **The account's list shows a Whombat set up at its own address by name only**, with “Its address is in your Whombat app and on your Whombat's screen.”, and no Open, rename or recovery kit. | Design §7.1: app.whombat.com never opens a box and never shows its address. |
| AP-9487 | **“Link a Whombat”** on the list opens a page: the Whombat terms ticked first, then the code (`orgs.createWhombatLink`) with its countdown, a new one when it runs out, and the account passkey beside it (control's options with no Whombat, no PRF: `createAccountPasskey`). | The link carries the terms (design §7.1); the account passkey is offered while getting the code. |
| AP-9488 | **Settings → This Whombat → About → ADDRESS**: the address with Copy and whether it works, the switch “Reach my Whombat's page from anywhere”, the link row, the certificate's end, the last check and each stretch the watch couldn't check (“Whombat couldn't check certificates from … to …”). A certificate the box didn't ask for, still valid, turns the state line red; the banner is the notice's. Nothing shows on a box without an own address or before 4.3 (`unknown_op`). | Design §6 and §7.1, in the part where the box's facts are. |
| AP-9489 | **The phone keeps the address a device link carries** (`KnownAppliance.ownAddress`, apart from `direct`, which each welcome replaces) and dials `wss://<host>/v1/direct` first (`ownAddressRoute`, sent as a TLS route; the connector reads only the socket). About shows ADDRESS with Copy. `passkeysForBox` gives the box's own host as RP ID for its passkeys and the hosted UI's for the account's; nothing calls a box ceremony yet. | OWA-19 keeps the address out of `DirectWay`; the in-app ceremonies are wave 5's. |
| AP-9490 | **The iPhone app's associated domains never carry a wildcard or a `box.`/`dev.whombat.app` entry**; `app-config.test.ts` checks it. | OWA-17: a file at a parent host Cybex runs would let any app it names use box passkeys. |
| AP-9491 | **The fake world has a box set up at its own address** (`maple-otter-river.dev.whombat.app`, claim link `kxmprt`): `faults.ownBox(true, {foreign, missed})` shows it on the box target, `ownLetters`, `ownClaimLink`, `makeWhombatLink` and `ownLinked` drive it; control makes link codes and lists it by name once linked. Review shots: `OWN_SHOTS=<dir>` with `e2e-managed/own-address-shots.spec.ts` (the box page's: `LINK_SHOTS`, AP-9514). | Visual checks and the journey test (`ownJourney.test.ts`) without a door or Pebble. |
| AP-9492 | **Devices → PASSKEYS on the box's own pages, for a box with an own address, shows the box's own passkeys** (`BoxPasskeysSection`): the §7.5 words with “Why?”, Add a passkey at the address (elsewhere a link to it), the box passkeys (`rpId` = its host) with Remove. The hosted shared passkey isn't offered there; the hosted app keeps today's section. | Inside the own address the hosted passkey can't open the box, and app.whombat.com never opens such a box. The page can't tell A3 apart, so any box's own pages get it; Home's shared passkey stays reachable at app.whombat.com. |
| AP-9493 | **Once the box's passkey is made, a backup key it couldn't arm never reads as a failure**: no backup service (`not_implemented`) says the passkey opens the Whombat and there are no backups to unlock yet; a dismissed touch or a refusal says to touch it again in Settings → Devices. | The passkey works; only the backups wait. |
| AP-9494 | **The box page lets a browser in with the recovery kit** (`recovery.enroll` over its own enrollment session): from the box passkey screen and from pairing, on every commercial box. The kit file names the account; a typed key works where this browser knew the account. A kit naming another Whombat's identity is refused before anything is signed. | One of the ways into a box set up at its address (OWA-15), with today's contracts. |
