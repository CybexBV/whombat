# No Work view on the web; Deploys a page of its own (AP-849…AP-853)

John, 2026-10-08, looking at the sidebar's Work page: “This is absolutely useless … Remove it fully.” Its RECENTLY DONE
listed every chat reply as “Dusty’s turn · asked in a mention”, and everything useful in it already lived elsewhere:
NEEDS YOU is the Inbox's top section (web-efficiency.md WE-11, with the same rows and controls), a failed turn is a
“Turn failed” card with Try again in its conversation, a live run is a card or line in its thread, and an agent's
question that holds a run is a QUESTION item in Needs you. The one real feature under Work was its Deploys tab (WE-17).
The Android app drops its Work screen in parallel (its own decisions); this file is the web and `@whombat/client`.

| ID | Decision | Why |
|---|---|---|
| AP-849 | **No Work view on the web.** The sidebar's Work row, the `/work` screen with its sections (RUNNING, QUEUED, BLOCKED, FAILED, RECENTLY DONE), its Work · Deploys tabs, empty states, `?section=` scrolling and tests are gone, and so is `features/work`. The burrow shell no longer reads `work.overview` on every page for the row's count; it is read where it shows: the Inbox's NEEDS YOU and the agent pane's Stop. Comments that named the Work view as a place now name the Inbox or `work.overview`. | John asked to remove it fully. A list of every finished turn was noise, and each useful part has a better home where the work happens. |
| AP-850 | **Deploys is its own page, `/deploys`, with a sidebar row.** The environments board and the history (`features/deploys`, moved from `features/work`), under a header in the Inbox's language: 1040px page, 36px title “Deploys”, and the old tab's muted line, “What runs where: every deploy agents and deploy jobs recorded, the live version first.” On a Whombat without `deployments` the page says “Update your Whombat to use Deploys.”, as the tab did. The **Deploys** row (the mock's `deploy` icon slot) shows only with `deployments` and at least one environment on the board: `useShowsDeploys` in `@whombat/client/react` reads the board itself (`deployments.environments`, `retry: false`, the page's key, so the page opens from the cache) and `deployment.recorded` refetches it, so the row appears with the first deploy. It sits right after Files and above the Inbox (the burrow-wide pages together), selected on `/deploys`; the visual comparisons hide it like the other additions (`[data-nav-deploys]`). | The deploys board was the only real feature hiding under Work. A row that opens an empty board on a Whombat that never deploys is noise, so it follows the Files (AP-772) and Automations (BP-C13) rule: there once there is something to show. |
| AP-851 | **Old Work addresses and Work links keep working.** `/work` (with or without `?section=`) redirects to `/inbox`, `?section=needs_you` to `/inbox?filter=needs_you`, and `/work/deploys` to `/deploys`, replacing the address. The old form `/<burrow>/work…` works too. `/work` and `/work/deploys` stay in `BURROW_ROUTES`, so `splitBurrowPath` still reads them and the router can redirect them. The mapping is shared: `workPath(section)` in `@whombat/client` (`deploys` → `/deploys`, `needs_you` → `/inbox?filter=needs_you`, anything else → `/inbox`), with `DEPLOYS_PATH`, and `appPath({ type: 'work', section })` uses it. The deploy line's “Deploys” link goes to `/deploys`. | The servers still send `{ type: 'work', section }` links (a deploy event's `section: 'deploys'`, a plan step without a place), and old messages, emails, pushes and Android app links still say `/work…`. One mapping in the shared package lets the phone send them to the same places without a contracts change. |
| AP-852 | **The NEEDS YOU rows live in the Inbox, and the server's `work.overview` stays.** `NeedsYouRow` (was `WorkRow`), its action logic (`needsYouModel.ts`: labels, tones, `buttonActions`, `actionReady`, `activitySource`) and its CSS moved to `features/inbox`, unchanged: Approve, Decline, Details, Report back, Try again, Stop, Take over, Retry, Reassign, Ask for a report, Show activity and Technical detail behave as before. `work.overview` and `work.needsYou` stay on the server and in `@whombat/core` (no contract change), and so do `useWorkOverview` and `useInvalidateWork`. | The overview backs the Inbox's NEEDS YOU, the agent pane's Stop (`RightNowStop`) and older apps that still have a Work view. John asked to remove the view, not the data behind the Inbox. |
| AP-853 | **The #general welcome no longer sends people to Work.** In `generalWelcome` (`@whombat/client`, shared with Android), the line about handing an agent a task now ends “… asks before anything that needs approval, and you can follow its progress there.” (it was “… under Work.”). | It pointed to a place that no longer exists. An agent's progress shows in the thread it replies in, as run cards and lines. |
