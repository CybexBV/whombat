# The phone app keeps going: a newer Whombat, a locked phone (2026-10-31)

John, 2026-10-31: “On iOS when I click "Automations" the app crashes … Also it happens occasionally that when I return to
Whombat I see the login screen, but when I force close and open the app again I am logged in.” His TestFlight crash
report (3.25.1, App Store Connect's beta feedback) was a JavaScript error while the Automations tab drew. Home's two
The tracker automations carry recipe members newer than the app (`decideFeatures`, `t3Review`), and `recipeOf` rebuilt the
recipe with a strict parse that threw, so the tab never drew and React Native ended the app. 3.26.0 knows
`decideFeatures` but not `t3Review`, so it crashed too. The sign-in screen came from the Keychain: its entries are
locked while the phone is, and the control client reads a token it can't read as none.

| # | Decision | Why |
|---|---|---|
| AP-6370 | **`recipeOf` is null for a recipe this version can't parse** (core `rebuild`: `AutomationRecipe.safeParse` first), so the list, the page, the glance and the plan treat it as a definition of its own and say what its steps do. | An answer that doesn't decode tolerantly (a strict definition with members this version doesn't know) reaches the screens as it came. Code that only describes an automation must never throw on it. |
| AP-6371 | **Every tab and page has its own error boundary** (`navigation/PageBoundary.tsx`, the navigators' `screenLayout`): a page that fails to draw says “This page didn’t load.” with *Try again*, plus *Go back* on a page over another; the tab bar stays. | One page shouldn't take the app down: a Whombat newer than the app can always send something it doesn't expect yet. |
| AP-6372 | **A keystore call refused while the app is away is made again back in the foreground** (`foregroundStore` in `managed/stores.ts`, `managed/secureStore.ts` over `AppState`). A refusal in the foreground stays the store's answer (AP-594). The entries stay `WHEN_UNLOCKED_THIS_DEVICE_ONLY`. | The app still runs for a moment after the phone locks (a reconnect, a list a push reloads), and iOS may start it while locked. The cloud token then read as none: `auth.session` said signed out (the sign-in screen), or a ticket went without it and control's 401 showed “Sign in again”. The token was there all along, so a force close helped. Waiting keeps the Keychain's protection, where `AFTER_FIRST_UNLOCK` would have loosened it for the endpoint key too. |

## The app tells its Whombat what stopped it (2026-11-13)

John's TestFlight report of 2026-11-13 (“Swiped back to the app”, 3.117.1) was again a JavaScript error ending the app,
350 ms after the phone's session opened on its return (Home's log), outside any page's boundary. Apple's crash report
names neither the error nor where it was, the phone kept no analytics copy, and the app wrote nothing down, so the cause
couldn't be found.

| # | Decision | Why |
|---|---|---|
| AP-9260 | **An error that ends the app is written down before the app goes** (`errors/nativeErrorNotes.ts`: React Native's exception decorator, a synchronous file in the app's documents), and so is one a page's boundary caught. The note is the error's name and words, its innermost frames, its components and the build; never what was on screen. The newest five are kept. | The decorator sees every error React Native reports, the ones thrown outside drawing and the ones no boundary caught, with the error's own words, a moment before the native side ends the app: an asynchronous write would never finish. |
| AP-9261 | **The notes go to the Whombat as the next session opens** (`devices.reportErrors`, a page's at once while one is open), and the box writes each into its log as a warning (“app error noted on the phone”), storing nothing. They leave the phone only once the box has them. | Whoever looks into a report reads the cause on the box (remote help's Look), without asking the person to find and share a file. |
| AP-9262 | **`publish:ios` keeps each build's bundle source map on the Mac** (`~/whombat-ios-build/sourcemaps/<build>-<rev>.map`). | A note's frames are lines of the minified bundle; the map turns them back into the code's. |

## The ways the app could end, and endings it couldn't see (2026-11-18)

John, 2026-11-17: several crashes of the iPhone app in a week, no logs. Home had no error note from the phone in the
four days its log went back, on builds that all carried the notes: so the app was ended in native code or by iOS (its
memory, not answering), which the notes couldn't see, or while its code was still loading, which they missed. A council
of three models read the code; what follows removes the ways they found the app could end and makes the next ending
name itself. None is proven to be the crash of that week.

| # | Decision | Why |
|---|---|---|
| AP-9400 | **The live activities module keeps its tasks under one lock** (`modules/whombat-live` iOS: `tokenTasks` and the two observer tasks; a check-and-insert is one locked step, tasks are cancelled outside the lock, the lock is never held across an `await`). | `upsert`, `end` and `endAll` run on Swift's concurrent pool and `observe` in a task of its own; two of them writing one dictionary is memory corruption, and the app starts and ends several activities on every return to the foreground. |
| AP-9401 | **A pick's photos are prepared one after the other** (`oneAtATime`, `preparePhotos`). | Each holds its decoded original until it is saved, about 190 MB for a 48-megapixel photo; ten at once got the app closed for memory. |
| AP-9402 | **Voice typing's recorder lives on one queue and raises nothing Swift can't catch** (`modules/whombat-voice` iOS): `start`, `stop` and `cancel` each enter the queue once and nothing on it enters it again; the microphone is tapped in its own format (`format: nil`) with the converter made from the buffer's; a new engine per recording; a buffer of an earlier recording is ignored; the file calls are the throwing ones; a start that fails gives the audio session back. | The engine was stopped from two threads at once, a format read before a headset connected raised an Objective-C exception at the tap, and so did a write to a full disk: each ends the app. |
| AP-9403 | **A list is scrolled to a row only while it has that row** (`screens/scrollToRow.ts`, Chat's and a file's delayed scrolls). | React Native's list throws on an index past its rows; in a frame or timer callback that is outside every page's boundary and ends the app, and a list can get shorter between the asking and the scroll (a saved copy replaced by a fresh answer). |
| AP-9404 | **A session listener that throws stops nothing else** (`@whombat/client` `session/listeners.ts`: the connection's state, notices, subscriptions, live events, collab): the others still hear, the connection stays, the error goes to `onListenerError`, and the topic of a live event a listener threw on is read again, as after a gap. | From a timer the throw ended the app; from the read loop it was taken for a lost connection, which hid the error behind a reconnect. |
| AP-9405 | **One more boundary around everything the app draws** (`App.tsx`, the page boundary and its words, inside the theme and safe area it needs). Errors in timers and promises are outside it, as outside any boundary. | The tab bar, the bridges and the sign-in screens had none. |
| AP-9406 | **A stray `%` names nothing instead of throwing** in an attachment's path (`resourceFromUrl`) and in the link a finished sign-in opens (`thingOfUrl`). **`NSPhotoLibraryAddUsageDescription`** is set for the share sheet's Save Image. | The two decodes the 16 Nov pass left; older iOS ends an app that saves to Photos without the line. |
| AP-9407 | **Errors while the app's code loads are noted too**: the notes start in `index.ts`'s first import after the polyfills (`errors/start.ts`, which loads nothing of the app) and also listen on React Native's native error handler (`RN$registerExceptionListener`), the only one called until the bundle has loaded. An error both hooks saw is noted once. | The decorator is never asked for those errors, so a start-up crash left no note. |
| AP-9408 | **Quiet errors are noted** as `kind: 'page'` with a `name` saying which: a promise nobody caught (`UnhandledRejection`, Hermes's tracker, which release builds leave off) and a session listener that threw (`ListenerError`). A rejection is held for two seconds and let go when someone caught it after all (`createRejectionHold`). The same error is noted once a run, at most three quiet ones a run, and in the five-note file a note of something the app went on after never pushes out an ending of the app. A note the box would refuse isn't kept. No contract change: `kind` and `name` are what they were. | They say what went wrong before something visible does; unbounded they would fill the box's log and push the one crash note out, and one refused note would hold back every later one. |
| AP-9409 | **“Ended while open” is noted at the next start** (`errors/endedWhileOpen.ts`, iPhone only): a small file is written while the app is in the foreground (again on a page change, a memory warning and once a minute) and removed in the background; one still there, with no JavaScript error noted in that run (what iOS reported late about an earlier ending doesn't count), becomes `kind: 'app'`, `name: 'EndedWhileOpen'` with how long it was open, when it was last alive, whether iOS warned about memory, whether it was inactive, and the page's route name. It claims no more than that. | A crash in native code, a memory or watchdog ending and a frozen app leave nothing else behind. Android's own updater ends the app while it is open, which would be noted at every update. |
| AP-9410 | **What iOS reports about the app's endings becomes notes** (`modules/whombat-diagnostics`, MetricKit; `errors/diagnostics.ts`): a crash is `NativeCrash` (iOS's reason, the build and time span it is about, the crashed thread's frames as binary, UUID and offset), a hang is `Hang` (`kind: 'page'`), and a day's counts of endings that weren't ordinary (memory limit, watchdog, bad access…) are `ExitCounts`. The module keeps each payload as iOS's JSON until it is noted; one that can't be read stays. **`publish:ios` keeps each build's dSYMs** (`~/whombat-ios-build/dsyms/<build>-<rev>/`, the newest 30). | The only place a native crash is described and a memory or watchdog ending is named, with no third party. It arrives a start or a day late and can't be tried on a simulator: it is proven by the first real payload. |
| AP-9411 | **Each note also goes into the phone's sync log** (`noteLine`, within the length the log reads back), the pending ones again at the start. | A note exists where the person can share it even when no session opens to send it. |
