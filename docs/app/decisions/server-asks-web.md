# Asks you first per server: the web (stream web, 2026-10-18)

The web and shared-client part of Whombat `docs/decisions/server-asks.md` (SA-01…SA-09), built to contracts 0.86.0
(CT-380…CT-382): the “Asks you first” row on a server's System tab, and “Don’t ask again on {server}” on a Servers
approval card and in its modal. Android has its own stream; the shared pieces below live in `packages/client`.

| # | Decision | Why |
|---|---|---|
| AP-1717 | **The row sits in the Agent card of the System tab, after the six switches** (`AsksFirstRow` in `SystemTab.tsx`): label “Asks you first”, the hint for the current choice under it, `SegmentedControl` size `sm` as a `radiogroup` on the right (the KEYS rows' Off · Ask · On shape), described by the hint. On the server this Whombat runs on (`detail.server.hostsThisWhombat`) the hint adds `selfNote`. Value: the settings' `asksFirst`, else the detail's, else `risky`. Words verbatim from `HOST_ASKS_FIRST_WORDS`. | Same place and row shape as the other things an owner decides about Whombat on that server; no mock exists, so the nearest existing row pattern. |
| AP-1718 | **Owners only, on a Whombat with `hosts.asks`; members see nothing new.** The row shows only when the server settings were read (owners, `hosts.status.canManage`), the same rule as the switches, which members don't see either. Never opens the existing `ConfirmDialog` (`confirmTitle`, `confirmBody`, “Stop asking”, not the serious red); back to Before risky actions saves at once. Both save `hosts.updateServer {asksFirst}` alone and toast `changed(name, asks)`; a refusal shows inline in the dialog (Never) or as a toast. The name is the server's id, as everywhere on the server page (`HostServerInfo` has no display name). | SA-05, SA-08: the confirm is for widening only; one read-only value for members would be a new pattern the switches don't have. |
| AP-1719 | **The fixture world keeps “Asks you first” like Whombat does** (`packages/client/src/hosts/fixtures-sa.ts`, outermost layer of `createHostsFixtures`, `world.asks`): the fleet rows, `detail.server` and the settings carry `asksFirst` (`risky` until changed); `PATCH servers/:id` with `asksFirst` stores it, a body with only `asksFirst` doesn't reach the hosts routes, a member gets 403. The one-Whombat restart approval on pve-02 carries `params.server`, and its decide with `scope: 'agent'` sets pve-02 to Never through the web's hosts layer (`stopAsking`). | SA-04, SA-05, SA-07 as the server does them, so fixture mode and tests read back what they did. |
| AP-1720 | **“Don’t ask again on {server}” sits where “Always allow …” does**: on the card, a secondary button between Approve (and “Tonight at 03:00”) and Details, `data-always-allow`; in the modal, above Decline · Approve. A `connection_call` with `params.server` takes the risk-row layout instead of the command choices (`stopAskingServer`). It sends `approvals.decide {decision: 'approve', scope: 'agent'}`, toasts `toasts.always` (`approveToastFor`), and the decision refetches `hosts.serverSettings`, `hosts.getServer` and `hosts.fleet`. On a Whombat without `hosts.asks` the card and modal drop the server (`withServerAsks`), so they show Approve and Details as before. Owners only comes from `approvalView` (SA-07). | RA-06/AP-680's pattern, one click instead of a yes per command; the feature flag as the protocol asks for. |
| AP-1721 | **`SegmentedControl` items are `position: relative`.** Their visually hidden radio was positioned against an ancestor outside the page's scroll area, so it made the app frame scrollable; a dialog handing focus back to it (the Never confirm) scrolled the whole frame off screen. | Found in the visual check of AP-1718; the fix belongs in the primitive and changes nothing visible. |
| AP-1722 | **`FEATURE_NAMES['hosts.asks']`: “letting Whombat act on a server without asking”** (“Update your Whombat to use …”). | Every runtime feature needs its words; the Android stream doesn't edit `packages/client`. |
