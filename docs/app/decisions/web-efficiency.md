| # | Decision | Reason |
|---|---|---|
| WE-01 | Every route screen is a `lazyRouteComponent` of its own module (not its feature's barrel), and the route component gets the screens' `preload` (`withScreens` in `router.tsx`): TanStack Router awaits a route component's `preload` before rendering, so a screen never suspends the page it replaces, and `defaultPreload: 'intent'` fetches the chunk on hover. The shell's panes and modals (`hosts.tsx`) and the sidebar's knowledge and new-message modals are `React.lazy` behind `Suspense fallback={null}`, mounted only when shown. Route search validators that lived in screen modules moved next to them (`automations/search.ts`, `feedback/search.ts`). | The main chunk held every screen (3.1 MB). A chunk failing after a deploy (old hash gone) reloads the page once (`lazyRouteComponent`'s own handling). Panes are small and the screen under them usually loaded their code already. |
| WE-01a | Rolldown `codeSplitting.groups` instead of `manualChunks` (deprecated in Rolldown, the same thing): `react` (react, react-dom, scheduler), `router` (TanStack router, history, store), `query`, `zod`, `contracts` (`@whombat/core`, `@whombat/protocol`), `editor` (Tiptap, ProseMirror, Yjs, Hocuspocus), `app` (every other module the entry needs, `$initial`), and `shared` (modules two or more lazy chunks share, grouped by who uses them, merged below 20 kB). `shared~a~b~…` chunks are written as `shared-<hash>`. The 2 048 kB chunk warning limit is gone (Vite's 500 kB default is back; nothing exceeds it). | Libraries change only with a dependency or contracts bump, so the browser keeps them across app releases; an app release re-downloads `index` (≈ 136 kB gzip) and the screens that changed. Without the `app` group Rolldown split the entry's own modules into ~50 tiny chunks; without merging, lazy screens shared ~100 sub-kilobyte chunks. Short names keep `release:dist`'s ustar paths under 100 bytes. |
| WE-02 | *In part superseded by look-around.md AP-9727: the hosted app's demo loads the mock world on demand.* Fixture mode has one door, `src/app/fixtureMode.ts` (the mock world's fetch, the settled cards' seed, the canvases' local hub); a production build loads it as `export const fixtureMode = null` (vite.config `noFixtureMode`, `load` hook, `mode === 'production'` builds only). `createAppServices({ fixtures })` throws in a build without it. | A runtime `if` left `@whombat/fixtures`, 14 `*Fixtures.ts` and the fake AI in every production bundle (≈ 365 kB raw). A build-time module swap is certain (no reliance on tree-shaking side-effect analysis) and keeps tests, Storybook, the visual suite and the e2e builds unchanged. |
| WE-03 | The self-hosted build (`VITE_WHOMBAT_TRANSPORT=http`, what `release:dist` packs) writes `<file>.br` (brotli 11) and `<file>.gz` (gzip 9) next to every compressible hashed file under `assets/` (js, mjs, css, svg, json, html, txt, wasm, xml; ≥ 1 KiB; kept when ≤ 90 % of the original): `precompress.ts`. The hosted build doesn't (its static host compresses). | Whombat's static server picks a sibling by `Accept-Encoding` (SV-13). Deterministic bytes, so `release:dist` stays reproducible; the archive grows by the siblings (≈ 2.6 MB gzip + 2.1 MB brotli before tar's gzip). |
| WE-05 | Every build imports `src/app/fonts/fonts.css` (this origin's copy of the design references' Google Fonts files); `index.html` has no Google Fonts links (the hosted hardening now refuses one). `preloadFonts` adds `<link rel="preload" as="font" crossorigin>` for Bricolage Grotesque latin (one variable file, 400–700) and DM Mono 400 latin, build only. Storybook and the cards harness keep the Google stylesheet. | The self-hosted build loaded fonts from Google, render-blocking and third-party. The two latin files are what every first screen draws with; the others (500 mono, latin-ext, vietnamese) load on use. |

## Realtime and polling

| # | Decision | Reason |
|---|---|---|
| WE-04 | A resync (reconnect, `seq` gap, snapshot) invalidates per topic kind the endpoints its events change (`TOPIC_ENDPOINTS` in `packages/client/src/query/connect.ts`, now with a `burrow` list: the sidebar/roster reads, the reads whose cards run/approval/plan events patch, PRs, audit, automations, Work, Files) instead of every endpoint query for a `burrow:` topic. The open conversation's reads come from its `conv:` topic as before. A test pins the lists to real read endpoints. | Every reconnect (each deploy, each laptop wake) refetched every active query: the session, runtime capabilities, AI sign-ins and clients, the Vault, usage, settings panels. Those don't change by burrow events; they keep their own staleness. `reconnectNow` (visibility/online) only acts when the socket is gone, so it needed no change. |
| WE-06 | The AI side's status reads stop polling in the shell: `host.agents` (`useAgentSetupStatus`) polls every 30 s only while agents can't reply (the notice shows; 2 s during “Check again”, 5 s with `watch` on setup screens); the shell's sign-in notice polls `signins.list`/`clients.list` only while it shows (`poll` option, default on for the setup screens, which keep 30 s). Otherwise they're read at mount and refetched on `agent.updated` when stale (`refetchQueries({ type: 'active', stale: true })` in `apply.ts`, so at most once per 30 s staleTime). | 1–3 requests per 30 s per open tab for a notice that rarely shows. An agent changing is when the AI side's readiness can have moved (a turn failed on a signed-out provider, the runner came back); outside that nothing changes it except the setup screens, which keep polling. |
| WE-08 | `useTyping`, `usePresence` and `useAgentNow` read their cache entries through one query-cache subscription per `QueryClient` (`subscribeCacheEntry`: listeners by key hash, the cache subscription dropped with the last listener). `usePresence(id)` selects that principal's entry, so a dot re-renders only when its own person's presence changes. | Every reader subscribed to the whole cache and filtered every cache event itself: a sidebar with 20 presence dots and a room with typing lines ran ~25 callbacks per cache change (every query update, not only realtime state), and every dot re-rendered on anyone's presence. |
| WE-09 | The audit log's and search's rows get `content-visibility: auto` with their measured content height as `contain-intrinsic-size: auto …` (audit 64 px + padding = 96 px rows, search 45 px = 78 px rows), on the row buttons themselves (so their own focus ring isn't clipped by the paint containment). No virtualizer. | Both lists are paged (Load more, search pages), so DOM counts stay in the hundreds; what costs is layout and paint of every row, which this skips for rows out of view. Keeps find-in-page, screen readers and keyboard order intact, needs no new dependency (`@tanstack/react-virtual` isn't in the lockfile), and the `auto` size keeps the scrollbar steady once a row was seen. |

## Navigation and the shell

| # | Decision | Reason |

| WE-13 | `SidePane` (`takeFocus`, on by default; off for the branch room's pane, which is part of its page) focuses the pane's first heading when it opens (waiting up to 3 s for content that is still loading) and, on close, gives focus back to what had it when the pane opened if focus was in the pane or fell to the page.
