# Add a server on Android (AP-1697…AP-1716)

John, 2026-10-18: “We need an easy way to install a whombat agent to a server, for example by logging in once via ssh or a
very simple command (one liner).” Whombat decides what that means in `docs/decisions/server-signin.md` (SI-01…SI-13); this
is the phone's part, stream M of `docs/implementation/server-signin/assignment.md` (§2.5): SI-12 gives the phone **Add a
server** (reversing AP-1367 for it), with SI-01's two ways in, SI-06's level, SI-09's key and SI-10's card. Contracts 0.85.0
(CT-373…); the rules and words shared with the web are `@whombat/client/hosts` `install.ts` (`server-signin-web.md`
AP-1677…). The screen is `apps/mobile/src/screens/AddServerScreen.tsx`, the phone's own parts `data/addServer.ts`, the
demo world `fixtures/hostsSi.ts`.

| ID | Decision | Why |
|---|---|---|
| AP-1697 | **A screen of its own** (`AddServer`, `whombat://servers/add?address=…&user=…&control=…&name=…`), not a sheet: a title, the level, the two ways as the segmented control, the way's parts scrolling, its buttons in a sticky footer that the keyboard pushes up (`KeyboardAvoidingView` with `padding`, as the sign-in and the chat do; on the keyboard the footer drops the gesture-bar inset, as the composer does), so Add server stays in sight while the password is typed. Not restored after a killed process (not on `persist.ts`'s list). | A form with a keyboard and a job that runs for half a minute; a sheet would fight the keyboard and the back gesture. |
| AP-1698 | **From Things**: owners get a last row in SERVERS, “Add a server · Whombat installs its agent on it.” (a plus in `brand`), on a Whombat whose servers' service is there and says `canManage`; with no servers yet the card shows that row alone. | Things is the phone's Servers list (AP-1363); the web's button sits on its Servers page. |
| AP-1699 | **From Home**: “nas-02 wants to be added” → Review (`/things/servers?add=1`) opens the screen (`assistantScreenUrl`), and **Waiting for you sits at the top** when a server waits, above the level — the web lists it under the dialog's ways. | Review must land on what it is about; on a phone the bottom is two screens down. |
| AP-1700 | **The level above both ways** (§2.5, SI-01): `HOST_CONTROL_QUESTION`, three segments (the mock's control: `sf2` track, the chosen one raised on `sf` and bold; two lines where a title needs them; 48dp), a radio group, and the chosen level's line (`HOST_CONTROL_LEVEL_WORDS`) under it, read when it changes. Full control at first, or the link's level. | The brief puts the level above the tabs and shares it; the mock drew it inside Sign in once. One choice, two ways in. |
| AP-1701 | **Sign in once's fields**: Address and User name side by side (1.75 : 1, mono, as the mock), with autofill, autocorrect and suggestions off and the `url` keyboard; Password masked (`secureTextEntry`, no autofill: no “save password?” after a password that is forgotten); “Used once to install Whombat’s agent, then forgotten.” and a 44dp “Or use a key from the Vault” under it. With a key: the person's SSH keys as radio rows (name over the short fingerprint, the whole one for TalkBack), “Use a password instead”, “Password for sudo (only if it asks)”. A name field only when the link named the server (the web's). | The web's inline link is no finger target; a native select is worse than three rows for one or two keys. |
| AP-1702 | **SI-09's checkbox is off at first**; ticked, “Key to leave on it” lists the same keys and “Make a new key” (“A new key named “Servers” in your Vault.”), starting at the key signed in with; both pickers show their defaults until the person picks (`withKeyDefaults`, computed, not stored). | SI-09; the web's rule, so both start at the same key, and a key list read again never overrides a choice. |
| AP-1703 | **The password lives in the form only**: never in route params, the saved place or the query cache; cleared when the job starts (the mutation is reset after it is sent) and on Try again; kept after a refusal that came before any job (a bad address, too many at once), because it wasn't used. | SI-03 as far as the phone goes; retyping a password for a typo in the address helps nobody. |
| AP-1704 | **The assistant's card opens the screen**: a guide action whose href is Add a server's (`addServerPrefillFromHref`, the web's rule) opens `whombat://servers/add?…` filled in; the web only if the navigator can't. Every other path on this Whombat keeps opening the web (SUB-11). A link only fills in: nothing is sent until the owner presses Add server, and a later link fills the open screen in again. | SI-10: one tap from the chat; `whombat://` is a public scheme, so a link must never act. |
| AP-1705 | **The job, step by step**: the shared `installSteps` (✓ done in `ok`, a spinner in `brand` under way, an empty ring still to come, ✗ in `bad` where it stopped, a `warn` ring for installed-but-quiet), the system under “Installed Whombat’s agent”, the key note (`installHostKeyNote`) in a bordered box with the **whole** fingerprint in mono, then `installOutcome`'s sentence. Footer: **Open pve-03** and Done; **Try again** (back to the form, passwords cleared, the rest kept) and Close, with **More detail** folding the installer's lines (selectable mono on `code`); Hide while it runs. The job can't be read any more (the box restarted): its error words instead of the end. | The mock's second pane at phone width. The web shows the whole fingerprint too; a key worth remembering is one you can check. |
| AP-1706 | **Live**: `useHostInstall` (the `hosts.install` frame through the shared applier, every 2 s while it runs) under `useHostsLive`; when it ends the fleet, the servers' status and Home are read again. Leaving while it runs says “Whombat carries on. pve-03 shows up under Servers when it’s ready.” (a toast, the web's words on Hide). | §2.5; a person who backs out should know nothing was cancelled. |
| AP-1707 | **Run a command**: `COMMAND_COPY`'s lead, the pre-approved command for the chosen level in a code block (selectable), Copy the command (Android 13+ says “Copied” itself), “Works for an hour, on one server. Linux, as root.”; a command is made the first time a level is shown and kept per level while the screen is open. Once it has run (`commandOutcome` on the enrollments, every 10 s), “web-04 is added.” with Open web-04 and Done. | The web's tab, at phone width; making a new command for every tap on a level would litter enrollments. |
| AP-1708 | **A Whombat without `hosts.install`** (before contracts 0.85) gets the command alone with today's words (“Run this on the server you want to add. …”), no level (its enrollment takes no body), Waiting for you (“No server yet. Once the command has run, …”) and Done. | SI-01's fallback for older runtimes, as AP-1318 had it on the web. |
| AP-1709 | **Waiting for you**: each server as a card — its name in mono, OS · address · the level it will get (when its command stored one), “Asked 6 min ago”, a Name field (the web's rule), Not this one / Add it side by side; the notes are the web's (“Turned nas-02 away.”, “Added nas-02. Its first report comes in a moment.”). | ONE-15's approval, for commands made before SI-07. |
| AP-1710 | **Owners only**, in the web's words: “Only owners add servers. Ask one of them to.”, “Servers aren’t set up on this Whombat.”, “Servers aren’t reachable right now.”; members don't see the Things row. | Whombat ONE-DH05. |
| AP-1711 | **The “‹ …” label** is what lies under the screen: Things from Things, a tab's name, a chat's title, else Back. | A link opens it from anywhere. |
| AP-1712 | **Accessibility**: the level's segments 48dp, text links and the checkbox row 44dp, key rows 52dp, Buttons 44/52dp; radio groups for the level and the keys, a checkbox for SI-09; a step reads “Done: Signed in to 10.100.0.14”, “Under way: Waiting for its first report”; the steps, the outcome and the level's line are live regions. `test/touch-targets.test.ts` and `test/talkback-order.test.ts` list the screen. | README “Accessibility”, AP-1378. |
| AP-1713 | **One set of rules and words**: the phone reads `install.ts` (`addServerPrefill`, `addServerPrefillFromHref`, `signInFormDefaults`, `signInFormErrors`, `signInFormForRetry`, `installBody`, `sshKeyChoices`, `withKeyDefaults`, `NEW_KEY`, `SIGN_IN_COPY`, `COMMAND_COPY`, `installSteps`, `installTitle`, `installHostKeyNote`, `installOutcome`, `commandOutcome`) and the contracts' `HOST_CONTROL_LEVEL_WORDS`; `error.message` is shown as it comes. `data/addServer.ts` keeps only what the phone adds (its screen words, TalkBack's step words, the key rows' fingerprints, Waiting for you's rows, the note on leaving). The local mirror of 0.85.0 the screen started on is gone. | Web and phone say the same thing (§2.5). |
| AP-1714 | **The demo world plays the web's scripts on mock 4's servers** (`fixtures/hostsSi.ts`): 10.100.0.14 → pve-03, a server's name or address (10.100.1.11, or the web's 10.100.1.21) → updated in place, 10.100.0.22 → pve-02-2, the password `wrong` → `sign_in_failed`, a Vault key as another user without a sudo password → `sudo_password_needed`, 10.20.0.5 → `cant_reach_whombat` with the installer's lines; a pre-approved command runs on the second list read (web-04). Jobs move by the clock with a `hosts.install` frame per step. `EXPO_PUBLIC_WHOMBAT_SI=1` adds nas-02 waiting (Home and Waiting for you) and Dusty's card in “Add the new Proxmox box”; without it Home stays mock 4's three items. Mara's SSH keys (Deploy key, Home lab) join `vault.list`. | The web's `fixtures-si.ts` wraps `createHostsFixtures`' world, which the phone's demo world doesn't use (and isn't exported); a clock-driven job also tries the phone's frame path. |
| AP-1715 | **Key rows show a short fingerprint** (`SHA256:q3Vx…T8w`, the mock's form) and say the whole one to TalkBack; the job's note shows the whole one (AP-1705). | A row picks a key by its name; the note is where a fingerprint is read. |
| AP-1716 | **The Things row and Home's item are the only ways in besides links**; the server page has no “Add a server” and the Ask box isn't changed — the assistant's `server_add` card covers asking for it in words. | §2.5's three entries; more would be noise on a small screen. |
