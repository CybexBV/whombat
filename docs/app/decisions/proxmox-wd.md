# Full Proxmox support — consoles on the web (stream WD, 2026-10-17)

Stream WD of the Proxmox build (Whombat `docs/implementation/proxmox/assignment.md` §3; PX-01 in Whombat
`docs/decisions/proxmox.md`): the console tools Rackoon's `features/console/` had and ONE-13's first port left out.
Owned files: `apps/web/src/features/things/console/**`. SPICE stays out (ONE-13).

| # | Decision | Why |
|---|---|---|
| AP-1475 | **Send keys** is a menu in the console's toolbar. A VM's screen: Ctrl+Alt+Del, Ctrl+Alt+Backspace, Alt+Tab, Windows key, PrtSc, Esc, Tab, then a “Ctrl+Alt+” grid of F1…F12 (each item named “Ctrl+Alt+F1” for screen readers). Keys go down in order and up in reverse as keysyms with their `code` (noVNC `sendKey`). A shell: Ctrl+C, Ctrl+D, Ctrl+Z, Esc, Tab and the four arrows as the bytes a terminal sends. The status line says “Sent Ctrl+Alt+Del.” and the keyboard goes back to the console. Arrow keys, Home and End move in the menu; Esc closes it (not the dialog). | Rackoon had four F-keys; Proxmox guests use all twelve text consoles. One grid keeps the menu short. |
| AP-1476 | **The key row** shows at ≤ 600 px only (CSS): Esc, Tab, Ctrl, Alt, ↑ ↓ ← →, 44 px keys, two rows of four under 420 px. Ctrl and Alt are **sticky** (`aria-pressed`): they change the next key, from the row or the phone's keyboard — in a shell Ctrl+letter becomes its control character and Alt puts ESC in front, arrows get xterm's modifier codes (`ESC [1;5D`); on a VM's screen the modifiers go down before the next key and up after it. “Ctrl+ held for the next key” in the status line. The row's buttons don't take focus, so the phone keyboard stays open. | Rackoon's row showed on `pointer: coarse` without sticky modifiers; the brief asks for narrow screens and modifiers. Eight 44 px keys don't fit in one 366 px row. |
| AP-1477 | **Safe paste** (`paste.ts`, from Rackoon's): at most 64 KB, line endings as `\n`, control characters left out unless the person chooses “Paste them too”. Into a **shell** it asks first when the text has more than one line (one trailing newline doesn't count), more than 400 characters or control characters: “Paste 2 lines into pve-02?” · “Each line runs as a command as soon as it arrives.” with the first eight lines shown. Into a **VM's screen** it types without asking, 8 characters every 20 ms (≈ 400 a second, slower than Rackoon's 1,600 so BIOS screens and installers keep up), Shift held around shifted US characters, with “Typing 120 of 1,200 characters… Stop”. A paste into the terminal by the browser (⌘V, Ctrl+Shift+V, the context menu) goes through the same check instead of straight to the shell. Where the browser won't give the clipboard, a box to paste into. | The danger in a shell is a line that runs on arrival; on a screen it is keys lost at speed. |
| AP-1478 | **Copy** (shells): the selection, or all of the shell's text when nothing is selected (“Copied the selection.” / “Copied 24 lines.”); Ctrl+Shift+C copies the selection too (instead of the browser's inspector). Without the async clipboard (a box opened over plain HTTP) it falls back to `execCommand('copy')`. | Local addresses are often plain HTTP. |
| AP-1479 | **Screenshot** (VM screens): noVNC's canvas at the guest's own size as a PNG, `<guest>-<yyyy-mm-dd-hhmmss>.png`, made in the browser. | No hub round trip (Rackoon's screenshot endpoint isn't proxied); the canvas is already the picture. |
| AP-1480 | **Full screen** takes the whole stage (tools, screen, key row, warning, status line), so the tools stay at hand. A VM's screen also asks for Chrome's Keyboard Lock, so Alt+Tab and Esc reach the guest; then “Hold Esc to leave full screen.” | The brief's tools are useless if full screen hides them. |
| AP-1481 | **“Stay connected”**: a minute before the service closes an idle console, “Nothing’s been typed for a while, so this console closes in a minute.” with a countdown (hidden from screen readers; the line is an alert once) and **Stay connected**, which sends `activity` at once. The countdown counts from when the service last heard of input: the transport still sends `activity` at most every 30 s, but now also the last input of a burst when the 30 s are up (the service was up to 30 s behind before), and `heardAt` is the socket's open or the last `activity` sent. | Rackoon counted from the last key and warned 90 s early to cover the 30 s it might be wrong by; counting what the hub heard is exact. |
| AP-1482 | **Start from the console**: a switched-off guest shows “web is switched off.” with **Start web** (a paused one **Resume web**) through the existing `hosts.guestAction`, “The console opens once it’s running.”; when the guest's state turns running the session starts by itself. Without the power switch the screen says why. A running guest's **Power** menu (`GuestPower`) sits in the console's head, as Rackoon's toolbar had Shutdown, Reboot and Force stop. | Switching to a stopped guest from the side list would otherwise be a dead end. |
| AP-1483 | **Superseded in part by console-maximize.md AP-7500 (the list starts closed).** **The side list** (“On pve-02”): the server's own shell (when allowed), then every guest with its state dot (named), name and kind (“VM 118”, “CT 140”); the open one is `aria-current`. Picking one switches `?console=` (replace), so a new session starts; the list's open state survives the switch. **Guests** / **Hide guests** in the toolbar collapses it; it starts open above 900 px wide and closed below, and sits under the screen there. | Rackoon's list, collapsible as its “Wider”. |
| AP-1484 | **Superseded in part by** `docs/decisions/runtime-ci.md` RTC-02: the review shots no longer reached their screens and are deleted. **The keyboard**: the screen's frame is the Tab stop (`role="application"`, named like the dialog); a click or Enter gives the keys to the console, which also takes them when it opens; **Ctrl+Alt** (not AltGr) gives them back. While the console has them nothing else takes any — Esc goes to the guest and the dialog stays open (`Modal` gains `onEscapeKeyDown`); an open menu closes before the dialog. A ring (`--brand`) shows while the frame or the console has focus. The tools act only when clicked or tabbed to and give the keys back afterwards; notices are in the status line (`aria-live`), not toasts, so they show in full screen. **The fake world plays it**: the fixture's console token says its protocol and the guest (`fixtures-wd.ts`, one hook in `fixtures.ts`), a started or stopped guest's console comes and goes, and the web fake answers a `vnc` token with a tiny VNC server drawing a Debian login that echoes keys and names combinations (`managed/fake/console-vnc.ts`); the fake shell is the guest's and knows Ctrl+C, Ctrl+D and escape sequences. Review shots: `CONSOLE_SHOTS=<dir> pnpm exec playwright test --project=managed e2e-managed/console-shots.spec.ts`. | “Nothing steals keys from the console unless it isn't focused”; a visual check needs a screen to look at. |
