## Gaps (for the server or the next contracts)

- **AI search has no answerer in the assistant shell**: `ask_search` asks the first active Associate, and AN-06 retires
  them all, so the web shows no Ask card there (AP-1515). It could ask the person's own assistant (then the card says
  “Ask Dusty”).
- **Burrow-wide packs reach no assistant** (`appliedPacks` gives a personal agent only its own attachments): in the
  assistant shell a burrow-wide pack applies to nobody and the Skills grid shows no column for it.
- **Pickers need the server to accept the person's own assistant**: `connections.update` `lookedAfterById` (OW-09
  allowed only team agents), an automation step's `dispatch_agent`, and `vault.giveKey`'s eligible ids in the assistant
  shell (AN-06 hands over to assistants; the same writes from the UI must pass).
- `agents.list` in the fake world has no assistant; the web reads the own assistant from the bootstrap for pickers.

## The assistant's keys in the assistant shell (AN-10, contracts 0.82.1)

Whombat AN-10 (CT-361): in the assistant shell a person's assistant may hold a team agent's keys — it does what the
crew did. Core: `personalAgentMayHold(id, {assistantShell})`, `grantFitProblem(…, {assistantShell})`,
`KeyRequestAgent.assistantShell`, `assistantShellGrants`. The crew shell is unchanged.

| # | Decision | Why |
|---|---|---|
| AP-1525 | **The assistant's Access page in the assistant shell** (More settings → its settings page → Access) shows what a team agent's does — the six risk rows Off · Ask · On, the locked rows, **All keys** (switches, a pack's write tools in three states), REPOS (“Dusty works in the repos…”) — each filtered to what it may hold there (`assistantShellKeyOptions`: `personalAgentMayHold` with `assistantShell`, never an automation's key), then **YOUR ACCOUNTS**: its owner's mail, calendar, files and contacts (`assistantAccountKeys`: the personal keys All keys doesn't show), “What Dusty may do with the accounts you connected. No other agent can hold these keys.”. The switches read as each part's rule reads them (`assistantKeyState`: All keys on at `can`, an account key on at `can` or at `ask` when capped). One Save, the same `agents.setKeys`: the team rows through `configureGrants`, then the accounts through `personalConfigureGrants` on that result (`assistantKeysSave`). The two option helpers are in `@whombat/client` for the phone; the state and save are the web's. | AN-10: “the same key rows a team agent's Configure shows together with its personal switches, saving through the same path”; no key shows twice (the web, memory and skills are All keys' rows). |
| AP-1526 | **The fake world's assistant** holds `assistantShellGrants` (its own and a team agent's, the risk rows asking), and `agents.setKeys` / `agents.setChannels` answer for it, with a Keys event per change. | The Keys page can be looked at and saved in the fake world as on a server after AN-10. |
| AP-1527 | **Learn a skill** in the assistant shell lets the owner give the assistant the web from the dialog, as for a team agent; the crew shell keeps “A personal assistant doesn’t browse the web.”. | A skill from a URL needs the web, which AN-10 lets the assistant hold. |
