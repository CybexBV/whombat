# No Agents row in the sidebar; Skills is a Settings tab (AP-881…AP-887)

John, 2026-10-08: “When I click on ‘Agents’ in the sidebar, I see all the agents that are also visible in the sidebar.
When I click on ‘Hire an agent’ I see the same screen as when I click on the + next to Agents in the sidebar. The only
thing that’s useful there is ‘Skills’.” He asked whether to drop the nav row or the AGENTS list. I proposed keeping the
list (one click to an agent, the status dots at a glance; channels have no nav row either), dropping the row and moving
Skills to Settings; he answered “Agree, implement this fully”. Contracts 0.64.1 (CT-318) and Whombat
`docs/decisions/skills-settings.md` carry the copy on their side. This revises settings-simplify.md SS-10 (Skills as the
Agents page's tab) and SS-21's nav list.

| ID | Decision | Why |
|---|---|---|
| AP-881 | **No “Agents” row in the sidebar's nav.** The nav starts at Canvases (`NavRow['id']` loses `agents`, and so does `NAV_ICONS`); its right-click menu with “Hire an agent” goes with it. The AGENTS section is now always rendered: its `+` (hover or focus) opens Hire an agent as before, and with no agent yet (all retired, or only personal agents) it shows a “Hire an agent” row (`[data-agents-hire]`, a button styled as a nav row in `--mut`). An agent's row still opens its profile over the roster and is the selected row there. The visual comparisons take the mock's `Agents` nav entry out of the desktop reference with the Audit log one (`tools/visual/src/removals.ts`, SS-50); the mock's roster screen stays. | The row showed the same agents as the list under it; the list is the one that earns its place (status dots, one click to an agent, right-click Message/Configure/Audit trail). Without the row, the section is the only way to hire from the sidebar, so it must not disappear when it is empty. |
| AP-882 | **Settings → Skills (`/settings?tab=skills`), between AI and Connections.** The seventh tab shows `PacksTab` unchanged (a Whombat with `packs`; otherwise the usual “update your Whombat” gate): PROPOSED, INSTALLED, SHIPPED, IMPORT, “Learn a skill”, the jump links. Settings' subtitle reads “Your profile, your agents’ AI and skills, who’s in {burrow} and this Whombat.” Each agent's own skill switches stay in its Configure → Skills. | AI, Skills and Connections together are what the agents have to work with. A library that is seldom opened (since AC-52 agents learn a skill on their own) belongs in Settings rather than in the sidebar; `PacksTab` was built in Settings' styles and drops in as it was before SS-10. |
| AP-883 | **Old addresses open Settings → Skills.** `/agents?tab=skills` (also with an agent, `/agents/banjo?tab=skills`) redirects in the route's `beforeLoad`, keeping the `#anchor` (`#skills-import`, …) and replacing the entry; `/settings?tab=packs` (SS-02) now goes straight to `/settings?tab=skills`. `validateAgentsSearch` still reads `tab=skills` only so the route can redirect it. | Links in older messages, toasts, the phone's text and bookmarks keep working, as with every earlier move (SS-02, AP-671). |
| AP-884 | **The Agents page is the roster only.** No tabs; the header (“Agents”, the count line, Hire an agent) and the card grid as in the mock. It is reached behind an agent's profile (the AGENTS rows and every other link to `/agents/:agent`), under the hire modal (`?hire=1`), when a profile closes with nowhere to go back to, and as a burrow's home when it has no channel. | Nothing needs a nav row to it any more, and the mock's roster without the SS-10 tabs is closer to the reference. |
| AP-885 | **“Agents → Skills” becomes “Settings → Skills” everywhere.** Web: the agent's Configure → Skills empty note and the profile pane's “Manage packs” link go to `/settings?tab=skills`; comments follow. Android copy (no layout change): the Skills and packs screen's “Owners attach them on the web, in Settings → Skills.” and “Secrets are set on the web, in Settings → Skills.”. The hire toast's skipped-pack line comes from contracts' `packSkippedReason` (0.64.1, CT-318); the assistant's skills guide lines from Whombat's `guides/copy.ts`. | One name for one place. The phone keeps its Agents tab: it has no sidebar, so there the tab is the only way to the agents (and to Automations, Plans and Deploys, AP-857). |
| AP-886 | **Contracts 0.64.1.** The vendored contracts move to 0.64.1, a copy-only patch (no schema, feature or session API level change); the recovery vectors read 0.64.1. | CT-318. |
| AP-887 | **Tests, release.** Unit: the sidebar model has no `agents` nav row and selects the open profile's agent; the sidebar has no `/agents` nav link and AGENTS' `+` opens the hire modal; Settings shows seven tabs in order; Skills is reachable from the tab row; the roster has no tabs; `/agents?tab=skills#skills-import` and `/settings?tab=packs` land on Settings → Skills in place of the old entry; the packs and skills suites open `/settings?tab=skills`; the reference removal drops the mock's Agents entry.
