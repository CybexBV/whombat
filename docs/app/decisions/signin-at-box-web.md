# Sign in at the box, and no kit at the claim: client and web (AP-3500…AP-3524)

John, 2026-10-20: “I want to loosen up the security a bit, when we enroll a device we have to download a recovery kit,
I don't want this anymore. If we have physical access to the appliance we should be able to auth / re-enroll again.”
The spec is Whombat `docs/decisions/signin-at-box.md` (BX-01…BX-08, server BX-S…), the build brief
`docs/implementation/signin-at-box/assignment.md` there; contracts 0.106.0 (CT-620…CT-639). Android is
`signin-at-box-android.md` (AP-3525…AP-3549). There is no mock (B-05): the screens reuse the sign-in frame
(`AuthLayout`), the setup card and Settings' rows. Decided by the implementer (feedback-decide-yourself).

## Shared (`@whombat/client/managed`)

| ID | Decision | Why |
|---|---|---|
| AP-3500 | **Contracts 0.106.0, vendored like every bump**, after merging main (whombat-app 0.108.0, contracts 0.105.0's desk voices) so only the 0.106.0 directory stays. `SESSION_API_LEVEL` 41 (window 39…42) needs nothing else here. An older runtime answers `unknown_op` for the three ops (no feature flag, CT-628): that is the `old` words, “Your Whombat needs an update before its screen can let devices in.” | CT-620…CT-639. |
| AP-3501 | **Built first against stand-ins, then swapped.** Until the release existed the client used `screen-standin.ts` with stream C's exact names, built on the vendored CPace primitives; the fake appliance knew the ops as provisional ones. Both went in the vendoring commit. The app's exchange is checked against the release's fixed runs (`vectors/cpace.json` `screenSignIn`: the same share and client tag byte for byte, and the box trusted only in the run where both sides agree) in `recovery-ceremony.test.ts`, the file that reads the vendored release. | Work started before the contracts were out; the vectors prove the swap. |
| AP-3502 | **One step machine for web and phone (`screen-signin.ts`).** Steps: `email` → `letters` (`signinId`, `expiresAt`) → `enrolled` (the box's tag matched) or `already` (`endpoint_enrolled`: this key is let in there) or `stopped`. `screenSignInRequest` (“Show a code”, “Show a new code”) and `screenSignInSubmit` (“Let this device in”) take one step and never throw; `screenSignInFailed` says where a refusal leaves the person: `unknown_op` → stopped `old`; `screen_unavailable` → stopped; a tag that doesn't match, a share that isn't an element, or a handshake that reached another key (`identity_mismatch`) → stopped “This isn’t the Whombat whose screen you’re looking at.”, nothing pinned; `screen_no_account` → back to the email; `screen_code_invalid` / `screen_signin_missing` → the letters with their words; `screen_backoff` (from the begin, or the request, CT-622) stays where it is with whole minutes from `retryAt`, at least 1; `screen_rate_limited` and the unenrolled budget's `rate_limited` stay; `screen_begin_missing`, `screen_share_invalid` and the rest are “That didn’t work. Try again.” (trying again runs a new begin; neither is a guess); `appliance_offline` is the claim's offline words. An email that isn't one is refused before anything is sent (“That email address doesn’t look right…”). | The brief's error → words table in one tested place; the phone gets the same steps. |
| AP-3503 | **The identity (BX-03): `screenSignInPeer` and `screenSignedInRecord`; `PinSource` gains `screen`.** A pinned device connects with its pin (it stays as it was, source and all); a pin that differs from the directory is the identity-changed hard stop before anything is asked; a device without a pin connects with the directory's PeerId for this exchange only and stores it, `pinSource: 'screen'`, only after the box's tag matched. The registry's own rule still holds (a different pin is a `PinConflictError` → the hard stop). | The directory never becomes a pin by itself; the tag proves the key, as the claim's does. |
| AP-3504 | **Typing the letters.** `formatScreenLettersInput`: upper-case, spaces and dashes dropped, at most six, shown `KXQ MTR` once there are more than three (backspace over the space closes the group). Validity is the contract's `normalizeScreenSignInLetters`; anything else is “Type the six letters from the screen.” before anything is sent, so a typo costs no guess. | One field, the grouping the screen shows. |
| AP-3505 | **Words.** `COPY.screen` is §2's block; `screen_backoff` is a function of the minutes like the claim's (`claim_backoff`), same words; `lettersPlaceholder` `KXQ MTR` like the claim's letters field. Reused, not new: “Letting this device in…” while it works (the kit's), “Back” (the kit's), the claim's offline, rate-limited and failed lines. | §2's words are the words; nothing else needed new ones. |
| AP-3506 | **No kit at the claim (BX-01).** The claim's kickers count two steps (“CLAIM · STEP 1 OF 2”, Protect “CLAIM · STEP 2 OF 2”); Protect's button is “Continue” (it opened the kit before). The kit screen's kicker is “RECOVERY KIT”, its sub §2's. `kitPending` is written false and read by nothing, so an old record's `true` asks for nothing. This Whombat's Overview: no kit is a quiet AT A GLANCE row (grey dot, “No recovery kit”, “Not needed: you can sign in at your Whombat’s screen. A kit helps if it has no screen.”) that opens Backups, never NEEDS YOU, for owners and members alike; `kitMake` is “Make a kit”. The `saveKit` action stays in the type for the phone's mapping. `enroll.claim`'s `recoveryKitRequired` is ignored (runtimes answer false). | No kit is not a warning; owners can still make one for a box without a screen. |

## Web

| ID | Decision | Why |
|---|---|---|
| AP-3507 | **Claim → Protect → the Whombat.** After the claim the record is pinned (`claim`), enrolled, `kitPending: false`; Protect's Continue (or Skip, or no Protect needed) opens the Whombat at `/`. `/appliances/<device>/recovery-kit` stays: “Make a kit” in Settings goes there, the same save → confirm screen, then back into the Whombat. | BX-01. |
| AP-3508 | **No kit reminder.** The quiet strip “Recovery kit not saved · Save it” (MA-04 §4's reminder) is gone. Settings · This Whombat · Backups: RECOVERY KIT shows “No recovery kit” with a grey dot and, for owners, “Make a kit”; a saved kit reads as before. | BX-01: it leaves Needs you and shows as a quiet row. |
| AP-3509 | **“Let this device in” offers the screen.** Above the email form, one bordered card (labelled “Let this device in”) with the passkey's row when the browser has WebAuthn and the screen's row: “At your Whombat? Its screen can show a code for this device.” with “Use its screen” (secondary, small, a monitor icon). The kit link under the form reads “Have a recovery kit? Use it instead”. | A row like the passkey's (brief); one card, not two stacked. |
| AP-3510 | **“Set up this device” offers the screen as a way** after the passkey's and before the links, with its button; the kit way reads “A recovery kit, if you made one.” | Same card, same pattern as the passkey's way. |
| AP-3511 | **`/appliances/<device>/screen` (`ScreenFlow`).** The directory entry first (not this organization's → “This Whombat isn’t in your organization…”; retired → the retired notice), then `screenSignInPeer`; an enrollment session to that PeerId lives only while the flow is open, and the flow leaves for the list when control ends it for good (AP-694). Let in → the record (`screenSignedInRecord`), last used, the passkey nudge due, `/` — as a pairing approval. `already` with a pin → opens; without one → “This device is already let in to this Whombat.” and the list (nothing checked, nothing to pin from). Back returns where it was opened (pairing or Set up this device); dead ends go to the list. | BX-02, BX-03 on the web's routes. |
| AP-3512 | **The screen, in `AuthLayout`** like the other ways in: kicker “ADD THIS DEVICE”, title, sub, the tip in the bubble. Email step: “Your email on this Whombat” prefilled with the signed-in email (`type=email`, `autocomplete=email`), “Show a code”, Back. Letters step (“Type the code from its screen”): one field at the claim letters' size (`display`, mono, 320 px), `autocomplete="one-time-code"`, `autocapitalize=characters`, focused; “Let this device in” and the link “Show a new code”; the field empties after a wrong guess or a new code (the screen shows new letters). Stopped: the words and Back. No countdown here: the box's screen shows it (BX-06); an ended code is said when the box answers. | The surrounding auth screens' sizes and spacing; no new pattern. |
| AP-3513 | **The fake world's box** answers `enroll.screen.request` / `.begin` / `enroll.screen` as the runtime does: claimed boxes only (`screen_unavailable` otherwise, or with `noScreen`), the email among its accounts (`screen_no_account`), one sign-in per box in memory, a new request replacing it, the begin only from the asking key while it shows, the responder with its own letters, a wrong tag counted with `claimBackoffSeconds`, the letters rotated, the begin ended; a match adds the endpoint. `__WHOMBAT_FAKE__.screenSignIn(device)` is what its screen shows (`KXQ MTR`, letters, name, device label, expiry); `expireScreenSignIn` ends it. Claims answer `recoveryKitRequired: false`. | The e2e reads the letters the way a person reads the screen. |
| AP-3514 | **End-to-end.** `support.ts`: `claimFresh` (claim, Protect skipped, in the Whombat), `makeKit` (Settings' kit route, saved and confirmed) and `claimAndSaveKit` = both, for the recovery journeys. The claim, retired, switcher and updates specs no longer walk through a kit; claim checks the quiet row and “Make a kit”; updates checks that a kit made later carries Protect's SFTP destination. `screen-signin.spec.ts`: from “Let this device in” (a wrong code → new letters → the right ones, typed lower-case with a space and shown grouped; the claim's pin unchanged) and from “Set up this device” (pinned `screen` after the tag; a lying directory stops it with nothing asked or pinned). The old “the app opened” check `#billing-v2` (no channel list since the one-Whombat shell) is the sidebar in the specs touched here. | One e2e for the screen sign-in, the kit-walking specs updated (brief). |
| AP-3515 | **Visual check.** `MANAGED_SHOTS=1` writes `tmp/shots/screen-signin-{light,dark}-*.png` at 1440×900: Protect (2 of 2), Settings without a kit, “Let this device in” with the screen's row, the kit's screen beside it, the screen's email (and an unknown email), letters (empty, typing, wrong), stopped, and “Set up this device”. Compared with the kit and pairing screens in both themes: same frame, type, field and button sizes, error line. | No mock (B-05); the neighbours are the reference. |

| AP-3517 | **The pin conflict after the exchange** (another tab pinned another identity meanwhile) shows the hard stop and opens nothing; the box has let this key in, which an owner can see and remove under Devices. | The pin rule wins over a finished exchange. |
