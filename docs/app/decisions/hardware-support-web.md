# Better hardware support on the web, and the shared network and hardware models (AP-3200…AP-3249)

John, 2026-10-20: “I installed a whombat appliance and the mic is not working, also WiFi is not working by default. Is
there a way to implement better hardware support, including WiFi? … we should support other devices as well.” The
product decisions are Whombat's `docs/decisions/hardware-support.md` (HD-01…HD-11); this is stream W of
`docs/implementation/hardware-support/assignment.md` there: the client's network and hardware models (shared with the
phone, stream M, `hardware-support-android.md`, AP-3250…) and the web's Settings → This Whombat → Overview → NETWORK
with its Wi-Fi dialog and About → HARDWARE with Download report. Contracts 0.102.0 (CT-560…CT-576: `HostHardware`,
`hardwareProblems`, `HostNetwork`, `NetworkChange`, `WifiScan`, `ssidValid`, the `host.hardware`, `host.network` and
`host.wifi.*` session ops with `WIFI_ERROR_CODES`, features `host.hardware` and `host.network`). No mockup: Settings' own
rows and dialogs, looking like SCREEN and DIAGNOSTICS.

The rules and words are `@whombat/client` (`packages/client/src/host/network.ts`, `hardware.ts`, tested), the fake
machines `@whombat/client/host/fake`; the web's parts are `apps/web/src/features/machine/` (`NetworkSection.tsx`,
`WifiDialog.tsx`, `HardwareSection.tsx`, `useMachine.ts`), the fixtures `app/machineFixtures.ts` and the fake world's ops
in `managed/fake/world.ts`. This Whombat only gains two insertion lines (`ThisWhombatTab.tsx`).

|---|---|---|
| AP-3200 | **The wire shapes are the contracts'**, re-exported in one place (`host/contract.ts`, as `desk/contract.ts` is). Until 0.102.0 was vendored they were local stand-ins written from the brief's §2; C's differences (no `previous: null`, `failure` exactly in reverting/reverted/failed, refusals in `details.code` on a generic code) are what the models and the fake follow now. | Contracts first; one file to swap. |
| AP-3201 | **One network model for both clients**: `NetworkApi` (`networkApi(session)`, null on the HTTP transport; `networkOffered`), `networkSectionView` (the rows and their words), `networkChangeView`/`networkChangeShown`, the dialog's `wifiRows`, `wifiNeedsPassword`, `wifiPasswordProblem`, `wifiNameProblem`, `wifiJoinInput`, the refusals' `networkErrorCode`/`networkErrorText`, and `createNetworkPoller`. Every word is `NETWORK_TEXT`. The ops are `sessionOps.hostNetwork`, `hostWifiScan`, `hostWifiJoin`, `hostWifiForget`. | The brief puts shared state and words in `packages/client`; the phone builds its NETWORK card and Wi-Fi sheet on the same functions. |
| AP-3202 | **The connection rows**: a row per cable, “Cable · Connected” (or “Not connected”) over its address; the interface's name only when there is more than one cable, to tell them apart. The Wi-Fi as HD-11 says it, “Wi-Fi · Home · Strong signal”, with its bars, its address and, while a cable is plugged in too, “Used when the cable is unplugged” (HD-05's metric, said plainly). “Wi-Fi · Connecting to Home…”, “Wi-Fi · Not connected”. | Interface names mean nothing to most owners; which connection the box uses does. |
| AP-3203 | **No Wi-Fi says why**: “No Wi-Fi card” / “This machine connects by cable.” (`no_adapter`, muted), “Wi-Fi isn’t working” / “This Wi-Fi card has no driver yet.” (`no_driver`, amber) and “Wi-Fi is switched off” / “Turn it on with the machine’s Wi-Fi key or switch.” (`disabled`, amber). The last two get **See hardware**, which opens About at HARDWARE (`#hardware`), where the card and its ids are. | HD-11's words; the report is what support needs next. |
| AP-3204 | **“Can’t reach Whombat right now”** leads the rows when `online` is false after a check (`checkedAt` set; HD-10), with “It keeps trying. A cable or another Wi-Fi network may help.” Not before the first check. | Rare (the app usually reaches the box through Whombat), but true on the local network. |
| AP-3205 | **Saved networks** follow, the one in use first: the name, “In use now · Secured” or “Saved · Open”, and **Forget**, asked once (“Forget “Office”?”, “Burrow HQ won’t join it again until someone types its password.”). Forget and Join wait while a change runs. | HD-06: owners join, switch and forget here; forgetting is destructive. |
| AP-3206 | **Following a change** (`createNetworkPoller`): `host.network` once when NETWORK opens and the tab is visible, then every 2 s while the answer's change runs, never otherwise. A join or forget puts its change on screen at once (`started`), and an answer asked before it is dropped. While a change runs a failed answer is ignored and asked again: switching networks can cut the box off for a moment. Without a change, a failure with nothing shown says “The network couldn’t be read right now.” with **Try again**. | §2.3: no realtime, poll every 2 s while a change runs. |
| AP-3207 | **A change in words** (`networkChangeView`): “Joining Home…” with the guard's note, “Joined Home” / “Checking that Burrow HQ reaches the internet there…”, “Joined Home”; going back: “Going back to Office…”, then “Couldn’t switch to Home” over HD-11's sentence, “Joined Home, but Burrow HQ couldn’t reach the internet there, so it went back to Office.” (or “…didn’t give Burrow HQ an address…”); failing: “Couldn’t join Home” over “That password didn’t work.”, “Couldn’t find Attic nearby.”, …; forgetting likewise (“Kept Home” when forgetting it cut the box off). Network names without quotes, as HD-11 writes them. | HD-11's words; every phase has a line. |
| AP-3208 | **When a change is told**: while it runs; once it ended, if this view saw it running; and a change that went back or failed until 15 minutes after its deadline, for whoever looks next. A change that simply worked isn't told again later. | `HostNetwork.change` stays “for a while after”; a revert is worth explaining, a success isn't. |
| AP-3209 | **Signal words**: 4 bars “Strong signal”, 3–2 “Good signal”, 1–0 “Weak signal”; the bars are four rising bars drawn in ink and the line colour, hidden from screen readers (the words say it). | HD-11 names three words for five values. |
| AP-3210 | **The form's checks** before asking: a password of 8–63 characters or 64 hex digits (“A Wi-Fi password is 8 to 63 characters.”), a typed name that `ssidValid` accepts. A saved network joins without its password (“Saved on this Whombat: it joins without the password.”), an open one never asks. The password is sent only for a secured network and is never logged, toasted or kept after the dialog closes. | `WifiPassphrase`, `ssidValid`; secrets never in logs or errors. |
| AP-3211 | **Refusals by their Wi-Fi code**: `error.details.code` (`WIFI_ERROR_CODES`) before the error's own code, plus `forbidden`: “Another network change is still running. Try again in a moment.”, “Burrow HQ reaches the internet through this network. Plug in a cable or join another network first.” (`in_use`), … else “That didn’t work. Try again.”. | CT-569 carries the code in `details` on a generic session code. |
| AP-3212 | **The Whombat's name in the words** is the burrow's name (“If Burrow HQ can’t reach the internet …”), the brief's `{burrow}`. | The guard note names the box the way the app does everywhere else. |
| AP-3213 | **One hardware model for both clients**: `hardwareLoader(session)` (null on HTTP), `hardwareOffered`, `hardwareSectionView`, `hardwareStatusText`, `hardwareMachineName`, `formatLinkSpeed`, `hardwareReportText`, `hardwareReportFileName`; words in `HARDWARE_TEXT` (with the phone's “Share report”). | The phone's HARDWARE card and its share sheet use the same text. |
| AP-3214 | **The machine in one row**: vendor and model (“ASUSTeK COMPUTER INC. ROG Flow Z13 GZ302EA”), or “Virtual machine (KVM)”, over “AMD Ryzen AI Max+ 395 w/ Radeon 8060S · 16 cores, 32 threads · 32 GB memory · Linux 6.18.53”. | What support asks first; the kernel shows which LTS runs (HD-02). |
| AP-3215 | **The groups**: Network (wired, Wi-Fi, Bluetooth) · Sound · Graphics & screens (graphics, screen connectors) · Storage · Power (batteries) · Other (cameras, input, USB, the rest), empty ones left out. | The brief's groups; every kind has a place. |
| AP-3216 | **Problems first** in the contracts' order (`hardwareProblems`: Wi-Fi, wired, sound, graphics, then the rest), one line each in HD-11's words made for every kind (“This Wi-Fi card has no driver yet.”, “This sound card needs firmware that isn’t there.”, “This Bluetooth adapter is switched off.”), red for a missing driver or firmware, amber when switched off. In the groups the same devices carry the dot; the driver column says “No driver” only where one is missing (a battery needs none). | HD-03, HD-11. |
| AP-3217 | **The report** (`hardwareReportText(h, { burrow, version })`): “Whombat hardware report”, the Whombat, the versions (“Whombat 0.120.0 · app 0.105.0”) and when it was collected (UTC); the machine's facts one per line; “Problems (n)” in words; “Devices (n)” as aligned columns KIND · NAME · VENDOR · BUS · ID · DRIVER · STATUS (NO DRIVER, NO FIRMWARE, switched off) · DETAILS (interface and link, speed, card, capture/playback, screen, size), in the section's group order; “Kernel messages (n)”. Plain UTF-8, `\n`, no trailing spaces; columns at most 44 wide (a longer cell runs over). | Readable in any mail or ticket; ids and drivers are what a driver lookup needs; never serials or MACs. |
| AP-3218 | **The file name** is `whombat-hardware-YYYY-MM-DD.txt`, the day it was collected in the viewer's time zone. | The brief's name; the day the person sees. |
| AP-3219 | **Download** is a `text/plain;charset=utf-8` blob through an anchor's `download` (the diagnostics' way, AP-16), made in the browser from the answer on screen: nothing is asked again. | The text is the client's, from the same data (HD-03). |
| AP-3220 | **The phone shares, the web downloads**: `HARDWARE_TEXT.share` (“Share report”) is the phone's button for the same text and file name through the share sheet; the web's is “Download report”. | One report, each platform's way of handing over a file. |
