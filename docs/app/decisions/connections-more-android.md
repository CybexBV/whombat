# More connections, on the phone (AP-2810…AP-2859)

John, 2026-10-19 (Whombat main checkout): “Implement group 1 and pi-hole + Nginx Proxy Manager + IMAP/SMTP + TrueNAS,
ESPHome.” Whombat `docs/decisions/connections-more.md` CM-01…CM-30 (contracts 0.97.0, CT-470…CT-499); this is stream A
of the build (Whombat `docs/implementation/connections-more/assignment.md`), mainly CM-19…CM-22, CM-28 and CM-29. The
web, `@whombat/brand` and `@whombat/client` are `connections-more-web.md` (AP-2760…AP-2809). Not in the mocks (B-05):
the phone shows the new connections the way it shows every connection.

| ID | Decision | Why |
|---|---|---|
| AP-2810 | **Email (IMAP) is shown on the phone and connected on the web, like Google and Microsoft 365** (CX-74, AP-767): the phone has no connect form for any account, so it gets none for IMAP. The person's IMAP account (from `connectors.status`) is a row of Settings → Connections: the envelope, “Email (IMAP)”, its address, “Only you”, a dot and ↗, opening its page on the web (`/settings?tab=connections&connection=imap`); when it needs its password again it is in NEEDS YOU with **Connect again**. Add a connection lists Email (IMAP) under Accounts, tagged Connected once there. | CM-29: the IMAP page follows the Google and Microsoft 365 pages, which on the phone are their web pages. A password form only for IMAP would be the phone's one connect flow. |
| AP-2811 | **The sixteen entries need no phone code of their own**: Add a connection, its search and chips, the Connected and Set up tags, the CONNECTED and NEEDS YOU rows and the Connection screen are drawn from the catalog (`@whombat/core`) and the server's views. Each draws its mark from `@whombat/brand` (AP-2760…AP-2763) through `connectionLogo`, which finds one for all sixteen ids (TrueNAS the operating system's `truenas`, Email (IMAP) the envelope). | CM-28, CM-29: one catalog for web and phone. |
| AP-2812 | **A socket connection is a row like any** (TrueNAS, ESPHome; CM-13): nothing on the phone reads a connection's transport. Its row says its host and port from the address (`connectionHost` reads the entry's `baseUrl`, not its `request`), the Connection screen lists its one tool `call` with its tier, its page is the server's. A phone on contracts before 0.97.0 leaves such a connection out of the list (tolerant decoding, AP-255) and its screen says it didn't load; it doesn't break the others. | CM-13's “an older app leaves such a row out”. |
| AP-2813 | **Session sign-ins and Plex's sign in once are the web's**: Pi-hole's app password, Nginx Proxy Manager's email and password, Plex's account with its code, TrueNAS's https-only rule and Use this fingerprint all happen in the web's connect form. A refused password makes the connection `needs_reauth`, which the phone says as everywhere: “Needs connecting again” with Connect again (AP-1171; one set of state words, AP-1176). | Connecting stays on the web (CX-74); the web's form says which password. |
| AP-2814 | **A mail account's Services row goes where its link says.** The server lists a person's Google mail on Connections as a thing of a builtin entry (`catalogId: 'google'`, `href: '/settings/connections'`) — and Email (IMAP)'s once it lists that — but makes no page for it (`things.page` answers 404 for a builtin entry), so the row opened “That isn’t one of your connections.” A Services row of a builtin entry's connection now follows its `href` (`serviceRowOpens`), unless that is a thing's page itself; servers, devices, catalog connections and entries the phone doesn't know (a newer server's) open their page as before. `/settings/<tab>` opens that tab's page as `?tab=<tab>` does (`/settings/connections` → Settings → Connections), burrow-less or after the burrow; a deeper path (a feedback report) doesn't. | The server already says where it goes; the phone only stopped ignoring it. |
| AP-2815 | **The demo world answers Settings → Connections** (`fixtures/connections.ts`): `connections.list` (the demo's Home Assistant at 10.100.0.131:8123, UniFi at 10.100.0.1 — its entry `unifi_network`, the catalog's — and Hetzner), `connections.catalog` (every entry offered, none waiting for an app) and `connectors.status` (Mara's Google, `mara@cybex.example`, the Gmail of Home's Mail row). So Settings shows Connections in the demo too (amends AP-767's “not in the demo world”), and the new entries and accounts can be looked at without a server. Home's rows (mock 4) are unchanged. | The lead's check runs on the demo world; a screen that only errors there showed nothing. |
| AP-2816 | **Add a connection offers only what this Whombat has.** Its statuses (`connections.catalog`) list every entry the Whombat knows, so an entry they don't list is newer than the box — the sixteen on a Whombat before 0.97.0 — and is left out; until the statuses answer, or when they fail, the catalog as it is (AP-1173). Email (IMAP) also needs `connectors.status`'s `imap.available` (absent on an older Whombat, CT-482), unless the viewer already has an IMAP account (then it stays, tagged Connected). The list waits for both answers (or failures) before it shows, so a row doesn't arrive under a finger. | A row whose web page the Whombat doesn't have would open a page that isn't there; the web leaves the tile out the same way. |
| AP-2817 | **Mara has her own mailbox over IMAP in the demo**: `mara@okafor.example` at Fastmail (`imap.fastmail.com`, `smtp.fastmail.com`), beside her Google, and the demo's `connectors.status` says `imap: { available: true }`. Settings → Connections shows CONNECTED · 5 with Email (IMAP) second; Add a connection tags it Connected. The row says the address only (as Google's); the servers (`Connection.mail`) are on its web page. | The account row can be looked at without a server; the address is what tells two mailboxes apart. |
| AP-2818 | **Checks.** Unit tests: the sixteen ids draw a mark, the IMAP account row (name, address, Only you, envelope, web page, TalkBack label) and its Connect again, Email (IMAP) offered only where available or connected, none of the new entries offered by an older Whombat, TrueNAS's and ESPHome's rows saying their address, a refused Pi-hole app password in NEEDS YOU, search (“pi-hole”, “fastmail”, “dns”, “usenet”), the demo's answers against their schemas; “Search 47 services” on a Whombat with everything (31 before).
