# Remote help on the web, in the client and on Android (AP-4440…AP-4499)

John, 2026-10-21: “We need to have some kind of debug mode that I can enable so you do have access to it … How can we
implement this in a way that customers can allow this also when they are in need of remote assistance, but still keep
it safe?” Whombat `docs/decisions/remote-help.md` RH-01…RH-13 decide the feature; contracts 0.120.0 (CT-930…CT-969)
carry it. This is the app side: the shared client, the web's card, the admin panel's line and the legal texts
(AP-4440…AP-4469); Android continues from AP-4470 on the client below. The sketch (`mockups/remote-help/index.html`)
gives layout and words; the brief's §4 and the contracts' `REMOTE_HELP_WORDS` win where they differ (the transcript link
is “Show”, not the sketch's “Watch”).

| ID | Decision | Why |
|---|---|---|
| AP-4440 | **Contracts 0.120.0**, vendored after merging app main (0.121.0, contracts 0.119.0). Built first against a stand-in, swapped when 0.120.0 was released. Two amendments the lead took into the contracts: `remoteHelp.confirmBegin` takes the choice (`{level, duration}`) and answers `{nonce, options}`, so the challenge can bind the level and duration and the client can recompute it; the feature is `remote_help`, since runtime feature names are lower case (`Capability`). `FEATURE_NAMES.remote_help` is “remote help”. | The brief's `confirmBegin {}` couldn't bind the choice, and `remoteHelp` fails the welcome's schema. |
| AP-4441 | **Client ops** (`sessionOps.remoteHelp*`): get, confirmBegin, start, stop, visits, and the transcript through an export stream bounded by `REMOTE_HELP_LIMITS.transcriptBytesPerVisit`, its refusal thrown as the op's `OperationError`. `remoteHelp.*` answers are **read strictly** (AP-266): a grant, a connection or a step this app can't read says the app needs an update instead of vanishing. `remoteHelpApi(session)` wraps them (null over HTTP); `remoteHelpOffered(runtime)` is the feature. | Who may get into the box and what they did is a security view. |
| AP-4442 | **Turning it on** (`turnOnRemoteHelp`): begin for the choice; no options → the dialog (“Turn on remote help?”); options → the challenge recomputed from the nonce, this device's PeerId (`managed.devicePeerId` on the web), the level and the duration, and **a mismatch signs nothing** (`RemoteHelpError('challenge_mismatch')`); user verification is always required; the Whombat's `allowCredentials` are kept (unlike control's sign-in options: here the Whombat is the verifier and lists the owner's own passkeys). An owner with a passkey on a device without WebAuthn reads “This device can’t use your passkey. Turn remote help on from a device that can.” A dismissed prompt or dialog changes nothing and says nothing. | RH-04; the same rule as PK-03, applied to the Whombat's own challenge. |
| AP-4443 | **One hook for both apps**, `useRemoteHelp(api)` in `@whombat/client/react`: `remoteHelp.get`, the 20 newest visits and whether the viewer has a passkey (`passkeys.list`, own ones; only for the hint, the box decides) in the query cache; asked again every 10 s while it's on or someone is connected (there is no realtime frame for remote help); turnOn and stop put the answer in the cache and read the visits again; the last problem in words. | Android adds only its UI, its passkeys and its dialog. |
| AP-4444 | **What support did** (`remoteHelpVisitRows`): the newest visit first, each visit's steps in the order they happened; the time is the clock today, else “21 Oct 10:02”; a Fix command is “Ran” and the line in code style (core's `steps.exec` split at `{line}`); “Show” on a visit's first command line or command (else its first step) when the box kept output; “Earlier steps aren’t shown.” first when the box left older steps out. The list shows whether remote help is on or off: the records stay 90 days. | The sketch's list, with visits that can be told apart and a record that outlives the grant. |
| AP-4445 | **The card's states** (`remoteHelpCard`): not available — an older runtime without `remote_help`, or `available: false` (no support key pinned, RH-10), both “Remote help isn’t available on this Whombat yet.”; loading; off; on. The first choice is the sketch's, Look for 1 day; Forever only where `foreverAllowed`, and a picked Forever falls back to 1 day if the box stops allowing it. No change control while it's on: Stop, then turn it on again with the new choice. | One honest sentence for both kinds of “not here”; one button per state. |
| AP-4446 | **The app's own words** (`REMOTE_HELP_TEXT`), only where the contracts' say nothing: the no-WebAuthn sentence (AP-4442), “Earlier steps aren’t shown.”, “Couldn’t load the command line. Try again.”, “Couldn’t load remote help. Try again.” with “Try again”, “That didn’t work. Try again.”, “Close”, and the accessible names “Remote help is on”, “Connected” and “Show command line”. `passkey_required` and a challenge mismatch say `passkey_failed`'s words. | Everything else is `REMOTE_HELP_WORDS`, shared with the desk, the panel and the runtime. |
| AP-4447 | **The fake** (`@whombat/client/remote-help/fake`): checks what the box checks — owners only, Forever not on prod, a help code on prod, the passkey assertion against the begun choice, the session's key and the owner's credential ids (not the signature) — ends visits on Stop, expiry or a lower level, and turns a Look visit's restarts and commands into “Was stopped: that needs Look and fix”. Support's side (`visit`, `step`, `leave`) brings the demo steps and a command line. The web's fake world keeps it in `ApplianceState.remoteHelp` with the faults `remoteHelpVisit`, `remoteHelpLeave`, `remoteHelpBox` and `remoteHelp`. | E2e, demos and Android's demo world from one place. |
| AP-4448 | **Where on the web**: Settings → This Whombat → About, above DIAGNOSTICS, owners of a managed Whombat only (RH-12). One section labelled “Remote help” (Settings' uppercase label), one card. | Help and diagnostics belong together. |
| AP-4449 | **Off**: the intro, HOW MUCH as two radio cards side by side (one column under 720 px) in the backup destination's choice-card style, FOR HOW LONG as the audit log's segmented control (a radio group), “Turn on remote help” with “You’ll confirm with your passkey.” under it as the sketch has it. The no-passkey dialog is This Whombat's dialog (title, lead, Cancel and Turn on). | The surrounding Settings components, the sketch's order and words. |
| AP-4450 | **On**: the state line with a warning dot, tinted like NEEDS YOU, Stop beside it; the help code in DM Mono 20 px under its label with its hint; one line with a green dot per connection. | The sketch's on-card in Settings' rows. |
| AP-4451 | **The command line** opens in a modal (“Command line”, 760 px): the text in a scrolling, keyboard-reachable block, Close and Download. The app strips terminal control sequences again before showing it (`cleanTranscript`); Download saves the box's bytes as `application/octet-stream` under the protocol's `whombat-remote-help-<visit>.txt`, never a navigation (AP-16). | Defence in depth for what a terminal can contain. |
| AP-4452 | **Tests**: client unit tests (the challenge check and its refusals, the flow with and without a passkey, the card, the rows, the words of refusals, the transcript's cleaning, the fake's rules, the ops over a real session with an export stream, the hook); the managed e2e `remote-help.spec.ts` (a test Whombat through the dialog with Forever, a visit, Show and Download, Stop; a customer box through the virtual authenticator with the help code and a Look visit; a box without a support key), with `RH_SHOTS=<dir>` writing light and dark shots at 1440×900. | Check facts, not long sentences (TS rules). |
| AP-4453 | **Admin panel**: the panel has no device page, so the line sits in Fleet → Whombats' Health cell from the last report's `status.support` (`remoteHelpPanelLine`): “Remote help: off” quietly, else the level and hours left (or forever) as a line with a warning dot (`DotLine`, text in ink; a mono badge was too wide) and “{n} connected”. Nothing for a report without `support`. The fake fleet gives every reporting Whombat a report, two internal ones on. | Operators scan the fleet for boxes someone can get into. |
| AP-4454 | **Legal**: Appliance Terms `2026-10-21-draft` (`APPLIANCE_TERMS_VERSION`): section 1 says there is no standing vendor login, a new section 7 “Remote help” (off unless an owner turns it on, at most a week, Look and Look and fix, the key and help code, the record, Stop, consent per visit), sections 8–13 renumbered; Privacy Policy and Terms of Service `2026-10-21-draft` say the same in their places (what control sees, retention, the legal ground). Existing owners aren't asked to accept again (RH-11). The appliance's copy (LC-21) must be byte-identical to `apps/web/src/legal/appliance-terms.md`. | RH-11: the texts promised “no remote access”. |
| AP-4455 | **`docs/privacy-and-security.md`**: §5.3 describes remote help instead of “No remote access” (levels, durations, the confirmation and where the client checks it, the three checks on the box, the record, what control sees), §2 and §4.1 name it, §9 names the limit it adds (*Look and fix* is root while allowed). | The published model must say what exists. |

## Android (AP-4470…AP-4499)

The same card on the phone, on the shared client above (AP-4441…AP-4447): Android adds its UI, its passkeys, its
dialog, the phone's key for the challenge, and Share and Download for a command line. Built on `rh-mobile` from
`remote-help` (a74e1a96, contracts 0.120.0).

| ID | Decision | Why |
|---|---|---|
| AP-4470 | **Where**: This Whombat → About (`WhombatAboutScreen`), REMOTE HELP above DIAGNOSTICS, owners of a managed Whombat only (`status.owner`), as on the web (AP-4448). `useRemoteHelpHere(owner)` picks the ops: `remoteHelpApi(session)` where the runtime offers `remote_help`, the demo world's (AP-4478), or none (a self-hosted server). The challenge names this phone's key: the managed context gains `devicePeerId` (the session key's PeerId, beside `deviceFingerprint`); the passkeys are `PASSKEYS` (Credential Manager, passkeys.md AP-798). | One place on both apps; the phone already has the key and the platform, only the context didn't pass the PeerId. |
| AP-4471 | **The shared hook and model, unchanged**: `useRemoteHelp`, `remoteHelpCard`, `remoteHelpChoice`, `remoteHelpVisitRows`, `REMOTE_HELP_WORDS`/`REMOTE_HELP_TEXT`, in the viewer's time zone (`useBurrowBase`). It asks only while About is in front and the app in the foreground (`useIsFocused`, `useForeground`), as the phone's other live parts do, and reads again when it comes back. | No phone copy of the flow or the words; no polling behind other screens or in the background. |
| AP-4472 | **Off**: the intro (14/1.5 `ink2`), HOW MUCH as the phone's radio cards (`RadioCards`, stacked: two cards side by side don't fit a phone), FOR HOW LONG as the segmented control (Forever only where allowed), then **Turn on remote help** full width (a spinner while it runs; the choices are disabled meanwhile) with “You’ll confirm with your passkey.” under it (also its TalkBack hint), the problem under that. The part labels are the section label's type; TalkBack reads the groups' own names instead. | The web's order and words in the phone's controls (Diagnostics' and the desk's language). |
| AP-4473 | **The no-passkey dialog is Android's alert** (`remoteHelpConfirm(Alert.alert)`): the shared title and sentence, Cancel and Turn on; Back or a tap beside it is Cancel, and only the first answer counts. With a passkey, Credential Manager asks; a dismissed prompt says nothing (AP-4442). | The phone's confirmations are alerts (the desk's Unpair, Wi-Fi's Forget). |
| AP-4474 | **On**: the state line (15/600) on NEEDS YOU's warm wash (`warn` at 7 %) with the warn dot named “Remote help is on” and **Stop** (44 dp, disabled while it stops rather than a spinner, which would narrow it under the finger); the help code in DM Mono 20/500 with 0.12 tracking, selectable, read by TalkBack as “Help code, K Q 7 2 M X” (`helpCodeSpoken`), its hint under it; one row per connection with the ok dot named “Connected”. | The web's on-card (AP-4450) in the phone's rows; a code read as letters is a code support can type. |
| AP-4475 | **What support did**: one row per step, the time in mono 12 `mut`, the words 13.5 `ink2` (“Earlier steps aren’t shown.” in `mut`), a command line in mono on `sf2` with no-break padding so the wash doesn't hang at a line's end; each row is one TalkBack element (“14:02, Ran systemctl status whombat-voice”, `remoteHelpStepLabel`). **Show** is a 44 dp link-style button in `brand` named “Show command line”. | The web's list (AP-4444); a step read in pieces means nothing. |
| AP-4476 | **The command line opens in a sheet** (`ui/sheet`): the title “Command line” (19/700), the record in mono 12/1.55 in a scrolling `sf2` block (at most half the screen, selectable), Share and Download side by side; the backdrop, the handle and Back close it (“Close”). The sheet shows at most 64 Ki characters, the start, cut at a line (`transcriptShown`), with the phone's line “Only the start shows here. Share or download it to read all of it.”; trailing blank lines are left out. | A visit's record can be 50 MB (`transcriptBytesPerVisit`), which one Text can't hold; the file has all of it. |
| AP-4477 | **Share and Download**: Share writes a copy to the cache for Android's share sheet as `text/plain` and deletes it afterwards, also when sharing fails (as DIAGNOSTICS and the hardware report share, AP-1249, AP-3260); Download asks where with Android's “Save as” (the backup file's `whombat-transfer`, else the folder picker, AP-1214) and writes the box's bytes as `application/octet-stream` (AP-4451); a write that fails deletes the half file; backing out says nothing; a failure says “That didn’t work. Try again.”. The file's name is always `whombat-remote-help-<visit>.txt` from the visit's id (`remoteHelpTranscriptName`, which checks it), never a name the box sent: it becomes a path in the app's cache. | “Share” is how the phone sends support a file; “Download” keeps it, as the web's button does. |
| AP-4478 | **The demo world** (`fixtures/remoteHelp.ts`): the shared fake (`createFakeRemoteHelp`) for the demo's owner (account `acc_demo_owner`) on a test Whombat, shown on the demo's This Whombat after HARDWARE (About's order). Turned on, Claude from Whombat support connects 5 s later with the fake's steps; an owner with a passkey confirms with the demo's own authenticator (it signs the challenge it's given after 0.6 s; the demo Whombat isn't a relying party Credential Manager knows). `?help=<state>` starts over: `off`, `passkey`, `on` (Look and fix, forever, Claude there), `customer` (prod: Look for an hour, the help code, refusals), `history` (two finished visits, one truncated, one with a command line), `unavailable`; a restart reads every `remoteHelp.*` query again. | Checks on the emulator without a Whombat, as the desk's and the machine's demos. |
| AP-4479 | **Accessibility and tests**: every target 44 dp (the touch-target audit lists `RemoteHelpSection.tsx` with its one Show; the rest are audited primitives), dots named, the section and the sheet in the reading-order audit. Unit tests: `managed/remoteHelp.test.ts` (the dialog's answers, the sheet's cut, the file's name, Share's and Download's clean-up, the TalkBack lines) and `fixtures/remoteHelp.test.ts` (every demo state in the contract's shapes, the dialog and the demo passkey through `turnOnRemoteHelp`, Claude's visit, Stop, starting over). Checked on the emulator in the demo world, light and dark: off, off with a passkey, the dialog, on, a customer's Whombat, history, not available, the command line, Share (the share sheet with the file) and Download (“Save as” wrote the bytes). Not run against a managed Whombat here: the lead checks the passkey prompt for the Whombat's RP ID on DEV. | DEV fast; the logic is in pure modules, the screen is shared pieces. |
| AP-4480 | **“Support is connected now”** (contracts 0.121.1, CT-1050): the card's connected line lets the name stand alone, as DEV's tool now connects as “Support” (was “Claude”); the fake's default visitor, the demo world's and the e2e's are “Support”. | John: when Whombat connects, the owner reads “Support”, not “Support from Whombat support”. |
