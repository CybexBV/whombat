# Home redesign: one Home on web and phone (2026-10-18, stream W)

The app's side of Whombat `docs/decisions/home-redesign.md` (HR-20…HR-24, and HR-05/HR-08 for Done recently) on
contracts 0.91.0 (CT-403 `HomeChat`, CT-404 `ThingSummary.usedAt`). Wireframe: `docs/design-handoff/home-redesign/`
(order and content; drawn with mock 1's Home cards, no highlight outlines). The phone's side is
`home-redesign-mobile.md` (AP-2250…).

## The shared model (`packages/client/src/home/sections.ts`)

| # | Decision | Why |
|---|---|---|
| AP-2206 | **`homeSections(overview, options)` is Home** for both apps: Needs you (only with items; its count is the summary's when the server holds some back), Chats (always), Servers (where `hosts.status.present`), Your things (when there is something, or the viewer may add a connection), Done recently (always), pinned panels (only when there are any). `HOME_LIMITS.web` is 4 chats and 5 changes, `.phone` 3 and 3. The apps draw the list; neither decides what is on Home. | HR-20: same sections, same order; a new section is one change in one place. |
| AP-2207 | **Chats** (`homeChats`, `homeChatRows`, on core's `HomeChat`; `homeSections` reads `HomeOverview` itself, `HomeInput` is its `Pick`): `overview.chats` (CT-403), or, from a server older than 0.91 that sends no `chats`, one row made from `working` (its active or waiting step is the row's `step`); an empty `chats` from a newer server means no chats. Sorted working → waiting → recent, each newest first, then cut to the limit. A working row has its bar (`done/total`, none without a plan) and “Working · step 3 of 4” (the step after the done ones, never past the last; “Working” without a plan); a waiting row “Waiting for you”; a recent row only its time (Done recently's clock/weekday/date). The step's own words are the row's tooltip, not a line. The default chat (`HomeChat.default`, titled with the assistant's bare name) is “Your chat with Dusty” (`defaultChatTitle`). The greeting's sentence reads the working chat when `working` is empty, never the default one (“I’m working on Dusty” says nothing). `home.changed` already refetches the whole overview, so the server's `working` part refreshes chats with no client change. | HR-21; the client sorts so an older or newer server's order can't put a recent chat above the one being worked in. |
| AP-2208 | **Your things** (`homeThingRows`): every connection and device, figures first, each group in the server's order; servers (their own section) and parts of a server (CP-10) left out. A row has its tile title (`thingTileTitle`: “Network” for UniFi), the web tile's meta, its figures, and one line for the phone: its first three figures as phrases (`factPhrase`, moved here from the phone), else `connectedLine`: “Connected · used today / yesterday / Wednesday / 10 Sep” from `usedAt`, or “Connected”. A thing that isn't fine says so instead of “Connected” (“Offline · used yesterday”, “Learning”, “Needs a look”); `unknown` is still “Connected”. The full weekday (“used Wednesday”): it is a phrase, not a column. | HR-23. A dead connection saying “Connected” would be the kind of untrue line HR-01 removed from Done recently. |
| AP-2209 | **Done recently**: `doneRows` is unchanged for Undo/Review — Review is the change's `link`, which after HR-08 is the chat it was made in (else the thing's page); the server decides, the client doesn't make links from `thingId`. New `by` (`changeBy`): “You” for the viewer's own change, the person's name for someone else's, null for an agent's. | HR-05, HR-08. |
| AP-2210 | **The web's grid** (`homeWebSlots`): Needs you (left) beside Chats (right), Done recently (left) beside the first pinned panel (right), everything else across the width; a pair missing a member gives the other the whole width. Slots follow the sections' order, so the page reads as the phone's. Done recently moved to the wide left column: its titles are longer now (HR-02) and its time column is fixed (AP-2214). | HR-20 names the pairs in this order; mock 1 had the widget on the left, but Done recently's rows now need the room more than a chart does. |

## The web's Home

| # | Decision | Why |
|---|---|---|
| AP-2211 | **Chats with Dusty** (`ChatsCard`, Working on's place and size): the header names the assistant, “All chats” at its end. A row is one link to its chat, laid out like a Needs you item: a 32px lead column (the assistant's face on its tint for the working chat, as a chat draws it; a dot otherwise: warn for waiting, ok for recent), the title (600 15.5px, two lines at most), the working chat's bar (Working on's 5px bar) and its line (13px muted; “Waiting for you” in the warn tone, as Working on's waiting step), the time in mono at the end. With no chats: “No chats yet. Ask me something above and it shows here.” AUTOMATIONS TODAY stays its footer. Working on's steps list is gone (the chat has them); `WorkingCard` is deleted. | HR-21 and the wireframe's order; mock 1's type and tokens. |
| AP-2212 | **Your things on the web**: the figures' tiles as mock 1 draws them, then a grid of small tiles (`minmax(240px, 1fr)`, the card's border, radius and surface; mark or glyph, name 600 15.5px, the line 13px muted, the status dot with its words) for things without figures, ending with a dashed “+ Add a connection” tile. That tile shows for every person (a member adds their own connection; a shared one asks for a manager on its page, CX-03 — the sidebar's `+` already offers it to everyone) and opens Add a connection (`?tab=connections&connection=add`) where the catalog is, else Settings → Connections. | HR-23. Two sizes in one grid would leave holes; the small tiles read as a row of “also connected”. |
| AP-2213 | **Who made a change**: every Done list (Home, Everything I did, a thing's “Changes here” panel and Activity tab) puts “You” or the person's name before the detail (“You · 2 → 4 GB”); an agent's change says nothing more. The Activity tab's title is “Changes here” too (it was “What Dusty changed here”), its empty line “Nothing yet. What you or Dusty change in <thing> shows up here.” The demo world keeps a person's edits off Home and Everything I did, as the server does. | HR-05: the thing page now lists people's edits, so it must say whose. |
| AP-2214 | **Done recently's time column**: the time and the action share one column of 150px (the time right-aligned in what is left of it, the action in 58px), so times end at one edge and Undo (with its icon), Review and Undone start at one edge whatever a row has. Home shows the newest 5 (`HOME_LIMITS.web.done`). | Times line up whatever a row offers (the assignment); mock 1's column moved with the action. |
| AP-2215 | **All chats** (`/chats`, `ChatsScreen`, `allChatRows`): the page Home's “All chats” opens — every chat with the assistant that isn't archived, newest first, the default one as “Your chat with Dusty”, each with its last words, an unread pill and its time; “Ask Dusty” starts another. `/chats` joins `BURROW_ROUTES`. | The web had no list beyond the sidebar's twelve; the phone has its Chats tab. |
| AP-2216 | **The pairs follow Home's own width** (`container: home-grid`): a pair stacks when Home is under 860px wide (a 1024px window with the sidebar open), not when the window is under 1100px. | The less-is-more rule (AP-1760): the room a card has, not the window's, decides; at 1200px the pairs now fit. |
| AP-2217 | **Undo asks the agent** (contracts 0.91 `UndoChangeResponse.state: 'requested'` with `conversationId`, CT-406; Whombat HR-03): `undoOutcome` says what pressing Undo did — “Undone.”, “Undoing this needs an approval first.” (with the approval), or “Asked Dusty to undo this.” with the chat (the toast's “Open the chat”); not an error and not undone. The server's change doesn't carry the request, so `useUndoChange` keeps it in the query cache (`useUndoRequests`, per burrow, for the session) and `doneRows(…, { requests, assistantName })` gives the row `requested` (“Asked Dusty to undo this”, a link to the chat, in place of the detail) without Undo for `UNDO_REQUEST_HOLD_MS` (10 minutes, the server's refusal window); once the agent marks it undone the row says Undone, after the 10 minutes Undo is offered again. The demo world has one change Dusty reported in the default chat (“Removed 14 old Zonneplan entities from Home Assistant”): Undo posts “Please undo this: …” there and answers `requested`; a second press within 10 minutes is refused. | The agent puts a reported change back, so the honest answer is that it was asked; the phone reads the same model. |

## AP-2218 The connect form suggests the name the server gives

A new connection's name field suggests what the server will name it when left empty (Whombat HR-07): the service's
name, with its address only when a connection of the same service is already listed (`useAutomaticLabel`, the same
`defaultConnectionLabel(…, { onlyOne })` rule). Custom APIs keep their address.
