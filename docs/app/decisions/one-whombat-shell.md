## Visual check

Compared in Playwright at 1440 wide against `index.html` rendered at the same size (both themes), element by element:
Home matches the mock to the pixel down to the Servers card, whose rows are WT's (the stand-in is shorter, so the
widget and Done recently sit 62px higher until WT's card lands); the heat pump chat matches within 1px. Deliberate
differences: the fixture's people and burrow (Mara, Burrow HQ), “I’m adding your Daikin heat pump.” (the task's
title, AP-1265), the chat's ⋯ menu and the composer's paperclip (AP-1260), the chat's line “about Heat pump” (no
“uses …” in the contract), the widget without “Using 1.2 kW” (see Gaps), Network without “A new device joined”
(assignment §9). Shots: `~/.cache/wb-tmp/one/ws/shots/`.

## Gaps in contracts 0.80.0 (for 0.80.1)

- A widget value that isn't a line (mock 1's “Using 1.2 kW”): `Widget.latest` has no label and `WidgetSource.values`
  is at most 3, the same as the lines.
- A chat's “uses your network and Home Assistant” (mock 3): nothing says which connections a chat used.
- The device skill card has no link to its profile or manual (“Show the skill” shows what the card carries).
- Home sends no Ask suggestions and no tile title (made in the client: AP-1267, AP-1273).
- The HTTP transport says nothing about the runtime's shell: a legacy server with `WHOMBAT_SHELL=crew` still gets the
  assistant shell here (AP-1257).
- No `chats.unarchive` and no `watch.acknowledge` (both announced for 0.80.1).

| AP-6454 | **`pnpm test` fails when web, admin or widget code reads a CSS-module class its stylesheet doesn't define** (`apps/web/css-modules`, 2026-11-12). The stylesheet's names come from Vite's own CSS-module transform with `camelCaseOnly`, as the build makes them; the lookups judged are `styles.x`, `styles['x']`, a conditional of two names, `const { x } = styles`, a template key or `variantClass(styles, 'base', key)` with a fixed start (some class must start with it), and the same through a re-export (`export { f as frameStyles }`).
