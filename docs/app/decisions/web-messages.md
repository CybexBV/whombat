# Web conversations: the improvement review's messaging items (WX-01…)

John, 2026-10-07: “Implement this fully so everything you recommend” for the improvement review
(Whombat `docs/implementation/improvement-review/report.md`, sections A3 4/6/7, B 4 and C 3/4/6/10–13). This is stream
WM (web conversations) of that build: the room's render cost, the thread's reply box, drafts, permalinks, the unread
divider, `/ command` in agent DMs, toasts with Undo, and with contracts 0.55.0 thumbnails, Stop, thread paging and the
`deploy` card. Choices are ours (feedback-decide-yourself); the item ids are the decision ids.

| # | Decision | Reason |
|---|---|---|
| WX-01 | **The room no longer renders again while an agent thinks.** The “is thinking” line keeps its own one-second clock (`TypingLine.at`, read by `TypingIndicator`'s `useTicker`); `useTypingLines` no longer ticks. Rows are `ListRow`, a `memo` around `MessageRow` that compares every prop by identity except the thread's work (`ThreadWork`, compared by value); the room hands it stable handlers (`useStableCallback`: a function whose identity never changes and that calls the latest closure), `renderCard` keyed on the burrow, `renderEditor` on the edit state, and `renderAfter` returns null for a row with nothing under it. `useMessageActions`' handlers are stable too. `groupByDay` is memoized. The sidebar's 30-second clock lives in the moon (`QuietMoon`), not in the footer. Measured (`renderCounts.test.tsx`, jsdom, #billing-v2's 7 rows, Pippa thinking, ten one-second ticks with `setInterval` and `Date` faked): before, 70 row renders, 10 commits, 58–63 ms rendering; after, 0 row renders, 10 commits (the line itself), 0.7–0.8 ms. The test keeps it at 0. | The room re-rendered every row, card and attachment once a second for as long as an agent worked; on a long channel that is the whole page's work, sixty times a minute. |
| WX-02 | **In a long list, off-screen rows skip layout and paint: `content-visibility: auto` on a slot around each row** (`MessageList.module.css .slot` + `.skip`, the room and the thread pane, from 30 rows: `SKIP_ROWS_FROM`), `contain-intrinsic-size: auto 120px`. The slot reaches 10px past the row on each side and takes it back with a negative margin, because `content-visibility` contains paint: the hover toolbar (6px above the row), the pins pane's highlight (8px ring) and focus rings stay visible, and rows sit where they did. Short lists don't skip: containment snaps a row to whole pixels, which moved the text of rows at fractional offsets by a fraction of a pixel (the mock comparisons went from 0.18 % to 0.43 % on #billing-v2); with the threshold `pnpm visual messaging toasts` measures exactly as before. Not on the day sections: a day can be thousands of pixels, one guessed size for it would jump the scroll; a row's guess is small and `auto` remembers its real size once seen. | The cheapest windowing there is, where it pays (a first page is 50 messages); it keeps find-in-page, links to a message and screen readers working, which a virtualizer would not without more work. |
| WX-03 | **Image tiles show the Whombat's thumbnail** (contracts 0.55 CT-298): `Attachment.thumbnailUrl` when there is one, the file otherwise, an SVG always the file (a `data:` URL, AP-100). On a self-hosted Whombat the `<img>` has `srcset` with width descriptors (`thumbnail 720w, file {width}w`, `sizes` the tile's box: 360px or 210px in a gallery), so a 1× or 2× screen takes the thumbnail and only a 3× one the file; without both widths, the thumbnail alone. Over a session (managed) the thumbnail is the download's `preview` variant of the file's ref, cached apart from the file (`resourceKey`, shared with the phone's MX-09), no `srcset` (one read per tile). When the thumbnail won't load (none made, `variant_unavailable`, an older server) the tile loads the file. Tiles decode with `decoding="async"`; the lightbox always shows the file. | A 250 MiB upload's tile downloaded the whole original for a 360×240 box. |
| WX-04 | **The thread's reply box is the composer** (`Composer variant="reply"`): the mock's one row (`Reply in thread`, “To Banjo”, `+ file`, Send; 13px 14px padding, 14px radius) with the composer's `@` list, `/` list, `+ file`, paste, upload chips (above the field, the box's width), ↑ to edit, too-long note and mention auto-correct; files dropped on the pane attach to the reply (`useFileDrop`, the room's drop zone). The thread's chips are its own (`useUploads(burrow, conversationId, threadRootId)`), uploaded to the conversation. `/` offers the agents' skills only in a thread: `/topic` and `/invite` act on the conversation, and `useSend` already sends a thread reply that starts with `/` as words. The pane is keyed by its thread (`hosts.tsx`), so caret, chip dismissal, chips and scroll don't carry over; focus mode keeps the same pane. `pnpm visual` hides `+ file` there (`[data-composer-file]`): the mock's reply box has none. | A thread could take no file or screenshot, and its draft leaked to the next thread and was lost on close. One composer means one behaviour to keep right. |
| WX-05 | **Drafts persist** (`drafts.ts`): `localStorage` under `whombat:draft:<burrow>:<conversation>`, a thread's under `whombat:draft:<burrow>:thread:<root>` (known before the thread loads), as `{text, at}`; written on every change, removed when emptied or sent; a draft left for 30 days is dropped when read; where storage refuses, the tab keeps it. `clearDrafts` removes them all, and now runs on the self-hosted sign-out too (`useSignOut`), besides the managed scope guard (AP-17). | A reload, a crash or a closed tab lost what someone was writing. Drafts in the browser are like the theme and recent emoji: this browser's, gone with the session. |
| WX-06 | **“Copy link” in the message menu** (room and thread, after Add reaction): the conversation's own link (`summary.link`, so a branch room keeps its repository) with `#msg_…`, a reply's as `?thread=<root>#msg_…`; burrow-less with `?burrow=`, on a managed Whombat through `applianceLink` (the canvas's Share, MR-45). It toasts “Message link copied.”; when the clipboard refuses, “Couldn’t copy the link: {url}”. Opening such a link scrolls the room to the message and highlights it for 1.6 s (the pins pane's `data-flash`); the thread pane opens at the reply and highlights it. | The room already opened `#msg_…` links and the memory editor asks for one (`MemoryEditor`), but there was no way to get one. |
| WX-07 | **The “New” divider and “New messages ↓”.** When a room opens, `unreadStart` (pure, tested) puts a divider (the day divider's hairline and mono label in `--bad`, `New`, 16px from the rows around it) above the first message after `lastReadMessageId` that someone else wrote — only when the sidebar counted something unread (a cached detail can be older than the marker) and the marker is loaded (older than the first page: the top of the page; gone: none). It stays put while the room is open. With more unread than fits, the room opens at the divider instead of the bottom. Marking read now also writes the marker into the cached details (`rememberRead`), so the next visit starts there. Messages someone else writes while the reader is further up raise a pill at the bottom centre of the message column (the active chip's colours, 13.5px 600, the toast's shadow); it takes them to the first of those (near the top) or to the bottom when that is closer, and goes when they reach the bottom or send. Fixture mode: `VITE_FIXTURE_UNREAD=1` puts the seed's read markers on #incidents and Pippa's DM, and with `VITE_FIXTURE_RICH=1` makes Pretzel's six messages in #general unread. | The room jumped to the bottom with no sign of where reading stopped, and a reader scrolled up never learned that someone had answered. |
| WX-08 | **`/ command` goes from an agent's DM once its agent's skills have answered with none** (no command works in a DM): it stays while they load or when they couldn't be read (an error isn't “none”). The DM asks for them at once (one cached request) instead of at the first `/`; channels and branch rooms are unchanged. The visual suite gives the DM's agent one skill in the cache (`messaging.spec.ts`), as the mock's agents have. | The chip opened a list saying “Commands work in channels and branch rooms.”: a control with nothing behind it. |
| WX-09 | **Toasts: two at once, with an optional action; delete has Undo.** `ToastApi.show(message, {duration, action, onEnd})` returns an id; a third toast ends the oldest (`replaced`), the same plain words replace the toast saying them, the newest sits nearest the bottom edge (8px apart). With an action the default is 6 s (2.6 s otherwise, the mock's); the clock stops while the pointer is over the toasts or focus is in them. The action is a real button in the toast's colours, 600, underlined, its focus ring in `--btnfg`. **Delete message** (own message, no replies) hides the message at once (`pendingDeletes.ts`, read by the room and the thread pane) and toasts “Message deleted.” with **Undo**; the delete is sent when the toast ends (time, dismissed, replaced), when its conversation's room closes (`leaveConversation`, focus mode keeps the room) or on `pagehide` (as far as the browser lets it out). Undo brings the message back and sends nothing. A refusal or an error brings it back with the reason in a toast; a delete that went through without its answer (CT-195) stays hidden. Deleting the open thread's root closes the pane at once. | The mock shows one toast at a time, but a quick second toast (a pin) hid the first's Undo; a delete without a way back made people confirm everything. |
| WX-10 | **Stop** (contracts 0.55 CT-295, Whombat RF-01). On the thinking line (room and thread) when the `typing` event names the agent's turn (`TypingEntry.dispatchId`) and the viewer may stop it (`useCanStop`: the Whombat has `dispatches.cancel` and core's `canStopTurn` says so for a live, non-run turn): **Stop** after the words, the app's inline action (13.5px 600 `--brand`), named “Stop Pippa” for assistive technology, busy while the answer is out. In the profile pane's RIGHT NOW: the same button after what the agent is doing, for the agent's turn the Work view offers `stop_turn` on (running before queued; the server decides who may), asked for only while the agent works. On Work items: `stop_turn` is offered when the item names its turn and the Whombat has the feature. All three go through `useStopTurn`: `dispatches.cancel`, the thinking line leaves the cache at once, “Stopped Pippa.”; a refusal says the server's words (“Pause the run instead.” for a run's turn), 403 “You can’t stop Pippa here.”. The toast says the agent's name, not “turn” (WE-16: no runtime words in the product). **On a run's line, Pause while it works and Resume while it is paused** (`runControls`, the run page's `useRunControl` and toasts), before Watch run / Open run. | An agent could only be stopped by deleting its thread or from the run page; a person who sees it go the wrong way should stop it where they see it. Resume beside Pause so a pause from the line doesn't strand the run there. |
| WX-11 | **Thread paging** (contracts 0.55 CT-299, `messages.thread_paging`): a thread asks for its newest 50 replies (`limit`), and **Load earlier replies** (the room's “Load earlier messages” button) right under the root asks for the 50 before the oldest one loaded (`more.before`); “Loading…” while it does, gone when nothing is earlier. Each page is its own cached `messages.thread` query (`useThreadPages`), so realtime edits, reactions and deletes reach every page; the replies are merged by id (the newest page's copy) and ordered by time, because the reducers add a new reply to every page of its thread. Earlier replies coming in above keep the reader where they were; a new reply at the end follows as before; a link to a reply still opens at it when it is in the newest page. A Whombat without paging is asked as before (every reply, no `more`). | `threadView` sent every reply of a thread, however long, on every open. |
| WX-12 | **The `deploy` card is a settled line** (contracts 0.55 CT-297; `cardDisplay` → `line`, `deploySettledLine`, shared with the phone): `Deployed api to production · 3f9c2a` with an ok dot, `Deploy of api to production failed · 3f9c2a` with a bad one, then the deployed address as its host with ↗ (a new tab, `noopener noreferrer`, “api.example.com (opens in a new tab)”, the whole URL as its title; only http(s)) and **Deploys** (the board, `/work/deploys`, WA's WE-17). Nothing opens under it: the board has the rest. A deploy a run made shows inside that run's line (`nestedRunId`). | A deploy is a record, not something waiting on anyone; the run line's anatomy says it in one line, and the two places worth going are one click away. |
| WX-13 | **Delete asks first only when it takes more than your own words**: a message with replies (they go with it, AP-553) and a burrow owner removing someone else's message keep the dialog (AP-442), then go with Undo too (`deleteAsks`). | Undo makes the dialog redundant for your own message; for others' words and whole threads the dialog's sentence is still worth reading first. |
