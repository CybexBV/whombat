# Chat as an inbox: the web (2026-11-14)

The web's side of Whombat `docs/decisions/chat-inbox.md` (CIB-01…CIB-13), against the mockup John approved
(`chat-inbox.html`: the desktop window's list column, rows, toolbar, foot and thread). Where the mockup and the decisions
differ, the decisions win: no “Later”, no day headings in the list, the filter reads “Waiting”, the person is “You”, the
assistant's own name, and the Ask box stays at the bottom of the list. The words are `INBOX_WORDS` (`@whombat/client`),
verbatim. The phone is `chat-inbox-phone.md`.

Code: `apps/web/src/features/chats/` (`ChatRoomScreen`, `InboxRow`, `inboxNav.ts`, `useInboxComposer`,
`useThreadMarks`), the shell's `.main[data-beside]` (`ShellLayout`, `BurrowShell`, `hosts.tsx`), `messaging/ThreadPane`,
`ThreadView` and `Composer`, `settings/ProfileTab`, and the fixtures.

## Where each thread stands, on the web and the phone (2026-11-28)

John, 2026-11-28: he couldn't tell from Chat's list which threads wait for a reply, which are at work and which are
done; he approved the mockup (“Yes, keep mobile apps in mind also for this”). The box's side: Whombat
`docs/decisions/chat-inbox.md` CIB-19, CIB-20. Code: `@whombat/client` `chat/inbox.ts` (`rowStatus`), the web's
`features/chats/` (`InboxRow`, `ThreadIcon`, `ChatRoomScreen`), the phone's `screens/ChatInbox.tsx` and
`ui/threadIcon.tsx`.

| # | Decision | Why |
|---|---|---|
| AP-9391 | **Every row has one status** (`InboxRow.status`, `rowStatus`), the first that holds: **Waiting for you** (the thread's `waiting`, or its T3 Code job asks for the person's OK); **{assistant} is working** (its turn, a run, or its live work before the list says so); **T3 Code is working · 6m** (or “is finishing up”, “asked {assistant} something”), from the conversation's hand-overs; **Waiting for checks**; **Working** (a council or a checklist, or T3 Code before the hand-overs were read); then how the latest job ended: **Didn’t finish**, **Stopped** or **Done** (`ChatThread.job`, or a hand-over that ended since the list was read), dropped once the person wrote after that end. Otherwise none. Web and phone share the rule and its words. | One place on every row says where the thread stands, in the same words everywhere. |
| AP-9392 | **The status leads the second line** as the waiting chip did (12px on `--sf2`, 6 round): Waiting for you and Didn’t finish in `--warn-text` 600, Done in `--ok-text` 600, work in `--ink2` 500, Waiting for checks and Stopped in `--mut`. | AP-9394 | **The filters are All · Waiting · Working · Done · Unread**, each number only above 0 (Waiting's `--warn-text`, Working's `--ink2`, Done's `--ok-text`, Unread's `--chart1`); Settled stays at their end. | AP-9395 | **What a screen reader hears** after the title is the status: the inbox's own words in lower case (“waiting for you”, “done”), words that start with a name as written (“Neo is working”, “T3 Code is working”). | Names keep their capitals. |
| AP-9396 | **The phone reads the conversation's hand-overs and live work for its list** (`useHandoffs`, `useThreadWork`), as the web does, so T3 Code's work shows on its rows too; a row's clock redraws only that row each minute. The web passes its language to the rows, so their words follow it. | Before, the phone's list showed nothing while T3 Code worked. |
| AP-9397 | **A row that waits or works doesn't settle** (no Settle on hover, no left swipe), T3 Code's OK and live work included. | A settled thread would leave the list while its status still says something. |
