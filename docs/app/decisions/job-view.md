## A finished job's receipt stays where it finished (John, 2026-11-13)

John, 2026-11-13, in a Chat thread on Home: the Done card of T3 Code's job stayed at the bottom while the chat went on
for another ten messages (the box lists an ended job for a week, and its parts followed the newest message all that time).

| ID | Decision | Why |
|---|---|---|
| AP-8944 | **Superseded in part by AP-9348: no stage track.** **An ended job's parts stay under the last message from before it ended once someone wrote after that** (`jobPartsAfter`, `@whombat/client`; the web's `ThreadPane` draws `JobDetails` in that message's `renderAfter`, among the rows as drawn, not one folded into a run). While the job works, and after it ended until someone wrote, they stay the thread's last, under T3 Code's line. The stage track under the head stays. | The receipt is a record of a moment, like a message: it reads where the job finished, and the newest messages stay last. Hiding it would lose how the job went; keeping it last made it look as if the chat had stopped there. |
| AP-8945 | **The phone does the same**: `ChatView`'s `footerAfter` names the message `JobPanel` goes under (`MessageRow`'s `below`, outside its long press), `ThreadScreen` gives it `jobPartsAfter`. | As the web. |

## No stage track (John, 2026-11-16)

John, 2026-11-16, on the thread of a job that only looked into a bug report: the bar of eight stages over the thread
“is not accurate, sometimes it shouldn't show it at all”. Replaying real jobs through the box's rules: two looks sat on Reading
from start to end and after; a fix jumped to Tests three minutes in (a folder named `e2e` in a read) and stayed there
through 37 minutes of editing; another went from Reading straight to Pull request. Only 5 of the last 40 jobs handed to
T3 Code opened a pull request. He agreed to take the track out.

| ID | Decision | Why |
|---|---|---|
| AP-9348 | **No stage track** on the web or the phone: no bar under the thread's head (`StageTrack`, `JobTrack` and `jobTrack` are gone) and no segment per stage on a T3 Code job's row, which keeps the soft sweep while it works. The box still keeps `Handoff.stage`: the steer box shows for a box that gives one (AP-7866). | The stage was guessed from shell commands, only moved forward and stayed lit where it last got after the job ended, and most jobs (a look, a sync, a council) never go near a pull request. A track that is wrong as often as right says less than none. |
| AP-9349 | **What T3 Code does now is its latest step** (“changing the code”, “running the tests”, from `Handoff.steps`); `jobDoing` adds only what the box knows for sure: “fixing a failed check” while a check on its pull request failed, “waiting for the checks on #48” once its run ended waiting for them. Never the furthest stage reached. | The step follows the work back and forth; the furthest stage said “running the tests” through half an hour of editing. |
| AP-9350 | **A Pull request part** (`jobPullRequest`, web `JobDetails`, phone `JobPanel`): once the job has a pull request and until the receipt says it, “PULL REQUEST · #48 · open” (draft, merged, closed) as a link to it, before Changes; on the phone one row at least 48dp / 44pt tall. A screen reader hears “Pull request #48, open”. | Whether it has a pull request and whether that is merged are GitHub's facts: the part of the track that was right. |
| AP-9351 | **The demo worlds' jobs carry T3 Code's steps** (`@whombat/fixtures`' `jobSteps`, kept apart from `jobFixture` so a world's own steps aren't overwritten by its spread). | So their rows and lines say what each job does without a box. |

## The first build, in Code


John, 2026-11-07: “make this section more enjoyable for software development … nice status / progress in the thread
view”. He approved this proposal: a stage track (Reading, Plan, Editing, Tests, Review, Pull request, Checks, Merged),
T3 Code's plan as a live checklist, changes at a glance, checks inline with fix attempts, answering T3 Code's questions
and steering from the thread, and a finish receipt; phone notifications only for needs-you, done and failed. This
reverses AP-7808's “Changes and Checks are not shown”. The box's side is Whombat `docs/decisions/t3code.md`
T3-30…T3-41 (`Handoff.stage`, `.stages`, `.plan`, `.changes`, `.checks`, `.question`, `.pullRequest`, `.receipt`,
`conversations.handoffAnswer`, `conversations.handoffSend`).
