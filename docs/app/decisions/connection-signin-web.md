# Connections that sign in properly: the shared client and the web (AP-3900…AP-3949)

John, 2026-10-21: “We have lots of connections, but some of them don't work correctly regarding the sign-in process. For
example Plex auth is not working when it has 2FA.” The product decisions are Whombat's
`docs/decisions/connection-signin.md` (SG-01…SG-22); this is stream W of
`docs/implementation/connection-signin/assignment.md` there: the client side of SG-01…SG-22 in `packages/client` (shared
with the phone, stream A, `AP-3950…`) and the web's connect form, connection page and Dropbox app setup. Contracts
0.111.0 (CT-730…CT-749: `service_login`, `StartServiceLoginBody/Response`, `PollServiceLoginResponse`,
`ConnectionErrorDetails.challenge`, `CreateConnectionBody.login.challenge`, `twoStep` with `code`, feature
`connections.service_login`). No mockup: the connect form's steps and the Nextcloud wait (`connections-setup.md`
AP-843…).

## The client (shared with the phone)

| ID | Decision | Why |
|---|---|---|
| AP-3900 | **`signInChoices(entry, signInOnce, serviceLogin)`**: a third flag, off by default, leaves the `service_login` sign-in out on a runtime without `connections.service_login` (CT-744), so Plex offers its token there; `tokenIndex` still counts every token sign-in. The phone passes its feature the same way. `FEATURE_NAMES` names it “signing in to a service on its own page”. | CT-744: offer the sign-in only where the runtime has it; existing callers unchanged. |
| AP-3901 | **Its button is the entry's label** (“Sign in with Plex”, `connectButtonText`), and the way out after a refusal naming it (`details.method: 'service_login'`) is “Sign in with {Name} instead” (`switchText`), as the OAuth ones. | SG-05. |
| AP-3902 | **The http warning for it is the token's** (“the token crosses your network unencrypted”): Plex's page is https at plex.tv, only the token it gives uses the server's address. The Plex branch of sign in once's warning (CM-06) is gone with that sign-in (CT-739). | SG-04: plex.tv over https. |
| AP-3903 | **It takes the level** (`asksAccess` true: the start carries `access`, CT-738), so no level note under it (`elsewhereLevelNote` null) and the guided token beside it keeps the level's link. | The assignment: “it takes the level, so none”. |
| AP-3904 | **Recommended when first**, as sign in once and an OAuth client (`recommended`): it makes a lasting token without the person reading XML, and handles two-step codes, Google and Apple accounts and passkeys. Nextcloud's own login (first since SG-15f) keeps its card without the tag: not this stream's form to change. | SG-01; the tag says which card to pick. |
| AP-3905 | **Its card's line is the entry's `note`** (`signInNote`: “Sign in to Plex in a new tab and allow Whombat.”); under the cards, as Nextcloud's, `CONNECT_FORM_TEXT.serviceLogin(name)` “{Name} opens in a new tab: sign in there and allow Whombat. This page carries on by itself.” (`serviceLoginPhone` with the browser for the phone). | SG-05; Nextcloud's words in the entry's name. |
| AP-3906 | **A session's two-step code** (`asksTwoStepCode`: a token sign-in whose session has `twoStep`, CT-732: Synology): the code shows only once the service asked (`codeShown`), with the server's words as its help; `draftProblems` asks for it then (`codeProblem`: “Enter the code.”, “Enter the whole code.” under 4); `createBody` sends it as `code` beside the secret (CT-733), and `setSecretBody` for Replace password. The field is sign in once's (“Code from your authenticator app”, `one-time-code`). | SG-09: asked once, then DSM trusts Whombat. |
| AP-3907 | **The bodies**: `serviceLoginBody` is what every way of connecting sends plus `access` where agents use it (none for automations' and gateway entries, as `createBody`); `reconnectServiceLoginBody(conn)` sends the connection's own entry, scope, fields and level with `connectionId`, so signing in again never changes the level. | CT-738: the level is set on save; SG-02 reconnects by id. |
| AP-3908 | **The wait's words** (`SERVICE_LOGIN_WAIT_TEXT`) are Nextcloud's in the service's name: “Waiting for Plex…”, “Sign in and allow Whombat in the tab that opened. This page carries on by itself · 9 minutes left”, “Open the Plex sign-in”, Cancel, “The sign-in took too long. Start again.”, “Plex didn’t finish the sign-in.” (the server's sentence when it sends one, SG-05's owner refusal). `serviceLoginEnds` caps at `SERVICE_LOGIN_MAX_MS`; `serviceLoginCode` is the `userCode` to show (“Enter this code when {Name} asks for it”, with Copy), null for Plex; `serviceLoginPollStep` reads the poll (Nextcloud's schema, CT-738). | SG-05: “While waiting: as Nextcloud's”; CT-738's nullable `userCode`. |
| AP-3909 | **The challenge** (`ConnectProblem.challenge`): kept from `second_factor_needed` and from a `code` refusal that carries a new one; `ConnectDraft.challenge` (optional, so a form that keeps none sends none) goes back as `login.challenge`, and only with a typed code (CT-731). The form forgets it when the account, the password or the sign-in changes, and after connecting. | SG-06: UniFi's emailed code belongs to its challenge. |
| AP-3910 | **Dropbox's app setup** (`APP_SETUP_TEXT`): step 2 “…tick these and click Submit before anyone signs in:”; step 3 after the redirect URI “Leave Allow public clients (Implicit Grant & PKCE) on Allow.” and “Under Development users, click Enable additional users, so people other than you can connect.” (`dropboxPublicClients`, `dropboxMoreUsers`). Still four steps. | SG-22: a new Dropbox app links only its owner; scopes added later need a new sign-in. |

## The web

| ID | Decision | Why |
|---|---|---|
| AP-3911 | **The connect form signs in on the service's own page as it does Nextcloud's**: offered only with `connections.service_login`; the tab opens inside the click (`openLoginTab`, `about:blank`), goes to `loginUrl` once the start answers (`pointLoginTab`, `opener` null) and is closed if the start fails; `ServiceLoginWait` polls every `pollEveryMs` until connected, expired (at most 10 minutes) or failed, with Nextcloud's card, spinner, minutes left, “Open the Plex sign-in” (for a blocked tab) and Cancel; connected, it closes the tab (Plex has no `forwardUrl`, SG-04), toasts “{label} connected.” and opens the connection. `userCode`, when not null, shows under the line with Copy. A failure goes above the button in the server's words (“Plex let Whombat in, but…”). The OAuth branch no longer takes `service_login` by accident. | SG-01, SG-04, SG-05; the assignment's “modelled on Nextcloud's”. |
| AP-3912 | **The connection page**: an entry with a `service_login` sign-in, on a runtime that has it, offers **Sign in again** beside Replace token (primary when the connection needs you; Replace token is then secondary) and waits in SIGN-IN for the same connection (`reconnectServiceLoginBody`), staying on the page with a toast. **Replace password** asks a session's two-step code once the service does (the code field under the password with the server's words, “Enter the code.” / “Enter the whole code.”, a refused code under it) and sends `code` with the password (`setSecretBody`); its toast names the secret (“Password replaced.”, “App password replaced.”, else “Token replaced.”), never a token for a password (CM-10). | SG-02 (`connectionId`), SG-09 (“same on Replace password”). |
| AP-3913 | **The fixtures walk it** (`catalogFixtures.ts`): `startServiceLogin` answers Plex's PIN page URL (`app.plex.tv/auth#?clientID=…&code=…`, no `forwardUrl`), `userCode` null, and connects on the second poll at the level asked (`detail` “mara”), or that connection again with `connectionId`; an address with `notowner` fails in SG-05's words. UniFi's sign in once with the password `2fa` asks with a challenge, a code without the newest challenge is asked for again with a new one, `000000` is refused with a new one. Synology's password `2fa` asks for its code (connect and Replace password), `000000` is refused (“…current code…”). A connection's transport follows its sign-in's (`transport` per sign-in, contracts 0.111: Todoist's token is REST beside its MCP sign-in). | Demo and tests without a server; CS-03's fixture rules extended. |
| AP-3914 | **Checked.** Client unit tests (choices with and without the feature, buttons, switch, http warning, level, the challenge kept and sent only with a code, a session's code shown/asked/sent on connect and Replace password, the start and reconnect bodies, the wait's deadline, code and poll). Fixture-app tests (`connectionSignIn.test.tsx`): Plex's tab opened in the click, pointed at Plex, closed when connected, the connection at Look only, Sign in again on its page; the owner refusal; UniFi's challenge sent back and forgotten when the password changes; Synology's code on connect (a refused one under the field) and on Replace password; Todoist, Airtable, Mollie and Cloudflare offer “Sign in with {Name}” first and their token beside it. Looked at with Vite in fixture mode (`VITE_FIXTURES=1`), light and dark at 1440×900 against Nextcloud's form and wait: Plex's form with Sign in with Plex chosen, waiting for Plex, Synology's and UniFi's code asked, Plex's SIGN-IN with Sign in again, Synology's Replace password asking a code, Dropbox's app steps, Gmail's hint with both links, Todoist's form. Not in the mocks (B-05): no `pnpm visual` comparison. Not checked: a real Plex PIN, UniFi, DSM or Dropbox (never signed in to a real service). | The assignment's tests and visual check. |
| AP-3915 | **A mail hint with two links** (`hintLinks`): the connection to use instead (“Connect Google instead”) and the provider's page, which beside a connection is where the mail-only app password is made (“Make an app password”, `myaccount.google.com/apppasswords`); one link otherwise, as before (`hintLinkText` stays for the phone until it moves). Side by side under the hint's sentence. The IMAP fixtures use the contracts' Gmail and Outlook hints. | SG-18d, CT-747: Gmail's hint carries both. |
| AP-3916 | **The vendors' own MCP sign-ins need nothing new**: Todoist, Airtable, Mollie and Cloudflare's `mcp_oauth` “Sign in with {Name}” is Notion's card, note, level note and “Continue to {Name}” button, and the managed callback already takes any catalog id at `/connect/<id>` (`isManagedConnectionReturn`: any `[a-z][a-z0-9_]` id but google and microsoft), as the self-hosted return does (`returnTo` on this form, the server's callback). | SG-20; the lead's check for S2. |
| AP-3917 | **The code field doesn’t name an app**: “Two-step code” (“Two-step code (optional)” where the service can’t tell a missing code from a wrong password), web and phone alike; the hint under it keeps the service’s own words (“Enter the code UniFi just emailed to …”). It said “Code from your authenticator app” on every service, but UniFi may email the code. | Found by stream A on the phone. |
