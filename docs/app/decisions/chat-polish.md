# Chat polish (web and phone, 2026-10-28)

John, 2026-10-28, in the main checkout: “In the Chat when we click on the message (instead of the replies) we should
navigate to the thread as well”, “Remove the ‘Add reaction’ when we hover our mouse over a chat message” and “By default
we have ‘the tracker’ support in Automations, this should be removed because this should only appear when the tracker is actually
configured.” No contract or runtime change.

| # | Decision | Why |
|---|---|---|
| AP-6140 | **A click on a message in Chat or Feedback opens its thread**, as its replies link does, with or without replies (web: `MessageRow`'s `threaded` rows; phone: a tap on a top-level row, `ChatRowEnv.opensThreads`). What the message holds keeps its own click: links, buttons, inputs, a card's controls, the toolbar. A click that ends a text selection in the message opens nothing, nor does one with a modifier key or on a message still being sent. On the web the row shows the pointer cursor; no hover background (the mock has none). The keyboard and screen readers keep the replies link, Reply in thread and the menu. | In Chat every message is a thread, so the message itself is the obvious thing to click. |
| AP-6141 | **No “Add reaction” on hover.** Amends AP-440 and AP-444 (essentials-messages.md): a message's hover toolbar has Reply in thread and More actions only, and the small “Add reaction” pill after the reactions is gone. Add reaction stays in the message's menu (More actions or a right-click), and a reaction pill still toggles. Everywhere a message row shows (Chat, Feedback, threads, branch rooms). The phone has no hover and keeps its own. | A reaction button on every hover was noise in a chat with one assistant; the menu still has it. |
| AP-6142 | *Superseded in part by AP-6200 and AP-6212 (automation-chat.md): there is no form or step editor, and the subtitle no longer lists sources.* **The tracker shows in Automations only where a tracker connection exists** (Settings → Connections; `useTrackerConnections`): New automation's step one has four choices without it (`triggerChoices`), the automation's Steps editor drops the tracker trigger and the two tracker steps from Add a trigger / Add a step (an automation that already has them keeps them), and the list's subtitle says “Work that starts on its own, from GitHub, a message or a schedule.” With a connection everything is as AP-1016 and AP-1080 say. Supersedes AP-1016's “only on a Whombat with `automations.tracker`”. | The tracker is one company's tool; offering it to everyone was noise. Connecting it is what says the person uses it. |

John, 2026-11-01, in the main checkout: “When Dusty sends a message in the chat and then sends another message, it’s
unclear where the new message starts. I think there should be a subtle divider or something.”

| # | Decision | Why |
|---|---|---|
| AP-6144 | **A faint hairline above the same author's next message.** Where a message by the same author follows without its own name line (a thread on the phone, `ChatItem.continues`; the web's task-chat look, `MessageRow`'s `continued`), a 1px `--line` hairline sits halfway down the gap above it: full width on the phone, from the text's edge on the web, where the gap grows from 12px to 16px (8px to 12px in a side pane). Decoration only (hidden from screen readers; the row's label already names the author). Not above a day divider, the “New” line or a model-switch divider, which already separate. Rooms that name every message's author (Chat's and Feedback's top level, the web's thread pane) have no hairline. | Two replies in a row read as one long message; a name line on each would be heavy, a hairline is enough to show where the next one starts. |
| AP-6444 | **The same author's next message runs on only within five minutes, on the phone as on the web.** A message drops its author's face, name and time (and gets AP-6144's hairline) only when the one before is by the same author, at most five minutes earlier, and neither is deleted; later, the author line with the time is back. One rule for both, `continuesMessage` in `@whombat/client`, used by the web's `MessageList` and the phone's `chatItems`. | The phone ran every next message on, so a reply Dusty sent half an hour later showed no time; on the web it did. |
