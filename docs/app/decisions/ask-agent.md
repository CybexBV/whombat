# Ask an agent, and the chip's suggestions from an agent's area (AP-950…)

John, 2026-10-09: in #general he always has to name the agent a question is for. He chose local word rules over hosted
decision models (data stays on the Whombat), plus his own idea: a wombat icon in a message's toolbar to send it to an
agent afterwards. He drew the icon (24×24 line icon, the brand mark's face: head, ears, eyes and nose). Contracts
CT-320 (0.65.0: `suggestAgent`, `looksLikeRequest`, `messages.ask`, `Message.asks`, `SendMessageBody.suggested`,
feature `messages.ask_agent`); Whombat `docs/decisions/ask-agent.md` SA-01…SA-14 for the rules and the server.

## Shared (`@whombat/client`)

| ID | Decision | Why |
|---|---|---|
| AP-950 | **`packages/client/src/askAgent.ts` builds core's rules from what a client has.** `chipTarget` = the reply rule's agent (`replyTarget`, AP-750) or, on runtimes with `messages.ask_agent`, the area's (`suggestAgent` over `areaAgents`: the place's wakeable agents with the shared connections each looks after, from `connections.list`); `{agent, rule: 'reply' \| 'area', about}`. `chipSuggested` is what the send carries as `suggested` (the chip's offer before ×; null when it offered nobody; left out without the feature or where the chip doesn't apply). `chipReason`: the chip's tooltip, “Dusty looks after PVE-01”, “This sounds like Dusty’s work”, “Banjo answered you here”. `askChoices`: Ask's rows — the agents the viewer may wake there (`replyAgents`), the one the message's words point at first (`suggested`), each with `asked` (`Message.asks`, or an agent the message names: it woke them already, SA-10) and `covers` (“Operator · looks after PVE-01 and PVE-02”). `canAsk`: the feature, core `canAskAboutMessage`, and at least one agent. `askButtonLabel`: “Ask Dusty” / “Ask an agent”; `askedText`: “Asked Dusty”. `FEATURE_NAMES['messages.ask_agent']`: “asking an agent about a message”. | One implementation for both apps; core decides, the client only gathers its input. |
