# The iPhone app builds (AP-5772…AP-5774, AP-5800…AP-5802, AP-5790)

John, 2026-10-26: “Build the iOS app using my Mac Studio.” The iOS side (DECISIONS D-08: Android first, iOS must
remain possible) had been written but never compiled. On John's Mac Studio (Xcode 27.1, iOS 27 simulators) it compiled
as it was, Live Activity widget included, but stopped at launch.

| # | Decision | Reason |
|---|---|---|
| AP-5772 | **iOS adopts the UIKit scene lifecycle** through `expo-build-properties`' `ios.enableSceneSupport` (Expo 57.0.23+): `expo prebuild` makes the AppDelegate an `ExpoReactNativeFactoryProvider` without its own window, and Info.plist names `EXExpoAppSceneDelegate` as the one scene's delegate. The scene delegate passes cold-start and later URLs, universal links and shortcuts on to the AppDelegate and `RCTLinkingManager`, so links open the app as before. Remove the option with Expo SDK 58, whose template has the scene lifecycle. | Built with the iOS 27 SDK, an app without the scene lifecycle stops at launch (`EXC_BREAKPOINT` in `_UIApplicationEvaluateRuntimeIssueForNoSceneLifecycleAdoption`). Expo's own option, not a hand-written delegate. |
| AP-5773 | **The Mac Studio builds iOS**: a Mac Studio (M2 Ultra), also the simulators’ device host. Node 24 from Homebrew (`node@24`, keg-only, so the Mac's own `node` stays), CocoaPods from Homebrew, pnpm through corepack in `~/.local/bin`. The checkout at `~/Code/whombat-app` is copied from The Titan with rsync, so the Mac needs no GitHub credentials: `rsync -az --delete --filter=':- .gitignore' --exclude node_modules --exclude /apps/mobile/ios/ --exclude /apps/mobile/android/ --exclude /tmp/ --exclude /dist-release/ ./ me@10.100.0.9:Code/whombat-app/`. The explicit excludes keep the Mac's generated `ios/` and `node_modules` (the `.gitignore` filter alone let `--delete` remove `ios/`). After a Homebrew install there, `brew linkage --test` must show nothing broken. | The only Mac with Xcode. Installing `node@24` upgraded a shared library (simdjson) under the Mac's `node` and broke it, and the repair cascaded, so the check is part of the setup. |
| AP-5774 | **The simulator build is a Release build against DEV, signed with John's Individual team `4R8P9MTF9T`**: `EXPO_PUBLIC_WHOMBAT_CONTROL_URL=https://api-dev.whombat.com EXPO_PUBLIC_WHOMBAT_UI_URL=https://dev.whombat.com`, `xcodebuild -configuration Release … DEVELOPMENT_TEAM=4R8P9MTF9T` (apps/mobile/README.md “iOS”), which signs it to run locally with the app's entitlements. The team goes on the command line, not in app.config.cjs, until Whombat has its own Apple team. A build for a real iPhone signs with the same team (automatic signing, `-allowProvisioningUpdates`) once the iPhone is paired with the Mac. | The JavaScript is bundled into the app, so it runs without Metro, against DEV, as the DEV APK does (`publish-apk.mjs --env dev`). Unsigned (`CODE_SIGNING_ALLOWED=NO`), the Keychain refuses the app (`-34018`): no device key, so “This phone can’t keep a device key safely”, and no push registration. |
| AP-5800 | **The iPhone app moves with the Android app** (John, 2026-10-26: “from now on we should always update the iOS app also when we update the Android app”): whenever an APK is published, the iOS app is built from the same commit on the Mac Studio (AP-5773) and published to TestFlight (AP-5802). The report names the build that is published. | Voice typing reached Android 3.1.0 while the iPhone app stayed on a build from the morning. |
| AP-5801 | Superseded by AP-5802. **John's iPhone gets an ad hoc build from a page on the tailnet, without a cable** (John, 2026-10-26: the Mac Studio is in a rack, “Are you able to build the IPA and provide me a download link?”). `apps/mobile/scripts/ios-adhoc.sh` archives and exports a `release-testing` IPA on the Mac over SSH, signed with team `4R8P9MTF9T` for every iPhone registered on it; `apps/mobile/scripts/ios-install-page.mjs` on The Titan, published with `tailscale serve` on `https://thetitan.tail1a2b3.ts.net:10521`, reads a new iPhone's device ID through a Profile Service profile (John registers it at developer.apple.com → Devices) and offers “Install Whombat” (an `itms-services` link to the export's manifest). The Mac's login password comes through T3's secret prompt on stdin: it unlocks the login keychain, which is locked to SSH sessions, and lets Apple's signing tools use the signing keys (`security set-key-partition-list`), without which codesign fails with `errSecInternalComponent`. The page and its `tailscale serve` entry run only while an install is waiting. | No Developer Mode, TestFlight, App Store Connect record or cable; an ad hoc profile lasts a year and the page needs only the tailnet. The first IPA (3.1.0, `77dde6898`) is signed for John's iPhone (iPhone19,4). |
| AP-5802 | **The iPhone app is published to TestFlight** (John, 2026-10-26: “can we build a method so I can easily update my app when we dev further with the app?”). `pnpm --filter @whombat/mobile publish:ios --env dev` on The Titan copies a commit to the Mac's own checkout (`~/Code/Whombat-publish`), archives it and uploads it to App Store Connect (app “Whombat”, `com.whombat.mobile`); the internal group “Whombat”, with every user of the team in it, gets every build, and TestFlight's Automatic Updates install it. It runs unattended: an App Store Connect API key with Admin access (John's, in the Mac's `~/.config/whombat/ios/`) lets Xcode make the profiles and sign for the App Store in Apple's cloud, and the archive is signed from the script's own keychain (`whombat-build.keychain-db`, its random password beside the key) with an Apple Development certificate the script makes through the API and renews a month before it runs out. The keychain is in the keychain search list only while the archive is signed: Xcode chooses the identity from that list (not from `--keychain` in `OTHER_CODE_SIGN_FLAGS`), and while it's listed Xcode chooses its identity in every SSH session, each of which finds the keychain locked, so another session's device build fails (`errSecInternalComponent`). Simulator builds sign to run locally and aren't affected. Its `.p12` comes from macOS's `/usr/bin/openssl`: `security import` can't read one from Homebrew's OpenSSL 3 or later. | Every ad hoc build needed John's Mac password and a tap on a page; TestFlight needs neither, takes any iPhone whose owner is on the team without registering it, and is the road to the App Store. A TestFlight build lasts 90 days, and a version uploads once (its build number is the APK's `versionCode`). |
| AP-5790 | **A production build also joins the TestFlight group “Public”** (2026-11-20, for John's public link): after processing, `publish:ios --env prod` adds the build to the external group of that name, and says so when the group is missing. It submits nothing for review: public testers get a build once someone submits it in App Store Connect and Apple approves it. DEV builds stay internal. | An external group has no “all builds”, so without this public testers would stay on the first build until it expires after 90 days. Review stays a person's choice. |
