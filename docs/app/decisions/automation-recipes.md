# Automations from a simple form, GitHub issues, and Delete (AP-966…)

John, 2026-10-09: an automation that has Banjo assess a repository's new issues and pull requests was “way too
complicated” — the step editor (step ids, `{{steps.x.text}}` templates, conditions, limits, keys, JSON) was the only way
to build one — issues weren't supported, and an automation couldn't be removed. He asked for a flow led by the trigger:
“GitHub → repo → new issues and new PRs → Banjo → Assess → answer in a thread and on GitHub” in about five clicks.
Contracts CT-322 (0.66.0: `AutomationRecipe`, `recipeDefinition`, `recipeOf`, `recipeSentence`, `issue_opened`, the
drafts/bots filters, `github_comment`, `workspace.pullRequest`, `automations.delete`/`samples`, `runNow`'s `sample`,
`Automation.summary`/`deletedAt`, features `automations.recipes` and `automations.delete`); Whombat
`docs/decisions/automation-recipes.md` for the server.

## Fixing bugs

and that it matters — and fixing on its own must be an explicit opt-in: “never on by itself”. Contracts CT-323 (0.67.0:

`docs/decisions/automation-recipes.md` (AR-24…) for the server. Everything below shows only on a Whombat with
`automations.fixes`.
