# Automations by talking to the agent, on the phone (AP-6225…AP-6249)

The phone's side of Whombat `docs/decisions/automation-chat.md` (AT-01…AT-20; contracts 3.9: the `automation_plan`
card, `AutomationPlanView`, `Automation.talk` and `waitingPlanId`, `automations.acceptPlan` / `declinePlan`). John,
2026-10-28: automations are made and changed only by talking to the agent; he approved a mockup of the plan card in
Chat, the change card and an Automations page without an editor (a desktop chat column), which the phone adapts to its
own cards and lists. Code: `data/automationPlan.ts`, `ui/automationPlanCard.tsx`, `screens/AutomationsScreen.tsx`,
`screens/AutomationRow.tsx`, `screens/useStartAutomation.ts`, `screens/agent/scheduleActions.tsx`.

| ID | Decision | Why |
|---|---|---|
| AP-6225 | **A plan is the card while it waits and one line once decided**, as a device skill card: `ChatItem.automationPlan` holds the card's view and `display` is `full` while `waiting` (or while the plan isn't resolved), `line` after. The rule is the phone's (`planDisplay`, `planSettledLine` in `data/automationPlan.ts`) because the shared `cardDisplay` doesn't know the kind yet. | One card to decide on; a decided plan shouldn't take a screen of the thread. |
| AP-6226 | **The card's anatomy at phone width**: a 7dp dot and the state in mono 11 (`NEW AUTOMATION · WAITING FOR YOU`, `CHANGE · WAITING FOR YOU`, from core's `AUTOMATION_PLAN_STATE_LABELS`), the name 19/700, the agent's sentence 15 `ink2`, then WHAT CHANGES, Whombat's rows, “How I thought about it” and “What Dusty is asked”; `sf` on a `line2` border, radius 16, as the device skill card. | The mock's card, in the phone's card language. |
| AP-6227 | **Whombat's rows stay label beside value**: the label in mono 11 `mut` in an 80dp column, each line 14.5 with its detail 13.5 `mut` under it, a hairline between rows; one TalkBack stop per row (“WHEN: A new issue on …, Not from bots”). | The longest label (“ASKS YOU”) fits in 80dp and leaves the value most of the width; stacking them would double the card's height. |
| AP-6228 | **WHAT CHANGES** (a change only): `+` added in `ok`, `−` (U+2212) removed in `bad`, `~` reworded in `mut`, bold in an 18dp column, on `hi` with a `line` border, radius 12; TalkBack reads “Adds: …”, “Removes: …”, “Changes: …”. | The diff stats' colours; a sign alone means nothing read aloud. |
| AP-6229 | **“How I thought about it” is open; “What Dusty is asked” is folded** behind a 44dp row with a chevron (`expanded` state); each prompt shows its step's name and its words, selectable. | The thinking is the agent's case for the plan; the prompts are long and for someone who wants to check them. |
| AP-6230 | **The buttons**: Turn it on (Use this version for a change) full width and primary; Try it and Not now (Keep the old one) side by side under it, each half; then “or reply to change it” in `mut`. All 44dp, each with a hint. | Three labels don't fit on one phone row; the yes is the widest target. |
| AP-6231 | **Try it** says “Try it on #12” for the newest issue, pull request or report (`automations.samples`, asked only for a waiting `sample` plan and kept a minute), “Try it now” for a `now` plan or when there's nothing to try it on, “Try it” while the list loads. It starts a test run (`runNow {test: true, sample}`), toasts “Trying “Name” on #12.” and opens the run's page. | The run page shows it working step by step, as the web opens it. |
| AP-6232 | **Refusals stay on the card in the server's words** (`bad`, read out), from a 409 (“A newer plan replaced this one…”) or a blocked result; what went through is a toast (““Name” is on.”, ““Name” wasn't turned on.”). The card isn't patched locally: it folds when the server re-sends the message. | The server decides whether the plan is still the one waiting; the toast covers the moment before the frame arrives. |
| AP-6233 | **The settled lines**: “You turned on “Name” · 14:02” in `ok` (“Mon 14:02” another day, someone else's name when it wasn't the viewer), “Not now: “Name””, “Replaced by a newer plan”, ““Name” was deleted”, the last three quiet. Tapping one opens the card in place with “Hide card” and no buttons. | The mock's line; the card-settle pattern the phone already has. |
| AP-6234 | **A plan that isn't resolved shows only the agent's words**: no card, no placeholder. | The server resolves every plan card on read; an empty card would only say less than the text. |
| AP-6235 | **The Automations page is an overview**: under the title “What Dusty does on its own. To make one or change one, tell Dusty.” and a 52dp field-like button “Tell Dusty what should happen on its own…” with the send mark, which opens the new-thread sheet as “Tell Dusty”. No example chips. | The mock's field; the sheet is how the phone starts a Chat thread already, and examples would be words to keep up for little. |
| AP-6236 | **`NewChatSheet` takes its own words** (`words`: title, label, placeholder); the page keys it by what opened it, so text typed for one automation never shows for another, and it still slides away when closed. | One sheet for every new thread. |
| AP-6237 | **Superseded by automation-page.md AP-6330, AP-6331:** **A row's actions are buttons under it**: Talk about it, then Run now or Try it, then Delete (quiet), in the column beside the tile. The ⋮ and the long press with their action sheet are gone. | Three actions were too many to hide; visible buttons are how the phone's schedule rows already act. |
| AP-6238 | **Superseded by automation-page.md AP-6330, AP-6331:** **“Waiting for you”** (`waitingPlanId`) is a 44dp line under the row, `warn` dot and “Open”, opening the plan's thread. | The plan waits in Chat; the list only points at it. |
| AP-6239 | **Talk about it** opens `talk` (the thread of the latest plan); without one, the new-thread sheet with “About “Name”: ” ready to finish. | Every automation can be talked about, even one made before plans. |
| AP-6240 | **Run now** shows only for an automation that is on and whose live definition starts by hand; otherwise **Try it**, a test run of the waiting plan's draft, else the live version, on the newest sample when something like that starts it (core's `planTryIt`). Both open the run's page; a refusal is an alert with the server's words. | The server refuses Run now without a “started by hand” trigger; a test run works for every automation. |
| AP-6241 | **On/Off, Run now, Try it and Delete never ask the agent** anything: they are the automation endpoints alone. | An automation must stop and start even when the AI is signed out. |
| AP-6242 | **Superseded in part by automation-page.md AP-6330 (under ONLY TELLS YOU):** **The agent's schedules are rows on the same list** that only tell you: a clock tile, what it does with an `ONLY TELLS YOU` tag (mono 10.5 on a `line2` border), the dot and when it runs, NEXT, and Pause or Resume and Remove. Ended ones stay in Settings → Agent → Schedules. The section counts both. | One list of what happens on its own; an ended schedule does nothing on its own any more. |
| AP-6243 | **Pause, Resume and Remove are one piece** (`useScheduleActions`, `ScheduleButtons`), used by Settings → Agent → Schedules and the list: Remove asks first, a change toasts, a refusal is a line at the top of the card. | The same words and behaviour in both places. |
| AP-6244 | **The empty page** says “No automations yet.”, under the intro and the field. | The intro already says how to make one; “Set one up on the desktop” is no longer true. |
| AP-6245 | **Publishing a draft from the phone is gone**: `PublishDraftSheet`, `automationDraftModel`, `AUTOMATION_PUBLISH_TEXT` and the row's “Review and publish” with their tests. The plan card is how anything is turned on. | Plans replace drafts the person publishes. |
| AP-6246 | **A waiting plan isn't a Needs you row yet**: Needs you is the shared client's list (`needsYou`), which doesn't know the card; the list's “Waiting for you” and the card in Chat are where it shows on the phone. | The shared rule belongs with the web's; the phone shouldn't fork it. |
| AP-6247 | **Superseded by automations-tab.md AP-6312 and automation-page.md AP-6337:** **The demo world has no automations or plans.** | The fixture world never had automations; adding them is a separate piece of work. |
| AP-6248 | **Accessibility**: the card's head (state, name, sentence) is one stop, each row and each change one stop, the fold says whether it is open, every button has a hint, the refusal is a live region; the touch-target audit counts the fold, the page's field and the waiting line. | README “Accessibility”. |
| AP-6249 | **Checks**: unit tests for the card's view, the chat item and its line in a conversation and a thread, the settled lines, Try's words and body, and the list's waiting line, Talk about it, Run now or Try it, the actions and the schedule rows; mobile typecheck and tests. Not rendered: the phone has no way to draw a screen without an emulator or a device. | What the data says is tested; how it looks needs a device. |
