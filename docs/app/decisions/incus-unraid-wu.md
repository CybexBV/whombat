# Full Incus and unRAID support — the Unraid server page on the web (stream WU, 2026-10-17)

Stream WU of the Incus and unRAID build (Whombat `docs/decisions/incus-unraid.md` IU-01…IU-12; brief
`docs/implementation/incus-unraid/assignment.md` §2.3, §2.4, §3 WU). An Unraid server's own page on the web: its tabs,
the array with parity and disks the way Unraid's Main page lists them, pools, shares, plugins, Unraid's notifications,
Docker the Unraid way and libvirt's autostart, with the Proxmox pages (PX-01…PX-11, `proxmox-w*.md`) as the pattern for
cards, questions, tasks and hints. Contracts 0.83.0 (CT-363…CT-367). In the UI the vendor's name is written “Unraid”.

| # | Decision | Why |
|---|---|---|
| AP-1587 | **An Unraid server gets its own tabs**: Summary · Array · Shares · Guests · Plugins · Sensors · System (`UNRAID_TABS`, `parseUnraidTab`, an unknown `?tab=` opens Summary). `ServerPage` picks them with `isUnraidServer` (the kind `unraid`, or a hub that sent `detail.unraid`) and hands the panel to `unraid/UnraidPanel.tsx`; Sensors and System are every server's tabs, unchanged. No Storage or Backups tab: the disks and pools are the Array tab, and Unraid has no backups of its own. | IU-03; one switch in `ServerPage`, everything else in WU's own files. |
| AP-1588 | **Client helpers in `packages/client/src/hosts/unraid.ts`** (pure, for the web and Android): the tabs, sizes in Unraid's decimal units (`unraidSize`: “2 TB”, “13.6 GB”), Unraid's slot names (`unraidDiskName`, its `my_disk`: “Parity 2”, “Disk 1”, “Apps 3”), disk status words, the array view, the parity view and history words, what may be done now (`unraidAbilities`), pools, shares, plugins, the version line, notification titles, Docker on Unraid, hints with their way out and every change's words. The 0.83.0 types (`HostUnraidDetail`, `HostGuest.autostart/webUi/template`) are used directly; the brief's local mirrors went with the merge. | Brief §3 WU; MA reads the same words on the phone. |
| AP-1589 | **Summary**: open alerts first (the shared notices), the five figures with **Storage as the array's data disks plus every pool** (“23.8 TB / 106 TB · array and 3 pools”), the array card, “Worth a look”, then Pools and Updates side by side and “From Unraid” (unread notifications). No temperature chart or busiest guests: Sensors and Guests have them. | The brief's Summary list; the mock's figures stay where every server has them. |
| AP-1590 | **Array tab like Unraid's Main**: the array card, then a table per group — Array devices (parity, then data), each pool (“Pool data · btrfs raid6, encrypted · 9 disks · 22.3 TB used · 47.7 TB free” with its bar), Boot device (the flash drive) — with Device (status dot named for screen readers, Unraid's name, `sdX`), Identification, Temp, Errors, File system, Size, Used, Free and Spin. Every table has the same fixed columns, so they line up as on Unraid's page. Free data slots without a disk are left out (Unraid lists all 28); a parity slot that lost its disk stays (“Disabled, no disk”). A pool's members after the first show “—” for its file system and use, as Unraid does. Then the parity checks so far (newest first, “Jul 10, 2024” for other years) with the schedule, or “No schedule: set one in Unraid under Settings → Scheduler.” | Brief: “unRAID's own Main page is the reference for what the Array table shows”. |
| AP-1591 | **What Whombat asks first** (IU-06): Stop the array (says what stops with it: “12 running containers, 1 running VM and the shares stop too until the array is started again on blackbox.”, plus “The parity check is cancelled.” / “The mover stops halfway.” when so), stopping a running parity check (“Stop the parity check?” — Unraid's Cancel, but “Cancel the check” beside the dialog's Cancel read wrong — sent with `confirm`), updating plugins (each “name old → new”) and updating a container from its template. Start the array, Pause, Resume, spinning, the mover and the checks go at once. | PX-02/PX-04's rule: stopping and software changes are asked, the rest isn't. |
| AP-1592 | **Unraid changes are tracked as Unraid tasks with their own words**: every change sends `platform: 'unraid'` (top level; Whombat's server ignores it where a route doesn't take it), also the guest ops, so the tracker asks `hosts.getTask` for `unraid:<id>` as Unraid's. `useManage` gains `platform`, `started` (the toast when its task started) and `finished` (the toast when it ended well); the tracker keeps `finished` and `HostTasks` uses it instead of “<what> finished.” Words by op (`unraidChangeWords`): “Starting the array on blackbox.” → “The array on blackbox is started.”; “Starting a parity check on blackbox.” → “The parity check on blackbox is running.”; “Updating plex on blackbox.” → “plex on blackbox is up to date now.”; failures stay “Starting the array on blackbox failed: …” with Show log. | IU-07; “Array start on blackbox started.” isn't English. |
| AP-1593 | **Guests on Unraid**: an **Autostart** column (dockerMan's list for containers, libvirt's for VMs; a switch, done at once: “immich_redis starts with blackbox now.”), a container's **web page** (an icon link, http/https only, while it runs), **Update** when an update and a template are there, and **Check for updates** in the card's head. `GuestsTab` gains an optional `extras` prop (a column, row tools, head buttons); other servers pass none. | Brief §3 WU; one table for every server, the platform adds to it. |
| AP-1594 | **A guest's page** shows an “On Unraid” card (Docker on Unraid) or “On this server” (libvirt anywhere) above its Summary: Autostart with what it means, “An update is out” with Update or, without a template, “There’s no Unraid template for it (Compose or the command line made it), so update it where it was made.”, and the web page with Open. The guest this Whombat runs in keeps its autostart switch locked (“That’s this Whombat itself.”). | IU-05 (libvirt autostart everywhere); IU-02. |
| AP-1595 | **Plugins tab**: an Unraid card with the version line (“Unraid 7.3.1 · Pro”; “Unraid 7.3.2 is available — update it in Unraid.” with **Update in Unraid**, a link to the server's own Update page, and why: it restarts the server), then every plugin with its author, version, “2026.10.16 is out”, Support (the plugin's forum page) and Update; **Check for updates** and **Update all** in the head. Unraid's own `unRAIDServer.plg` isn't listed. Plugin names are shown as Unraid has them (`fix.common.problems`), in mono like guest names. | IU-05, IU-10: the OS is updated in Unraid. |
| AP-1596 | **Shares, read only**: share (with its note and a lock when encrypted), Stored on (“data”, “Array”, “cache → Array” the mover's way), SMB (Private, Public, Secure, Not shared), NFS, Free; “Change shares in Unraid’s own page.” with a link. No Used column: `shares.ini` reports the pool's use, the same number for every share on it. | IU-10; a column of identical numbers would mislead. |
| AP-1597 | **Unraid's notifications** (“From Unraid”): the dot by importance (named Alert, Warning, Notice), the subject without Unraid's “Alert [BLACKBOX] - ” in front (`notificationTitle`), the description, the event and how long ago; **Archive** per row and **Archive all**, done at once (“Archived the notification.”). | IU-05; the dot already says how important it is. |
| AP-1598 | **Hints with their way out** (`unraidHintFixes`, IU-08): array stopped → Start the array, parity errors or an old check → Check parity (the dialog), disk errors and a full pool → Open Array, plugin updates → Update all and Open Plugins, an Unraid alert or warning → Archive, a newer Unraid → Update in Unraid (link), a container update → Update <name> (with a template) or Open <name>; without the Manage switch the buttons open the tab instead. An alert with section `storage` opens Array. The Summary's “Worth a look” leaves out what its own cards carry with the same way out (notifications, plugins, Unraid, containers); the Array tab shows the `array` (and `storage`) section's hints. | ONE-07: no hint without an action, and no hint twice on one page. |
| AP-1599 | **Unraid's own page** is linked as `http://<server address>/<page>` (`Tools/Update`, `Shares`), opened in a new tab; Unraid sends it on to https itself when it uses it. Without an address there's no link, only the words. | The brief: a link “when its address is known”. |
| AP-1600 | **Who may change it**: owners (`hosts.status.canManage`), with the server's Manage switch on and a Whombat that advertises `hosts.unraid` (contracts 0.83 feature, like `hosts.backup_jobs`). Otherwise the buttons aren't there and owners get one line: the Manage reason with **Agent settings** (the System tab), or “Update your Whombat to use the array, parity, plugins and Docker updates on Unraid.” Reading needs nothing extra. `FEATURE_NAMES` gains `hosts.incus` and `hosts.unraid` (both, so the type is whole; WI may word Incus's differently at merge). | IU-06; the lead's note on the feature flag. |
| AP-1601 | **Parity in words**: a running check “Parity check · 42 %” with time left, speed and “no errors so far” and a progress bar (warn colour while paused); “Parity is disabled” (red) when a parity slot is disabled or lost its disk, with “Nothing protects the array if a disk fails. Replace or reassign the parity disk in Unraid.”; “No parity disk” when none is assigned; else “Last checked 3 months ago” with its result and duration. **Check parity…** shows only with the array started, nothing running and parity that works. | BlackBox's real state: both parity slots `DISK_NP_DSBL`. |
| AP-1602 | **Disk temperatures** in Unraid's default colours: hard drives warm from 45 °C and hot from 55 °C, SSDs from 60 °C and 70 °C; a spun-down disk has no temperature (“—”). | Unraid's own Display settings. |
| AP-1603 | **The parity check dialog**: “Write corrections to parity” off by default, with “Only when you know why parity is wrong: it changes parity to match the disks.” | Unraid's scheduled checks don't correct by default either. |
| AP-1604 | **The array's state reads as itself**: Started is green, Stopped amber, missing disks or an invalid configuration red; disabled disks are said on the parity and Disks lines, not by colouring “Started” red. | A red “Started” read like it wasn't. |
| AP-1605 | **Spinning**: Spin up all and Spin down all in the array card's head (Array tab), and Spin up / Spin down per hard drive in the tables; SSDs (“SSD”) and the flash drive have none, nor does anything while the array is stopped. | IU-05; Unraid can't spin an SSD. |
| AP-1606 | **Fixtures** (`packages/client/src/hosts/fixtures-wu.ts`, one hook in `fixtures.ts`): BlackBox as it is (read on 2026-10-17, no serials, GUIDs or tokens) — Unraid 7.3.1 Pro, the array started with disk1 (a 2 TB SSD, xfs) and both parity slots disabled, the encrypted btrfs pools `apps` (raid10, 4 SSDs), `data` (raid6, 9 × 10 TB) and `storage` (raid1, 2 × 12 TB, spun down), the flash drive, 17 shares, 12 plugins, its parity log, the *arr apps, Plex and Immich with dockerMan's templates and autostart, the PBS VM — plus for review two plugin updates, a Plex update, three notifications and Unraid 7.3.2. Eight stopped containers keep the mock's “66 of 133 guests running”. Patched when read, so the main world's refreshes keep it; changes answer as the hub does (`unraid:<16 hex>` tasks whose log grows a line per read; archive and autostart at once) and change the world when they end (a stopped array stops Docker and the VM, a start starts what has autostart). Review scenarios before the page loads: `localStorage['whombat.fixtures.unraid']` = `parity-ok`, `parity-running`, `stopped`. | Brief §3 WU; the visual check needs every state. |
| AP-1607 | **Superseded in part by** `docs/decisions/runtime-ci.md` RTC-02: the review shots no longer reached their screens and are deleted. **Checks**: unit tests for the helpers and the fixtures' flows (`unraid.test.ts`), web tests for the tabs, archiving, the stop question and autostart (`unraid/unraid.test.tsx`), and review shots `apps/web/e2e-managed/wu-shots.spec.ts` (`WU_SHOTS=<dir>`, light and dark at 1440×900, with pve-02's Summary for comparison). | WB/WD's pattern; not baselines. |
| AP-1608 | **How full a pool is** = used ÷ (used + free), not used ÷ size: btrfs reports a raid pool's raw size (BlackBox's `data`: 90 TB raw, 22.3 TB used, 47.7 TB free → 32 %). The size is still shown as Unraid shows it. | Otherwise a raid6 pool never looks full. |
