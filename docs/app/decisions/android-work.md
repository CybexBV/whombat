# Android as the primary device: work (AP-707, AP-711, AP-712, AP-713, AP-719)

John, 2026-10-04: the Android app becomes the primary device. Stream C of the Android batch covers work: an agent's
screen that failed with “This agent didn’t load.” on his phone, managing agents (the phone was read-only: “Hire one from
the desktop app”, keys “set on the web”), the run screen's controls, a pull request view (the phone had none) and pull to
refresh where it was missing. No contract change (contracts stay 0.45.1): every request is one the web already makes.

## Open

- **Hire on the phone doesn't pick the AI provider or untick packs**: it sends the Whombat's default provider and every
  pack of the role (RUNS ON moves the agent afterwards). The web's picker allows both.
- **Not ported from the web's agent settings**: RUNS ON's credential source on a managed Whombat (`CredentialSection`),
  the always-allowed commands, the agent's Computer (Start, Stop, Reset), Notes, Schedules, Skills and the Assistant's
  connections. Each needs its own screen.
- **The file view has no syntax colours and no change-by-change arrows** (the web's `useHighlighted` is DOM-bound).
- **No `whombat://` links for the pull request screens**: stream D owns links; a `pr` link still opens the branch room,
  which now links its pull request.
- **Workspace's admin check reads `auth.session`**: where a managed session doesn't answer it, the workspace shows
  read-only with “Only admins of this Whombat …” although the person may be one. No server change in this batch.
