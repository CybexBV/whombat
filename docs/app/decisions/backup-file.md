## What the server is assumed to do (from the contracts)

- `backups.list` answers the caller's files, uploads and restores newest first; a failed file stays listed (its `error`
  shown above the choices) until it expires or is removed.
- `backups.defaults` answers 404 on a server without backup files (the section then stays out); `backups.estimate`
  answers every category in order.
- A refused `backup-file` download stream carries `backup_file.expired` (or `not_found`) as its reason; a refused upload
  stream `backup_file.upload_mismatch` or `upload_expired`.
- A staged upload made without `sha256` accepts the session stream's whole-file hash (the app never hashes before
  staging); its `received` stays where the last chunk ended, and `getUpload` says `uploaded` once the stream's
  `stream_done` came.
- A REST chunk below `received` with the same bytes answers the current state without writing; a 409 carries
  `details.received`.
- A finished restore's view keeps `madeAt` and `sourceName`; a failed one keeps its upload when trying again can
  bring back the rest.

### What the server is assumed to do (0.117)

- `backups.estimate` lists `servers` with `offered: false` where this Whombat watches no servers; the defaults it answers
  and applies leave out what it doesn't offer.
- A preview's `servers` is `blocked` or `unavailable` with no counts on the category row; `address` is set only when the
  file's address differs and the servers can come back.
- `hosts.addressChange` answers owners (403 otherwise) and null when nothing is waiting; `hosts.repoint` answers the job
  at once (202); `hosts.getRepoint` reads it while the server keeps it; `hosts.repoint` frames travel on `hosts`.
- BF-16's Needs you item is kind `enrollment`, ref `{kind: 'address_change'}`, one `open` action “Point them here” with
  href `/things/servers?repoint=1`.
- Add a server filled in with a known server's address installs its agent again in place (SI-08) and points it here.
