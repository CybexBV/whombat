# Feedback from the tracker in the web app (AP-819…AP-824)

John, 2026-10-06: “I would like to use the tracker its own feedback system, can you research how to implement this and build
it?” Whombat reads the reports people send with the tracker’s own Feedback button and writes the assessment, status and
replies back (Whombat `docs/decisions/archive/feedback-sources.md` FBS-01…FBS-12; contracts 0.52.0, CT-288/CT-289, feature
`feedback.sources`). This is the web side. Without `feedback.sources` every screen stays as it was.

| ID | Decision | Why |
|---|---|---|
| AP-819 | **Superseded by report-trackers.md (the connected-system source was removed).** **The source is the first choice of New integration.** With `feedback.sources` step 1 starts with WHERE REPORTS COME FROM: two radio cards, “Your website” (the widget's steps, unchanged) and “The tracker”. The tracker has its own three steps: **The tracker** (NAME, PRODUCT starting as “The tracker”, TRACKER ADDRESS), **Where reports go** (the website's fields, plus “Retention and limits” folded), **API token** (a password field, `autoComplete="new-password"`). Create sends the settings, then `feedback.setSourceToken`, then opens the integration's page (no Install step). A token that wasn't saved says so in the toast (“… created, but the token wasn’t saved: <reason> Add it under Connection.”) and the page shows “Not set” with Add token…. The token is never part of the form model, the URL or a query cache. | One page and one stepper for both sources; the token is required before Create because an integration without one reads nothing, but it can only be sealed once the integration exists. |
| AP-820 | **Superseded by report-trackers.md (the connected-system source was removed).** **A tracker form is the same `FeedbackIntegrationSettings`.** `SettingsForm` gets `source` and `sourceUrl`; for the tracker `source = {kind: 'tracker', url}` and `allowedOrigins = [url]` (what the server sets anyway, FBS-01), and a problem with either shows once, on TRACKER ADDRESS (“Add the tracker address as the browser shows it: https://manage.example.com.”, or the schema's origin message). The widget's fields travel unchanged and unused. The source can't be changed when editing; the address can. | The server validates one schema for both, so the form keeps showing exactly what the server would refuse. |
| AP-821 | **Superseded by report-trackers.md (the connected-system source was removed).** **A tracker integration's page: STATUS, CONNECTION, HEALTH, settings; no widget, no Install.** “Accept reports” reads “Read reports from the tracker” (its own hint and toasts), and a managed Whombat's drop never disables it. ## The assessor reads the reporting organization (AP-825…AP-828)

For each report from the tracker, Whombat can ask the tracker for an hour of read-only access to the organization the report
came from, and the assessor reads it there with `feedback_source_get` (Whombat `docs/decisions/archive/feedback-sources.md`,
the server's decisions after FBS-12; contracts 0.54.0, CT-292/CT-293, feature `feedback.source_access`). This is the
web side. Without `feedback.source_access` every screen stays as AP-819…AP-824 left it.

| ID | Decision | Why |
|---|---|---|
| AP-825 | **Superseded by report-trackers.md (the connected-system source was removed).** **A switch on Where reports go, the tracker only:** “Let the assessor read the reporting organization”, under ASSESSMENT AGENT, in a bordered card like the source choice (title, hint, `sm` switch on the right; the hint is its description). Hint: “For each report, Whombat asks the tracker for read-only access to the organization it came from, for an hour, and the assessor checks computers, Blueprints, Policies, deployments and Nest there. The tracker logs every grant. The token needs `reports:assess`.” Off for a new integration. The same field shows in the edit form's Where reports go. It is `SettingsForm.assessorAccess` → `settings.source.assessorAccess`, sent for a connected source only (the widget's source is sent as before); an integration from an older runtime reads as off; a server error on `settings.source.assessorAccess` shows on the switch (field key `assessorAccess`, step Where reports go). | Whether the assessor may look inside a customer's organization is an owner's choice per integration, made where the assessor is chosen; off by default because it reaches into the customer's data. |
| AP-826 | **Superseded by report-trackers.md (the connected-system source was removed).** **The token help names the scopes:** `reports:read` and `reports:write`; with `feedback.source_access` “add `reports:assess` when the assessor may read the reporting organization, and `reports:platform` to read every organization’s reports (platform administrators only).” (the create step and Replace token…). | Without `reports:assess` the tracker refuses the grant; saying so where the token is made avoids the refusal. |
| AP-827 | **Superseded by report-trackers.md (the connected-system source was removed).** **CONNECTION gets “Assessor access”** after Written back: “Off”, “On”, or “Refused · <the server's words>” (warning colour) from `health.source.access`; a server that doesn't say (`access: null`) shows the switch (`accessLine` in `copy.ts`). | The owner sees on the integration's page whether the last grant worked, and why not, next to the token that causes most refusals. |
| AP-828 | **Superseded by report-trackers.md (the connected-system source was removed).** **Fixture mode:** the seeded tracker integration has `assessorAccess: 'on'`; `health.source.access` follows each tracker integration's switch (never refused there; tests replace it). The report's details are unchanged: what an assessment got of the organization (`FeedbackSourceAccess`) is the runner's, not part of `FeedbackReport`. Visual baselines: Where reports go with the switch on (`feedback-new-tracker-reports-*`), the token step and Replace token… with `reports:assess`, the page with Assessor access, the edit form with the switch, light and dark. | The screens can be seen and pinned without a tracker or a runtime. |
