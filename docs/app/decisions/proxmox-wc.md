# Full Proxmox support — host and fleet pages (stream WC, 2026-10-17)

Stream WC of the Proxmox build (Whombat `docs/implementation/proxmox/assignment.md`; product decisions PX-01…PX-11 in
Whombat `docs/decisions/proxmox.md`). A server's Guests, Storage, Summary and System tabs and the fleet-wide guests
list, ported from Rackoon's React UI (`hosts/web/src/features/{manage,server,guests}`), restyled to Whombat's
tokens, English only. Contracts 0.80.3 (nothing here needs 0.81.0).

| # | Decision | Why |
|---|---|---|
| AP-1445 | **Create** on a server's Guests tab for owners with Manage on: a menu with *Virtual machine…* and *Container…* on Proxmox, one *New instance* button on Incus. One dialog per kind (`CreateGuestDialog`, `kind` prop) with sections General, OS / Template, Disk, CPU, Memory, Network, DNS (containers) and a collapsed **Advanced**. | Rackoon's `CreateMenu` and dialog (PX-01); one menu, no new navigation. |
| AP-1446 | **Defaults as Proxmox's wizard** (`vmDefaults`, `ctDefaults`, `incusDefaults` in `@whombat/client/hosts` `manage.ts`): x86-64-v2-AES (or the host's first CPU type when it lacks it), VirtIO SCSI single with an IO thread, a VirtIO NIC on the first bridge with the firewall, guest agent on, SeaBIOS on the default machine; containers unprivileged with nesting and IPv4 DHCP, 1 core, 512 MiB, 512 MiB swap, 8 GiB. **Start it once it's made stays on** (Whombat's earlier dialog did; Proxmox's wizard leaves it off). | The brief; a new guest is usually wanted running. |
| AP-1447 | **The Windows preset**: picking a Windows guest OS sets UEFI (OVMF) with an EFI disk on the disk's storage, q35 and a TPM 2.0 (`withOsType`); UEFI goes with q35 and SeaBIOS back with the default machine (`withBios`); the ISO moves to a Windows image when there is one, never the VirtIO driver disc (`preferredIso`). | What Windows 11 needs, as Proxmox's wizard does it; the right ISO is the one people want. |
| AP-1448 | **ISO images and container templates come from the choices** (`choices.isos`, `choices.ctTemplates`: every ISO and template storage of the node), grouped by storage in the select (`SelectField` groups). *Get templates…* under the template opens Proxmox's catalogue on the first template storage. | “ISO from any ISO storage”; the old dialog read only the first storage. |
| AP-1449 | **Advanced** holds what most people leave: BIOS, machine, TPM, guest agent, start at boot, start after create; for containers the root password, SSH keys (one per line, sent as Proxmox's newline list), nesting and Unprivileged shown ticked and locked. VMs get no address fields (the guest or Cloud-Init sets them); containers get IPv4/IPv6 DHCP, SLAAC, static (with gateway) or none, and DNS. | The brief's list; Proxmox creates VMs without an address. |
| AP-1450 | **Templates (n)** under the guest table (Proxmox, Manage on), collapsed, from `choices.templates`; owners get *Clone…* and *Delete…*, which are stream WB's `CloneDialog` and `DeleteDialog` (imported, unchanged) with the template as a stopped guest (`templateGuest`). | Rackoon's `TemplatesList`; one set of guest dialogs. |
| AP-1451 | **Bulk power** (`bulk.ts`, `BulkBar`): row checkboxes for owners on servers with power on; the bar “N selected: Start · Shut down · Restart · Stop… · Clear”. Each guest gets the action the power menu would offer it (`bulkAction`: a Docker container's Shut down is Stop, its Restart is restart, a VM's Stop is Force stop); what doesn't apply is left out and said. Everything but Start asks with the names (12, then “and N more”); three at a time; one toast at the end naming what failed and why. The bar says **Restart**, not Rackoon's Reboot. | Rackoon's bulk actions; Whombat's power menu already says Restart, and the same word should do the same thing. |
| AP-1452 | **A ⋯ menu per guest row** on the server's Guests tab and the fleet list (`GuestRowMenu`): Console (Shell for containers), the power items the guest's state allows (asked first where the power menu asks), *Snapshots…* (opens the guest's Snapshots tab), *History…* (a dialog with CPU and memory over a day or a week) and *Open*. It replaces the row's Power button; the console button stays. Menus open in the app's context menu at the button, so a card doesn't cut them off. | Rackoon's `GuestMenu`; one tab for snapshots (WB owns it) instead of a second snapshots dialog. |
| AP-1453 | **The fleet's guests are a view of the Servers page** (`?view=guests`, a Servers · Guests toggle beside Add a server), not a sidebar entry: search (by name, ID or tag, typed text debounced), state with counts, server, tag (the `tags` facet, `?tag=`), sortable Guest, Server, State, CPU and Memory (`?sort=` as the hub's `cpu`, `-name`, `+memory`), pages of 100 with Previous and Next, bulk power across servers (“web on pve-02”). Leaving the view drops its filters. A name opens the guest on its server's page. | The brief: no new navigation; `hosts.listGuests` does the filtering. |
| AP-1454 | **Storage → Contents…** only on storages holding ISO images, container templates or imports (`hasContents`), for owners with Manage on. The dialog lists the files (size, when added) with Delete (asked), **Download from a link** only when `choices.download`, else one line why (“needs Proxmox VE 8.3 or later”, the agent's `Sys.AccessNetwork` check), and **Get templates** for template storages. Download checks the link (http(s), no user or password), the file name (Proxmox's characters and the content's endings) and an optional checksum (SHA-256…MD5, its length) before sending `checksum` and `checksumAlgorithm`. | Rackoon's `StorageContentDialog` and `download.ts`; Proxmox refuses the same things later and less clearly. |
| AP-1455 | **Storage volumes are read as the hub sends them** (`volume`, `name`, `content`, `sizeBytes`, `created`; `contentItems` also takes the older `volid`/`size`). The fixture world answers in the hub's shape. | The previous dialog read `volid`/`size`, which the real hub doesn't send, so it listed nothing against a real server. |
| AP-1456 | **Hints with their fix** on the Summary as a “Worth a look” card under the busiest guests (`hintFixes`): storage overbooked → *Open Storage*, guests in no backup job → *Add to a backup job* (the server's Backups tab, WB's jobs), a backup too old → *Back up <guest> now* (WB's dialog), changes waiting → *See <guest>'s changes* (its page, where Restart to apply is), old snapshots → *<guest>'s snapshots*, guest agent down → *Open <guest>*; any other hint opens its tab. Guests come from the names the hub folds into the hint's detail (at most three buttons), else from their fields. | PX-07, ONE-07; below the mock's cards so the mock's top stays as drawn. |
| AP-1457 | **System → Tasks and replication** on Proxmox servers: failed (and warned) tasks of the last 48 hours and running ones, newest first, in words (“Backup of k3s-worker-1 · Failed 5 h ago”, the message under it, node and user at the end), replication jobs (“Copy of web to pve-01 · Failing 4 times in a row”) and Ceph. Says “No failed tasks in 48 h” when there are none. | Rackoon's `ProxmoxActivity`; a failure nobody sees helps nobody. |
| AP-1458 | **Cluster nodes link to their server page** when added to Whombat (not this node); a node that isn't says “not added to Whombat”. | The cluster table is the way to the other nodes. |
| AP-1459 | **The agent command** (PX-04): a switch the server itself blocks says “Switched off on <server> itself.” with `sudo whombat-agent allow <switch>` (no sudo when the agent's install is `unraid`), Copy, and “Run this on <server>, then come back.” When some switch is blocked and the agent may be older than the command, a row *Update the agent first* comes before the switches: “older than the commands below” when the agent is older than the hosts service or an update waits, else “If <server> says it doesn't know “allow”…”. *Show the install command* makes an enrollment on demand and shows its command without `--token`/`--enroll`, which the installer reads as an in-place update. | The brief §2.3; an enrollment is a one-time key, so it's only made when asked for. |
| AP-1460 | **Fixtures** for all of it in `packages/client/src/hosts/fixtures-wc.ts`, one hook line in `fixtures.ts`: ISO images on two storages (a Windows one and the VirtIO disc on pve-02), templates and VM templates, Proxmox's catalogue, contents that change with downloads and deletes, creates that add the guest, tags across pve-01 and pve-02, three guests in no backup job and the Proxmox hints, failed tasks and replication on pve-02, a third cluster node that isn't added, and pve-01's agent at 0.15.2 with the shell and server power blocked (downloads off there). Server details and settings are patched when read, so the main world's refreshes keep them. | The visual checks and tests need every state; the shared file stays as it was. |
