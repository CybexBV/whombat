# Use Wi-Fi only and the servers' move in the apps (AP-6630…AP-6649)

John, 2026-11-03: Home (the Z13) runs on a USB cable and should move to Wi-Fi only without losing its servers. The
product decisions are Whombat's `docs/decisions/network-move.md` (NM-01…NM-12); this is the app part: the shared
client (`packages/client/src/host/network.ts`, `fake.ts`), the web's and the phone's NETWORK in Settings → This Whombat
→ Overview. Contracts 3.13 (`host.cable.set {use}` → `{change}`, `CableChange`, `HostNetwork.wifiOnly`/`cableChange`,
the cards' `plugged`/`mac`/`prefixLength`, `HostNetworkOutput.move`, `CABLE_ERROR_CODES`, `sameSubnet`). Builds on
`hardware-support-web.md` (AP-3200…) and `hardware-support-android.md` (AP-3250…). No mockup: NETWORK's own rows,
buttons and dialogs.

| # | Decision | Why |
|---|---|---|
| AP-6630 | **The client carries the contract and the op**: `host/contract.ts` re-exports the 3.13 pieces; `sessionOps.hostCableSet` and `NetworkApi.setCable(use)` (the session's and the fake's). | One place for the shapes, as for the Wi-Fi ops. |
| AP-6631 | **Offered only by a manager that knows Wi-Fi only**: the Wi-Fi row's button shows when `wifiOnly` is present or a cable reports `plugged`. | An older box would refuse an op it doesn't have; both fields are absent from managers before 3.13. |
| AP-6632 | **The buttons belong to their rows** (`NetworkRowView.action`): **Use Wi-Fi only** on the Wi-Fi row while a cable and Wi-Fi are both connected, Wi-Fi only is off and nothing runs; on Wi-Fi only each cable is “Cable · Switched off” (muted dot) with “Home uses Wi-Fi only. You can unplug the cable.” (or without the second sentence when unplugged) and **Use the cable again** on the first plugged-in one while nothing runs. Wi-Fi only with no cable interface left (a USB adapter pulled out) still shows the switched-off row, without a button. A running cable change makes the section busy like a Wi-Fi change (Join, Forget and both buttons wait). | The choice is the cable's and the Wi-Fi's; it stays visible however the cable is unplugged. |
| AP-6633 | **A cable change is a line like a Wi-Fi change** (`cableChangeView`, `cableChangeShown`): one sentence per direction and phase (NM-12's, plus “… Going back to the cable…” while reverting), the guard as its meta while applying; shown while it runs, after it ended when watched here, a revert or failure for 15 minutes after its deadline; the box's own backup (`by: backup`) whenever the box reports it, with an amber dot. A switch that simply worked isn't told to the next visitor: the switched-off cable row says it. | Same rules as HD-06's join line, so nothing new to learn; the backup is something broken the person should see. |
| AP-6634 | **The servers' move** (`serverMoveView`): “4 of 6 servers found Home’s new address.” while servers are still to come (running dot); from 5 minutes after `since` the missing ones are named with **Point them here** (web `/things/servers?repoint=1`, phone `RepointServers`); once all came, “All your servers found Home’s new address.” (plus “You can unplug the cable now.” on Wi-Fi only with a cable plugged in) until an hour after `since`. One server reads “Your server found …”, “1 server hasn’t …”. No line without servers. | `ServerMove` has no time for the last arrival; an hour after the start covers a move that took minutes. BF-16's wait is 5 minutes. |
| AP-6635 | **The router tip** (`addressTip`, NM-08) shows while a move with a known `from` ≠ `to` is reported: the card that carries `to` (the Wi-Fi card, or the cable), its hardware address upper-case, left out when unknown. A muted line of its own under the move. | The person (or Dusty) needs the exact address to type into the router; the move lasts 24 hours, enough to act on it. |
| AP-6636 | **Use Wi-Fi only's words** (`wifiOnlyDialogView`): the network it stays on, the guard (“… after 2 minutes.”) and NM-11's note only when `sameSubnet(cable, wifi)` is false (unknown says nothing). Use the cable again asks with its own title, lead and “Use the cable”. | Shared by the web's dialog and the phone's alert. |
| AP-6637 | **The poller follows a cable change and then the move**: every 2 s while either change runs (an answer that fails meanwhile is ignored, the box is between networks), then every 5 s while `move` has servers still to come, for at most 10 minutes after the move started (or was first seen here, if the box's clock is ahead). It keeps `move` and whether the cable change was seen running (`cableStarted`). | The move is quick for current agents (they're told first, NM-05); older ones search for a minute or two. Ten minutes covers both without asking forever. |
| AP-6638 | **Cable refusals in words**: `not_connected`, `no_cable`, `unchanged` join the Wi-Fi ones (`busy`, `no_wifi` shared) in `networkErrorText`. | The same code path reads `details.code` first. |
| AP-6640 | **The fake switches the cable** (`host.cable.set` in `createFakeNetwork`): the change runs `applying → confirming → committed` on the injected clock (Wi-Fi only on Café Wombat goes back with `no_internet`); refusals as the runtime sends them; the cards carry `mac`, `prefixLength` and `plugged`, both on 192.168.1.0/24; the move goes from the old to the new address and one of six servers finds it every 2.5 s (`moveTotal`, `moveStepMs`, `moveMissing`). The web's managed fake world routes `host.cable.set` to it. | The flow can be clicked through in fixture mode and the demo world, and tested without timers. |
| AP-6642 | **Web: buttons in the rows, small and secondary**: Use Wi-Fi only before Join a Wi-Fi network, Use the cable again at the cable row's end. | Settings' row actions look like this everywhere (Forget, See hardware). |
| AP-6643 | **Web: one dialog for both directions** (`CableDialog`), Forget's layout: title, lead, the guard and the subnet note as hints, a refusal in the dialog (`role=status`), Cancel and the primary button (“Switching…” while sent). The dialog closes once the change started; NETWORK follows it. | The question is short; what happens next is NETWORK's line. |
| AP-6644 | **Web: the move and the tip are rows of the card** (`data-row` `network-cable-change`, `network-move`, `network-tip`), after the Wi-Fi change line and before the saved networks; Point them here is a real link that navigates in the app. | They are about the connection, read in order: the change, the servers, what to do next. |
| AP-6645 | **Web baselines** (`visual/machine.spec.ts`): Use Wi-Fi only's question, NETWORK at 3 of 6 and once all came, light and dark; the laptop's NETWORK baseline now has Use Wi-Fi only. The harness zeroes Home's needs-you count too (the Inbox's badge reads it). | Visual check against the existing rows; the harness failed on every screen since the Inbox took its badge from Home. |
| AP-6646 | **Phone: the button across the bottom above Join** (Use Wi-Fi only or Use the cable again, whichever applies), asked in the system alert as Forget is (`cableConfirm`: lead, guard and the subnet note as paragraphs); a refusal is an alert titled “Couldn’t use Wi-Fi only” / “Couldn’t use the cable”. | The phone's NETWORK puts its actions across the bottom (Join); a long label doesn't fit beside a row's title on a phone. Alerts are the phone's confirm pattern here. |
| AP-6647 | **Phone: the cable change and the move as change lines** (spinner while running), Point them here as the move row's 44dp button (`onRepoint` from This Whombat and the demo's settings page), the tip as a muted line. | Same pieces as the Wi-Fi change line. |
| AP-6649 | **Phone demo world**: `?machine=wifionly` starts the Z13 on Wi-Fi only with its cable plugged in; the start state (`z13`) has cable and Wi-Fi to click Use Wi-Fi only. | For checks on the emulator. |
| AP-6639 | **“You can unplug the cable” only once Wi-Fi only is kept** (no cable change running), on the cable's row and the move's line (NM-14). | The servers' move finishes long before the 2-minute check; unplugging then and failing the check left the box with neither. |
| AP-6641 | **The poller asks for a minute after a cable change ends** (every 5 s, `NETWORK_CABLE_SETTLE_MS`), besides following a move still under way. | The cable's address and the servers' new move come a few seconds after the change; the section otherwise stopped on “Cable · Not connected” and missed the move. |

AP-6648 is free for this workstream.
