# Full Incus and unRAID support — Whombat's server (stream SV, 2026-10-17)

Stream SV of `docs/implementation/incus-unraid/assignment.md` under `docs/decisions/incus-unraid.md` (IU-01…IU-13),
contracts 0.83.0 (CT-363…CT-368) and, for QEMU/KVM through libvirt, 0.84.0 (CT-369…CT-372). Code: `apps/server/src/hosts/`; how that directory works is `one-whombat-servers.md`
(ONE-DH01…) and `proxmox-server.md` (PX-S01…PX-S13), whose rules hold here too.

| # | Decision | Why |
|---|---|---|
| IU-S01 | **The server's kind is the hub's `detail_view`** (`serverPlatform`): `proxmox`, `incus`, `unraid`, anything else `standard`. Servers and server details carry `hostsThisWhombat` only when the hub says `hosts_this_whombat`. A detail gets `incus` and `unraid` when the hub sends them (any kind, IU-03's “Docker and libvirt guests stay in Guests” keeps `workloads` next to them), mapped field by field and leniently (ONE-DH08): an unknown array state or disk status is `invalid`, an image without a fingerprint and a notification without an id are left out (Whombat can't act on them). | The contract's enums are closed; one odd field mustn't empty BlackBox's page. |
| IU-S02 | **Guests gain `self`, `autostart`, `webUi`, `template`.** `template` and `webUi` are read only on Docker guests: on Proxmox `template` means a template guest (`resolveGuestOrTemplate`), not a dockerMan template. `self` only when true. Tasks gain `cancellable` (also from `may_cancel`), backups `expiresAt`. | §2.3 defines `template` for Docker on unRAID; the hub's Proxmox guests already send a `template` flag of their own. |
| IU-S03 | **Every new op has its route in `MANAGE_ROUTES`** with what it passes (PX-S01 refuses the rest): path parts `fingerprint`, `profile`, `pool`, `volume`, `disk`, `plugin`; `config.set` also takes `devices` and `profiles` (Incus); `guest.create` `project`, `pool`, `network`, `cloud_init` and takes `template` as the service's `image` (`alias`, refused when both say different things); `guest.clone` `project`, `instance_only`; `backup.create` `name`, `expires_at`, `instance_only`, `optimized`, `compression`; `backup.restore` `name`; `backup.delete` the request's guest as `guest` (Incus). Bodies are snake_case of the contract's camelCase params (`cloudInit`, `expiresAt`, `copyFrom`, …). `parity.cancel`, `array.stop`, `plugin.update`, `container.update` send `confirm`. The reads `profile.get`, `network.leases`, `log.get` and `choices` with `project` go to §2.2's routes. | Contracts first; the hub refuses unknown fields, so naming them here is what keeps a call from failing late. |
| IU-S04 | **The guest this Whombat runs in is refused before the hub is asked** (IU-02), with the contract's rule (`HOST_SELF_GUEST_ALLOWED`, `selfGuestAllows`) and words (`HOST_ERROR_WORDS.self_guest`, 409 `self_guest`): the person's routes (`guestAction`, `manage`: the guest is read first, as before for its name) and every Servers tool that changes a guest (power, snapshot restore, settings, disks, clone stays allowed, template, delete, migrate, rename, move, publish, firewall, HA, restore over it, autostart, container update). A restore that makes a new guest stays allowed: always on Incus, on Proxmox with `newId`. | The hub refuses too; asking it anyway would sign nothing but costs a round trip, and the tools must not even post “Stopping … now”. |
| IU-S05 | **The tools ask the server's kind, not `platform: 'pve'`** (`resolveServer` → `kind`, `managePlatform`): `guest_create`, `server_choices` (with `project`), `server_tasks` (`platform=incus`/`unraid` for an Incus or unRAID server's list; ids `UPID:…`, `incus:<uuid>`, `unraid:<hex>`; `canStop` from `cancellable`), `task_stop`, `guest_backup` (Incus: a name and an expiry from `expires_days`, default 7; restore always as a new instance named `name` or `<name>-restored`; delete with the guest; protect and notes refused), `guest_backups` without a guest lists Incus instances too. `storage_content` stays Proxmox's. | §2.5; a server of an unknown kind still asks the service (`choices`), as before 0.83. |
| IU-S06 | **An argument for the other platform is refused in words**, not dropped (PX-S02's spirit): `project`, `profiles`, `pool`, `network`, `cloud_init` on a Proxmox create (“Incus only”), `id`, `storage`, `bridge`, `iso`, `password`, `ssh_keys` on an Incus one (“on Incus give pool, network, profiles or cloud_init”); `full`/`id` on an Incus copy; `devices`/`profiles` on a Proxmox guest's settings; an Incus disk can't move (`guest_move`). Incus names follow `INCUS_NAME_PATTERN`. Devices are checked here too (`nic` or `disk`; a disk's `source` never a host folder). | The schemas are shared by both platforms; a silently dropped `pool` makes a different instance than asked. |
| IU-S07 | **Restarting the server this Whombat runs on says so** (IU-02): the ask reads “reboot the-titan, the server this Whombat runs on” (the approval's question is its title plus “?”, so the sentence can't follow it there), the card adds `HOST_SELF_SERVER_POWER_TEXT` (“This Whombat goes down too.”) through a new optional `CallWords.note` (`connections/adapters/index.ts`, `connections/call.ts`), the words after a yes and the tool's `next` say it goes down too. Which servers those are comes from every fleet read (`noteSelfServers`, by id and host name), since the words are written without a lookup. | IU-02; the brief's sentence, where the copy can carry it. |
| IU-S08 | **Long work ends with one message** (IU-07, PX-S03's mechanism): followed — Incus create, copy, backup (“web on the-titan is backed up.”), restore as new, rename, move, publish, image download, refresh and delete; unRAID array start and stop, parity check, the mover, plugin check and updates, container update and check. Pausing, resuming and cancelling a check and spinning disks take seconds and aren't followed (the words after a yes say “now”). A parity check, a plugin check and a container check add what the server's report says after a clean end (`taskAfterText`): “No errors.” / “It found 3 errors.”, “2 plugins have an update.”, “plex has an update.”; a parity result comes from the task's own message, else the detail's last check when it is newer than the task, read once more after 35 s (the report comes every 30 s), else nothing is added. The server is named by its host name when that is its id with its own capitals (“BlackBox”), else by its id. | “The parity check on BlackBox is done. No errors.” is the brief's; a stale report must not say “No errors.” of an older check. |
| IU-S09 | **New tools in two files** (`tools-incus.ts`: `incus_overview`, `incus_profile`, `network_leases`, `guest_log`, `guest_rename`, `guest_move`, `guest_publish`, `incus_image`, `incus_profile_set`, `storage_volume`; `tools-unraid.ts`: `unraid_overview`, `unraid_array`, `unraid_plugins`, `container_update`, `guest_autostart`). Roles as the routes (§2.2/§2.3): reads operator (the overviews viewer), rename/move/publish/image download and delete/profiles/volume create and delete/array start and stop/plugin and container updates admin, the rest operator. A tool for one kind on another answers `{error: "<id> doesn’t run Unraid, so this tool doesn’t work there.", code: "unsupported"}`. `unraid_array spin_*` without `disk` spins every disk; `incus_profile_set update` needs the digest from `incus_profile`. | The brief's “split past ~1000 lines”; reads stay cheap and compact (ONE-DH16): overviews in GB and percentages, no raw report. |
| IU-S10 | **Undo** by the inverse call (PX-S11): a rename ↔ renamed back (the id changes with the name), autostart on ↔ off. None for moves, publishes, images, profiles, volumes, the array, parity, plugins, containers, notifications. A person's autostart has no Undo yet (it would need a new undo kind). | What clearly goes back; an archived notification or an updated container doesn't. |
| IU-S11 | **`guest_autostart` is Docker on unRAID and libvirt**: an Incus instance is pointed to `guest_config_set {"boot.autostart": "true"}`, a Proxmox guest to `{"onboot": "1"}`; the same value again answers “already …” without a call. `container_update` refuses a container without a template (`template: false`) in words before the service does. | IU-05; the autostart op is the service's for those two. |
| IU-S12 | **Hints link to where they are fixed** (IU-08, PX-S05): `incus.no_snapshots` like the Proxmox guest hints (the guest's Snapshots tab, “Give it a snapshot schedule.”; its guests are the names before “ · ”, the hub's one hint per host reads “web, db · no backup in 30 days either”, its extra `guests` field isn't in the contract and is dropped); host hints to their tab with the way out — `incus.pool_full` Storage, `incus.warning` System, `unraid.array_stopped`/`parity_errors`/`parity_old`/`disk_errors`/`pool_full` Array, `unraid.plugin_updates` Plugins, `unraid.notification` Summary (“Archive it once it’s handled.”), `unraid.os_update` Plugins (“Update it in Unraid.”, the page has the link); `docker.update_available` on an unRAID server links to the container (“Update it.”), elsewhere as before; a storage hint of an unRAID server opens Array. New tabs: `array`, `plugins`, `shares`, `images`, `network`, `summary`. | Watch items link inside Whombat; the Unraid version line on Plugins carries the outside link. |
| IU-S13 | **The fake service plays both** (`testing/fake-incus.ts` on basalt, now an Incus host running this Whombat's guest `incus:whombat-dev-box`; `testing/fake-unraid.ts` on the new `blackbox`): a route handler may answer `null` to pass the request on (the Incus and unRAID sides answer their own guests' backups, configs and tasks and leave the rest to the Proxmox side); `FakeManage.startTask` makes `incus:<uuid>` and `unraid:<hex>` tasks; the fake refuses the self guest's power and changes like the hub. The fixture's BlackBox has a parity disk (the real one doesn't) so parity can be tested. | Tests without Go (ONE-DH20). |
| IU-S14 | **QEMU/KVM is libvirt's on every host** (IU-13): the kind `libvirt`, a detail's `libvirt` part (pools, networks, Unraid's folders, firmware, the backups folder) mapped like Incus's; a guest of platform `libvirt` is managed wherever it runs (basalt, BlackBox, kvm-lab), and `manageable` (and the tools' `allowed.manage`) now include it. The tools pick `libvirt` by the guest's platform, else by the server's kind; ISO images and downloads are libvirt's on every server but a Proxmox one (Unraid's ISO folder, a pool). | One code path for every libvirt; BlackBox stays `unraid` and its VMs still get all of it. |
| IU-S15 | **The shared tools widen to libvirt**: `guest_create` (`kind: vm` only, `os_variant`, `iso`, `storage` a pool or `folder:domains`, `disk_gb`, `network` or `bridge` but not both, `cores`/`memory_mb` as `vcpus`/`memory_mb`; Incus's and Proxmox's own arguments refused in words), `guest_clone` (`name`, `storage`; no `id`/`full`/`project`), `guest_rename` and `guest_log` (Incus instances and libvirt VMs), `guest_delete` (`purge` deletes its disks and NVRAM), `guest_disk` (grow only; moving is Proxmox's), `guest_backup` (running or not, `compress` sent as `zstd`, restore always as a new VM, `name`/`expires_days` refused), `guest_backups` without a guest lists VMs too, `storage_contents`/`storage_content` (ISOs only; `get_template` and appliances Proxmox's), `server_tasks`/`task_stop` (`libvirt:<hex>`), `server_choices` (networks, OS types, firmware), `server_detail` (pools and networks in short), names by `LIBVIRT_NAME_PATTERN`, storages may be `folder:…` (`plainName`). | The contract widened the same tools; one rule (IU-S06) for what belongs to another platform. |
| IU-S16 | **A libvirt pool's volumes and a libvirt network's leases are under `/libvirt/…`** on the service (`/libvirt/pools/{pool}/volumes…`, `/libvirt/networks/{network}/leases`), Incus's under `/incus/…` (HI's routes): `volume.*` and `network.leases` pick the prefix by `platform`. The tools find whose pool or network a name is from the server's detail (basalt has both), else by its kind. **Cross-stream point for the lead**: the QEMU hosts stream must serve these two paths (or the lead changes `poolsOf`/`networksOf`). | §2.6 names the ops, not the routes; the host routes are named by platform elsewhere (`/incus/…`, `/unraid/…`). |
| IU-S17 | **Words for libvirt** follow Incus's: “win11 on kvm-lab is backed up.”, “debian-web-2 is ready on kvm-lab, restored from yesterday’s backup.”, a backup's day from its folder (`20261016-020000`), Unraid's folders by what they hold (“the ISO folder”, “the VM folder”). Hints: `libvirt.pool_full` → Storage (“Make room on the pool or grow it.”), `libvirt.no_backup` → the VM's Backups tab (“Back it up now.”). `hosts.libvirt` is advertised. | IU-07/IU-08 for QEMU. |
| IU-S18 | **The fake plays kvm-lab** (`testing/fake-libvirt.ts`, fixture `server-kvm-lab-libvirt.json`, a `libvirt` part on BlackBox with its folders): the libvirt VMs of every server answer the shared guest routes there, tasks are `libvirt:<hex>`. | ONE-DH20. |
