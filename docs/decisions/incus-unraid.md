# The Titan as a server, full Incus, unRAID and QEMU support (2026-10-17)

John, 2026-10-17 (main checkout): “Add The Titan as a server (install the agent). Then add full support for Incus and
unRAID.” The Titan (`thetitan`, 10.100.0.7) is his workstation and the Incus host of the DEV Whombat itself
(`whombat-dev-box`), `whombat-prod-box`, the CI templates (project `ci-platform`) and the stopped `rackoon`; it also runs
45 Docker containers. BlackBox (10.100.0.40) is his unRAID 7.3.1 server (array with one data disk and three ZFS pools
`apps`, `data`, `storage`; Plex, the *arr apps, Immich; the PBS VM). After the Proxmox build (PX-01…PX-11) the agent
already watched both, but Incus stopped at settings, create, copy and delete, and unRAID was watch-only (no array,
parity, pools, shares, plugins or Docker templates). The build brief is `docs/implementation/incus-unraid/assignment.md`.

| # | Decision | Why |
|---|---|---|
| IU-01 | **The Titan reaches its own Whombat through a relay container.** The DEV box hangs off The Titan's network card as a macvlan VM, so The Titan can't talk to it over IP (a host shim was rejected on 2026-10-07: it touches the card the tunnel connector uses). The Incus container `whombat-link` on The Titan has its own macvlan link (a sibling of the box, LAN 10.100.1.120) and an Incus proxy device: The Titan's `127.0.0.1:18443` → `10.100.1.160:8443`. The agent was installed with `--hub wss://127.0.0.1:18443` (the agent pins the hub's CA, not a host name) and approved as **the-titan** (“The Titan”); remote control is off. `whombat-link` has `boot.autostart` and `security.protection.delete`. | Nothing changes on The Titan's own network; one small container, the same kind of link the box itself uses. |
| IU-02 | **Whombat knows its own guest.** The agent reports each guest's network MAC addresses (Incus, Proxmox VE, libvirt); the hosts service compares them with its own machine's and marks that guest `self` (“This Whombat”) and its server `hostsThisWhombat`. Changing the guest the Whombat runs in is refused (`self_guest`: “That’s this Whombat itself.”): stop, shut down, restart, pause, delete, rename, move, migrate, convert, restore, snapshot restore, settings and disks. Snapshots and backups of it are allowed. Restarting or shutting down the host it runs on still works but the question says the Whombat goes down with it. | The Titan holds the DEV Whombat: one wrong tap from the phone would switch off the thing you tap with. |
| IU-03 | **Two new server kinds.** `incus` (a host whose agent reports Incus and not Proxmox VE or unRAID: The Titan) and `unraid` (`/etc/unraid-version`: BlackBox) get their own page and phone screen, like `proxmox`. Docker and libvirt guests on them stay in Guests. | Each platform has its own objects (pools, images, profiles; array, parity, shares); a generic page hid them. |
| IU-04 | **Full Incus**: every instance setting Incus lets a non-root person change safely (the allowlist of MANAGE.md §2.5, plus profiles), devices (network cards on an Incus network or host bridge, disks on a pool, never a host path), snapshots with their schedule, **backups** (back up now with expiry, list, delete, restore as a new instance), tasks (Incus operations: list, follow, cancel), the instance log, create from an image (any project, profiles, pool, network, limits, cloud-init user data), copy, **rename**, **move** to another pool or project, **make an image** (publish), delete. Host level: projects, storage pools and custom volumes (create, grow, delete, attach), images (download from the images server, refresh, delete), profiles (create, edit with the same allowlist, delete unused), networks with their address leases, Incus warnings, the Incus version. | John asked for “full”; these are what `incus` offers a homelab day to day. |
| IU-05 | **Full unRAID**: the array (start, stop), parity (check with or without corrections, pause, resume, cancel, history, schedule), disks (status, temperature, spin state, errors, size and use; spin up or down one or all), pools, shares (read), the mover (run), Docker the unRAID way (update a container from its template, autostart on/off, its web page link, check for updates), VMs (autostart on/off, besides power, snapshots and console), plugins (installed, updates, update one or all, check), unRAID's own notifications (read, archive), the unRAID version and whether a newer one exists. The agent uses what unRAID's own web page uses (`emcmd`, `mdcmd`, `plugin`, dockerMan's `update_container`, the files under `/var/local/emhttp`), with every argument checked. | The webGUI's own commands work on 6.12 and 7.x alike; the GraphQL API needs a key and 7.2+. |
| IU-06 | **Same switches and questions as Proxmox.** All of it needs the server's `manage` switch on both sides (the agent's `agent.toml`, then Whombat); reading works without it where the report carries it (array, disks, pools, shares, plugins, notifications, pools, images, networks, profiles). Whombat always asks before: stopping the array, cancelling a parity check, updating a plugin, updating a container, moving or deleting a guest, restoring a backup, deleting a backup, a profile, an image or a volume. | PX-02/PX-04's rules; one place to learn them. |
| IU-07 | **Long work reports back** like PX-05: an unRAID command the agent runs (array start/stop, parity, plugin and container updates, mover) is a task `unraid:<id>` with its output as the log; an Incus operation is `incus:<uuid>`. A task Whombat started ends with one short message (“The parity check on BlackBox is done. No errors.”). | The same toast, progress and outcome everywhere. |
| IU-08 | **Hints with a way out** (ONE-07, PX-07): Incus — no snapshot schedule and no backup in 30 days → Snapshots schedule; a pool over 85 % → Storage; Incus warnings → System. unRAID — array stopped → Start the array; parity errors or no check in 35 days → Check parity; disk errors → Array; a pool over 90 % → Array; plugin and container updates → Plugins / the container; an unRAID alert or warning notification → its text, Archive; a newer unRAID → “Update in unRAID” (link). | A hint without an action is noise. |
| IU-09 | **The phone** gets the Incus instance screen (Summary, Settings with the everyday edits: memory, CPU, autostart, protection, description, snapshot schedule; Snapshots, Backups, Tasks; Back up now, Copy, Rename, Delete) and the unRAID server screen (Array with parity and disks, its actions, plugin updates; a container's Update and autostart). Devices, profiles, images, volumes, networks and moving stay on the web, and the screen says so. | AP-1367/PX-06: room and a keyboard. |
| IU-13 | **Full QEMU means VMs that libvirt runs** (server kind `libvirt`, shown as “QEMU/KVM”; precedence Proxmox VE > unRAID > Incus > libvirt > standard, so BlackBox stays `unraid` and its VMs still get all of it): settings (name, title, notes, vCPUs, memory, autostart, boot order, CPU mode, what happens on power off/reboot/crash; machine type, firmware and passed-through devices shown locked), devices (disks: new or existing volume or file, grow, detach keeping the file; CD/DVD: insert or eject an ISO while running; network cards on a libvirt network or a host bridge, link up/down), snapshots (as today, with a plain refusal when the disks can't take internal snapshots), **backups** (libvirt's own backup job, running or stopped, into a backups folder with the VM's XML: list, delete, restore as a new VM with a new UUID and MACs), create (OS type presets incl.
