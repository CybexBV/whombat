# Multi-language support, starting with Dutch (`i18n`)

Whombat speaks the person's language across every surface — web, phone, desk screen, console installer, server dashboards, emails, pushes and the AI assistant — starting with English (`en`) and Dutch (`nl`), built so more languages add cleanly without breaking contracts, Nix caching or existing visual baselines.

## Decisions

| # | Decision | Why |
|---|---|---|
| I18N-01 | **One tiny, catalog-free engine in `@whombat/core/i18n`** (`./i18n/locale`, `./i18n/engine`, `./i18n/schema` subpaths), zero runtime dependencies, `sideEffects: false`, pure ES2023 (no DOM, no `localStorage`, no `eval`/`new Function`, no React). React helpers live in `@whombat/client/i18n`; `apps/web`'s Dutch catalog loads lazily as its own chunk while `@whombat/core` and `@whombat/client` stay synchronously importable; `@whombat/screen` stays dependency-free with its own self-contained locale lookup in `ScreenEnv` so `appliance/console/ui` vendors it byte-for-byte. | Fits all five toolchains (Node 24 server, Vite 8 strict-CSP web, Expo/Metro/Hermes mobile, 8 KiB gzipped widget loader, offline Nix-vendored console UI) with zero new packages in `contracts:release`, zero `THIRD_PARTY_NOTICES.md` additions and zero Nix fixed-hash churn. |
| I18N-02 | **Co-located declarative catalogs per owning package** (`packages/core/src/i18n/`, `packages/client/src/i18n/`, `packages/screen/src/i18n/`, `apps/server/src/i18n/`, `apps/web/src/i18n/`, `apps/mobile/src/i18n/`, `apps/widget/src/i18n/`, `appliance/console/ui/src/i18n/`). Entries are plain data (strings or CLDR plural maps `{ zero?, one?, two?, few?, many?, other }`), never functions, with stable keys, per-key English fallback, a built-in `pseudo` locale (`[Ŝéţţîñĝš…]` + ~25% length padding), English source-hash staleness checks, placeholder/plural parity tests and PO/JSON export/import scripts (`scripts/i18n/`). | Preserves Nix narrow source isolation (`appliance/nix/lib/sources.nix`), keeps `tsc` fast, supports multi-form CLDR plurals for future languages, flags stale translations when English edits land, and lets external translators work in standard PO/JSON without editing TypeScript. |
| I18N-03 | **One stored preference: `accounts.preferences.locale`** (optional BCP-47 `LocaleTag`, e.g. `en-GB` or `nl-NL`, null = default `en-GB`). Zero DB migration; already read by desk, push and digest code without an active session and already exported/restored by settings backups. Unknown future locale tags fall back safely to English at runtime without discarding the rest of `preferences`. Cached per box in client local storage for instant pre-paint `<html lang>` and pre-connect screens. Public/visitor surfaces (installer, claim, hosted account site, `/s/shr_*` share links, `apps/widget`) resolve from explicit choice → `data-lang` / `<html lang>` → `navigator.languages` / OS locale → `en-GB`; share-link viewers and website feedback reporters never inherit the box owner's locale. | One source of truth avoids drift between two DB columns, preserves full BCP-47 formatting (keeping `en-GB` day-first dates and `nl-NL` comma decimals), and backs up/restores automatically. |
| I18N-04 | **Session protocol minor 21 (`LOCALE_MINOR = 21`) and control/local sync.** Optional `locale` on claim requests (`EnrollClaimInput`, `EnrollClaimLocalInput`, sent only when `protocolAtLeast(protocol, LOCALE_MINOR)`), on `ConsoleState` and `DeskPaired` (for `console.json` / `desk.sock`), and on `link.mail.set` / `mail.send` (so Control stores the box's language ahead of time for offline emails, waiting digests and fallback pushes, retrying without `locale` on 400/502 compatibility refusals without marking it synced). | Backwards-compatible minor addition (no major bump); keeps older boxes (including 5.20) and older Control builds working cleanly. |
| I18N-05 | **Server renders what it owns; internal codes stay inside the box.** The server renders `ThingPage` dashboards, Home/Inbox lines, system notices, approval cards, emails, pushes and desk views in the owner's locale (clearing/keying `ThingWidgets` and client query caches on language change, and notifying listeners on backup restore). Internal services (`hosts/internal/rules`, `appliance/backup`, live stored DB rows like `activities`, `incidents`, `notice_quiets`, `dispatches.failure`) carry structured codes + params rendered on read, leaving signed remote `whombat-agent` and macOS `Whombat Helper` untouched and avoiding Go's ASCII sanitizer corrupting Dutch diacritics. | Matches Whombat's server-driven dashboard design (`thing-page.ts`), lets older apps show Dutch server text immediately, and avoids a fleet-wide signed agent rollout. |
| I18N-06 | **Privacy and preview checks never read translated prose.** `ThingPageKpi`, `ThingControl`, `ThingPagePanel`, and desk list/figure resolvers carry and enforce explicit machine metadata (`private`, `figure.key`, `person`, panel ids) so locked desk screens never match English words or slug titles (`f-doors`). `PushPayload.preview` (`false` when previews are off) is a contracted boolean forwarded through APNs/FCM and enforced in `sw.js` (for both managed and path-based pushes) and Android `WhombatPush.kt`, with legacy `CONTROL_GENERIC` fallback; push titles identify direct chats via a structured `direct` flag rather than matching `'Direct'`; `sw.js` reads locale via URL/message/Cache API without `localStorage`. `packages/screen/src/times.ts` stays pinned to `'en-GB'` as an internal weekday parser. `packages/client/src/managed/recovery.ts` keeps English recovery-kit field parsing and checksum compatibility. | Translating prose must never leak private data on a locked desk screen or break push previews or recovery kits. |
| I18N-07 | **AI assistant switches language immediately, including open threads.** `DispatchContext` carries `locale` (resolving to `'en-GB'` on owner turns when preferences have no override so switching back to English still emits a reply-language cue). `SOUL.md` and `whombat.md` stay language-neutral ("plain everyday words in the person's language"), while the per-turn preface and `replyLengthLines` name the active reply language, Dutch tone/glossary rules and localized voice cue so resumed Hermes sessions switch at once. Protocol markers (`NO_REPLY`, `MORE:`, `VERDICT_*`, `JOB_REPORT_MARK`) and MCP tool schemas/enum values stay ASCII English while user-facing tool text uses the owner's language. Settings place names share one translated table across UI, agent instructions, `settings_open` cards and `settings_find`. Outsiders' turns (feedback, report trackers, incoming mail) keep matching the outsider's language. | Hermes freezes `SOUL.md`/`whombat.md` per session; per-turn cues reach existing threads immediately, and keeping tool schemas/markers English preserves tool-calling reliability. |
| I18N-08 | **Search fixes Dutch stopwords without per-language index columns.** `apps/server/src/read/search.ts` strips Dutch stopwords before English stemming when the burrow's active language is Dutch (preserving quotes, boolean operators and English queries untouched), binds `locale` into pagination `scopeKey`, and stores an additive `language` column on `search_answers` (`0043_search_answer_language.sql`, null = English) so changing language keeps saved and in-flight answers readable by id while keying answer reuse per language. Existing `'simple'` indexing already matches exact Dutch words; if stemming is warranted later, add a single locale-aware `tsv_local` column rather than N per-language columns. | Preserves saved and pending answers across language switches, keeps rollback-safe expand migrations, preserves keyset `ts_rank` pagination and scales cleanly to N languages. |
| I18N-09 | **Signed audit log and automations keep canonical integrity.** Immutable Ed25519-signed `events` keep canonical English envelopes (`EventEnvelope` untouched; verified CSV export stays canonical); the audit viewer (`packages/core/src/audit/log.ts`) localizes chrome, filters, pills, key labels and high-frequency structured events, falling back to signed `event.text`. Stored `automation_versions.definition` stays canonical English (preserving AR-59 / `EARLIER_RECIPE_WORDS` auto-upgrades), while visible recipe titles, summaries, step labels and flow stories render in the active locale. | Never breaks tamper-evident signatures, Go verifiers or automatic recipe upgrades. |
| I18N-10 | **Legal texts, voice consent, recovery and visual baselines.** Legal documents keep English as the governing version (`LGL-03` version untouched) with a clear Dutch notice until lawyer-reviewed Dutch editions land sharing the same version date; Open RAIL-M stays English with a plain Dutch summary and explicit opt-in consent (never auto-enabled when switching to Dutch). Emergency tty1 recovery (`recovery.nix`) and factory-printed cards (`card.go`) stay English; the graphical installer (`appliance/console/ui`) and user-printed web backup sheet (`KitScreen.tsx`) translate to Dutch. Existing `pnpm visual` mock baselines stay pinned to `en-GB`, complemented by Dutch and pseudo-locale Playwright checks (`apps/web/e2e-managed/i18n.hosted.spec.ts`) and a ratcheting literal-text lint check (`scripts/i18n/lint-literals.ts` + `lint-baseline.json`, enforced in `scripts/i18n/check.test.ts`). | Keeps emergency recovery reliable without DB/Unicode fonts, protects legal compliance and keeps visual regression suites green. |

## Dutch Glossary & Style Guide

Tone: short, plain Dutch using informal **"je"** / **"jouw"** (matching `plain-words.md`, `hosts/web/src/locales/nl.ts` and `packages/core/src/domain/tracker.ts`). Keep familiar Dutch IT loanwords (*server, back-up, container, VM, passkey, Tailscale, pull request, Wi-Fi, Bluetooth, DNS, SSH, API, GitHub*) rather than stiff calques. Keep Whombat's typography (`’`, `“ ”`, `·`, `−`, 24-hour clock, day-first dates `23 sep`, `€1.234,56` / `90,5`).
