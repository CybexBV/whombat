# Shared archive field parsing — 2026-10-20

Research opportunity 5, based on runtime `70c4d22e`. This extracts existing mechanics into
`@whombat/node-io/tar`; it does not change an archive's authority, entry policy or storage path.

| # | Decision | Reason |
|---|---|---|
| RA-T01 | Share bounded C strings, optional ustar prefixes, numeric fields, PAX decimal sizes and record framing, unsigned checksums, block padding, zero-owner ustar header writing and byte-counted PAX records. No archive dependency and no changes to vendored core. | All three readers duplicated these mechanics. Filesystem writes, compression, stream ownership and archive validation still belong to the caller. |
| RA-T02 | Numeric parsing requires explicit base-256 and termination policies. Releases select `octal-only` and validate the whole padded field after the original Latin1 trailing NUL/space removal and trim (including leading NBSP); binary GNU fields still fail octal syntax. Client installers accept nonnegative safe base-256 and stop octal at NUL; packs reject any leading high bit even for small values and stop octal at NUL. Callers supply their existing error types and words. | BP-F14 is stricter than upstream client compatibility. Preserve the original release parser's padded-field acceptance as well as its diagnostics; checking the high bit before text trimming incorrectly rejected previously accepted NBSP padding. |
| RA-T03 | PAX record framing has explicit strict and compatibility options. Releases require exact positive decimal lengths, newline and key/value syntax, and tolerate trailing NULs. Clients retain decimal-prefix lengths, throw for invalid bounds and skip unframed tails or records without keys. Packs retain numeric lengths and stop on invalid bounds. Local PAX size is applied only by releases and clients (clients retain their 15-digit cap); packs continue to use ustar body sizes. | These existing policies differ. This refactor neither tightens accepted upstream archives nor weakens the disk extractor's validation. |
| RA-T04 | Keep archive traversal and end handling local. Releases stream to disk with their existing cap, modes, link allowlist, realpath checks and link-chain refusal. Clients stream only the selected regular file and stop immediately, retaining GNU long names, metadata/entry/total caps and iterator cleanup. Packs decompress into bounded memory, report links/special entries for validation and retain their entry cap. Releases and clients validate checksums; packs retain their existing checksum tolerance. Releases apply prefix fields unconditionally; clients and packs require ustar magic. | Unifying whole readers would conflate security boundaries. Pack parsing still writes and follows nothing; its caller validates every reported path and type. |
| RA-T05 | Share an independent hand-built malformed-archive corpus under `packages/node-io/src/tar/testing/`, imported directly by tests only. Each reader asserts its own result and diagnostics for the same bytes. Preserve the existing installer, release and CLI security tests. Pin pre-refactor writer hashes for representative release headers and deterministic pack exports. | The corpus exposes intentional differences rather than deriving expectations from the new parser. Writer hashes protect reproducibility, including UTF-8 PAX lengths and ustar prefix splitting. |

No new integration database is needed: framing, extraction, permissions and streaming cleanup are
observable in unit tests with temporary directories and async iterators. The parent runs the full
repository checks and integrates this workstream; this worktree does not restart or deploy shared services.
