# The person's prompts (PRL-*)

John, 2026-11-12: the person keeps the prompts they use again and again (“Find what’s broken”, “Prune the tests”) and
runs one on a repository from Chat in two taps, the way T3 Code's own users paste the same few prompts into new threads.
Whombat ships a set to start with (`STARTER_PROMPTS`).

Related: [t3code.md](t3code.md) (the connection, its tools, threads waking the agent),
[delegate.md](delegate.md) (a task's AI: provider, model, effort, fast), [concise-replies.md](concise-replies.md) (the
hidden brief), [assistant-settings.md](assistant-settings.md) (the assistant changing settings on the person's word),
[chat-runtime.md](chat-runtime.md); contracts `packages/core/src/domain/prompts.ts` and
`packages/core/src/contracts/prompts.ts`.

| ID | Decision | Reason |
|---|---|---|
| PRL-01 | **Prompts live after `/` in Chat and in Settings → You → Prompts**, no new place: `/` offers them above the skills, Settings lists, adds, edits and removes them, and a message's menu can keep its words as a prompt. | Prompts are something the person reaches for while writing; a new tab or page would be one more place to look for a short list. |
| PRL-02 | **A repository prompt goes through the agent to T3 Code**: choosing one asks which T3 Code project (`prompts.projects`, T3 Code's `t3_project_list` at Manage, kept a minute), then `prompts.use` posts the person's message in Chat and the agent starts a new T3 Code thread in that project with `t3_thread_launch`. Without T3 Code at Manage the projects answer `not_connected` and using one is refused in words the person can act on. | The existing hand-over then does everything else: the thread is watched, the agent is woken when it finishes or asks, the job view shows in the Chat thread. A second path straight to T3 Code would need its own watch, card and wake. |
| PRL-03 | **The words reach the thread unchanged; Chat shows one short line.** The person's message is “<title> · <project>” (`promptLine`); the prompt's words travel to the agent in a hidden brief (`briefAgent`) between two marker lines, with the instruction to launch exactly them, nothing added, removed or reworded, then say in one line that it started. The message goes through the same `send_message` path as a typed one, so the thread, unread state and the agent's turn start as if the person had typed it. | Prompts like “remove 20% of the tests while keeping coverage within 2%” only work as written; an agent paraphrasing them loses the guard rails. A 3000-character prompt in Chat would bury the thread. |
| PRL-04 | **A brief on the person's own message works like one on Whombat's**: the brief is recorded in the same commit as the message, before its turn is queued, so the turn reads the line followed by the brief and the message gets a turn of its own (never joined to an earlier queued one, never offered to a running turn). A brief may be up to 6000 characters. | The mechanism was built for messages Whombat posts; it keys on the message, not its author, so it needed no change but its size: a prompt of 3000 characters with the ownership line, the last run and the instructions doesn't fit 4000. |
| PRL-05 | **Shipped prompts live in code; a row records only what the person changed.** `STARTER_PROMPTS` is the list; a shipped prompt has no row until the person changes, removes or runs it, and on its row a title or words left as shipped stay null. Removing one hides it; “Bring back Whombat’s prompts” clears every change and hide and keeps where each ran. Its id stays `starter-<key>`. At most 60 prompts, the shipped ones included. | Improving a shipped prompt in code improves it for everyone who didn't change it, and a reset needs no copy of the original. |
| PRL-06 | **The ownership switch** (“Let it reshape the code”) adds one line telling the AI the codebase is its own to shape (`PROMPT_OWN_IT_LINE`). Off by default. | Anthropic's prompting guide for Claude Fable 5.2: with it the model merges duplicates and fixes what it finds nearby far more often, at about half the tokens again and with the odd change nobody asked for; the person chooses that per prompt. |
| PRL-07 | **The thread is told when the prompt last ran on that project** (`promptTask`, from the prompt's `runs`, one entry per project, the latest first, at most 12), computed before this run is recorded. | A second audit can start from what changed since the first instead of reading everything again. |
| PRL-08 | **A prompt may name the AI its thread runs on** (provider, model, effort, fast, as a delegation's task does). Using it resolves that choice against what T3 Code runs now and hands the agent the exact `modelSelection`; when T3 Code can't run it now, the thread runs on T3 Code's default and the agent says so. | The person's choice reaches T3 Code as T3 Code takes it, and a model that went away doesn't stop the work. |
| PRL-09 | **Only the person keeps and uses prompts**: every command refuses another actor. The assistant reads, keeps and changes them through its settings tools on the person's word (as them); removing one and bringing back the shipped ones always ask first; using one is the person's own press. | Prompts are the person's words; the assistant changing them silently would make them unreliable. |
| PRL-10 | **No session minor bump**: a Whombat without the ops answers `unknown_op`, and the apps then show no prompts. | Nothing older breaks, and the apps already treat a missing op as the feature not being there. |
| PRL-11 | **A shipped prompt's open points go to a council, not to the person** (John, 2026-11-17). The four that ended with a list for the person to review (find what's broken, remove needless complexity, hunt for bugs, make the docs match) end with `PROMPT_COUNCIL_LINES` instead: the thread puts what it isn't sure about to three independent reviewers on different AI models (its council skill when its T3 Code has one), does what they agree on with the tests passing, and leaves the person only what the council can't settle or says is theirs (a product decision, something that can't be undone), with the council's advice; it finishes with what it changed, what the council decided and what is left. The security review's ranked rest, the dependency list and the agent-instructions prompt (which changes nothing until told) stay as they were. Words only: a prompt the person changed keeps their words (PRL-05). | A cleanup of one of his repositories came back with ten points for John to decide, most of them judgement calls about code he would hand to a reviewer anyway. The council runs in the thread that did the work, where the code and the reasons are, so no second hand-over and no new card. |
| PRL-12 | **“Merge into main when it’s done”: Whombat merges the work itself** (John, 2026-11-17). A repository prompt has a third switch, off by default. On, its thread is told (`PROMPT_MERGE_LINES`, after the words and the ownership line) to commit, push its branch, open a pull request into the default branch, get its checks passing (watching it, at most three rounds, never weakening a check, then stop watching) and not merge it itself; the agent's brief says Whombat merges. The thread's watch is marked when the agent starts it with those lines from a turn whose brief has them (`t3_watches.merge` `wanted`). Once the job is done (its end told, T3 Code's run completed), each watcher pass waits for the pull request's checks as an automation's merge step does (`mergeReadiness`, three hours from the job's end; failed checks aren't run again: the thread already got them passing), merges on GitHub with a merge commit (squashed where the repository allows no merge commits) at the head whose checks passed, records it, and says in the person's thread in one line that it merged or why it left the pull request for them; no pull request ten minutes after the end says there was nothing to merge, and a failed or stopped job leaves it quietly (its report says why). Whombat merges as the agent, on the person's word: the switch is their go-ahead, so no Merge key or approving review is asked. An app from before the switch leaves it out when saving, and the prompt keeps it. | Always a pull request, merged by Whombat, works the same whether or not main takes direct pushes, waits for the checks, and merges only the commit they passed on; two prompts on one repository then can't overwrite each other's work. |
