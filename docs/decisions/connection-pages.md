# Connection pages: every connection and device gets a page like a server

John, 2026-10-18 (main checkout): clicking a server in the sidebar gives a summary/dashboard, clicking another
connection (Home Assistant) gives a configuration page; he wanted all connections to get a similar experience. My
research and mockups (`~/.cache/wb-tmp/mockups/connection-pages/`), then John on Home Assistant: “I am not sure if we
should create a dashboard with entities from Home Assistant itself … that should be in Home Assistant itself … keep it
technical and show information about Home Assistant itself, like processes, CPU usage, disk space.” Revised mock
`ha2.png`, then “implement this fully”.

Replaces app `one-whombat-things.md` AP-1300 (“connections and devices open their existing page in Settings”).
Contracts 0.88.0 (CT-390…CT-393), app 0.85.0 (web AP-1900…AP-1949, phone AP-1950…AP-1999), candidate 0.96.0 (IN-283).
Built beside the less-is-more release (contracts 0.87.0, app 0.84.0, candidate 0.95.0); migrations from 0110.

| Id | Decision | Why |
|---|---|---|
| CP-01 | **Every connection and every device has its own page** at `/things/<thingId>` (`connection:con_…`, `device:con_…`, `device:dvp_…` while learning). The sidebar, Home's tiles, Settings → Connections' rows, search and links open it. **Its Settings tab holds what the Settings page held** (sign-in, Look only / Manage, Looked after by, checks, tools and tiers); “Add a connection” stays in Settings and lands on the new page. | One place per thing, like a server; the configuration is one click away, not the first thing you see. |
| CP-02 | **Whombat shows how a service runs, not what is inside it.** Home Assistant's page shows its version, integrations, log, database, backups and the machine's CPU, memory and disk, never the house's lights, rooms or energy; UniFi's shows its network equipment, not who is online; Hetzner's its servers and their cost. The service's own app is one click away (“Open Home Assistant”). | John: the data belongs in the service's own dashboards; Whombat's job is to keep the service healthy. |
| CP-03 | **The page has the server page's shape**: crumb “Your things”, icon, name, status badge, buttons (Ask Whombat, the kind's actions such as **Restart**, **Open <service>**), a fact line, tabs; Overview = a row of figures, a 24-hour chart beside “Worth a look”, then tables and lists. Same tokens, cards and tables as the server page; less-is-more rules (AP-1749…AP-1755) apply: no empty sections, healthy detail folded, trouble first. | John knows the server page and liked it; one visual language. |
| CP-04 | **The server builds the page** (`things.page`, contracts CT-390): panels with their words and figures already formatted; clients draw panels by kind and know nothing of Home Assistant or UniFi. Read live with a 30-second cache per connection; an open page reads again every 60 seconds. A read that fails keeps what the page has and says why in one line (`problem`). | New kinds of connection get a page without a client release; the phone and the web can't disagree. |
| CP-05 | **Tabs**: the server's (Overview first, then the kind's own: Integrations, Logs, Backups…), then the clients' **Activity** (what Whombat changed here, newest first, with Undo) and **Settings** (CP-01; a device's actions and their tiers). | The order of the server page; Activity answers “what did Whombat do with it”. |
| CP-06 | **Every connection gets a useful Overview**, also without a kind of its own: figures **Status**, **Response time**, **Last used**, **Problems** (failed checks in 24 h); the response-time chart; **Worth a look** (failed checks, “needs to be connected again”, new tools waiting for a decision, couldn't read); **Whombat did here** (changes); **What Whombat may do** (its tools grouped by read / change / always asks with their tier, “Change” opens Settings); **Show more here** (CP-14). A kind's page replaces the figures and the chart with its own and keeps the rest. | Hetzner, Proxmox, Grafana, a custom API: all of them get a page today, not when someone writes a dashboard. |
| CP-07 | **Home Assistant's page** reads Home Assistant's WebSocket API with the connection's own sign-in (an administrator account; if it isn't one, the page says so in plain words and shows what it can): version and installation type, integrations and their state, Repairs, the log's errors and warnings, the recorder's database (engine, size), Home Assistant's backups, updates waiting, entities that don't answer; on Home Assistant OS also the Supervisor's CPU, memory and disk per add-on. **Figures**: CPU, Memory, Disk (from the machine it runs on, CP-08, or the Supervisor), Database, Integrations (“169 of 171”); without a machine: Version, Integrations, Errors today, Updates, Database. **Chart**: CPU and memory over 24 h from the machine, else response time. **Worth a look**: integrations not loading, Repairs, errors in the log today, disk ≥ 75 % (≥ 90 % serious), updates, no backup for 7 days, safe or recovery mode, devices not answering (info). **Tabs**: Integrations (count), Logs, Backups, Add-ons (Home Assistant OS only). **Restart** (confirmed; CP-12). | John's revised mock: technical, with the figures he asked for; Home Assistant Container (his setup: Docker in CT 131 on pve-02) can't report its own CPU or disk, the machine can. |
| CP-08 | **What a connection runs on**: Whombat finds the server or guest by the connection's address — a server's address, a guest's addresses, a Proxmox guest's configured `ip=`, a host name through DNS — and keeps the answer 10 minutes. A person who may manage the connection can choose it, or say “not on a server Whombat watches”, or go back to automatic (`connections.setRunsOn`; stored on the connection). The fact line says “Runs on **pve-02 · CT 131**” linking to the guest. | Automatic for John's setup (CT 131 has `ip=10.100.0.5/23`), a choice when DHCP or NAT hides it. |
| CP-09 | *Superseded by service-slots.md SLT-40…SLT-43 (the page; no client lists stands).* **UniFi's page**: the controller's version, devices online, access points, the gateway's CPU, memory and uptime, the internet line now, firmware updates; chart: internet down and up over 24 h; Worth a look: devices offline, updates waiting, gateway busy; tab **Devices** (name, model, state, address, firmware). No client lists. | CP-02: network equipment is how the network runs; who is online is UniFi's own business. |
| CP-10 | **A Proxmox or Unraid connection to a server Whombat already watches is part of that server** (`partOf`, CT-391): the sidebar and Home's tiles leave it out, its page says “This is how Whombat reaches pve-02’s Proxmox API.” with a link, and the server's page shows “Also connected: Proxmox VE API” linking to it. | John's pve-01, pve-02 and blackbox each showed twice. |
| CP-11 | *Superseded by service-slots.md SLT-44…SLT-46.* **Hetzner's page**: servers (name, state, type with cores, memory and disk, location, address), cost per month (the server types' monthly prices), volumes; Worth a look: a server not running, no Hetzner backups on a server, delete protection off; tab **Servers**. | Technical and useful: what runs, where, at what cost. |
| CP-12 | **Actions are a person's change**: shown only to those who may manage the connection, always confirmed, refused on Look only (CS-10), run through the commit pipeline and recorded in Done recently (“Restarted Home Assistant”, no Undo). Only **Restart** for Home Assistant now. | Same rules as a server's Power menu; Whombat's own restarts still go through tools and approvals. |
| CP-13 | **Devices**: a switched-on device's page shows its readings (figures, a 24-hour chart of up to three numeric readings, a table of all), when it was last read and what failed, and its actions with their tiers and limits (Settings tab). A device still being learned shows what Whombat found and tested, with “Open the chat” to the proposal card. | Today a switched-on device opened the Connections overview and a learning one “Not found”. |
| CP-14 | **Show more here**: widgets can live on a thing's page instead of Home (`Widget.thingId`, `widgets.list?thing=`, `pin_widget` `thingId`; CT-392). The page shows the person's widgets for it and a few technical suggestion chips per kind (Home Assistant: “Database size”, “Errors per hour”; Hetzner: “Cost this month”, “Traffic used”; UniFi: “Gateway CPU”, “Clients over the day”); a chip opens the Ask pane with “Keep “…” on the … page.” | ONE-09's widgets, placed where they belong; the long tail of connections gets figures without code. |
| CP-15 | **24 hours of points per connection** (`connection_points`, migration 0110): the 5-minute health pass stores the check's response time (null when it failed) and the kind's series (UniFi internet down/up, a device's numeric readings); older points are removed hourly. | The charts need history; the hosts service only has it for servers and guests. |
| CP-16 | **Home Assistant's tile and sidebar dot become technical too**: line “Home Assistant 2026.10.2”, facts Integrations (“169 of 171”), Errors today, Updates; the dot is yellow while integrations don't load or a Repair is serious. Its glance no longer reads `/api/states` (6,000 entities passed the 64 KB answer limit, so the tile showed nothing). The tile is titled “Home Assistant”, not “Home”. | CP-02 for Home as well; fixes the empty tile. |
| CP-17 | **Ask about <thing>** on every page: the Ask pane (closed until asked, ONE-25) with the thing as the chat's subject, so Whombat knows which connection and its page; a notice's “Look into it” opens it with that question ready to send. | The server page's pattern; questions start where the problem shows. |
| CP-18 | **Older runtimes**: a client opens a connection's Settings page as before when the runtime lacks the feature `things.pages`. | Prod boxes and older DEV boxes keep working. |
| CP-19 | **The phone gets the same page** from the same contract: head, tabs as a segmented control, panels stacked, actions behind a confirm sheet, Ask opens a chat about the thing, Open uses the browser, Settings opens the existing connection screen. | One contract, two clients. |
| CP-20 | **Built in three streams** from integration branches `cp` (Whombat, whombat-app) after contracts 0.88.0: server S (`~/Code/.wt/whombat-cp-server`), web W (`~/Code/.wt/app-cp-web`, owns `packages/client`), phone M (`~/Code/.wt/app-cp-mobile`). DEV fast: one quick check per repo. | Fast, with file ownership to avoid collisions. |
