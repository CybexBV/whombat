# Server names and renaming from the sidebar

John, 2026-11-04: “At servers we should be able to name the server however we want, for example "The Titan" instead
of the-titan. Internally you can use the-titan. Same for connections, we should be able to rename a connection if we
want. In the sidebar in the WEB UI make right-click enable "Rename".” Then: the phone too, and renaming in place
(inline) rather than a dialog.

| Id | Decision | Why |
|---|---|---|
| SN-01 | **A server can be given a name** (“The Titan”): one line of 1 to 60 characters, spaces and any letters allowed (`HostServerGivenName`). Everything a person reads calls the server by it: the sidebar, Home, its page, notices, the desk, briefs, Done recently, activity lines and what the assistant says. Links (`/things/server:the-titan`), the hosts service, its agent, logs, SSH and the tools' `server` argument keep the id. A server without a name goes by its id (or its host name's capitals, as before). | The id is a host name chosen for a network; the person thinks of the machine by its own name. |
| SN-02 | **Kept by Whombat, not by the hosts service**, like “Asks you first”: table `server_names` (burrow, the id in lower case, name, who, when), changed only through the commit pipeline (`servers.rename`), signed `servers.renamed`, recorded in Done recently with Undo. It travels on `hosts.updateServer` / `hosts.serverSettings` as `name` (null puts the id back); a body with only `name` doesn't call the hosts service. Removing a server removes its name. Owners only, as the server's other settings. | Nothing changes on the server or in the hosts service; the hosts service, its agents and older Whombats keep working with the id. |
| SN-03 | **No two servers share a name**: a name another server goes by — its id, host name or given name, ignoring case — is refused with “Another server already goes by that name.”. The server's own name in other capitals is fine. | The assistant is told “restart Plex on The Titan” and must find exactly one server. |
| SN-04 | **The assistant knows the names**: `servers_overview` lists `name` beside the id when it differs, `server_detail` carries it, and every Servers tool's `server` takes the id, the given name or the host name (in that order, any case). It calls the server by its name to the person. Dusty can rename a server through its settings tools (`hosts.updateServer`, at Ask, as the person). | The person uses the name; the tools keep working with the id. |
| SN-05 | **A server's name is in the backup file**: `servers_hub`'s servers carry `givenName` (an older file has none; an older binary ignores it). Bringing a backup back gives a server its name when it has none here and no other server goes by it; a name given here stays. | The name is the person's work, like Asks you first. |
| SN-06 | **Rename where it is listed (web)**: right-clicking a server or connection in the sidebar (or the keyboard's menu key) shows **Open** and **Rename**; **F2** on a row in focus renames too. Rename turns the row's name into a box in place with all of it selected: Enter or clicking away saves, Esc puts it back; why a name can't be used shows under the box in the bad tone, and a server's box says “Leave it empty to use its id again.”. The row shows the new name at once. GitHub, the accounts and devices aren't renamed here (they go by their own names). | The person asked for right-click → Rename; in place is quicker than a dialog and what renaming in a list usually does. |
| SN-07 | **Rename on the server's page (web)**: **Rename** is the first item of the page's ⋯ menu and turns the title into the same box. A server with a name has its title in the sans face and its id quietly under it in the mono face. The connection page keeps its Rename. | A way to rename without a right-click; the id under the name tells which machine it is. |
| SN-08 | **The phone the same way**: a long-press on a server or connection in the list offers Rename, which edits the name in place with the same words; the server's screen shows the name with the id under it and has Rename in its header. | One behaviour on every device. |
| SN-09 | **A connection's name is its label** (`connections.update {label}`, 1 to 80 characters, never empty: an empty box keeps the name). | Connections could already be renamed on their page; the sidebar and phone reuse it. |
