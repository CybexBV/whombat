# Durable work and shared boundaries

Requested implementation of the codebase review, 2026-10-26. The personal-device domain, encrypted session,
permission keys, existing automation engine and integration adapter interfaces stay in force.

| # | Decision | Reason |
| --- | --- | --- |
| RRB-01 | **A message and its agent jobs commit together.** `beforeCommit` runs dependent database writes after the command stores attachments and the thread’s model choice, before outbox rows and the session receipt commit. Posting, “More detail”, answering a waiting run, queue coalescing, plan-step linking and signed dispatch events use the same transaction. Only typing, indexing, badges and notifications run afterwards. | A crash must not leave a saved message or request marker with no runnable turn. The selected model must be visible when the job resolves its runtime. |
| RRB-02 | **Manual and approved GitHub merges save intent, call GitHub outside the transaction, then save its answer.** The intent binds the PR, head, destination branch, method, actor, merge key and on-behalf-of identity. A required `complete` continuation runs after the lock is released and propagates failure to every caller, including `perform_action`. A pending intent is claimed under the lock after rechecking the head, keys, checks and review. One active intent per PR is enforced by the database. | The person’s other work must not wait behind GitHub. A pending action must not merge an unreviewed replacement commit or use a revoked permission. Local origins retain their existing compare-and-swap merge path; automation GitHub merges retain the engine’s existing fenced step. |
| RRB-03, CS-06 | **A saved intent is acceptance, not proof that the external action finished.** A command with a required continuation marks its receipt `pending_result` in the first transaction. If its process dies, status and replay return an uncertain outcome, never success or an automatic resend. Other accepted commands whose process died complete with their result redacted. Pending merge intents resume on boot and periodic recovery. Running calls become uncertain on boot; uncertain calls are never repeated. The GitHub mirror can later prove a merge of the bound head and destination branch and settle the intent. If the mirror sees success first, it records the same single signed event with the original actor, key and on-behalf-of identity; the intent retains its event id for the command’s result. A definite refusal releases it for a new request. | This preserves the receipt’s no-replay guarantee across the extra commits. No system can distinguish a lost answer from a successful merge without later evidence. |
| RRB-04 | **Share the recovery ceremony in `packages/client`.** Identity decisions, session opening, signed enrollment, the resulting pinned record, error mapping and session closure have one implementation. Apps keep directory loading, retired-box screens, file selection and platform labels. | Every device must enforce the same trust boundary without coupling its UI to another platform. |
| RRB-05 | **Keep catalog data per service and retain the public API.** Each entry and its exclusive tool data live under `connections-catalog/`; shared vocabulary, schemas and common builders stay pure. The original module assembles the same ordered catalog and exports the existing names. Server adapters and dashboard registries keep their established interfaces. | A service change should be reviewable in its own file without a new plugin framework or a contract change. |
| RRB-06 | **Session handlers receive only application context.** Runner handlers that need HTTP use `runnerRoute` and `RunnerHandlerContext`. The session dispatcher constructs no dummy request/reply objects. Server actions use their service logger; session console reads use their bounded wait without a pretend HTTP disconnect signal. | Transport-specific assumptions must be visible in types rather than hidden by proxies and exception handling. |
| RRB-07 | **Cover the real boundaries with small regression tests.** Postgres tests interrupt writes and delivery, check retry/coalescing, resume waiting runs, and exercise saved, refused and uncertain merges. `pnpm e2e:runtime` uses a disposable database, private home, real direct encrypted session, actual server and runner, and scripted Hermes, then tears them down. Existing fake browser suites remain broad UI coverage. | Unit and fixture tests cannot prove that a browser, session receipt, database and runner agree on one completed turn. |
| RRB-08 | **The handoff specifies the personal product and maps reference applicability.** Current shell, Chat, model, service, phone and face references take precedence in their areas. Original desktop/mobile references remain component references; their team roster, hiring, invites, roles and membership do not define product behavior. Preserve all reference assets and the orchestrator’s TODO. | Visual fidelity must not reintroduce domain concepts that the product has deliberately removed. |
