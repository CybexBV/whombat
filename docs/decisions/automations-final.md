# Automations, the final design (AF)

John accepted the final Automations design (`docs/design-handoff/council-ui-2026-11/16-final/automations/`, 2026-11-06),
built on web desktop, phone width, iOS and Android. It replaces the list's row (automation-page.md AP-6330, AP-6380 in
part) and a failed run's red (automation-list.md AP-1093's `bad`). Everything else about the list, the automation's page
and its runs stays.

| # | Decision | Why |
|---|---|---|
| AF-01 | **A row is one link: the mark and the whole name, then one line.** The source's real mark (GitHub's, or the owner's picture with GitHub's small badge once it loads; the tracker's own mark; a message, schedule, reaction, webhook or by-hand icon) at 24px/24dp beside the whole name (16/600, never cut), then one line joined with “ · ”: On, Off or Not on yet (600, `ink`), the last run, the next run, and a plan that waits in `warn-text`. It wraps only when it must; one chevron at the end. Rows are 44pt (web, iOS) / 48dp (Android) at least, with an inset hairline between them. What starts it in full and the run bars move to the automation's page, which already has them in its flow and RECENT RUNS. | Eight rows fit at 1440×900 and four on a phone; nothing is lost, it lives one tap away. |
| AF-02 | **The last run in words, with its finish time**: “Last run worked · 23 Sep, 11:06”, “Last run skipped · …”, “Last run failed · …”; a run that hasn't finished says “Last run waiting for you · started 23 Sep, 11:18”; none: “No runs yet”. The date is the app's (`formatDate`, the year only when it isn't this one's). | A date and a time are clear on any day; “worked” is plainer than “done”. |
| AF-03 | **The next run is a time or the event that starts it**: “Next run 24 Sep, 08:30” from `nextRunAt`; else from its triggers, “Next run on a new issue or pull request”, “on a new report or customer reply”, “on the next matching message”, “when you start it”. Off says “No next run”, not on yet “No next run yet”. | An event-started automation has no clock time; the words name what it waits for, from real fields only. |
| AF-04 | **On, Off and Not on yet say whether it runs, never how its runs went.** A run or a plan that waits is its own clause (the page keeps its line with Open). A failed or needs-you run is `warn`, on the bars, the run's dot and its page; red stays for something not working now. Off and not on yet rows keep full contrast. | A past failure isn't the automation being broken; dimmed rows were hard to read. |
| AF-05 | **A run's page says how it ended**: “Finished · worked”, “Finished · failed”, “Finished · skipped” once it has a finish time (`automationRunLabel`), else its status (Running, Waiting, Stopped…). RECENT RUNS on the automation's page says each run's result in words beside when (“worked · 23 Sep, 11:06”), with the last five as bars beside the heading. | “Finished” alone doesn't say whether it worked; colour alone never says a result. |
| AF-06 | **The list's head**: “Automations”, “What Dusty does on its own.” over a hairline, then “To make one or change one, tell Dusty.” over the field. Groups are headed “Automations n” and “Only tells you”. On a phone the field says “Tell Dusty…” and keeps attach, the mic and send on one row at every text size (web: the paperclip without its word below 640px; native: three fixed tool columns, the words shrink). | The composer's tools never wrap; the full purpose stays in the sentence above and the field's label. |
| AF-07 | **Loading, nothing yet, and a list that didn't load.** Loading: “Loading automations…” over two-line row placeholders, no count. Nothing yet (no automations and no schedules): a mark, “No automations yet”, what will appear and “Tell Dusty…”, which focuses the field (web) or opens its sheet (phone). Not read and nothing saved: “Couldn’t read your automations.”, Try again, Ask Dusty (the question put in the field, unsent) and More detail. A refresh that failed keeps the saved rows under “Couldn’t refresh your automations.” and “Showing the list saved at 11:22 on 23 Sep.”. Try again only reads the list again. | No fake empty list; what is on screen says how old it is. |
| AF-08 | **The suggestion chips stay under the web field.** The final drawing has none; they are today's and nothing the app has may go. | John: nothing the app has today may disappear. |
| AF-09 | **Schedules that didn’t load say so under Only tells you.** The overview reads the automations and the agent’s schedules apart (`automationOverview` in `@whombat/client`, web and phone). A schedules read that failed shows the schedules’ own notice, “Couldn’t load the schedules. Try again in a moment.”, with Retry on web (the Schedules tab’s `LoadErrorNote`) and Try again on the phone (`ErrorState`), over the rows already read; Retry reads only the schedules again. “No automations yet” shows only when both reads worked and found nothing; while the schedules are still on their first read and there are no automations, the rows without a count stay. | A failed read looked like “no schedules”, or even “No automations yet”, so the person couldn’t tell missing from none. |
