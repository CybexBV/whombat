# Own address per box (OWA-01…OWA-53)

Each Whombat serves its own page at its own address, `<name>.whombat.app` (boxes that haven't moved yet:
`<label>.box.whombat.app`; DEV: `<label>.dev.whombat.app`), with TLS ending on the box. Phase 1: the address, the door, the certificate and its watch, the claim and link at the address,
box passkeys and the joining rules. Phase 2 (adoption, containment, the DEV step, removing the shared passkey) adds rows
here. Design and reviews: whombat-ops records. Code: `apps/server/src/managed/own-address/`. Shapes: contracts 4.3.0
(CT-1743…); names the person chooses: contracts 4.16.0 (CT-1792…).

| ID | Decision | Why |
| --- | --- | --- |
| OWA-01 | **The name is random by default, or one the person chooses** (2026-11-23, John). By default three different words from the curated EFF short word list 2.0 (996 words, about 0.99 billion labels: 996 × 995 × 994), joined by hyphens, drawn by control (or by an older box with `crypto.randomInt`, drawing again when control says it's taken). The person may choose their own name instead when they confirm the box on the account site (OWA-43), and change it later in Settings (OWA-44). A name moves with a bring back. | Random says nothing about the owner and stays the default; a name of one's own is easier to remember and type. Box passkeys depend on the name, so changing it is a step with a 30-day overlap, not a free edit. |
| OWA-02 | **The word list is one frozen file in `@whombat/core`** (`own-address/words.ts`), credited under CC BY 4.0. A word is never removed after release; one to stop drawing moves to `OWN_ADDRESS_WORDS_RETIRED`, still accepted. | Control and the box must agree on every label ever issued. |
| OWA-03 | **Control keeps one live name per device, plus at most one leaving for 30 days** (2026-11-23). `address.register` answers the name a device has; a rename or a move (OWA-44) makes the earlier one leaving until its date. Names are never given to another box (OWA-41). The manager keeps the name and serves the host control names when it is the label under one of its environment's zones. | Control is the registry; the box never serves a host outside its own zones whatever control says. |
| OWA-04 | **Routing:** control signs `lbl` into the box's main-route appliance tickets, behind a switch turned on only after the relay takes contracts 4.3.0. The relay maps a label to the newest live control connection carrying it. | No registry to sync; a strict `AdmissionClaims` in an older relay would refuse the claim. |
| OWA-05 | **`accepts` in the control hello.** The box declares `acme` once it has a label and `web` once it serves a certificate and the owner's switch is on. It reconnects when its label or `accepts` change, or when its ticket starts carrying `lbl`. | An older runtime drops its control connection on an unknown class; the switch rides on the declaration. |
| OWA-06 | **Door streams** arrive as `incoming{session, class, src}`. `src` is used only for fair sharing in a `DirectGuard` of its own without lockouts; never for trust. Their budgets (64 `web`, 8 `acme`) are apart from the app's sessions. | The relay is inside the threat model. |
| OWA-07 | **The own-address server is HTTP/2 with HTTP/1.1 fallback**, its host only, `:authority`/`Host` equal to the host (port 443 implied), the box build with its strict CSP in a header, no HSTS header, no AASA, `assetlinks.json` from the contracts with a one-day cache. | The spike: HTTP/1.1 through the door is 78 % slower and trips the per-source limits; `.app` is HSTS-preloaded. |
| OWA-08 | **The certificate:** the manager orders it by TLS-ALPN-01 through the door, a new key per order, renewal at two thirds, retries forever; before each order it probes the whole path with its own probe certificate. The runtime records each serial and SPKI before serving. | The key stays on the box; a probe saves the CA's failure budget; no false alarm on renewal. |
| OWA-09 | **The certificate watch:** the manager asks Cert Spotter, keyless, every 6 h ± 30 min; the runtime calls a certificate for the host, a name under it or `*.<zone>` foreign when its SPKI isn't in its list. No fresh check for 12 h is a missed window, shown with its dates; 2 days is a notice. No catch-up source in phase 1. | Free sources only (John, 2026-11-18); silence is never a check. |
| OWA-10 | **Notices** that start on: a foreign certificate (screen, every session's banner, push), no fresh check for 2 days, the certificate ending in 7 days, no certificate after 24 h of trying. | Each is broken now or a security opening, and the person can act. |
| OWA-11 | **The A3 flag** (`shared_route_off`) is set once, at the runtime's first start, when the manager reports the own address enabled. Never set later. | A3 holds only for boxes that never had the shared route; the dev stack and `pnpm dev` keep today's claim. |
| OWA-12 | *In part amended by OWA-36: wrong tries never change the link; it changes after a claim and with new letters asked for at the box; and by OWA-39: control holds the link for the account that linked the box.* **Claiming an A3 box** happens on a page the box served: at the address with the claim link `/c/<6 letters>` shown on its screen, or on the LAN or Tailscale page with the letters. Through the relay and through control it is refused. The link changes after a claim and after 30 wrong tries in an hour. | Strangers who found the label in CT can't spend the claim backoff. |
| OWA-13 | **Linking:** the account at app.whombat.com shows a one-time code (10 minutes); the owner types it at the box, which asks “Link to <email>?” and signs `account.link`. The link carries the terms and the plan's limit. Then cloud ownership, tickets for phones, push and billing follow. The hosted list shows such a box by name only. | The account gets nothing on the box. |
| OWA-14 | **Box passkeys:** RP ID the box's host; origins the address and the Android release app; nonces the box's own; `user.id` random per account per box; ops `boxPasskey.*`. Kit keys armed with a random salt and checked with a second touch. | No page Cybex serves can use them. |
| OWA-15 | **Joining an A3 box:** a box passkey (any session), a device link, screen letters or the recovery key. Code-on-the-new-device pairing is off. Device links carry the address (`o=`). | A server can fake a page's origin. |
| OWA-16 | **Declared credentials:** the box sends control its full set of box-passkey ids (`kit.credentials.declare`); control keeps envelopes for declared credentials of linked boxes, deletes them when a credential drops out or the box is released, and keeps the kit drop rule on retirement. A skipped envelope is never marked stored; “ready” needs control's acknowledgement. | A full set heals itself; deleting at retirement would make a bring back impossible. |
| OWA-17 | **Phones:** the iPhone app never carries a `*.` `webcredentials` entry. Phase 1 first ships the browser plus device link; Android's in-app box passkeys after tests A1, A2, A5; the iPhone's sign-in sheet after I3. | An association file at `box.whombat.app` would be the gate. |
| OWA-18 | **The own address is off on the dev stack's own appliance and on `pnpm dev`** unless switched on. | Prod and DEV share Let's Encrypt's weekly limit for `whombat.app`. |
| OWA-19 | **The own address is not a direct way** in `appliance.status`; it is a member of its own (`ownAddress`). | Today's apps would fail to parse a new `DirectWay`. |
| OWA-20 | **Seams for phase 2,** present and inert: shutting the address to browsers while a foreign certificate is valid, refusing box-passkey joins then, and the signed certificate list for the kit files and control. | Phase 2 fills them without moving phase 1's code. |
| OWA-21 | **The runtime makes the TLS socket of a `web` door stream itself** and hands it to the HTTP/2 server as Node's own TLS server does (`secureConnection`), with the visitor's address as its peer. A name other than the box's own host fails the handshake. | A TLS socket the server makes over a stream that isn't TCP has no peer address, and the limits and the session need `src`. |
| OWA-22 | **The runtime reads the manager's state every 30 s while it waits for its first certificate (every 3 s in the first 10 minutes after a start or a move of Link, whombat-link.md LNK-87), and once the served one is past two thirds of its life** (when the manager renews it), else every 5 minutes. A register that couldn't reach control is tried again a minute later. | The manager probes and orders right after registering; a new box shouldn't wait 5 minutes for its page. |
| OWA-23 | **The A3 flag is decided at the first answer from the manager** while the box is unclaimed: a manager that can't be reached leaves it undecided, a claimed box gets false, and a box that ran before the release that brought it got false in its migration. | “At the first start” must not depend on the manager being up at that moment, and must never catch a box that already had the shared route. |
| OWA-24 | **Code pairing is off on the own address of every box**, not only inside A3 (`pairing_off`). | A page at the address could be anyone's for a while after a foreign certificate; the code proves nothing about the page that shows it. |
| OWA-25 | *In part amended by OWA-36: the wrong tries are kept per visitor address; and by OWA-39: control keeps a copy for the account that linked the box, which a restart replaces.* **The claim link and its wrong-try counter live in memory**: a restart shows a new link on the screen. | Nothing to keep secret on disk; the screen always shows the current one. |
| OWA-26 | *Superseded by remote-help.md RH-16: on the own address the step-up asks for box passkeys.* **Remote help's passkey step-up stays on the hosted RP** in phase 1: box passkeys aren't offered or counted there. | Its ceremony runs at the hosted app's name; box passkeys belong to another RP ID. |
| OWA-27 | **The foreign-certificate push has fixed words without the address**; the Inbox item and the screen name it. “No certificate after a day” counts from when the running runtime first saw the address without one. | Push words carry nothing from the box (push-words.md); a crash-looping runtime is named in the words instead. |
| OWA-28 | **Changing the owner's switch and linking the account are not signed appliance events yet**: contracts 4.3.0 has no event type for them. The next contracts minor adds them. | Contracts are frozen for phase 1's first wave. |
| OWA-29 | **A door stream's budget is taken before its data connection opens** and given back when the stream closes or never joins; `web` isn't taken while `webOpen` is shut. | Over budget the relay hears `refuse` at once, before any data connection. |
| OWA-30 | *In part amended by OWA-34: those sessions have places of their own, eight, and are counted when their hello is read.* **Through the door, a visitor address may hold 4 sessions of unknown devices at once** (the local network keeps 1, DC-06), counted apart from the local network's. | The door's `src` is a household's or a carrier's address, not a device's; one browser's setup mustn't lock out the next. |
| OWA-31 | **The phone passkey device test has a box side, DEV only and off by default:** the file `$WHOMBAT_HOME/own-address-device-test`, read at start, switches on a log of `/.well-known/*` requests (path, `src`, User-Agent), a test page at `/device-test/passkey` (a passkey for the box's host with PRF; it shows the first 8 hex digits of the PRF output's SHA-256, never the output) and, with the word `assetlinks-off`, a 404 for `assetlinks.json`. It is refused on a prod runtime, does nothing outside the DEV zone and stops a week after the file was written. | The device tests need to see who fetches the file and how long Google keeps it, and a page at the box's own origin; a file works on Home and on the dev stack alike, and can't stay on by accident. |
| OWA-32 | **The box's own page offers *Use its screen*** next to its passkey, pairing and the recovery kit (OWA-15's screen letters). The box answers `enroll.screen.request` with its device id too, which the exchange binds; the own page uses that answer, the app keeps its directory's. | A box moved to a new address has none of the person's passkeys there, and pairing is off: without the letters its owner is locked out. The answer comes from the same box whose key the page pinned. |
| OWA-33 | **A device link scanned by a device that is in already lets it in as it was** (2026-11-20): `enroll.link.accept` from a key the box has, not revoked, in the account that made the link, answers that device's enrollment and uses up the link; no second device, no event. A key of another account is still refused (`endpoint_enrolled`). | Found on Home after its move: the iPhone's key was kept from before, so its scan said “This device is already in.” and the app had no way on. |
| OWA-34 | *In part amended by OWA-36 (a wrong link in a hello is a try of the visitor's address and never changes the link) and OWA-37 (the screen names a second way in for when the address is kept busy).* **Sessions of unknown devices at the own address have places of their own, and the claim link keeps some** (2026-11-21; a second independent review of the claim; whombat-link.md LNK-71). They shared the four places of the local network and Tailscale, so one visitor who found the address could keep everyone from setting the box up on any direct way. Now: eight places for the own address alone (`MAX_UNENROLLED_DOOR_SESSIONS`), at most four of one visitor address (OWA-30's number, so no single address holds them all), counted when the session's hello is read (`SessionRegistry.attach`). And four more (`MAX_UNENROLLED_CLAIM_LINK_SESSIONS`) only for a session whose hello shows the claim link of a box nobody claimed: the page at `/c/<secret>` puts the secret in `hello.claimLink` (session minor 2; inside the encrypted session, so the relay never sees it). A wrong one counts as a wrong try at the link, as at the claim's start. Showing it opens nothing: the start asks for the link again (LNK-62). *What stays:* the address takes 64 connections at once, 32 of one visitor address; many addresses together can fill those and keep the public page out for a while. They never touch the local network or Tailscale. | A stranger on the internet must hold no place the person needs, at home or at the address. |
| OWA-35 | **The box names its own address only while browsers are let in there** (2026-11-21; the same review). The screen and the links the box makes took a valid certificate as “the address works”, so an owner who switched *Reach my Whombat’s page from anywhere* off still saw that address on the screen, where nothing answered, though Tailscale did. `OwnAddressService.serving()` is the test now: a certificate and the box taking `web` there (`accepts`). Without it the screen, the claim link, device links and the HTTPS addresses a plain-HTTP visitor is told fall back to the Tailscale name, then the local network; the switch redraws the screen at once. | A screen must only send its reader where something answers. |
| OWA-36 | **Only the box changes its claim link; wrong tries are a visitor address's own** (2026-11-21; the final check of the claim; whombat-link.md LNK-75, LNK-76). OWA-12 changed the link after 30 wrong tries in an hour, counted for everyone together: anyone who found the label could retire the link shown at home, and nothing drew the screen again. `ClaimLink.check` now takes the visitor's address and never changes the link: ten different wrong links per address in an hour, then no link is read from that address until one is an hour old; the same wrong link again and a missing link are no tries. Up to 1024 addresses are remembered (`CLAIM_LINK_PEERS`); past that the one remembered longest is forgotten, which can only give a stranger tries back. `rotate` is called after a claim and for new letters asked for at the box, and both draw the screen. The address is what the relay's door says; the relay is inside the threat model, and could always keep the page from opening. | A link on a screen is a promise that it opens. |
| OWA-37 | **The claim screen names a way in that the internet can't block** (2026-11-21; the same check; whombat-link.md LNK-77). OWA-34 left this open: the address takes 64 connections at once, counted before the claim link can be shown, so many visitors together can keep the page out. That limit stays, and is accepted for the public way only: beside the claim link the console file carries `fallbackUrl` (`ConsoleState`, only in `claimable`), the Tailscale page when the box has one, else its IPv4 address on the local network for the Whombat app. The screen is drawn again when that address changes. | The public way may be busy; the person at home must not depend on it. |
| OWA-38 | **A refused certificate says why and when the box tries again** (2026-11-22; the launch review). While Let's Encrypt refused a certificate for its rate limit, About said “Can't get its certificate. Check that this Whombat is online.”, though the manager knew the reason and the next try. `OwnAddressSummary` carries an optional `failure` (the manager's `acme.error` and `nextAttemptAt`, only while it is failing); for `rate_limited` the apps say many new Whombats are getting addresses and when it tries again by itself, in a calm tone, and for other reasons the old line with the time. Older boxes leave it out and older apps ignore it. | A wait that isn't the person's fault shouldn't send them to check their cables. |
| OWA-39 | **Control holds the claim link for the account that linked the box** (2026-11-22; John: after linking, the person types only the four letters; whombat-link.md LNK-79). The claim link was only on the box's screen, so Claim it now on the account site opened the box's root, which asked for the six letters after `/c/` first. Now, while nobody claimed the box and its own address serves its page, the runtime hands the link's letters to the manager (`own-address/claim-handover.ts`, `POST /v1/link/claim`), again when they change, and takes them back once claimed. The manager sends them with `link.status` (`claimLink`, contracts 4.13); control keeps the latest per box, forgets it when the box reports none, is claimed (`account.link`), leaves Link or starts it again, and answers `https://<host>/c/<letters>` as `LinkedBox.claimUrl` only to the account the box is linked to, while Link runs and the address exists. Never logged, never in an audit record or an operator's view. The relay never sees it: it goes box → control over the manager's signed device ops and control → account site over HTTPS. The page at the address still reads the account's name and email from the fragment. | The link keeps strangers who found the label in Certificate Transparency from starting a claim or spending its wait. Control isn't one: it shows the link only to the account that proved it saw the screen by typing the Link code. |
| OWA-40 | **A name's shape** (2026-11-23; contracts 4.16, CT-1792): 3 to 32 lower-case letters, digits and single hyphens, starting with a letter and ending with a letter or digit (`^[a-z](-?[a-z0-9])+$` plus the length; no `xn--`). Every three-word label ever drawn has it. TypeScript, Go and JSON Schema share the pattern; the cross-language subset admits plain groups only, so it is written without `(?:`. `isOwnAddressLabel` keeps meaning a drawn three-word label. | One pattern every parser reads alike; nothing a browser would show as another script. |
| OWA-41 | **Names nobody gets, and one registry** (2026-11-23). Control refuses (`ownAddressNameProblem` in `@whombat/core/own-address`) the service's own hosts and words (`box`, `dev`, `www`, `api`, `admin`, `support`, `dusty`, `hazel`, …), names starting with `whombat` or `cybex`, and a short plain list of rude words (English and Dutch: a name that is one, has one as a hyphen-part, or is one with hyphens in it; never a part of a word). A name once given to a box is never given to another, whatever happens later; a box may go back to a name it had. Wherever a person types a name: “Anyone can see this name, so leave out anything private.” | Certificate Transparency shows every name forever, so a reused name would hand one person's passkeys' host to another. |
| OWA-42 | **The zone is `whombat.app`; `box.whombat.app` is the old one** (2026-11-23, John). `OWN_ADDRESS_ZONES.prod` is `whombat.app`; `OWN_ADDRESS_OLD_ZONES` lists `box.whombat.app`, still parsed and served while boxes move. Hosts match `^[a-z](-?[a-z0-9])+[.]((box|dev)[.])?whombat[.]app$` (64 at most); `ownAddressZoneOf` gives the longest known zone. A box moves only when control says its zone is another (OWA-44); a box that hasn't updated stays at its old host, which keeps working. | Shorter addresses; nothing breaks for boxes that move later. |
| OWA-43 | **Choosing at setup** (2026-11-23). The account site's confirm step offers “Choose your own” beside the random name, with a live check (`link.name.check`, 120 an hour per account: free, taken, reserved, invalid). `link.confirm` takes `label`, checks it again in its transaction (`label_invalid`, `label_reserved`, `label_taken`, 409: nothing is linked) and keeps it for the box's grant; a name a race took by then falls back to a random one, which the person can change later. The code typed at the box (`account.link`) gives a random name. | The person names the box where they confirm it; a lost race never blocks the setup. |
| OWA-44 | **Rename and move are one mechanism with a leaving address** (2026-11-23). The box asks control (`address.check`, 60 an hour; `address.rename`): another label is a rename (owner only, Link on or in grace, at most 3 in 365 days, `rename_limit`); its own label while its zone isn't control's zone is a move to that zone (never counted). The earlier address keeps working for 30 days (`OWN_ADDRESS_LEAVING_DAYS`), then stops; at most one leaves at a time, so a rename while one is leaving keeps that one and its date and stops the one in between at once. Tickets carry `plbl` for a leaving label that differs from `lbl`; the relay maps both to the box. Only an updated box moves itself. In the session: `ownAddress.check` (read) and `ownAddress.rename` (the assistant asks first), session minor 6. | One path for the person's change and the zone's move; nobody's page or passkeys stop without a month's overlap. |
| OWA-45 | **The box during the 30 days** (2026-11-23). It serves both hosts (one certificate each, no new orders for the leaving one: it is served until its date or its certificate's end), watches both in Certificate Transparency, makes new passkeys only at the current host (`address_moved` at the leaving one, whose page offers the way to the new address), and signs in with passkeys at either until the leaving host stops; then passkeys only it served are dropped. Screens, links and claim links name the current host only. `OwnAddressSummary.leaving` says until when the old one works. | The person can move every device at their own pace, and nothing points at an address that is about to stop. |
| OWA-46 | **Older apps** (2026-11-23). A box names an own-address host outside the three-word `box.`/`dev.` shape only to a session at minor 6 or later (`OWN_ADDRESS_NAMES_MINOR`); to an older one it leaves the address out (`ownAddress` null), so an older phone keeps working without the address instead of failing the whole answer. | Older apps parse hosts strictly; a missing address is a state they already handle. |
| OWA-47 | **Cloudflare's two certificates for `*.whombat.app`** (2026-11-23, John). Cloudflare's Universal SSL issued two on 2026-11-18 (Google Trust Services and Let's Encrypt, until 2027-02-16; Cloudflare holds the keys). They cover every `<name>.whombat.app`. `OWN_ADDRESS_ZONE_CERTIFICATES` names them by SPKI: the box doesn't call them foreign within their dates, and says under the address that Cloudflare, which runs whombat.app's DNS, also holds a certificate for it until 16 February 2027. Any other certificate for the zone is foreign as before. | An alarm on every box for a known, accepted fact would teach people to ignore the real one. |
| OWA-48 | **A box passkey's RP is the host the session arrived at** (2026-11-23; the runtime of own names). On the own address that is the TLS name of the connection (the transport carries it as `host`); in the apps, on the local network and through the relay it is the current host. `boxPasskey.register.begin` at the leaving host answers `address_moved` (`conflict`, `details.host` the current host); joins and step-ups work at either host with that host's passkeys while it is served, and a host the box stopped answering at signs nobody in. The Android app keeps using the current host only. | The page at the old host can run a ceremony only for its own name; one rule (where you are) covers the page, the step-up and the apps. |
| OWA-49 | **The passkeys of a host the box left are removed when the running box sees it stop** (2026-11-23). Between two definite answers of the manager, a host that was served and no longer is (the leaving one's date, or the name in between replaced by a rename) has its box passkeys removed as an owner's removal would (a signed `passkey.removed` with `byAccountId: null`, their backup keys going with them), outside the person's request, and the smaller set is declared. Nothing is removed at a start, while the manager can't be read or while the address is off (Link off). A box that was off across the date keeps those passkeys listed until someone removes them; they open nothing. | A wrong or missing answer must never take away a person's passkeys and the backup keys they hold; a leftover row costs nothing. |
| OWA-50 | **`ownAddress.check` answers what every box knows itself** (2026-11-23). `ownAddressNameProblem` (core) gives `invalid` and `reserved` without asking control, so a person typing doesn't spend the 60 checks an hour; control is asked only for the rest. Its `host` (when `free` or `yours`) is the name under the current host's zone. A rename answers the manager's new state at once (`accept`: served hosts, relay, screen) and the box reads quickly for the new certificate. Like the reach switch (OWA-28) a rename is logged, not yet a signed appliance event. | Control's zone is the current host's for every box that moved; a box that hasn't moved yet moves before a person renames it. |
| OWA-51 | **A foreign certificate counts while it covers a host the box answers at** (2026-11-23). The judgement runs over the current and the leaving host (`foreignCertificates({hosts})`); one found for a host the box left drops out of the screen's alert, the summary and the notice. While the hosts aren't known (the manager unread) every one still counts. Cloudflare's two (`OWN_ADDRESS_ZONE_CERTIFICATES`) are left out when found and when read, within their dates. No host column: the names kept with each certificate say which host it covers. | An alarm must not go quiet for lack of an answer, nor stay for an address nobody uses any more. |
| OWA-52 | **Two calm notices of a changed address, in the Inbox only** (2026-11-23). `own_address.moved` (a heads-up, `info`) while the old address works: “Your Whombat’s address is now home.whombat.app. The old one works until 23 December.” `own_address.leaving` (`warn`) from 3 days before the old one stops, while some device has box passkeys only for it (the device that made a passkey; a passkey whose maker is unknown counts alone). Both start on; no push. | The person did it or needs to know; the second one is the last chance to keep a way in, and only where it matters. |
| OWA-53 | **What an older app reads** (2026-11-23; OWA-46 in the runtime). Below session minor 6, `appliance.status`, `ownAddress.status` and `reach.get` answer `ownAddress: null` when the current host isn't three drawn words under `box.`/`dev.`, `link.whombats` leaves such boxes out, `leaving` is never sent, and `ownAddress.reach.set` answers `own_address_unavailable`. The assistant and the box's own callers read everything. | An older app parses hosts strictly and fails the whole answer otherwise; it never had a way to show these. |
| OWA-54 | **More names nobody gets, and a list of our own** (2026-11-23). Besides OWA-41's, core refuses names that pass for a sign-in or payment page (`secure`, `verify`, `wallet`, `portal`, …), the names devices and mail programs look up by themselves under a domain (`autodiscover`, `autoconfig`, `wpad`, `mta-sts`, …), names starting with a distinctive company's name (`paypal…`, `google…`, `digid…`) and names that are a known company's name or have one as a hyphen-part (`apple-support`, `my-ing`), except a drawn label. Control also keeps operator-reserved names in its database (whombat-ops `ops reserve <name>`), which refuse like the built-in ones without a release. Reserving never takes a name from a box that has it. | `<name>.whombat.app` gets a real certificate under our domain, so a look-alike would make a convincing phishing page; and our own list must grow without a release. |
