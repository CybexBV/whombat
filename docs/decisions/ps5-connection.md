# PlayStation 5 connection

John, 2026-11-08: research his jailbroken PS5, including remote WebKit Autoloader updates, then “Build it.” Later that
day: research what could be better, then “Implement fully” (PS5-07…PS5-12), then expand remote updates and add remote
reboot (PS5-13…PS5-16). Then: see updates easily and click Update instead of asking (PS5-17…PS5-20).

| # | Decision | Reason |
|---|---|---|
| PS5-01 | A catalog Connection uses Payload Manager (tested with 0.6.3) and optional ShadowMountPlus (tested with 1.7beta11), without a bridge. Remote reboot adds the optional helper in PS5-13. The services stay on the same hostname with their own ports. Every request uses the connection's destination policy, bounded response and deadline. | These services provide the useful reads and homebrew actions. Each port still needs the home-network allowance. |
| PS5-02 | Typed reads cover installed payloads, startup, processes, logs, the Official Repository, games and storage. ShadowMountPlus's three fixed POST reads are reads; no arbitrary HTTP tool is offered. The dashboard uses the shared service slots. | HTTP method alone doesn't describe an API's effect. |
| PS5-03 | Downloading, running a payload, updating WebKit Autoloader and changing startup always ask first. Repository downloads name an exact approved version and SHA-256, recheck repository metadata before requesting the download, then verify installed metadata. The WebKit action rechecks that metadata before launch. No automatic retries or claim of completed caching. | Payload Manager installs by id, rather than an immutable artifact URL. A changed download is refused for launch; this verifies the manager's metadata, not an independent binary hash. The service is trusted on the home network. |
| PS5-04 | Startup writes patch only its three fields, compare the previously read startup settings, refuse absent slots and installers, and read back the result. | Preserve other preferences and avoid replaying an installer at each start. |
| PS5-05 | A downloaded installer's version is distinct from the installed offline cache, which these APIs don't report. After the loader accepts the installer, the person checks completion, separately requests a reboot or reboots by hand, and opens the autoloader. Sony firmware, waking, shutdown, arbitrary URLs, shell, deleting games and Remote Play are outside this connection. | A successful launch is not completion. Updating homebrew must not update Sony firmware or remove the jailbreak. Firmware compatibility must be checked from the release notes before proposing an update. |
| PS5-06 | (Power state in part superseded by PS5-08.) Management readiness is distinct from console power. Missing homebrew is a calm page with instructions; the optional `ps5.available` heads-up starts off and replaces the generic availability alarm for this kind. No disk or version alarms are added. | Rest mode and a reboot normally remove the management services. HTTP failure cannot identify the console's power state. |
| PS5-07 | A payload uploaded by hand (a `local/` slot) takes its version from its file name (`kstuff-lite_v1.10.elf`), shown as “From its file name”, and is matched to the Official Repository by its slot key or file name, as Payload Manager's own ids are the lowercased names. `ps5_payload_updates` compares every installed payload, with the release's firmware range and, for a newer release, its notes cut to 1,500 characters. | John's three startup payloads were uploaded by hand and reported no version, so kstuff-lite 1.11 went unseen. The notes are where firmware support is stated. |
| PS5-08 | Whombat asks the console itself with one Sony discovery search (`SRCH`, UDP 9302) under the connection's destination rule (`outboundDatagram`): awake or resting, its name and firmware, without pairing. The page and the card say “Resting”, “Homebrew isn’t running” or “Not answering”; no answer never claims the console is off. Waking it stays out. | It answers without credentials while awake or resting; silence can be off, rest without networking or a blocked port. Waking needs a PlayStation account pairing, and homebrew doesn't survive rest anyway. |
| PS5-09 | `ps5_update_payload` rechecks the approved release, downloads it by id and verifies what was stored. A repository slot is replaced in place; a payload uploaded by hand gets a repository slot, startup moves to it only if startup is unchanged since it was read, and the old copy stays to go back to (not Payload Manager's `replace_slot`, which deletes it). WebKit Autoloader and Payload Manager keep their own tools. The WebKit update refuses a release whose firmware range leaves out the console's firmware. | A bad kstuff-lite breaks the jailbreak at the next start; keeping the old copy makes going back one startup change. The installer gates firmware itself too, but refusing before the download is clearer. |
| PS5-10 | How the last startup went is read from Payload Manager's log (launched, transfer failed, missing, skipped, finished or stopped); `/autoload_status` is cleared by its own page once startup ends. A run is confirmed when the launch history starts with it. `ps5.startup` (a problem) and `ps5.updates` (a heads-up) both start off. | Startup failures can also be the person's cancel on the PS5, and updates start off by rule. |
| PS5-11 | After Whombat runs the WebKit installer, the connection keeps its version and time (`webkitVersion`, `webkitUpdatedAt`); “started again since” shows once the installer is no longer in the launch history, which starts empty with Payload Manager. | The installed version lives only in the PS5 browser's cache and its installer listens on 127.0.0.1 only. |
| PS5-12 | The library is a shelf of square covers from ShadowMountPlus's icon route (thumb size, through the page pictures, fetched on ShadowMountPlus's port); a full table only above 48 titles. More tools: one game's sizes, ShadowMountPlus's debug or kernel log, a rescan, ejecting a USB drive by its current source and mount id, and stopping a homebrew payload by pid and name (never the loader, kstuff or Payload Manager). Every write asks first. | These come with the services already running; a stale mount id or pid is refused rather than guessed. |
| PS5-13 | `ps5_enable_remote_reboot` downloads SystemStateManager 1.0.0 from a pinned commit, checks its SHA-256, exact size and ELF header before uploading a new local slot through Payload Manager, launches that slot and checks STATUS on TCP 9112. It changes no startup settings. `ps5_power_status` and the Summary show readiness calmly. | This small helper provides console reboot without a PC engine or pairing. Payload Manager's `/shutdown` stops only itself; ShadowMountPlus has no console power API. The helper disappears after reboot and can be started from its stored slot again or separately added to startup. |
| PS5-14 | Before downloading, updates recheck the approved Official Repository release and look for one stored copy with its exact source, id, version and checksum. Reuse that copy when it matches and check it again before launch. A mismatch still requires downloading and verification; a failed or ambiguous download never falls through to launch or retries itself. | Console GitHub downloads can time out despite already holding the approved installer. Reuse trusts Payload Manager's metadata; it does not independently hash a stored ELF. The helper's incoming bytes are independently hashed. |
| PS5-15 | `ps5_reboot` always asks, checks the helper's build and current pid, refuses a known active ShadowMountPlus storage job, and sends REBOOT once under the destination policy. TCP uses pinned DNS, a 3-second total deadline and a 512-byte reply cap. A lost reply after writing is uncertain; OK means accepted, never a completed reboot. No automatic reboot after an installer or retry after uncertainty. | The helper acknowledges before calling the reboot API. Caching must finish on the PS5 first; games and homebrew stop, and the person must reopen WebKit Autoloader. Shutdown remains upstream “in test”, so is not offered. |
| PS5-16 | On a tool listing, bundled definitions are compared with stored tool hashes and refreshed immediately when they differ, keeping the person’s tiers. Remote MCP discovery retains its hourly refresh. | An existing Connection must receive the added reboot tools after an upgrade without waiting an hour or being removed and added again. |
| PS5-17 | **Homebrew is updated from the PS5's page** (narrows service-dashboards.md SD-02 for this kind, as SD-31 did for ESPHome): while updates wait, Live is “To update” (id `updates`), a line per update with **Update**, and **Update all** on the card for two or more; Running homebrew moves below. Worth a look's update line carries the same button (or Update all). Each button confirms first, says what happens and when it takes effect, and is drawn disabled with the reason for a release outside the console's firmware, one without a checksum, or Look only. | Updating homebrew was a chat request for something the page already knew. A homebrew payload is not the service or Sony firmware: the old copy stays to go back to (PS5-09). |
| PS5-18 | **A press runs what the page showed**: Update sends the slot and the version shown, Update all a key of the slots and versions it listed. The server reads the PS5 and the Official Repository again and refuses (before any write) a changed version, a changed list, an update that is gone or no longer fits. It then runs the assistant's own steps (`ps5UpdatePayload`, `ps5UpdateWebkit`, `ps5UpdateManager`), so checks, reuse and startup moves are identical. Errors are said in plain words, without tool names. | The person approves exactly the version on screen; one code path keeps the button and the assistant alike. |
| PS5-19 | **Update all leaves out WebKit Autoloader**: its update runs the installer on the PS5 and needs a restart, so it keeps its own Update. Update all runs one after another and stops at the first failure, saying what was updated. Payload Manager's own update is one more line (`ps5ManagerUpdate`, slot `pldmgr`) unless the version it waits to restart into is already the newest; it only downloads. No reboot follows any of them. | A reboot stays its own explicit step (PS5-15). |
| PS5-20 | **The assistant's card uses the same words**: `things.action` with `update` or `update-all` shows “Update homebrew on your PS5” and each name with its old and new version (`describe`). `ps5_payload_updates` also lists Payload Manager. The `ps5.updates` heads-up still starts off. | Updates start off by rule (`watch-defaults.md`); the page shows them anyway. |

The initial live checks used reads on John's PS5 (the dashboard, discovery and ShadowMountPlus's read POSTs).
The remote reboot expansion uploaded and launched the hash-verified helper, confirmed its STATUS response and read
back unchanged startup settings. No reboot, shutdown, rest or eject command was sent. Reboot effects and uncertain
replies are tested against fakes. The APIs have no authentication; keep them on the
trusted home network. `X-PLDMGR-Request: 1` marks an intentional action for Payload Manager's CSRF protection and is
not a credential.
