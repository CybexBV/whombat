# Full Proxmox support — Whombat's server (stream SV, 2026-10-17)

Stream SV of `docs/implementation/proxmox/assignment.md` under `docs/decisions/proxmox.md` (PX-01…PX-11), contracts
0.81.0 (CT-353…CT-356) and the hosts service `f7c3052` (HS-23…HS-32). Code: `apps/server/src/hosts/`; how that directory
works is `one-whombat-servers.md` (ONE-DH01…ONE-DH23).

| # | Decision | Why |
|---|---|---|
| PX-S01 | **A manage request carries only what its route passes** (`manageCall`): a `params` name the op's route doesn't take — body, query or path part (`pathParams`: `disk`, `pos`, `task`, `job`, `storage` of a download, `jobId`) — is refused as `validation_failed` “This change doesn’t take “online”.” with `fields: {"params.online": …}`, nothing is sent. `backup.restore` takes the request's `guestId` as the guest to restore over (`guestField`); the web's `params.guest` still works, two different guests are refused. Its change reads “Restored web on pve-02 from a backup”. | PX-08: dropping `online` or a restore's guest silently gave a different result than asked. |
| PX-S02 | **The Servers tools refuse an argument they don't take**, naming it and what they take (`SERVERS_TOOL_ARGS`, checked before every tool; a unit test keeps it equal to the contract's schemas). `guest_migrate` takes `storage` (the service decides how a running guest moves; a running container's answer says it restarts on the way); `server_diagnose` passes `args` as strings (numbers and booleans converted, at most 16, refused without a `check`); `server_metrics` maps the old `net_mbps` to `net_rx_mbps` and `net_tx_mbps` and refuses names that aren't series. | PX-08, same reason as PX-S01; the schemas are the contract, so an argument outside them is a mistake to say, not to ignore. |
| PX-S03 | **Long work reports back** (`follow.ts`, PX-05): a tool call whose answer has a task (create, clone, template, delete, disk resize and move, backup, restore, a backup's delete, a job's run, downloads, migrate, a configuration change Proxmox still works on) is remembered — task, server, burrow, conversation, Whombat, person and the words — for 24 hours, at most 500. On `task.finished` that Whombat posts one message with `send_message` in the call's conversation (after an approval: where the approval was), top level: “The backup of win11-lab on shale is done.”, “… finished with 2 warnings.”, “Cloning win11-lab on shale as win11-copy didn’t work: the storage is full.” A finish that came before the call remembered it is kept two minutes (at most 200) so it is still told. Actions (power, snapshots, server power) aren't followed: they end in seconds and the after-a-yes words already say “now”. The agent's answer says `next: "This chat gets a short message when it ends; no need to check on it."`. Not retried, and a restart forgets them (the task itself goes on). | PX-05; a call has no thread, so the conversation is where it can be said; the agent shouldn't poll a task the server reports anyway. |
| PX-S04 | **Every call in words** (`words.ts`, ONE-DH21): each tool and action has its ask (“Delete win11-lab on shale?”, “Restore web on pve-02 from yesterday’s backup?”, “Create a container called dns on pve-02?”, “Reboot pve-02?”), what it is doing after a yes (“Deleting win11-lab on shale now.”) or what it did (“Protected yesterday’s backup of web on pve-02.”), and its task's words. A backup is named by its day (UTC, from the volume's name: today’s, yesterday’s, “the 3 October backup”); a schedule in words (“every day at 04:00”, “on Saturdays at 02:00”); an approval says “a backup job” (it only has the call's arguments), the change and the follow-up name the job by its comment. Guest names stay as written (never capitalised). A failed task's reason is a known Proxmox failure in plain words (stopped, storage full, already there, locked, too long, not allowed, unreachable), else the platform's first line without its id. | CLAUDE.md: plain English, no ids or logs in the chat. |
| PX-S05 | **Hints link to where they are fixed** (`sources.ts`, PX-07): a Proxmox hint that names one guest links to it — `/things/server%3A<id>?guest=<gid>` with `gtab=backups` (no job, backup old) or `snapshots` (old snapshot) — one that lists several to the server's Guests tab, storage overcommit to its Storage tab, other hints to the tab their section names; the body ends with the way out (“web. Add it to a backup job.”). Watch's own “Look into it” stays. The guest's id comes from a cached (30 s) guests read of that server, only when a hint names one guest. | The hub folds guest hints per host and names guests in `detail`; one read keeps Watch cheap. |
| PX-S06 | **Tool files and roles**: `tools.ts` (the reads and changes of 0.80, the argument table, the adapter), `tools-guests.ts`, `tools-backups.ts`, `tools-host.ts` (0.81's), `tools-shared.ts` (scope, names, answers, records, follow-up). Roles as each route needs (ONE-DH03): reads `operator` (`viewer` for the guests list); changes `operator`; create, clone, template, delete, restore, deleting a backup, downloads and deleting content, HA, backup jobs (but running one) and server power `admin`. | The brief's “split past ~1000 lines”; the service checks the role as a second line. |
| PX-S07 | **`guest_create` fills what Proxmox's Create wizard would**: a VM `ostype l26`, `scsihw virtio-scsi-single`, `scsi0 <first images storage>:32,iothread=1`, `ide2 <iso or none>,media=cdrom`, `boot order=scsi0;ide2;net0`, 1 socket, 1 core, `cpu x86-64-v2-AES`, 2048 MB, `net0 virtio,bridge=<first bridge>,firewall=1`, `agent 1`, and `machine q35` with an EFI disk only when `settings.bios` is `ovmf`; a container `rootfs <first rootdir storage>:8`, 1 core, 512 MB, 512 swap, `net0 name=eth0,bridge=<first bridge>,firewall=1,ip=dhcp`, `unprivileged 1` (always, whatever `settings` say), `features nesting=1`, the password and SSH keys. `settings` go over these; the service's allowlist decides the rest. Incus: `limits.cpu`, `limits.memory` and the image as `template`. A VM refuses `password`/`ssh_keys`, a Proxmox VM `template`. The password reaches the service only (not the change, not the chat). | PX-02 and the brief; the web's create dialog sends the same shape. |
| PX-S08 | **Clone, template, delete**: a clone is linked from a template and a full copy otherwise unless `full` says; linking a guest is refused in words; a template the guests list doesn't show is found through the server's choices. A delete sends `confirm_name` = the guest's own name (its id without one) and `purge` (default true); template, delete and restore over a guest send `confirm: true` — the approval already happened (sensitive rules). | PX-02; the service still wants what a person types. |
| PX-S09 | **Backups**: `guest_backups` without a guest reads every Proxmox guest's backups (the service lists them per guest), 40 guests, four at a time, newest first, at most 100. A restore goes over the guest the backup is of unless `as_new` (then `unique`, new MAC addresses, and an optional id); backing up uses the first storage that holds backups unless one is given; deleting a backup is followed when it runs as a task. | The routes are per guest; a copy shouldn't clash with its original on the network. |
| PX-S10 | **Backup jobs through the tools**: every change but create reads the job first and sends its digest (a change meanwhile: “Changed meanwhile — review again.”); pause and resume set `enabled`; add and remove a guest edit `guests` (a guests job) or `exclude` (an all job) and are refused for a pool job (“add or remove the guest in that pool in Proxmox”); create selects `guests` with the given guest, else `all`, on the first backup storage; run is followed. `backupjob.list` and the tools map the service's job leniently (`toHostBackupJob`); `backupjob.create`'s `id` becomes `newId`. `hosts.backup_jobs` is advertised (`runtime-features.ts`). | PX-03 and the lead's wire notes; the digest is the service's guard against overwriting. |
| PX-S11 | **Undo of a tool's change by its inverse call** (`hosts.tool_inverse` `{tool, args, serverId, expect?}`, run by the same Whombat as a new `connection_call`, ONE-DH13): backup protect ↔ unprotect; a backup's notes → the previous ones, only while the notes are still Whombat's; firewall on ↔ off; a rule's on ↔ off (only when the update changed just that); a job's pause ↔ resume; a guest added ↔ taken out of a job; HA set → removed when it wasn't there. Pausing a guest is undone by resuming it (`guest_power` now pauses and resumes). None for create, clone, delete, restore, downloads, runs, moves, deleting an unused disk. | The brief's list; refusing when changed meanwhile keeps Undo from overwriting a later edit (ONE-DH12). |
| PX-S12 | **A server-wide refusal says the service's own sentence**: `unsupported` and `not_allowed` without a guest (a job that runs on another node only, a job without storage, backup jobs on a server that isn't Proxmox) use the agent's sentence, capitalised; with a guest the words stay as before. | “That isn’t possible on this kind of guest.” was wrong for a job. |
| PX-S13 | **The fake service plays Proxmox** (`testing/fake-manage.ts`, `fake-http.ts`): every manage route and read with state per server (guests created, cloned, made templates, moved, deleted; backups, content, appliances; tasks whose log grows with each look and that end with `task.finished`; firewall with digests, HA, replication, snapshots; backup jobs whose cover sets the guests' `backup_job` and the “in no backup job” hint; the host's power). Like the hub it refuses unknown body fields, checks roles, the manage switch, confirmations and digests. Tests steer tasks with `taskOutcome`, `holdTasks`, `finishTask`, `taskMs`. | Tests and fixture worlds without Go (ONE-DH20). |

## Notes for the merge

  says `null` clears `pool`; the tools never send it, the web might. One of them should move.
- `runtime-features.ts` (outside `hosts/`) moves `hosts.backup_jobs` to `IMPLEMENTED_FEATURES`, as the lead asked.
