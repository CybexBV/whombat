# Workstream: Macs as servers (MAC)

John, 2026-11-17: “create a connector for [my Mac Studio] so I can manage my macOS server fully via Whombat … full
access (root if needed) and it should be able to accept dialogs on screen.” After research and a council (GPT 6 Astra,
Claude Fable 5.2, Muse Wonder Full 1.0, one round) he chose: customers too, the Mac's password in Whombat's keeping for
the screen, never ask (full access), keychains not off limits, FileVault off and auto-login on for his Mac, the helper
signed with the team's Apple developer account. The wire shapes are in `docs/implementation/macos/assignment.md`.

| ID | Decision | Reason |
|---|---|---|
| MAC-01 | **A Mac is a server like any other, through the same agent.** `whombat-agent` has a macOS build (`darwin/arm64`, `darwin/amd64`, cgo-free) that runs as a root LaunchDaemon (`com.whombat.agent`), dials out to the hosts service, enrolls, reports every 10 s, buffers through outages and updates itself like the Linux agent. Its server's platform is `macos` (`detail_view` `macos`). SSH only installs it (Sign in once, or the one-line command) and stays a fallback. | The council's three members chose the agent over SSH polling: pages, charts, alerts, switches on the server, backfill after a restart and signed updates all exist for agents, while a background SSH collector would be a second, weaker system holding a root key all day. |
| MAC-02 | **What a Mac reports**: CPU, memory, swap, load, volumes, disk and network rates and temperatures (gopsutil, cgo-free on macOS), plus the Mac's own facts in `macos`: macOS version and build, model and chip, SIP, FileVault, auto-login, who is at the screen, Screen Sharing, the screen account and the helper. Updates come from macOS's own background check (the Software Update preferences, never a network call of the agent's own); services are launchd's jobs; a disk's health is `diskutil`'s SMART verdict. | The Linux collectors read `/proc`, `/sys` and systemd; macOS answers the same questions through its own tools. Reading Software Update's own cache keeps the agent from contacting Apple every few hours, as the Linux agent never refreshes package lists. |
| MAC-03 | **Commands and consoles on a Mac**: a command runs `/bin/sh -c` as root in its own process group; the host shell is a root `zsh -l` on a PTY; the logs console is the unified log (`log stream`, `log show`); power is `shutdown -r now` / `-h now`; inspect lists processes, listening ports, launchd jobs and pending updates. OS updates install with `softwareupdate`, which on Apple silicon needs the screen account's password for updates that restart (it is passed on stdin). | The same switches and pages as a Linux server, with macOS's tools behind them. |
| MAC-04 | **The screen goes through the Mac's own Screen Sharing.** The agent signs in to `127.0.0.1:5900` with Apple's sign-in (RFB security type 30: Diffie-Hellman, MD5 of the shared secret as an AES-128 key over the user name and password) and hands the session to the browser as a host `vnc` console, exactly as it does for VMs (security None between browser and agent). Nothing new listens on the network. | Screen Sharing already has the Screen Recording and input permissions on a Mac where it is on; a third-party capture app would need a person at the Mac and monthly “still allow?” prompts. Tested on John's Mac (macOS 27.2.1): type 30 signs in, the frame is the real screen, and keys typed through it unlock the lock screen. |
| MAC-05 | **The screen account is kept on the Mac only**, root-only (`/etc/whombat-agent/screen.toml`, 0600): Sign in once stores the password it signed in with when that user is the one at the screen; otherwise the person types it once on the Mac's page. Whombat's database never keeps it, and the assistant never sees it: unlocking the lock screen is the agent's own `unlock` step, which types it. | The password is the Mac's own; root on the Mac can already do anything, so keeping it there adds nothing, while a copy in Whombat would be one more place to lose it. |
| MAC-06 | **The assistant has hands on the Mac**: look (a screenshot from Screen Sharing), click, double-click, right-click, drag, scroll, type, keys and unlock by position, and by name through the helper: list the buttons and fields of an app or window, press one, set or type into one, pick a menu item, bring an app forward, open the Accessibility settings. Name first; when nothing matches, the assistant looks and clicks by position. Every screen step needs the host-shell switch on both sides (the person's session is root-equivalent there). | John wanted dialogs accepted and buttons found by name (step 4), not pixel guessing. |
| MAC-07 | **The helper is Whombat Helper**, a small Swift app (`com.whombat.helper`, no Dock icon) in `/Library/Application Support/Whombat/`, started in every logged-in desktop session by the LaunchAgent `com.whombat.helper`. It needs Accessibility only (no Screen Recording: the pictures come from Screen Sharing), listens on `/var/run/whombat-agent/ui/<uid>/helper.sock` in a folder the agent makes for that user, and answers one JSON request per connection. From 1.0.6 it is signed with the team's Developer ID and notarized (hosts HS-480…HS-482), so its Accessibility permission survives updates; the step from the earlier ad hoc builds asked for it once more on each Mac. It is built on a Mac by `hosts/macos/helper/build.sh`, and the signed zip is committed there with its checksum; the hosts service serves it and `install.sh` installs it. | A process started over SSH or as a daemon has no desktop session and is judged by the wrong responsible process; a LaunchAgent in the session is the documented place. A stable signature keeps the one-time permission. |
| MAC-08 | **Accessibility for the helper is switched on in System Settings**, never by a profile: the Mac's page says it's off and offers “Open the setting on the Mac”, which opens Privacy & Security → Accessibility on the Mac's screen; the person (in the screen view) or the assistant (through the screen) switches it on. | Apple deprecated granting Accessibility by profile in macOS 27 and profiles need MDM; Screen Sharing input reaches Apple's own settings on John's Mac. |
| MAC-09 | **Asks**: a Mac follows its server's “Asks you first” setting like every server (default never). Screen steps are sensitive calls (they ask when the setting asks). John's Mac is at Full, never asks. | John: “Never ask, full access.” |
| MAC-10 | **What Whombat watches on a Mac starts calm**: on: the agent not checking in, a disk whose health isn't verified, the startup volume nearly full (the existing rules). Off: macOS updates, temperatures, memory pressure, failed launchd jobs, the helper or its permission missing, the screen account failing to sign in (shown on the page). | `docs/decisions/watch-defaults.md`. |
| MAC-11 | **Customers' Macs**: macOS 13 or later, Apple silicon and Intel. The agent builds for both; the helper is universal. Screen Sharing must be on (the page says how when it isn't); FileVault on means the Mac waits for its password after a restart (macOS 26 and later unlock over SSH; Whombat doesn't do it for them). | Customers have both kinds of Mac; the screen and the helper depend on the Mac's own settings, so the page names what's missing. |

## Whombat's side (stream W, 2026-11-17)

| ID | Decision | Reason |
|---|---|---|
| MAC-12 | **The contract names a Mac**: `HostServerPlatform` `macos` (appended), `osFamily` (`linux` · `macos`, absent is Linux) on the fleet row and the detail's server, and `HostServerDetail.macos` (`HostMacosDetail`). The hub's empty names, Go's zero times and missing booleans read as null. | One odd field must not empty a page (ONE-DH08); “not set” and “unknown” are what the page shows. |
| MAC-13 | *Superseded by MAC-44.* **Two ops for the screen**: `hosts.screen` (POST, every step; a secret op because `account.set` carries the Mac's password; never resent) and `hosts.screenLook` (GET, a screenshot; a read the apps take through an export stream). Reads (`status`, `look`, `ui.apps`, `ui.list`) go at operator, the rest are owner-only and go at admin, as `server_command`. | A screenshot is larger than a session message, and only a read can come through an export stream. |
| MAC-14 | **A screen step is signed once the Mac did it**, never with the typed text or the password; reads and `account.check` aren't signed. Clicks, drags and scrolls by position are everyday changes (the Mac's own list, not Done recently); named presses, menus, keys, typing, unlocking and the screen account show in Done recently. | “Clicked on Studio’s screen” twenty times says nothing; “Pressed “Allow” on Studio” does. |
| MAC-15 | **`mac_screen` and `mac_ui` are write tools whose steps ask by `action`** (all but `look`, `apps`, `list`), so the server's “Asks you first” decides as for `server_command`. `look` and every `mac_screen` step answer with a fresh JPEG at most 1280 px wide plus `screen_w`, `screen_h`, `image_w`, `image_h` and `scale` in the text; `mac_ui` steps don't attach a picture. A refusal is the person's sentence plus `next` for the assistant. | The assistant sees what its click did without a second call, and clicks in the screen's pixels; lists and presses by name need no picture. |
| MAC-16 | **A connection tool may attach a picture**: `CallOutput.image` (base64 and its type) goes to the agent through `connection_call` as MCP image content after the text, as `browser_preview`'s (`mcp/image.ts`, PNG unless said). Never logged or stored. | One path for pictures; other connections are unchanged. |
| MAC-17 | **Sign in once takes a Mac**: `uname -s` `Darwin`, then `sw_vers -productVersion` and the user at the screen before anything is enrolled; macOS older than 13 (or unreadable) is `unsupported` in Mac words. With Full control and a password, when the signed-in user is at the screen, the password stays in memory until the first report (at most that wait) and goes to the Mac as `account.set` as the person; a refusal there is not an install problem (the page shows it). | The person typed the Mac's own password once; asking again on the page would be a second chore. |
| MAC-18 | **A Mac's mark is `mac`**: Lucide's `monitor` in the text colour, for the `macos` platform and an OS named macOS, Mac OS or OS X. | Apple's logo is a trademark and isn't drawn. |
| MAC-19 | **A Mac's care plan has no weekly updates step**; the desk calls it “Mac”. | Its updates restart the person's own computer. |
| MAC-20 | **A Mac's own console is its screen**: Whombat passes `vnc` for the host through and signs “Opened the screen of {server}”; the hub opens `vnc` by default on a Mac. | MAC-04: the browser draws it as a VM's screen. |

The Summary is every server's; its Technical details say “macOS 27.2.1 (26B131)” and add a “This Mac” card (model, chip, System Integrity Protection, FileVault, Signs in by itself); a `macos.*` line in Worth a look opens the Screen tab. | Nothing runs on a Mac that Whombat lists, and its own facts belong with the other platforms' cards in the one fold (SPG-03). |
| MAC-31 | **The web opens the Mac's screen live**: “Open the screen” on the Screen tab and in ⋯ (above Open a shell; the head stays Ask · ⋯, SPG-07) opens `?console=screen`, the host's `vnc` console, titled “studio’s screen”, with a Screen · Shell switch and no guest list. A screen that asks the browser for a password says to check the Mac's password on the Screen tab. | MAC-20: the screen is a Mac's console; the shell stays one tap away for who wants it. |
| MAC-32 | **One line says what is missing**, first to last: the Mac not checking in, the shell switch (the screen goes with it, MAC-06), Screen Sharing, the Mac's password, a password the Mac refused (`macScreenView`, shared by both apps). Screen Sharing off adds how: “On the Mac, open System Settings → General → Sharing and switch on Screen Sharing.”; FileVault on adds that the Mac waits for its password after a restart. | One reason a person can act on, not a list of everything that isn't ready. |
| MAC-33 | **The Mac's password form** asks for the user (filled with the account, else who is at the screen, else who signs in by itself) and the password, sends it once with `account.set` and clears it from the form as it goes and on close; it is never kept in the app, a URL or navigation. A refusal names the user it was for. Check (`account.check`) and Forget (asked first, `account.clear`) sit beside it. | MAC-05: the password is the Mac's own; the app only passes it on. |
| MAC-34 | **The phone shows a still picture**, taken only when asked (“Look at the screen”, then “Look again”) through `hosts.screenLook` (JPEG, at most 1280 px, an export stream), and again after Unlock and Open the setting; the screen itself opens on the web. | Phones have no consoles; a picture on demand costs nothing while nobody looks. |
| MAC-35 | **Whombat Helper in words**: “On the Mac” (Running for mara · version 1.0.0, Installed but not running, Not installed and what that means), Accessibility On or Off; while off, “Open the setting on the Mac” (`ui.open` `accessibility`) and the note that the person switches it on in the screen. | MAC-08: the setting is switched on in System Settings, by a person or the assistant through the screen. |
| MAC-36 | **A fixture Mac** (`packages/client/src/hosts/fixtures-mac.ts`): studio, a Mac Studio with an M2 Ultra on macOS 27.2.1, user `mara`, Accessibility off until its setting is opened, and a 320 × 180 picture of a desktop drawn for it. The web's world lists it only with `localStorage['whombat.fixtures.mac']` (`setup`, `sharing-off`, `locked`, `failed`, `no-helper` pick a state), so the mock's five servers stay as drawn; the phone's demo world has it as a sixth server with the-falcon's day. | Every state of the Screen tab can be seen and checked without a Mac. |
| MAC-37 | **A failed Mac install shows the server's own Mac words** for `unsupported` (too old or unreadable macOS) and `sudo_refused` (sign in as an administrator of the Mac) on the failure card, its first sentence as the title. | The app's Linux words (“It needs Linux…”, “Sign in as root”) are wrong on a Mac. |
| MAC-38 | **The Mac types its own password into macOS's password prompts**: `mac_screen password` (op `password`) asks the agent to type the screen account's password into a macOS password prompt in front (an administrator prompt from SecurityAgent or a System Settings pane; the lock screen is `unlock`'s) and press Return; the body can't carry text, the assistant never sees the password, and the agent refuses with `no_prompt` when no such prompt is in front. It follows the server's “Asks you first” like the other screen steps. | Live on John's Mac (macOS 27.2.1): System Settings' own administrator prompt took the password typed through Screen Sharing once its field had focus; John wants dialogs accepted without being asked. |

## Council round 1, Whombat's side (stream CR-W, 2026-11-17)

Three reviewers read streams W and WA; the hosts service's side has a stream of its own (CR-H). The names shared with
it: the code `not_admin`, `message` on a step that worked, `status` the only read, and the limits below.

| ID | Decision | Reason |
|---|---|---|
| MAC-40 | **The apps send the Mac's password sealed.** `useHostScreenStep` takes `account.set`'s account out of the step and puts it in a one-shot box (`sealOnce`, the guide forms' pattern) that the request empties, so neither TanStack's mutation cache nor `useMutation().variables` holds it after the call; the form clears it as it goes (MAC-33). The form checks the user and the password against Apple's 63 bytes first (`macAccountProblem`). | TanStack keeps a mutation's variables for minutes after it settles, and `reset()` doesn't clear the cache's copy. |
| MAC-41 | **A screen step keeps to the hosts service's limits** (`HOST_SCREEN_LIMITS`): typed text 2,000 characters, a filled-in value 10,000, keys 500, app, window, name and each menu item 200, role 64 (one role or a comma list), target 2,048, a menu path 8 items, positions 0 to 16,384, scroll −50 to 50 steps, a look's width 0 to 8,192 (64 to 8,192 by query), a list 1 to 1,000, the account's user and password 63 UTF-8 bytes each. `HostScreenBody`, the `mac_screen`/`mac_ui` schemas and their refusals (“keys: at most 500 characters.”) say the same. | A step Whombat lets through must not be refused by the hosts service for a limit nobody told the assistant. |
| MAC-42 | **The Mac's own words come through.** When the Mac says why a step failed (`failed`, `invalid_request`), that reason is the sentence (one line, curly apostrophes, at most 300 characters: `screenMessageText`), so “the Mac may have refused it” or “the field isn't a password field” reach the person and the assistant. A step that worked carries the Mac's note (`HostScreenResult.message`, “The Mac locks again when this screen session ends.”): the tools answer it as `message`, the apps add it after their done words, or show it instead of “Done.”. A look's note isn't shown. | One fixed “That didn't work” hid the only useful part. |
| MAC-43 | **`not_admin`**: the screen user isn't an administrator, so the Mac can't type its password into a macOS admin prompt without Whombat Helper's Accessibility. The person reads that and that they switch Whombat Helper on in the screen themselves; the assistant's `next` says to stop and tell the person. No `next` leads back to the step the Mac just refused (`no_access` tries `password` once). | Pointing the assistant from `no_access` to `password` and back made a loop on a Mac whose screen user isn't an administrator. |
| MAC-44 | **Two ops for the screen**: `hosts.screen` (POST, every step; a secret op because `account.set` carries the Mac's password; never resent) and `hosts.screenLook` (GET, a screenshot, through an export stream). Only `status` is a read at operator; every other op, a look and `ui.apps`/`ui.list` too, is an owner's and goes at admin, as `server_command`. The hosts service audits a look and the two lists with the op and the app only; Whombat signs none of them (MAC-14). | A screenshot and other apps' field values are the person's whole desktop; the hosts service treats them as admin's. |
| MAC-45 | **A look and the apps' lists don't ask.** `mac_screen look`, `mac_ui apps` and `mac_ui list` stay out of “Asks you first” (MAC-15): they change nothing, the assistant needs them before and after every step, and being an owner's (MAC-44) with the hosts service's audit already covers who sees the desktop. The tools stay write tools. | A question before every look would make a Mac that asks first unusable for the assistant. |
| MAC-46 | **The screen goes with the host-shell switch only**, on both sides, as the hosts service asks; the consoles' switch is the guests'. `macScreenView`, the web's console dialog and the page's ⋯ (Open a shell, Open the screen) follow it for every server's own shell. | The apps greyed the Mac's screen out when consoles were off though the hosts service would open it. |
| MAC-47 | **Unknown isn't unlocked.** After Unlock, a lock the Mac couldn't read says “Whombat typed the password on studio’s screen. Look at it to see if it’s unlocked.”, not that it is unlocked; the lock line says “Can’t tell if it’s locked”. | Saying “unlocked” when nobody knows sends the person to a locked screen. |
| MAC-48 | **A screen step runs now or fails now** (`networkMode: 'always'` on `useHostScreenMutation`): offline, TanStack would pause it before the request takes the Mac's account out of its sealed box and send it later, after the person closed the form. | Council round 2: a paused `account.set` kept the password in memory and could send it unasked. |
| MAC-49 | **The Mac's own words come first for every refusal it explains** (`hostScreenProblemText`): `no_helper`, `no_access`, `locked`, `no_prompt`, `busy`, `timeout`, `unsupported` use the Mac's message when it gave one; `no_screen` says the Mac's words and then how to switch Screen Sharing on; `no_account`, `sign_in_failed` and `not_admin` keep Whombat's own words, which tell the person what to do in Whombat. | Council round 2: “something else answered on Screen Sharing's port” and “nobody is signed in” were lost behind fixed sentences. |
| MAC-50 | **`macos.agent_folder` is a Mac hint that starts on** and opens the Mac's System tab: the hosts service raises it when the Mac's agent runs from a folder that someone other than root could change (hosts HS-450; the agent no longer moves itself). | A root program anyone can swap is a security opening with one clear step, running the installer again (watch-defaults.md); `install.sh` puts new installs in a root-only folder, so it is rare. Council round 3 asked for on. |
| MAC-51 | **`password` and `unlock` may take a minute**: the Mac types its password one checked key at a time (hosts HS-460…), so the server waits 70 s on the hosts service for them and the apps 80 s on the session (`hostScreenTimeoutMs`); every other screen step keeps 35 s. | Council round 3: at the per-key checks' cautious cost a 63-character password needs about 42 s. |
