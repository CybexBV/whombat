# Connection pages: the server side

Decisions the server stream made building connection-pages.md (CP-01…CP-20) on contracts 0.88.0. Migration 0110.
Code in `apps/server/src/things/`.

| Id | Decision | Why |
|---|---|---|
| CP-S01 | **Migration 0110** (expand): `connection_points` (connection → cascade, `at`, `key`, `value` double nullable; primary key `(connection_id, key, at)`, an index on `at` for the prune), `catalog_connections.runs_on` jsonb null, `widgets.thing_id` text null with an index on `(owner_id, thing_id)`. Its journal `when` is three days after 0107's so 0108/0109 (reserved by the other session) can sit between. | The brief; old binaries never read the table and ignore the columns. |
| CP-S02 | **Superseded in part by one-person.md OP-S50**: `things.page` serves `connection:` and `device:` things, and every connection's page is the person's. **`things.page` serves `connection:` and `device:` things only**; a server, someone else's personal connection, a builtin entry (Servers) and the mail tiles' Google connections answer 404 `not_found`. A `connection:` id of a device connection is served as that device's page; a `device:dvp_…` of a proposal that was switched on meanwhile is served as the device. | CP-01's ids, `connections.list`'s visibility; nobody links to a builtin's page. |
| CP-S03 | **Points**: the health pass stores `rtt_ms` (the check's wall time, null when it failed or was refused) in the transaction that writes the glance; UniFi adds `wan_rx_mbps`/`wan_tx_mbps` (the gateway's uplink rates); the device reader adds `r_<key>` for the first three numeric readings (null for those when the device didn't answer: a gap). The chart puts them on a 96-step grid over 24 hours (15 minutes, the mean of each step) and starts where the history does, so a new connection's chart isn't 23 hours of nothing. A chart needs two steps with a value; the hourly job removes older points. | CP-15; a grid keeps the wire small and the phone's and the web's lines the same. |
| CP-S04 | **Superseded in part by CP-S24** (a server's every network card). **Runs on: one address index per hosts service, 10 minutes**: the fleet's servers (their detail's `address`), their running guests' `addresses` (CIDR cut) and, for Proxmox guests without any, the configuration's `net<n>`/`ipconfig<n>` `ip=`/`ip6=` (at most 60 configuration reads per build; `dhcp` skipped). A guest matches before its server (a guest's own address is the more precise answer). The connection's host is the address a person typed (`fields.url`); entries with a fixed public API (Hetzner) have none to match. A host name is resolved through the Vault's resolver (the outbound lookup, a test seam). Reads that fail are left out; a page waits at most 5 s for it, else shows no Runs on this time. | CP-08; John's CT 131 has `ip=10.100.0.5/23`; the index costs a handful of hosts reads every 10 minutes, not per page. |
| CP-S05 | **Superseded in part by one-person.md OP-S50**: `connections.setRunsOn` signs `connection.changed` for every connection. **`connections.setRunsOn`** checks the server (and guest) against the fleet and that server's guest list (a stopped guest can be chosen), stores `{mode:'chosen'}` / `{mode:'none'}` / null through `applyChanges` (a shared connection: signed `connection.changed` “Said Home Assistant runs on pve-02 · CT 131” / “… runs on nothing Whombat watches” / “Let Whombat find what Home Assistant runs on”; a personal one: the account-level write), and answers the resolved `ThingRunsOn`. The same choice again changes nothing. Chosen on a Whombat without servers: 503 `unavailable` with the hosts text. | CP-08 and the other connection updates' rules; `changeSharedConnection` takes the caller's words (`text`). |
| CP-S06 | **Part of a server (CP-10)**: a `proxmox` or `unraid` connection whose host is a watched server's address (servers only, not guests). Home's things use the index only when it is built already (it starts a build otherwise) and give each lookup 1.5 s, so Home never waits for the hosts service; the page waits for it. The page shows a text panel “This is how Whombat reaches basalt’s Proxmox API. Its figures, guests and backups are on basalt’s page.” with “Open basalt”. | CP-10; Home must stay fast. |
| CP-S07 | **Kind readers share one shape** (`kinds/read.ts`): a GET as the connection (`signedConnectionFetch`: its destination policy, its credential, one forced refresh after a refused OAuth token), answers up to 4 MB, a 15 s deadline for the whole read, a 30 s cache per connection keyed by its credential version and `updatedAt` (a failure isn't kept), and failures as plain `ReadProblem`s (“Home Assistant didn’t answer in time.”), never the other side's text. The page and the health pass share the cache, so a tile and its page say the same. | CP-04's 30 s cache and plain problems. |
| CP-S08 | **Home Assistant's WebSocket**: one socket per read under the connection's policy (`outboundConnectOptions`: checked URL, pinned lookup, a pinned certificate's agent), messages buffered from the moment it is made (Home Assistant asks for the sign-in before anyone may listen), the access token from the connection's bearer credential (its own OAuth or a long-lived token), `auth_invalid` refreshed and tried once more for `ha_oauth` only. Every command runs at once on the socket; `system_health/info` and `render_template` are collected until `finish` / their first result or 5 s. The reads are `get_config`, `system_health/info`, `config_entries/get`, `repairs/list_issues` (+ `frontend/get_translations` for their titles, else “<Integration> needs a repair”), `system_log/list`, `backup/info`, one template (`updates on\|unavailable\|entities`) and on Home Assistant OS `supervisor/api` (`/core/stats`, `/host/info`, `/os/info`, `/addons`, `/addons/<slug>/stats` for up to 40 started add-ons). Never `get_states` or a service call. | CP-02, CP-07; John's ~6,000 entities no longer cross the wire, which also fixes the empty tile (CP-16). |
| CP-S09 | **The page's generic part adds to a kind's**: a kind may replace the figures and the chart (`kpis`, `chart`; a kind without a chart, or without points yet, gets the response-time chart), puts its notices before the generic ones, gives the third row and its tabs, the head's first facts, a more precise status, the service's own page and its actions. Widths are paired after the panels are chosen (`pairWidths`: wide + narrow, narrow + narrow or narrow + wide share a row; a panel left alone is full width), so “Worth a look” without a chart becomes a full-width panel. | CP-03, CP-06: no empty sections, one layout rule for every kind. |
| CP-S10 | **Home Assistant's figures**: with a machine CPU (“5 %”, “of 4 cores”), Memory (“3.0 / 8 GB”, “38 % used”), Disk (“30 / 40 GB”, warn ≥ 75 %, bad ≥ 90 %), Database (“2.8 GB”, “MariaDB 10.11”), Integrations (“169 of 171”, “2 not loading”); on Home Assistant OS without a machine the Supervisor's CPU, memory and disk; with neither Version, Database, Integrations, Errors today, Updates. MariaDB is told from MySQL by its version (≥ 10). The guest's disk total is the Proxmox configuration's first disk in GiB (shown as GB, as Proxmox does); a server's memory and storage come from its fleet card. When Home Assistant can't be read the machine's figures and chart still show, with the problem line. | CP-07 and John's mock; the machine says how it runs even when Home Assistant doesn't answer. |
| CP-S11 | **Home Assistant's notices**, worst first: recovery mode (bad), integrations not loading (bad when one failed, warn while only retrying; “Shelly retrying · Daikin failed”; “Why are two integrations not loading in Home Assistant?”), each Repair not ignored or dismissed (critical/error bad, warning warn, at most 5), the disk, errors in the log today (warn from 10, else info; “Most from KNX, since 06:40”; “Show them” → Logs), no backup in 7 days (Home Assistant's or the machine's Proxmox backup, only when either is known), updates waiting (info, “Open” → its Settings → Updates), devices and sensors not answering (info). Errors today count each log entry's occurrences whose last time is after local midnight in the burrow's zone. | CP-07; a log with errors is common, so a few are information, not a warning. |
| CP-S12 | **Home Assistant's status**: “Needs a look” (warn) while integrations don't load, a Repair is critical or an error, or it started in recovery mode; otherwise the check's. The tile (CP-16) says “Home Assistant 2026.10.2” with Integrations (“169 of 171”, “2 not loading”), Errors today and Updates, and the same warn rule; when the check answers but the reader doesn't, the tile keeps what it showed. | CP-16; a reader that fails once shouldn't blank a tile. |
| CP-S13 | **Home Assistant's account isn't an administrator** when `config_entries/get` or `system_log/list` answer `unauthorized`: the page reads what it can (version, installation, database, counts) and says “Whombat’s Home Assistant account isn’t an administrator, so it can’t read the integrations and the log.” as its `problem`. | CP-07's words. |
| CP-S14 | **UniFi**: the first site; the gateway is the device with the `gateway` feature or a gateway model (UDM, UCG, UXG, UDR, UDW, USG, EFG, UX); firmware from a device's details when the list lacks it (at most 60 detail reads per read, kept 10 minutes each). Figures Internet (down / up now), Devices, Access points, Gateway CPU (with memory), Clients (a count, never a list); badge “1 access point offline” / “2 devices offline” / “The gateway is offline” (bad); the tile's dot follows (warn, bad for the gateway). Third row: the offline devices; tab Devices. | CP-09; the tile and the page agree. |
| CP-S15 | **Hetzner**: servers (50 per page is enough for a home project) with their type's gross monthly price at their location, shown “€ 4.51” (Hetzner bills in euros); “Cost a month” is the servers' sum “before traffic”; volumes with the server they're on. Notices: not running (warn), no Hetzner backups (warn), delete protection off (info). Its chart is the generic response time. | CP-11. |
| CP-S16 | **Generic figures**: Status (“Working”, “Needs a look”, “Not answering”, “Signed out”; “checked 4 min ago”), Response time (latest, “average 140 ms today”), Last used (“8 Oct”, “at 14:02”; “Not yet”), Problems (failed checks in 24 h). “What Whombat may do” groups the tools as Read, Change and Always asks first (a device's actions each by their label), with their tier, `mixed` when they differ, off for changes on Look only; it is left out when there are no tools and the connection isn't Look only. The head's last fact: “Whombat may **do things** · locks and alarms ask first” (UniFi: restarts and firewall changes; others: deleting) or “Whombat may **look only**”. | CP-06; the catalog's sensitive rules, in a line. |
| CP-S17 | **Devices**: a switched-on device's figures are its first five readings (value and unit apart), its chart the first three numeric readings, its table every reading (“Couldn’t read it” for one that failed), “The device” facts (make, model, address, Modbus TCP or HTTP and JSON, last read, the manual's title); badge “Not answering” when the last read failed. A device being learned shows a text panel (“Whombat read 4 values from this device to test it and changed nothing. Choose what it may change in the chat; until then it isn’t switched on.”, “Open the chat”), what it read, and no Settings. | CP-13. |
| CP-S18 | **Superseded in part by one-person.md OP-S50**: Restart is the person's on every connection, refused on Look only, and signs its text. **Restart** (`things.action`): Home Assistant only; a manager's (`mayManage`), refused 403 on Look only with “Home Assistant is set to Look only, so Whombat changes nothing there. Set it to Manage in Settings first.”; `POST /api/services/homeassistant/restart` as the connection (an external effect before the commit; the op is `never` resent), then `thing.action` signs it (a personal connection's with no text, PA-09) and records “Restarted Home Assistant” (kind `thing.restart`, no Undo). A 401/403 says the account isn't an administrator; a timeout says it may be restarting already. Toast: “Restarting Home Assistant. It’s back in about a minute.” | CP-12. |
| CP-S19 | **Widgets on a page**: `pin_widget` with `thingId` checks the person may see that thing (a connection or device as its page does, a server in the fleet of a burrow that sees servers) and counts the limit per place (Home, or that page); `widgets.list` without `thing` answers Home's only; remove and move answer the list of the place the widget was in, and move reorders within that place. | CP-14; Home stays Home. |
| CP-S20 | **A chat about a thing tells its assistant the page's thingId** (“Its page is connection:con_…: to keep a widget on that page, pass it as pin_widget’s thingId.”) in the turn's topic, never in the chat. | CP-14, CP-17; the agent can't guess the id. |
| CP-S21 | **Names**: a page and its tile drop “ · <address>” from a label made by default (“Home Assistant · 10.100.0.5:8123” → “Home Assistant”); well-known integrations keep their own spelling (KNX, MQTT, ESPHome, UniFi …), others get their domain with a capital (“Mobile app”). | CP-01's “without the address”; “Knx” reads wrong. |

## Left for a live check (the lead)

- John's real Home Assistant: that the account is an administrator, the system health's `current_recorder_run` (Restarted …), `estimated_db_size` and MariaDB's version, the template's counts on ~6,000 entities within its 3 s, and Restart's answer.
- pve-02's CT 131: that the hosts service's guest `disk_used_gb` and the configuration's `disks[0].size_bytes` agree in units (both GiB here), and the guest metrics' memory series name (`mem_used_mb` or `mem_pct`).
- UniFi: whether the device list carries `firmwareVersion` (else 45 detail reads the first time), and the gateway's feature or model.
- Migration order: 0110 is journal position 108 on this branch; once 0108/0109 land they must come before it, and a database that applied this branch's 0110 alone would need it again.
| CP-S22 | **“Log errors · since restart”, not “Errors today”** (found on John's box after 0.96.0: “Errors today 12033”). Home Assistant's log keeps one running count per error since it started, so a count can't be split by day: the tile, the figure and the notice count the errors still coming in today with their whole count since the restart (“12,033 errors in the log since it restarted · Most from KNX, still coming in today”), figures get thousands separators, and the tile leaves out “Updates” when none wait. | Honest words for what the number is; less is more for a zero. |
| CP-S23 | **Home Assistant's read doesn't wait for system health checks it doesn't use** (John, 2026-10-19: “the page is loading very slowly”). Measured on his box: every answer is in by 0.7 s, the system health's `initial` at 0.3 s, but its `finish` never came within 5 s (the cloud's and HACS's reachability checks), so every read, every page open and every health pass waited 5 s. The read stops once the keys it uses (`homeassistant` installation and version, `recorder` database, size and current run) are in and not pending, or at `finish`. | The page waited on facts it never shows; the health pass checks one connection after another, so UniFi's tile waited too. |
| CP-S24 | **A server answers on every network card it has**: the index holds a server's reported `address` and the addresses of its detail's `network` cards (CIDR cut), without loopback and link-local ones and without any address another server has too (Docker's 172.17.0.1, libvirt's 192.168.122.1). A connection to a server's second card is then that server's from the start, for runs on (CP-08) and part of (CP-10); SB-09's name match stays for a server the index can't read. | John's BlackBox: its agent reports 10.100.1.23 while Unraid, Plex and Seerr answer on 10.100.0.40 (its 10 Gb card), so a new Unraid connection wasn't part of BlackBox until the health pass read Unraid's name, up to 5 minutes later, and Plex and Seerr never ran on it. |
