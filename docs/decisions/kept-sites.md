# Kept sites (KS-*)

John, 2026-11-13: the agent's browser starts fresh, so every chat on a site with two-factor sign-in (Hetzner's
accounts.hetzner.com and konsoleh.hetzner.com, for his domain transfers) needed a new login and a new code from him.
“Ask t3 code to give you the option to keep a website alive, not as default but when required only.” Now the agent can
ask Whombat to keep one website signed in between its turns, for a few hours. Nothing is kept unless it asks.

Related: [browser.md](browser.md) (the agent's browser), [one-person.md](one-person.md) (OP-17: outsiders' turns),
[home-redesign.md](home-redesign.md) (Done recently and Undo), [hermes-native.md](hermes-native.md) HN-W05 (cookies
never carried over: superseded in part here), [hermes-engine.md](hermes-engine.md) HE-S141, HE-S307 (the Vault's fills); contracts `packages/core/src/contracts/kept-sites.ts`
(CT-1730…).

| ID | Decision | Reason |
|---|---|---|
| KS-01 | **Only when the agent asks, one website at a time, for a limited time.** A kept site is a set of https origins (a sign-in host and the hosts it signs in for); only its cookies are kept, nothing else of the browser. Default: nothing kept. | A sign-in kept for good is a standing door into the person's accounts; a few hours covers a piece of work without a new code every pod. |
| KS-02 | **Keep**: the runner reads the site's cookies from the live browser and sends them (`runner.keptSiteKeep`, the live lease); the server keeps them for `hours` (default 4, at most 24) from now. A kept site sharing any origin with the new one is replaced. | One site, one row: keeping it again after a new sign-in shouldn't leave two sets of cookies for the same host. |
| KS-03 | **Restore**: when a pod's browser starts, the runner asks for every kept site that hasn't expired, with its cookies, and puts them into the browser (`runner.keptSiteRestore`, runner token only). Expired ones are deleted, never answered. One Whombat has one person, so it is every site of the box. | A pod's browser starts outside any one turn. |
| KS-04 | **Renew**: after a turn or when the pod stops, a site that had a page open is sent back with its cookies as they are now and stays kept for its hours again from now (`runner.keptSiteRenew`). A site forgotten, stopped or expired answers 404 and the runner keeps nothing. | Sites refresh their sign-in cookies as they are used; a site in use shouldn't run out mid-work, one left alone should. |
| KS-05 | **Forget**: the agent forgets a site by any of its origins (`runner.keptSiteForget`); every kept site with one of them goes. | The agent names what it knows, a host, not an id. |
| KS-06 | **The person sees and stops them** in Settings → the assistant → What it may do, under what it can sign in to (“Kept signed in”, shown only while there is one): each site, until when, and Stop, at once. Soonest to expire first. | It is a permission the agent took for itself, so it sits with the others, and taking it away needs no confirm. |
| KS-07 | **Signed events, never a cookie**: `browser.site_kept`, `browser.site_forgotten`, `browser.site_stopped` (System), with the site, its origins, its hours and ids. A renew and an expiry are quiet. | The log says who kept or stopped what; the cookies are as secret as a password. |
| KS-08 | **Sealed before the commit**: the server seals the cookies with the box's custody key under `kept-site:<id>:cookies` before the command runs, so they never pass the pipeline's input, an event or a log; only restore opens them. A cookie the browser wouldn't send to one of the site's origins (its domain neither a host of them nor a parent domain) isn't kept. | The pipeline scrubs and may store an agent's input; a sealed value bound to its row can't be moved to another. Keeping only the site's own cookies keeps the agent from carrying other sign-ins along. |
| KS-09 | **Keeping is something the agent did** in Done recently (“Kept you signed in to accounts.hetzner.com for 4 hours”), with Undo until it would expire: Undo stops keeping it, as Stop does. | The person learns about it where they look for what the agent changed, and can take it back there. |
| KS-10 | **Never in an outsiders' turn or a Feedback assessment**: keep, forget and list answer 403 there. | Those turns stay apart from the person's sign-ins (OP-17). |
| KS-11 | **Settings refresh through `vault.updated` without an entry** (topic `me`): every change to the kept sites sends it, and the apps read the list again with the Vault. No frame of its own. | Kept sites are sign-ins; a new frame would mean a contracts change for one list. |
| KS-12 | **No session minor bump**: a Whombat without `keptSites.*` answers `unknown_op` and the apps show no list. | Nothing older breaks (as PRL-10). |
| KS-13 | **The agent asks with one browser tool, `browser_keep_site`** (`action` `keep`, `forget` or `list`; `site` a URL or origin; `also` more URLs or origins of the same site; `hours` 1 to 24), sent over the turn's logins socket to the runner, only in the person's own turns. Keep after signing in; forget when the work is done. The agent sees the site, its origins and until when, never a cookie. | Asking is the agent's when the person's work needs it; the cookies stay between the browser, the runner and the server as a login's password does (HE-S141). |
| KS-14 | **A site's cookies are those its origins would get**: a host-only cookie on one of its hosts, a domain cookie on one of its hosts or a parent of it. Only those are read, sent and put back; another site's never. | One site's sign-in, not the person's other accounts open in the same browser. |
| KS-15 | **Put back before anything reaches the browser; renewed only when used**: the runner restores in the start hook of the person's pod browser (on every start and restart), before any connection is handed to it, and never into an outsider's or an assessment's browser; a restore that fails is logged without values and the browser starts without it. It renews a site only when a page on it is open after a turn or at the pod's stop; one the server no longer has (404) has its cookies deleted from the live browser too. | Restored before the agent's first call, a kept site opens signed in and the Vault's fill and code are needed only when the site signs out; a site left alone expires on its own. |
