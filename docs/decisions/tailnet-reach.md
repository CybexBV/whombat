# The agent reaches everything on the person's tailnet

John, 2026-10-30, after signing Home into his tailnet (Settings → This Whombat → Tailscale, `direct-connection.md`):
“I want the agent to be able to reach everything on the Tailnet”, and “make sure we don't lose functionality”. Home's
tailnet when this was decided: 30 devices, MagicDNS on, “Override local DNS” with NextDNS, and a subnet router
(BlackBox) advertising the home LAN Home itself is on (`10.100.0.0/23`). Appliance NX-487, NX-488, MG-138, MG-139.

| ID | Decision | Why |
| --- | --- | --- |
| TN-01 | **The tailnet is part of the local network.** Tailscale's addresses (100.64.0.0/10, fd7a:115c:a1e0::/48 inside fc00::/7) are already in the local network's ranges, so “Agents may reach your local network” (`local-network.md` LN-01, on by default) opens every tailnet device on any port to the agent's commands, the Vault, the hosts checks and the server, as it does the LAN; production servers stay behind an opening (`one-person.md` OP-07). No second switch. The tailnet's own access rules are the only other boundary. | John's ask. The person signs the box into a tailnet themselves; a tailnet is their own devices, as the home network is. |
| TN-02 | **The box's own networks before the tailnet's routes** (appliance NX-487): the main table is asked first without its default routes (`ip rule 5200 lookup main suppress_prefixlength 0`), so a device advertising the box's own LAN can't pull its local traffic into the tailnet. In the image before the box accepts the tailnet's routes, so a rollback never lands on routes without it. | Home's tailnet advertises Home's own LAN: accepting routes without it would break the direct connection on the LAN. Tried on Home by hand before it was built. |
| TN-03 | **The tailnet's DNS stays the tailnet's; Whombat's own names don't depend on it** (appliance NX-488): Tailscale keeps answering every lookup when the tailnet overrides local DNS (its names, split DNS, its filter, as on the person's other devices), but `whombat.com` is asked of the local network's resolvers (a routing-only domain on the cable and Wi-Fi, still default routes). | Turning Tailscale's DNS off would lose the tailnet's names and the person's DNS choice; leaving everything to it would let a failed tailnet resolver cut the box off from control, the relay and its updates. |
| TN-04 | **What the box keeps in Tailscale's settings** (appliance MG-138): no exit node, nothing advertised, no Tailscale SSH or web client, shields down — put back by the manager whoever changed them. | The box's own traffic never leaves through another device, it is nobody's subnet router, and the direct port stays the only way in. |
| TN-05 | **The person hears when Tailscale signed the box out by itself** (its key ran out, it was removed from the tailnet): one message from their assistant in Chat (`TAILSCALE_SIGNED_OUT_TEXT`) when the runtime's own read finds it asking for a sign-in or an approval after being on (a moment of starting on the way counts as the same); never after the person's own sign-in, sign-out or off, and once per time it was on. The manager asks Tailscale for the sign-in link itself, so Settings shows **Sign in** rather than “Starting…” (appliance MG-139). Not a watch check: like the disk alerts, it is the box's own. | Otherwise the agent quietly loses the tailnet (Tailscale's keys run out after 180 days by default) and nothing says why. |
| TN-06 | **The agent can ask what is on the tailnet**: `tailnet_devices` (read-only, no key) lists the other devices, online first, with their short and full names, addresses, system, last seen and the networks they route, from the box's own Tailscale (the manager reads tailscaled, contracts 3.11 CT-1635; Mullvad's exit nodes, which aren't the person's devices, are left out). Off or signed out, it says so and where the person fixes it. | Reaching everything is only useful when the agent knows what is there; the person shouldn't have to list their devices. |
| TN-07 | **The box accepts the tailnet's routes** (appliance MG-140): a network a subnet router advertises is reachable through it, as from the person's other devices; the box's own networks still come first (TN-02). The box itself advertises nothing (TN-04). | “Everything on the tailnet” includes what its subnet routers share. Shipped a release after TN-02, so no rollback lands on accepted routes without the rule. |
