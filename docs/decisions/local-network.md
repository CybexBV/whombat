# The local network open by default

John, 2026-10-08: “remove the restriction that Whombat Appliances or agents are not allowed on the local network by
default, because they should have access by default” — adding Home Assistant at `10.100.0.x:8123` was refused with
“That address is on your network. Add 10.100.0.0/24 port 8123 to the home network list to connect.” Contracts 0.56.0
(CT-309), appliance NX-139.

| ID | Decision | Why |
| --- | --- | --- |
| LN-01 | **One switch, on by default, for the whole local network.** The burrow setting `agentsReachLan` (RA-41) becomes **Agents may reach your local network** and covers every private address — RFC 1918, shared address space (100.64.0.0/10) and unique local (fc00::/7) — on any port, for the agents' computers *and* for Whombat's own calls on their behalf: Vault entries, Connections (Home Assistant, Proxmox, Nextcloud, custom MCP), Vault SSH servers and the agent browser. Core's destination rules take `lan` and let a private address through when it is true. Amends VT-12, VT-13, VT-S06, BT-05, CX-40, CX-41, AC-10, RA-41. | A Whombat lives in a home or office to work with what is there; asking for a CIDR and a port first is the step John hit. |
| LN-02 | **Superseded in part by one-person.md OP-S114**: the same stays closed to commands, except the agent's own services on 127.0.0.1:20000–20099. **What stays closed whatever the switch says:** loopback, link-local, the metadata addresses (incl. 100.100.100.200 and fd00:ec2::254 inside private space), multicast, reserved and documentation ranges; a host name that resolves to public and private addresses at once (`mixed`); this Whombat itself and the computers' bridge; production servers (AC-11); port 25 from the computers. Public destinations keep their rules (https for the Vault, 80/443 for the browser, the SSH ports). | Those are not “the local network”; they are how SSRF and rebinding reach the host or the cloud. |
| LN-03 | **The home network list stays** (`vault_networks`, the appliance file, the Vault/This Whombat section, “Add this network”): with the switch off it is exactly as before, the only way to a private address. With it on it changes nothing. The refusal text is unchanged (it only appears with the switch off). | Owners who want the old, closed behaviour switch it off and list what they allow. |
| LN-04 | **Where the server opens it:** `WHOMBAT_LOCAL_NETWORK` = `auto` (default: on for a managed appliance, off self-hosted), `on`, `off`; open = the config allows it and no burrow switched it off (`localNetworkOpen`, `destinationReach` in `vault/store.ts`; an appliance holds one burrow, the list is the install's too). Self-hosted servers stay closed by default: dev.whombat.com and the like are reachable from the internet and sit on someone's LAN. | Only the appliance is the box “in the home” the switch talks about. |
| LN-05 | **Superseded in part by one-person.md OP-S114**: with `lan` the commands' proxy, whombat-agent-net, opens the local network instead of computerd's ACL. **The computers:** with the policy's `lan`, computerd's ACL opens every private IPv4 range plus the appliance's own networks (minus this host, the bridge, the deny list, production servers and 100.100.100.200); the runner's guard already allowed any private address with `lan`. The agent's prompt says it reaches “any device on the local network”. | Home Assistant on another subnet than the appliance (John's 10.100.0.x vs the box's 10.100.1.x) was out of reach under RA-41's own-subnets rule. |
| LN-06 | **Superseded in part by one-person.md OP-S114**: the outer firewall now gives whombat-agent-net's uid what the computers' forward chain had. **The appliance's outer firewall** (`whombat-egress`, NX-139) opens the private ranges (minus metadata) for the runtime server's uid (TCP and UDP, any port), the browser host's uid (TCP) and the computers' forward chain, statically. The per-burrow switch is enforced inside (server rules, computerd ACL, runner guard); the firewall stays the outer wall for what is never local (LN-02) and for every other uid. The Vault sets (`vault4`/`vault6`, VT-59) stay for the list. | The switch is a burrow setting the server owns; a second, privileged copy of it would need a new file format between runtime and host for no extra safety while it defaults to open. |
| LN-07 | **Copy:** “Agents may reach your local network” — “Agents, their computers and the Vault can reach the devices on your local network, like Home Assistant, a NAS, a printer or a server. Production servers stay closed. Off: only the home networks you list.” Keys log: “Let agents reach the local network” / “Closed the local network to agents (home networks only)”. The home network section: “While agents may reach your local network, all of it is open. When that’s off, only these networks and ports are.” | Says what the switch now does. |
| LN-08 | **Not changed:** link previews, skill links, push endpoints, automation callbacks, pack MCP servers and the managed sandbox (MSB-08 grants) stay public-only. | Not part of the ask; each is reachable by people who aren't the burrow's owners, or runs outside an agent's turn. |
