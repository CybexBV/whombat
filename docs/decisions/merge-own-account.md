# Merging an agent's PR that GitHub shows as your own (MOA-01…MOA-04)

John on DEV (2026-10-03), after “deploy the website” kept failing: “now I see a reject by Whombat?” Banjo opened
PR #2 on the website’s repository through Whombat, which acts on GitHub as John's own account, so GitHub
lists John as the author and won't take his approving review. John approved the merge card (#4); `merge_pr` refused it
in 17 ms with “It needs an approving review (and no changes requested) before it can be merged.” (MDS-03), and nobody
could ever give that review. The repo has no branch protection on GitHub (its plan has none), so the rule was Whombat's
alone.

| ID | Decision | Why |
| --- | --- | --- |
| MOA-01 | **A person's merge is the review of an agent's PR that GitHub shows as theirs.** In `merge_pr`, a person merging (or approving an agent's merge card) needs no separate approving review when an agent opened the PR (`pull_requests.author_id` is an agent) and the GitHub account Whombat acts as (`connectionLogin`) is that person's linked identity (`github_identities`). Changes someone requested still hold it, an agent merging at On still needs a review, and anyone else's merge still needs one (another person can review on GitHub). Extends MDS-D06 (the same rule for Whombat-only repos); GitHub's own branch protection, where a repo has it, still decides on GitHub. | Without it, a burrow whose GitHub connection is its owner's account can never merge its agents' PRs: GitHub refuses the self-review Whombat demands. |
| MOA-02 | **An agent merging at On needs a review only while someone could give one.** Its merge (Merge On, no card) skips the approving review when nobody else could review the PR: no other active team agent (`review_pull_request`; personal, system and retired ones don't count, nor the PR's author) and, for a GitHub repo, no active person other than the one Whombat acts as there (people review on GitHub; a Whombat-only repo has nowhere for them to, MDS-D06). Changes someone requested still hold it; open and green checks still apply. Where a reviewer exists, MDS-03's rule stands. | John on DEV, right after MOA-01: “I tried again, it failed again.” He had set Banjo's Merge (and Push to main) to On; Banjo, the burrow's only team agent, merged without a card and was refused for the same review nobody could give. |
| MOA-03 | **The account Whombat acts as is looked up for the burrow.** MOA-01 and MOA-02 asked `connectionLogin()`, which on a managed Whombat reads the burrow's connection only inside a `githubScope`; a command's `apply` has none, so it fell back to the host's gh and found nobody, and the merging person counted as someone who could review. `GitHubService.connectionLoginFor(burrowId)` runs the lookup in the burrow's scope; `merge_pr` uses it. | John on DEV: “It failed again...” (run #22, 0.36.6 live): the review was still demanded. |
| MOA-04 | **Only an agent that may approve counts as someone who could review.** MOA-02's “another active team agent” is now one whose `pr.approve` the keys engine allows or asks for the repository (`decide(…, 'pr.approve', {repo})` not deny). Team agents don't hold `pr.approve` by default (RA-02's `ALWAYS_ON_EXCEPTIONS`: reviews stay a person's thing), so on John's box Pippa and Dusty counted although neither could approve, and Banjo's merge at On waited for a review nobody could give. Test: `github/local-prs.int.test.ts` (red without the change). | 2026-10-04, John's box, Banjo's run #7 on whombat-app PR #1: CI green, Merge On, refused “needs an approving review”; Banjo asked John for a review GitHub won't let him give on a PR it shows as his own. |
