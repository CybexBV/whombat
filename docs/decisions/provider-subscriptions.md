# Provider subscriptions (workstream `provider-subscriptions`)

Customers sign in to Claude Code and Codex with their **own subscriptions** (Claude Pro/Max/Team/Enterprise,
ChatGPT plans) from the web UI, on a managed appliance and on a self-hosted install. This is permitted by both
vendors' published terms when done the way described here. Decisions are `SUB-nn`; they supersede PV-08 and the
subscription rows of PV-02 (`docs/decisions/managed-providers.md`) and resolve blockers X-01 and X-02
(`appliance/docs/implementation/blockers.md`). Decided by the maintainer on 2026-09-26.

## What the terms say (read 2026-09-26)

**Anthropic — Claude Code legal and compliance** (https://code.claude.com/docs/en/legal-and-compliance), verbatim:

- “Nor does it prevent an end user from signing in to the unmodified Claude Code binary with their own Claude
  subscription, including where a platform hosts Claude Code as described under *Can customers offer Claude Code
  in their products?* above.”
- “Unless we've mutually agreed otherwise, preinstalling or running Claude Code in your products or services (e.g.
  in hosted sandboxes or other agent infrastructure) requires agreeing to our Commercial Terms of Service and
  complying with the conditions below:”
  - “**The Claude Code binary must not be modified.** Claude Code must be installed and run as published by
    Anthropic, and customers may not remove, disable, or restrict any authentication method built into it
    (including methods that permit signing in with a Claude account or the user's own API key).”
  - “**Customers may not pay for, resell, or intermediate Claude usage on their end users' behalf.** Each end user
    must authenticate with their own Anthropic API key, Claude subscription plan credentials, or 3P inference
    provider credential (…). That usage is billed directly to the end user under their own agreement with
    Anthropic (…).”
- “Anthropic does not permit third-party developers to offer Claude.ai login into their own applications, or to
  route requests through Free, Pro, or Max plan credentials on behalf of their users. Moreover, developers may not
  collect, store, or intermediate Claude.ai credentials or session tokens — sign-in to a Claude account must
  complete through Anthropic's own flow.”
- “Advertised usage limits for Pro and Max plans assume ordinary, individual usage of Claude Code and the Agent SDK.”
- Naming: “You can accurately say, in plain text, that your product has Claude Code preinstalled or that it runs
  Claude Code”, but not use the Claude Code/Anthropic names or logos as part of our product or feature names.

**Anthropic — Agent SDK overview** (https://code.claude.com/docs/en/agent-sdk/overview), verbatim:
“Unless previously approved, Anthropic does not allow third party developers to offer claude.ai login or rate
limits for their products, including agents built on the Claude Agent SDK.” The same page documents running “the
CLI as a subprocess with the `-p` flag” as the alternative to the SDK.

**OpenAI — Codex authentication** (https://learn.chatgpt.com/docs/auth): ChatGPT sign-in is the option “for
subscription access”; for remote or headless machines “prefer device code authentication (beta)” — “Run
`codex login --device-auth`”, “Open the link in your browser, sign in, then enter the one-time code” (device code
login must be enabled in the ChatGPT security settings or by the workspace admin). “Treat `~/.codex/auth.json` like
a password … Don't … share it”. “API keys are still the recommended default for automation.” No statement
forbids a ChatGPT login inside a product that runs the official CLI on the user's own machine.

**How others do it (2026-09-26):** T3 Code drives the Claude Code CLI the user signed in to themselves; Hermes
Agent's `claude-subscription-directsdk` runs the official CLI and “never opens, copies, refreshes, or prints its
credential files”. Tools that ran their own Claude OAuth (OpenClaw, OpenCode, Hermes' old route) were cut off or
billed to extra usage. OpenClaw moved to Codex's ChatGPT sign-in.
