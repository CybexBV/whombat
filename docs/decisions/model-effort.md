# An agent's model and effort

John, 2026-10-10: “We have different agents that we can configure with a provider (Claude or Codex), but we cannot set
the model and we cannot set the effort. I would like to be able to configure this per agent.” After the proposal: “Yes,
give Claude agents medium by default and high for coding. For the rest use your recommendations, implement it.”

Before this, `AgentModelRuntime.model` existed end to end (contract, `update_agent`, `turn.ts`, Claude's `--model`,
Codex's `model`) but nothing let anyone set it, and Configure's Save sent the provider alone (a model set through the
API would have been dropped). Codex's effort followed the kind of turn (RA-DS57: `high` for code work, `medium` for
conversation); Claude Code got none and ran at its own default on every turn.

Both tools list their models without a sign-in or a model call (checked 2026-10-10): Claude Code 2.1.296's stream-json
`initialize` answers `models` (`value`, `resolvedModel`, `displayName`, `description`, `supportedEffortLevels` `low`…`max`)
— Default (Opus 5.5), Opus, Fable, Sonnet, Haiku — and Codex 0.162.1's app-server `model/list` answers `data` (`model`,
`displayName`, `description`, `supportedReasoningEfforts` `low`…`ultra`, `isDefault`, `hidden`).

Contracts 0.77.0 (CT-333).

## Decisions

| ID | Decision | Why |
| --- | --- | --- |
| ME-01 | **Model and effort are per agent, next to the provider:** Configure → Model (web) under AI PROVIDER, and Android's Runs on section, for whoever may change the provider today (`agents.manage`, `update_agent`). They are saved with the provider in one `agents.update` `runtime` `{provider, model?, effort?, acpRuntime?}` (the whole model runtime every time, so nothing is dropped). **Changing the provider clears both** (a model id is the tool's own). One Keys line per part that changed: `agentModelChangeText` (“Set Banjo’s model to Sonnet”), `agentEffortChangeText` (“Set Banjo’s effort to High”), beside the existing “Moved Banjo to codex”. A model change starts a new session (the session fingerprint already holds the model); an effort change doesn't (the next turn just sends another effort). Not for scripted agents or ACP runtimes. The hire form stays as it is (default model, automatic effort); `agents.hire` accepts both with the same checks for API clients. | One place people already go to; the provider decides which models exist. |
| ME-02 | **One effort setting per agent, “Automatic” by default.** Automatic: `high` for code work (a run, work handed over, an automation's step with a writable checkout — RA-DS57's rule) and `medium` for everything conversational, **for Claude Code as for Codex** (John). A chosen level (Low · Medium · High · Extra high · Max · Ultra, only those the model takes) applies to every turn, conversations too. Claude Code gets `--effort <level>` on every turn; Codex keeps sending `effort` on every `turn/start`. Separate levels for chat and for work were not built. | John asked for medium by default and high for coding; one knob is enough for most people. |
| ME-03 | **A turn's effort stays within what its model takes** (`turnEffort`): the nearest lower level the model has, else the nearest higher; none sent for a model that takes none. The runner uses its own list (ME-04); unknown list: the effort as set. | A model change never leaves an agent on an effort its model refuses. |
| ME-04 | **Superseded in part by HN-04 (hermes-native.md)**: ChatGPT's models come from Hermes's own catalog (the plugin's `models` step, HN-C07), not Codex's app-server; Claude Code's part stands. **Superseded in part by ME-08**: a Claude model released after the pinned Claude Code is added to its list. **The model list comes from the tools themselves**, read by the runner without a sign-in, a network call or a model call: Claude Code with an empty throwaway config dir (`--setting-sources=`, nonessential traffic off), one `initialize` control request, its `models`; Codex's app-server with an empty throwaway `CODEX_HOME`, `initialize` then `model/list` (all pages). Claude: `default` is left out, the entry whose `resolvedModel` equals default's is `isDefault`; Codex: `hidden` ones left out. Ids are what the tool takes (`opus`, `gpt-6.1-sol`), labels its `displayName`, descriptions without the price segments (“· $4/$20 per Mtok”), efforts filtered to `AGENT_EFFORTS`. Read once per tool version (and again after a failure, at most every 10 minutes), within 20 s, and reported in `ProviderCheck.models`; the server passes it on in `ProviderSetup.models`. **Aliases are stored as they are**, so an agent on `opus` moves to the next Opus by itself. The server checks a new model and effort against the list when it has one (“Claude Code has no model called “x” on this Whombat.” / “Opus doesn’t take Ultra effort.”, `validation_failed` on `runtime`); without one it accepts any id up to 120 characters. An agent whose stored model later leaves the list keeps it (ME-05 covers the turn). | No list to keep by hand; the pinned CLI version decides what exists. |
| ME-05 | **Superseded in part by one-person.md OP-09, OP-S09**: there is no requester, credential owner or organisation key to name; the fallback itself holds. **A model that isn't available falls back to the default for that turn.** When the tool refuses the agent's model (not on this sign-in's plan, not served by the AI gateway, unknown) before the turn did anything — no tool call, no message — the runner runs the same turn once more without a model and reports `CompleteBody.modelFallback {model, detail}`. The server keeps the agent's last fallback (model, where: the requester's or credential owner's name / the organization's key / the gateway's name, when) and shows it as `AgentProfile.modelFallback`: Configure → Model's quiet note `modelFallbackText` (“Fable wasn’t available on Sara’s sign-in, so Banjo used the default model for that turn.”). A later turn on the agent's model, or a change of model, clears it. Never in a conversation; a refusal that isn't about the model fails as before. | A person whose plan lacks the model still gets an answer; the owner sees why. |
| ME-06 | **Words** are contracts' `text/models.ts`: sections MODEL and EFFORT, “Default (Opus)”, “Automatic” with “Medium for conversations, high for code work.”, the fixed-level hint “Every turn uses this, conversations too. Higher thinks longer: slower replies and more usage.”, the profile line `agentModelSummary` (“Sonnet · High effort”, nothing for the defaults). | Plain words for people who aren't developers; web and Android say the same. |
| ME-07 | **Feature `agents.model_effort`** (contracts 0.77, `SESSION_API_LEVEL` unchanged): clients show the pickers only on runtimes that have it. | An older runtime would drop the effort silently. |
| ME-08 | **A Claude model released after the pinned Claude Code takes the place of the one it follows** (John, 2026-11-09: “Anthropic released Fable 5.2, add support for it please”). The pinned 2.1.302 runs `claude-fable-5-2[1m]` when named (checked 2026-11-09: 1M window, `xhigh` accepted) but lists only Fable 5.1; even 2.1.321 doesn't list 5.2 yet. So the runner's list (`claudeModelsFrom`) turns the entry that resolves to Claude Fable 5.1 into Fable 5.2, with its name and efforts: the `fable` alias then means Fable 5.2 (its API id `claude-fable-5-2` for Hermes's own loop), a full id `claude-fable-5-1[1m]` becomes `claude-fable-5-2[1m]`. Whombat's Hermes plugin adds the model to DirectSDK's catalog, with its 1M window, and points `fable` at it (the vendor files stay as upstream), so every agent on Fable moves to 5.2 by itself. A list that already names the newer model is left alone. Fable 5.1 drops out of the picker; an agent stored on its full id keeps it (ME-D08). | Fable 5.2 is better and cheaper ($8/$40 against $10/$50); the pin follows DirectSDK, not Anthropic's releases, and moving the pin is a release of its own. |
| ME-09 | **The `local` provider is labelled “Custom AI model” (“Custom” in short pickers)** across web, mobile, assistant settings descriptions/skills and docs, with help text naming OpenAI-compatible internet services over `https://` (such as OpenRouter or Google Gemini) alongside a model server on the person's own network (such as Ollama or LM Studio). The stored provider id stays `local` (no migration). The design mocks have no local-model screen; this copy deliberately supersedes the earlier “A model on your network” / “Local” wording (`hermes-engine-app.md` AP-5041, AP-5048, AP-5120, AP-5124). | `localModelBaseUrl` already accepts internet HTTPS endpoints with an API key; labelling it only “on your network” hid hosted OpenAI-compatible services. |

## Details

Decided while building it (Whombat side: agent-runtime, runner, server), 2026-10-10.

| ID | Decision | Why |
| --- | --- | --- |
| ME-D01 | **The runner decides each turn's effort** (`TurnInput.effort`: `turnEffort` with its own list; null: none sent). A provider called without one (tests, other callers) sends the agent's own or automatic, unclamped (`turnEffortOf`). RA-DS57's rule is one shared helper, `turnEffortKind` (agent-runtime); `codexReasoningEffort` is gone. | One place keeps an effort within its model; the providers stay usable alone. |
| ME-D02 | **Claude Code gets `--effort` on every turn**, resumed and forked sessions too; none for a model that takes none. An effort the list doesn't vouch for goes as it is: Claude Code 2.1.296 ignores a level it doesn't know with a warning, it doesn't fail. Effort stays out of the session fingerprint. The pinned 2.1.283 ran a real turn with `--effort high` (fixture `acceptedFlags`). | The CLI keeps a session's effort; saying it every turn means a resumed session never keeps another kind of turn's. |
| ME-D03 | **The runner lists models on the host, outside any task sandbox, in both modes**: the executable a turn would run (`clientCommandSync`: an operator's pin, the managed bundle checked against its digest, the self-hosted install, else the provider's own; Codex's npm launcher replaced by its native binary), a throwaway home in the runner's private temp dir (the system's when that isn't private), an environment of `PATH`, the locale and the tool's no-traffic switches only (Claude: non-essential traffic and the updater off; Codex: update check and analytics off). | It uses no credential, runs no prompt, no tool and no model call: what the managed sandbox walls in (a turn's tools, a person's sign-in) isn't there — the same footing as the drift check's `--version`. |
| ME-D04 | **Read in the background** after a check finds the CLI installed (ready, or signed out: a gateway turn needs no sign-in), keyed by the version the check reported; in memory only (a restart reads again, ~0.2 s each); a failure keeps no list, says so in the log and tries again at most every 10 min. The server shows the reporting runner's list, else the latest any runner reported for that tool. | Startup and claims never wait for it; one read per version is enough. |
| ME-D05 | **A refused model is told apart conservatively** (`modelRefused`, pure): Claude Code's own code `model_not_found`, or a message that says a model wasn't found / doesn't exist / isn't available, supported or served / can't be accessed and names the model, “the selected model” or `model:` — never one that mentions a sign-in, a key, a limit, billing, an overload or the context window, and never when the provider classified a credential state. Error events now carry the provider's own code (`TurnEvent` `error.code`: Claude's `assistant.error`, Codex's `codexErrorInfo`). Only on the first attempt, for an agent with a model, before any tool call, tool result, permission, answer or follow-up. | A wrong retry would hide a real failure behind the default model. |
| ME-D06 | **The retry** resumes what the first attempt resumed (a resumed session keeps the refused request, as when a person picks another model and sends again; a fresh session the refusal started is dropped; a fork copies the conversation again), takes no follow-ups (the first attempt closed them; they run as their own turns) and keeps its effort within the default model's. Once only. `modelFallback` goes with the completion whatever its outcome: a default that fails too fails as before and still says the fallback. | Same turn, same context; nothing else changes. |
| ME-D07 | **ACP runtimes and the scripted demo keep no model or effort**: `agents.update` and `agents.hire` drop them, as `acpRuntime` is dropped for other providers, rather than refusing. | Clients send the whole model runtime; the two that can't use them have nothing to keep. |
| ME-D08 | **Only what changes is checked**: an agent whose model has left the list keeps it with the next save; an unchanged effort is checked again only with a new model. Too long: “A model’s name has at most 120 characters.” The Keys line of a provider change no longer carries “(model)”: “Moved Banjo to codex”, and a model or effort chosen with it gets its own line; a provider change that only clears them says nothing more. Lines of one save are joined with “. ”. | ME-04's rule for stored models; one line per part (ME-01). |
| ME-D09 | **The fallback is `principals.model_fallback`** (jsonb, migration 0101: `{model, where, at, detail}`), written in the completion's transaction, kept only while the agent still has that model. The tool's words (`detail`) stay in the column and the server log, never in the profile. Any `done` completion without `modelFallback` clears it (older runners too); a failed one with it keeps it. No realtime frame of its own: the agent's status settle after every turn publishes `agent.updated`. | One nullable column; ME-05's “a later turn on the agent's model clears it”. |
| ME-D10 | **Superseded in part by one-person.md OP-09, OP-S09**: there is no credential source to read; a turn through the AI gateway still names the gateway, and any other ran on the person's own sign-in or API key. **Where it ran**: a dispatch that started through the AI gateway → `gateway` (the switched connection's name, else none: “through the AI gateway”); else the agent's credential source — `requester` → the person the work was for (their short name), an organization credential (also a `requester` source's fallback for work for nobody) → `org`, a person's own sign-in or a personal agent's → that person. A self-hosted agent without a source runs on the operator's own login, the Whombat's rather than any member's: `org` (“on the organization’s key”). | The same reading of the source as usage attribution (`usage.fromTurn`). |
| ME-D11 | **Fixtures**: the Claude Code fixture is regenerated with `--effort high` on every turn; the Codex fixture adds `model/list` (stable: `cursor`, `includeHidden`, `limit`), regenerated from the pinned 0.157.0 (npm tarball, integrity as pinned). The model lists themselves are recorded from Claude Code 2.1.296 and 2.1.283 and Codex 0.162.1 (`packages/agent-runtime/src/models/fixtures`); `live-models.test.ts` runs the real binaries when `WHOMBAT_CLAUDE_PATH` / `WHOMBAT_CODEX_PATH` name them. | What Whombat sends and reads is checked against the pinned binaries, as before. |
