# Open to the internet (EXP-01…EXP-14)

John, 2026-11-28, the look-after build: “What can the internet reach?” Whombat already reads the proxies, tunnels and
routers in the house; one page puts their openings together in plain words, says what it couldn't see, and tells the
person once when something new opens. Everything here keeps “What Whombat watches starts calm” (`watch-defaults.md`),
on-purpose (`on-purpose.md`) and checks never made from outside the house (`monitoring.md` MON-16).

| ID | Decision | Reason |
|---|---|---|
| EXP-01 | **An opening is what a connected thing's settings let in from the internet**: a proxy host or stream of Nginx Proxy Manager, a public name of a Cloudflare tunnel, a port forward of OPNsense or of a UniFi console. Whombat reads only those settings; it never checks from outside. A redirection host leads nothing inside and isn't listed; neither is a name only the house knows (`.lan`, `.local`, `.home.arpa`, `.internal`, `.ts.net`, an address). | The settings are where an opening is made, and Whombat already has the sign-in for them. Checking from outside was left out on purpose (MON-16). |
| EXP-02 | **Open to the internet is a page in the Servers place** (`/internet`): a row at the end of the Servers list on the web and the phone, with What’s protected beside it as the same kind of row, the list beside it on a wide window, “‹ Servers” on a narrow one. Every new opening's line links to it. It isn't in Settings: What Whombat watches is per thing, and there is no Settings-wide watch area to hang it on. | It is about what the servers expose, and the Servers list is where people look at them. |
| EXP-03 | **One row per opening**, worth a look first, then what is new, then by address: the address and what it leads to (“photos.example.com → Immich on pve-02”: a connection answering on that address and port, else a server or guest with that address, else the target), how it got there (“Through Nginx Proxy Manager”, “Cloudflare tunnel ‘house’”, “Port forward ‘Plex’ on UniFi Network · TCP”) and how it is guarded (HTTPS, an access list, Cloudflare Access, only from some addresses, nothing in front of it, or “Whombat can’t tell what guards it”). Under it: This is meant (only on what is new or worth a look), Ask {assistant} (a new thread about the place whose settings opened it), Open {thing} and Change it in {place} (its own page; Cloudflare's Zero Trust). The box words it all in the owner's language. | The person sees what is open and what it means without knowing the service, and the change itself stays in the service that made it. |
| EXP-04 | **Where Whombat looked, and what it couldn't see**: under the openings every place it read, with what it couldn't read there (streams it may not read, a tunnel set up on its own server whose names aren't in Cloudflare, Access it may not read, UPnP switched on, who may use Tailscale Funnel) and, when no OPNsense or UniFi is connected, “Your router” with Add a connection. Under the list: Whombat reads settings and never checks from outside, so something set up elsewhere can still be open. | The page must never look complete when it isn't. |
| EXP-05 | **The reads**: GETs with the connection's own sign-in, kept 10 minutes (the health pass asks every 5, settings change seldom). Nginx Proxy Manager's proxy hosts with their certificate and access list, and its streams; Cloudflare's tunnel settings (at most 20 tunnels) and Access applications per account; OPNsense's destination NAT rules (`/api/firewall/d_nat/search_rule`, OPNsense 25.7 and later; enabled WAN rules that redirect) and whether its UPnP service runs; UniFi's port forwards and UPnP switch through the console's older API with the same key (its official API has no port forwards); Tailscale's policy, for who may use Funnel. Endpoints that answer private keys are never asked. | Each is the one place that setting lives; no new sign-in, no new permission. |
| EXP-06 | **UPnP and Funnel are notes, not openings.** Neither OPNsense nor UniFi lists UPnP's mappings through an API, and Tailscale's API says only who may use Funnel, not what a device shares. The place says so (“UPnP is on: devices in the house can open ports by themselves, and Whombat can’t see which.”). Whombat doesn't discover routers over UPnP (SSDP) for this. | Saying what can't be seen beats a list that looks complete. A scanner on the house network for one fact isn't worth its noise. |
| EXP-07 | **Worth a look, few and certain**: a management page with nothing in front of it (what it leads to is a Proxmox, TrueNAS, Synology, QNAP, Unraid, Portainer, OPNsense, UniFi, Nginx Proxy Manager, Pi-hole, AdGuard or Pterodactyl connection, or a port only management uses: 23, 445, 3389, 5900, 8006, 8007, 9443, 10000), a proxy host whose certificate has ended, a proxy host without HTTPS. One per opening, the most serious. It is a highlight on the page: no line, Inbox item or push of its own. Ports others use too (8080, 8443, 5000) don't count. | A highlight that is wrong teaches people to ignore it; the new-opening line (EXP-08) is the one that tells. |
| EXP-08 | **Something new is open to the internet** (`exposure.new`) is a check of Nginx Proxy Manager, Cloudflare, OPNsense and UniFi connections, per item, asking the person, amber: one line per new opening on the connection whose settings opened it (“photos.example.com is open to the internet now” · “It leads to Immich. Is that meant?” · See what’s open), so an Inbox item with Stop watching and no incident or push. Ignore lasts until it closes. Tailscale has no such check: it opens nothing itself. **It starts on**: something newly reachable from the internet is a possible security opening, and Whombat can tell the person what it leads to. | The one moment worth interrupting for is a change: what was open yesterday the person already knows about. |
| EXP-09 | **The first list is silent.** Per connection, the first complete read is kept as its first list and says nothing; a read that missed part of a place adds what it saw silently until one is complete. After that, each opening not seen before is new. A closed opening goes quietly; back within 30 days it isn't new, closed for longer it is forgotten. An opening is its place, how, address and where it leads: pointing a name somewhere else is a new opening. | Connecting a proxy with twenty hosts must not raise twenty lines; switching a host off and on must raise none. A changed target is a real change. |
| EXP-10 | **This is meant is Stop watching that one opening** (`things.setWatch`, check `exposure.new`, subject `open:<id>`): the line, its Inbox item, New and the highlight go together, the toast has Undo, the page offers Point it out again, What Whombat watches lists it with the place's exceptions and Activity keeps it. | It is the on-purpose machinery (`on-purpose.md`), not a second one. |
| EXP-11 | **Only fingerprints are kept**: `exposure_openings` (the connection, the opening's id — a hash of place, how, address and target —, first and last seen, whether it was in the first list). Names, targets and guards are read again each time. Last seen is written at most once an hour. | Nothing about the house's network sits in the database that the place itself doesn't hold. |
| EXP-12 | **The assistant reads it**: `internet_exposure` (read-only, the person's turns) gives each opening in one line with how it is guarded, worth a look, new and meant, and each place with what it couldn't see, saying it is never the whole picture. A look on an `exposure.new` line reads it, says what it exposes, asks whether it is meant and, on the person's word, switches that one opening's check off with `watch_checks`; it never closes an opening itself. | “What can the internet reach?” and “Is that new opening safe?” are questions people ask; closing an opening is a change in another service. |
| EXP-13 | **Contracts**: `things.exposure` (GET `/burrows/:burrow/exposure`, the person only, a read), session minor 22. An app talking to an older Whombat shows no row and no page; an app from before it gets the line's `/internet` link, which it doesn't know. | Additive, like every page before it. |
| EXP-14 | **Left out**: checks from outside, router discovery over UPnP, the firewalls of cloud providers and ports a public server opens itself, a history of changes (the change log's part), certificates that end soon (an uptime check says that, MON-02). | Few sources read well beat many read badly; each can come later with its own reader. |
