# The council (CNL)

John, 2026-11-05 (main checkout), after reading T3 Code's council skill (independent reviewers on different providers,
fresh each round, a score out of 10, at most three rounds): “I think we should implement a council in Whombat when we
have more than one AI provider […] Especially in combination with T3 Code Connection […] I simple ask Dusty to ask the
council to improve the UI of a project until the council independently score the new UI 9/10. Or I want to use the
Council to research something.” Then: Dusty is the orchestrator, one T3 Code thread per member, a waiting card in Chat
with the members' provider marks and Dusty's running thoughts, the final message when all are in; for UI work Dusty
shows the new UI with its explanation in pictures; a council optimizes a project (each member researches on its own,
Dusty makes one plan from their input, they all agree on it). “Implement this fully.”

## What a council is

| # | Decision | Why |
|---|---|---|
| CNL-01 | **Superseded by CNL-80 (one T3 Code thread leads it; Whombat reads along).** **Whombat runs the council and the agent leads it.** A council is a question or a goal the person gave the agent in a Chat thread, put to 2–4 AI models of different providers, each working on its own. Whombat's server keeps the council (`councils`, `council_members`), starts each member, reads what it answered, keeps the score and wakes the agent; the agent writes the briefs, the plan and every word the person reads, and decides what to take from the answers. | John: “Why not use Whombat / Dusty to be the orchestrator instead and simple launch a new thread in T3 Code per council member”. Counting who is in, timeouts, round limits and independence are bookkeeping a model does badly across many wakes; the words and the judgment are the agent's. |
| CNL-02 | **Three kinds.** `review`: one round, each member reviews and scores, the agent sums up. `research`: each member researches, the agent writes one answer or plan from theirs, the members agree on it, then the report. `improve`: each member looks at the project and proposes, the agent writes one plan, the members agree on it, the person says go ahead, one builder carries it out, the members check the result and score it, and fixes go back to the builder until the target score is met. | John's two examples (improve a UI until 9/10, research something) and the review T3 Code's council mostly does. |
| CNL-03 | **Members run as T3 Code threads** on the person's computer: a council needs a T3 Code connection at Manage, and members are the providers T3 Code can run there now (`orchestrator_capabilities`: switched on, signed in, with models). Members on the box itself are not built (Not now). | T3 Code already runs Claude, Codex, Muse and others with their own sign-ins and tools, the project's checkout and a browser. |
| CNL-04 | **Superseded in part by CNL-92 (four seats, Claude Opus 5.5 at xhigh, Antigravity’s Gemini 4 Neon).** **Superseded in part by CNL-50…CNL-53 (the person's council; one company may sit twice).** **Different providers, never one provider twice.** By default one member per provider T3 Code can run, at most three, in T3 Code's order; each provider's best model — T3 Code's own council's choice where the provider has it (GPT 6.1 Sol, Claude Fable 5.2 else Claude Opus 5.5, Muse Wonder Full 1.0), else the first it lists — at that council's effort for it (Fable at `high`), else `xhigh` where it has it, else `high`, else its default. Fewer than two providers: no council, and the agent says why in a line. | T3 Code's council skill: “Do not … use three models from one provider.” Different providers have different blind spots; three Claudes share theirs. |
| CNL-05 | **Only when the person asks.** The agent may suggest a council for a big job, but starts one only on the person's word. Only the person's own turns are served the council tools (never an automation's step, a brief or an outsiders' turn). | A council at xhigh is three expensive agents per round. |

## Rounds

| # | Decision | Why |
|---|---|---|
| CNL-10 | **Superseded by CNL-80 and CNL-81 (the lead starts each round’s reviewers; Whombat reads their titles).** **Every round is new threads.** Each round starts one new T3 Code thread per member with Whombat's brief and the agent's words; a member never sees another member's answer, score or name, and never the earlier rounds'. Its title is “<agent> - Council · <member> · <stage> <n>”, and Whombat settles it once its answer is in (as T3-21). | Independence is the point; a reviewer that saw the others' scores anchors on them. |
| CNL-11 | **Members are read-only and answer in a fixed shape.** The brief says: work on your own, change nothing, don't ask (decide yourself and say what you assumed), don't start helpers or a council; end with `Score: n/10` when asked to score and `Verdict: agree` or `Verdict: changes needed` with the must-fix items when asked to judge. Whombat reads the last answer (up to 12,000 characters) and takes the score and verdict from those lines; none there is “no score”, never a guess. | The card and the target need numbers Whombat can trust; a missing score is shown as missing. |
| CNL-12 | **Superseded by CNL-85 in part (the lead keeps to the rounds; Whombat tells it once when it goes past them).** **At most three rounds to agree and three to check** (the person may ask for up to five). When the limit is reached Whombat refuses another round and the agent finishes with the plan or result as it is and the disagreement left. | Fresh reviewers find new small things every round: the target moves unless something stops it. |
| CNL-13 | **The plan says where each idea came from and what was dropped**, and the members judge that plan. | The agent runs on one provider and could favour its ideas; the dropped list lets members object. |
| CNL-14 | **Superseded by CNL-85 (the lead is told to go on without a late reviewer; the lead has twelve hours).** **A member has an hour, the builder four.** A member that hasn't answered by then is stopped (`t3_thread_interrupt`) and counts as “didn't answer”; a round is in when every member answered, failed or ran out of time. A member that asks a question wakes the agent as any T3 Code thread does (T3-17), which answers it itself. | A council never waits forever; an incomplete one says so. |

## One lead thread in T3 Code (John, 2026-11-13)

John asked how the council and the hand-over could be as efficient as running them in T3 Code itself. Measured from T3
Code's own records: a member's run costs the same either way (median 4.6 minutes in a Whombat council, 6.0 in T3 Code's
council skill, the same thread on the same model), and the agent heard of an answer within a minute. The fix loop was
the gap: where T3 Code's coordinator fixes in the checkout and asks again (17 minutes median between rounds), a
Whombat council went through the agent, a Tasks card, its Hand over, a lead thread, a pull request, the combined check
and the merge before it could check again (26 and 50 minutes a fix round, 230 minutes from the agreed plan to the
first check), and the agent, which can't see the code, could neither check a finding nor give the reviewers evidence.
John: “I don’t want Whombat to replace T3 Code, I want to use it as optimally as possible and offload as much as
possible to it, but keep the ui/ux experience in Whombat.” Then: “Implement this fully.”

| ID | Decision | Why |
|---|---|---|
| CNL-80 | **Superseded in part by CNL-89, CNL-90 (the lead runs on the chat’s AI and isn’t on the card).** **One T3 Code thread leads the council; Whombat reads along.** `council_start` starts one lead thread with the council's brief: what was asked as the agent wrote it and, when the person's own message started the turn, their words unchanged (t3code.md T3-49; `council_tell` carries them too), the seats as `delegate_task` takes them (provider instance, model, options), the rounds and the target. The lead runs on the council's builder seat, shows on the card as the Lead, and Settings calls that seat “Leads the council”. | The coordinator has to be where the code is. Whombat's sign-in already lists and reads a thread's `subagent` children (report-trackers.md TA-57). |
| CNL-81 | **The method is T3 Code's; the brief fixes only what Whombat reads.** The lead follows its own council skill where it has one (the brief wins where they differ), and the brief stands on its own where it has none. One Whombat can't keep is left out, never stopping the others.
