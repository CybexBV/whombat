# Workstream: the skills library (SL)

Workstream `agent-capabilities` (2026-09-28; assignment `docs/implementation/agent-capabilities/assignment.md` §4;
research: `~/.cache/wb-tmp/research/2026-09-27-agent-platforms/whombat-vs-hermes-buzz.md` §3, B-1…B-9). Skills become
something people see and switch per agent, roles bring the right skills, agents propose skills a person approves, a
shipped catalog is ported from Hermes Agent and Anthropic's skills, and non-coding agents get a throwaway scratch
workspace to run a skill's scripts.

Contracts 0.20.0 (CT-119…), runtime migration `0048_capabilities`, app 0.11.0 (AP-195…), appliance candidate 0.18.0.
Binding and unchanged: BP-D01…BP-D25 (packs; a pack approves nothing, owners attach — BP-D06; front matter is name
and description only — BP-D20; per-turn read-only materialization — BP-D12), BP-B04…BP-B08 (the proposal pattern),
BP-06, BP-07, PA-01…PA-10, MR-44, BP-C38 (the runner's private scratch space).

## Decisions (the assignment's requirements, settled)

| SL-01 | **Skills switch per agent.** Table `pack_skills_off (burrow_id, attachment_id → pack_attachments cascade, agent_id → principals, skill, set_by_id, set_at; primary key (attachment_id, agent_id, skill))`: a row means “this skill of this attachment is off for this agent” — for an agent's own attachment the agent is its target; for a burrow-wide attachment an owner switches a skill off for one agent at a time (there is no “off for everyone” other than detaching). | SL-02 | **Packs declare the roles they suit and what each skill needs.** Manifest `roles?: AgentRole[]` (≤ 18, unique, validated against the enum including the six new roles) and per skill `requires?: ('workspace' \| 'web' \| 'browser')[]` (unique). `skillReadiness(requires, agent)` (core, pure) answers the labels the UI and the prompt use: “needs a scratch workspace” (`workspace.scratch` or a writable checkout), “needs the web key” (`web.browse`), “needs the browser key” (`browser.use`). Android: the existing Packs screen gains per-skill switches (44 dp), nothing else. | One place for skills; everyday switching on the phone. |

Files the agent wants to share go through `upload_file` (the prompt says so). Default `can` for Analyst, Writer, Designer, Finance, Tester and Product (AR-05). Personal agents may hold it (`personalAgentMayHold`): without the web key the directory has no network. | Skills with scripts (documents, spreadsheets) need somewhere to run; a throwaway folder in the existing sandbox gives that without a repository or credentials. |
| SL-06 | **Agents propose skills.** Each agent that proposes gets an own pack `own-<handle>` (name shortened with a hash suffix when the handle is long; `packs.owner_agent_id`, publisher the agent's name, `created_by: agent` on its versions) whose versions exist only through approvals. | SL-08 | **Scanner** (`scanPack` in core, pure, unit-tested; run by `validatePack` and by proposals): categories `exfiltration` (network calls that carry environment variables, secrets or files — `curl`/`wget`/`fetch`/`requests` with `$…`/`env`/`os.environ`/`process.env`/`~/.ssh`/`.aws`; long base64 or hex blobs; DNS/pastebin/webhook exfil hosts), `injection` (“ignore previous/all instructions”, “you are now”, role-override and system-prompt phrases, fake delimiters `[[pack`, `[[memory`, `[[web`, `</system>`, hidden Unicode tag/bidi controls), `destructive` (recursive deletes of `/`, `~` or `*`, `mkfs`, `dd of=/dev/`, `git push --force` to shared branches, `DROP TABLE`/`DROP DATABASE`, `TRUNCATE`, `chmod -R 777 /`), `persistence` (crontab, systemd units, shell rc files, git hooks, `authorized_keys`, launch agents). Each finding `{category, severity: caution \| dangerous, path, line, excerpt ≤ 120}`; the verdict is the worst severity (`safe` when none). `dangerous` is refused (problem code `scan`), `caution` is stored on the version (`pack_versions.scan`) and shown on the pack and the proposal card. Applies to uploads, bundled packs and proposals alike; code blocks in prose count (a skill that tells the agent to run it is the risk). | Hermes' skills_guard categories on top of BP-D02's refusals; people see why. |

Android renders the chip and sends it from a typed `/name` when the agent holds the skill. | The quickest way to say which skill a request needs. |
