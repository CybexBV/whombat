# Seed wiring

Workstream: wiring `@whombat/fixtures`'s mock world onto `apps/server/src/seed/world.ts`'s `SeedWorld`
shape, so `pnpm db:reset && pnpm db:seed` loads "Burrow HQ" exactly as the design-handoff mocks show it.
The mapping itself lives in `packages/fixtures/src/seed.ts` (`seedWorld()`), picked up automatically by
`apps/server/src/seed/source.ts`. One file per workstream, per `CLAUDE.md`; this one doesn't reopen
anything in `DECISIONS.md`, `docs/decisions/fixtures.md` or `docs/decisions/server-core.md`.

| SW-13 | Three narrow type-only fixes made compiling `apps/server/src/seed/fixtures.int.test.ts` (the first `apps/server` file to statically import `@whombat/fixtures/fetch`, whose `exports` map points straight at `packages/fixtures/src/fetch.ts`'s TS source) work under `apps/server/tsconfig.json`'s Node-only `lib` (`["ES2023"]`, no `DOM`): (a) `fetch.ts#createFixtureFetch()`'s returned function now takes `input: string \| URL \| Request` instead of `input: RequestInfo \| URL` — `RequestInfo` is a DOM-only type alias (`Request \| string`) that `@types/node`'s own `fetch`/`Request`/`Response`/`RequestInit` globals (from `undici-types`) don't define, while `string \| URL \| Request` is the exact expansion and so is identical under `packages/fixtures`'s own DOM-lib tsconfig too; (b) `fetch.ts#handleAgentsHire()`'s and the `messages.send` case's `await req.json()` are now explicitly cast (`as {...}`), and (c) `fixtures.int.test.ts#serverCall()`/`fixtureCall()` are now typed to return `Promise<Record<string, unknown>>`, with the audit-list test's `fixture.events`/`fixture.counts` accesses cast accordingly — `undici-types`' `Body.json()` is typed `Promise<unknown>`, unlike DOM lib's `Promise<any>`, so property access and object spreads on an un-cast result fail to typecheck only under `apps/server`'s Node-only `lib`. No behavior changed by any of the three; `pnpm -r typecheck` is clean across the whole monorepo after them. | Adding `"DOM"` to `apps/server/tsconfig.json`'s `lib` (the alternative fix) was rejected: it would pull DOM's `Response`/`Request`/`Headers` declarations into every other `apps/server` file's compilation too, risking clashes with `@types/node`'s own (undici-backed) globals of the same names — a known common pain point combining Node types with DOM lib in one `tsc` program. Narrowly re-typing the three actually-DOM-only-shaped spots in `packages/fixtures` and the one new test file avoids that risk entirely and keeps `apps/server`'s `lib` Node-only, matching every other file in the app. |

## Integration test

`apps/server/src/seed/fixtures.int.test.ts` seeds `@whombat/fixtures`'s `seedWorld()` into a throwaway
Postgres database (its own `useTestDb()`/services/app — not the shared `useTestServer()` harness, to avoid
any risk to other workstreams' tests that rely on `useTestServer({seed:true})`'s current `testWorld()`
default) and, for bootstrap, each conversation's messages, the thread, the run, the approval, the agents
list, each agent profile, the audit list (with filters/counts), search results and canvas meta, compares
the real server's HTTP response (`app.inject()`) against `createFixtureFetch()`'s response for the same
request — both built from the exact same `Endpoint` (`buildPath`/`toQueryString`), so any drift is a real
behavioral difference, not a URL-construction one. Only genuinely volatile fields (server-generated
`accountId`s, `serverTime`, and similar) are normalized before comparing.
