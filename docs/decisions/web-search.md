# Web search with a Brave Search key (WSK)

The agent had no `web_search`: Hermes's config turns its keyless search off (`web.keyless_fallback: false`, no anonymous
traffic to Exa, Parallel or the others) and nothing gave Hermes a search backend, so its web toolset never loaded.
Scraping Bing or DuckDuckGo from the commands meets bot walls. John (2026-11-15): keep writing `config.yaml` every turn
and keep the keyless fallback off; add a proper setting Whombat writes into the config; make it as simple as possible
(a direct link to Brave's API key page, one field, done); Brave first, no big provider picker; web search stays under
“Browse the web”. Ids WSK-01…WSK-12.

| # | Decision | Why |
|---|---|---|
| WSK-01 | **Brave Search only**, one key per Whombat (`Burrow.webSearch`, `burrows.web_search` + the sealed `web_search_key_enc`). No provider picker; SearXNG is not offered now. | John: Brave first, keep it simple. A SearXNG address would need its own reachability rules from Hermes's sandbox (the home network, a public one) and its own check; not cheap. |
| WSK-02 | **Settings → Advanced → AI on this Whombat → Web search**, after “A model on your network”, on the web and the phone. Off: a button “Get a Brave Search key” straight to `https://api-dashboard.search.brave.com/app/keys`, a small “No account yet? Sign up” to `…/register`, one password field, Save. On: a dot, “On, with your Brave Search key.”, the last check, Check again, Use another key, Remove. Words in `WEB_SEARCH_COPY`. | It holds the other things the AI on this box uses (programs, the gateway, a local model). The person's whole job is: open Brave, copy a key, paste it. Both Brave pages checked on 2026-11-15. |
| WSK-03 | **The copy says what Brave asks**: about 1,000 searches a month free ($5 monthly credit since February 2026), and signing up asks for a card. | Brave dropped its free plan for a monthly credit; the person shouldn't be surprised by the card. |
| WSK-04 | **Save checks the key first with one search** (`burrows.setWebSearch`; `q=whombat&count=1`, at most 15 s, through `lib/outbound.ts`). A key Brave turns away (401, 403, 422 `SUBSCRIPTION_TOKEN_INVALID`) is `validation_failed` on `apiKey` and nothing is saved; no credit left (402, 429) or no answer saves with that check shown. `burrows.testWebSearch` checks the saved key again. | “A check that the key works” without a separate Test button. A key that is right but out of credit, or Brave being down, shouldn't stop the person. |
| WSK-05 | **The key stays on the server like a local model's** (sealed with key custody under `burrow_web_search:<burrow id>:key`): only the runner, for the person's own turns, and a backup file get it opened, never a client or a log. Setting, changing and removing it signs `burrow.web_search_changed` (Keys, never the key). `burrows.setWebSearch` is a secret session op. | The same rule as every key the agent uses. |
| WSK-06 | **The turn's key: `DispatchContext.webSearch`**, in the person's own turns only, never an outsiders' turn or an assessment. | Outsiders' turns are deny by default and must not spend the person's credit. |
| WSK-07 | **Hermes gets the key in a file of the profile, `whombat-web-search.key` (0600)**, written before a turn that may browse (“Browse the web” not Off) or a pod's turn, removed otherwise — never in `config.yaml`, the environment or `.env`. | HE-S49's rule: keys reach Hermes from files. Hermes's `.env` would be loaded into its process environment for its life, so a pod's Hermes would keep a removed or replaced key until it restarts. |
| WSK-08 | **The plugin's `whombat-brave` backend is Hermes's Brave backend on that file** (`whombat_hermes/web_search.py`: a subclass of `BraveFreeWebSearchProvider`, its endpoint, request and result shape, the key read at every availability check and every search). `config.yaml` names it (`web.search_backend: whombat-brave`) only while the turn has a key; `keyless_fallback` stays false. Without the key file it isn't available and Hermes offers no `web_search`. | The tool shows up by itself when set, and goes at once when removed, also in a long-lived pod. Hermes's own `brave-free` reads only `BRAVE_SEARCH_API_KEY`. |
| WSK-09 | **“Browse the web” gates it as before**: `web_search` is under `web.browse` (Allowed runs, Ask asks, Off blocks). | John's choice; nothing new for the person to set. |
| WSK-10 | **Search only: `web_extract` is refused with the way that works** (“open them with the browser tools, or fetch them with curl in your commands”) while “Browse the web” isn't Off. | Brave has no page reader here; Hermes's own error would ask the agent to configure an extract backend. |
| WSK-11 | **No line in the prompt.** The tool appears when set up; the settings skill (`whombat:settings`, from the settings map) names the page, so `settings_find` finds “web search” when the person asks. | Every prompt character is paid in every turn; the agent needs nothing to use a tool it is offered. |
| WSK-12 | **No contracts release**: the new ops, the burrow field and `DispatchContext.webSearch` are additions that only this repository's box, runner and apps use; a backup file keeps its schema version (an older reader leaves web search out). The migration `0001_web_search` is `expand`. | control, the relay and the appliance don't read any of it. |
