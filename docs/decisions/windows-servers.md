# Workstream: Windows PCs as servers (WIN)

The look-after build, 2026-11-28: “Windows PCs as servers: a Windows build of the hosts agent, a Windows service, an
install line, collectors, self-update, an Add a server choice.” A Windows PC is watched and restarted like any server;
Whombat reads its updates and virus protection but leaves changing them to the person.

## The agent on the PC

| ID | Decision | Reason |
|---|---|---|
| WIN-01 | **A Windows PC is a server like any other, through the same agent.** `whombat-agent` has a Windows build (`windows/amd64`, `windows/arm64`, cgo-free, `whombat-agent-windows-<arch>.exe`) that dials out to the hosts service, enrolls with the one-time code, reports, buffers through outages and updates itself like the Linux and Mac agents. The server's platform is `windows` (`detail_view` and `os_family` `windows`). Windows-only code is behind build tags and uses `golang.org/x/sys/windows`; its parsers are tested on Linux. | One agent and one hub for every kind of server: pages, alerts, switches, signed updates and the assistant's tools already exist for agents. |
| WIN-02 | **It runs as the Windows service `whombat-agent`** (“Whombat agent”), as LocalSystem, started at boot. Windows restarts it 5, 10 and 30 seconds after it fails, also when it stops with an error, and forgets the failures after a day. A reload (a switch allowed on the PC) is the service's parameter-change control; a restart after an update is an exit the service manager answers with a start. | LocalSystem reads Defender, BitLocker and Windows Update and can restart the PC; the service manager is Windows' own supervisor, as systemd and launchd are elsewhere. |
| WIN-03 | **Where it lives**: the program in `%ProgramFiles%\Whombat\whombat-agent.exe` (not on the PATH); its settings, identity and state in `%ProgramData%\Whombat`, and nowhere else: enrolling, installing the service and running the agent (as the service or in a console) refuse a settings or state folder outside it, also a state folder its `agent.toml` names. Before any of them reads or writes there, the agent creates that folder as its own or takes it over. It trusts only what nobody but SYSTEM and the administrators could have written: whatever someone else owns or may change (the folder itself or anything in it) moves out whole and unread, beside it as `Whombat.set-aside-<time>-<n>`, and the agent says so on the screen and in Windows' Application log. What stays becomes its own: the administrators own each folder and file, only SYSTEM and the administrators are on its access list, and a folder inherits nothing from above; what the agent writes is the administrators' too, whatever Windows' default owner policy says. It checks each result, refuses links (symbolic links, junctions, mount points) and files with a second name there, and doesn't start on a folder it can't make its own; the service says why in Windows' Application log, `enroll` and `service install` on the screen. | Program Files is where Windows expects programs and is admin-only to write; the identity's key must not be readable by other users. Every user may create folders in `%ProgramData%`, so one made before the install, or a link left in it, would otherwise let them read the key or change the scripts the agent runs as SYSTEM; and what they wrote there before the takeover (settings that send the state elsewhere, a rollback note naming their program) would stay theirs if the agent adopted it. Moved aside, it is out of the agent's reach and nothing of theirs is deleted, and a handle they opened earlier, which keeps its rights until it is closed, points outside the agent's folder. |
| WIN-04 | **What a PC reports**: CPU, memory, the page file, each drive's fill (with when it is full), uptime and last boot, the network adapters and their rates, and its processes. Its own facts come from PowerShell scripts the agent runs as SYSTEM: the version and build, maker and model (every minute); Microsoft Defender, Windows Security's antivirus list, BitLocker per drive and the physical disks' health (every 5 minutes); Windows Update's waiting updates, security ones among them, a pending restart and when it last looked and installed (every 30 minutes). Windows Update is asked for its own last search only, never to search online. No temperatures. | Windows answers these through CIM and its own COM objects; asking Windows Update offline keeps the agent from calling Microsoft or starting downloads, as the Linux agent never refreshes package lists. Windows tells no temperatures without the maker's tools. |
| WIN-05 | **Virus protection is on, off or not known.** On: Defender protects the PC (normal mode, running, real-time protection on), or Windows Security lists another antivirus that is on. Off: Windows Security lists none that is on, or a Windows Server's Defender runs with real-time protection off. Not known: a Windows Server whose Defender doesn't run (another product may protect it). | Windows 10 and 11 have Windows Security to ask; Windows Server doesn't, and saying “off” there would be wrong for a server with another product. |
| WIN-06 | **What Whombat watches on a PC**: on from the start, the existing rules (not checking in, a failing disk, a drive nearly full) and **virus protection off** (`windows.protection_off`, a warning; its words say how to turn it on, with real-time protection named when Defender is there but off). Off from the start: virus definitions older than 7 days (`windows.signatures_old`, information), updates waiting and a pending restart (the existing rules). BitLocker is shown, never watched. | `docs/decisions/watch-defaults.md`: a PC with no virus protection is a security opening now and only the person can fix it, so Whombat says what to do; old definitions are Windows' own business and catch up by themselves; a data drive without BitLocker is a choice. |
| WIN-07 | **Actions on a PC**: restart and shut down go through the existing power switch and approval; the PC runs `shutdown.exe` with a notice to whoever is signed in and 15 seconds before it closes their apps. Commands (`server_command`) run in Windows PowerShell as SYSTEM behind the host-shell switch. Look inside lists processes, listening ports, services and waiting updates. A PC has no console, screen or guests in Whombat. | The same switches as a Linux server; a person at the PC sees a restart coming. |
| WIN-08 | **Whombat doesn't install Windows updates.** It reads them and offers the restart they need; the page says to install them in Settings → Windows Update, the assistant's `server_update` refuses on a PC with the same words and `server_updates` says it can't install there, and a PC's care plan has no updates step. | Windows Update restarts the person's own computer at times it chooses (active hours, its own schedule); installing from outside goes round what the person set there and can leave a PC half-updated. Proposing is enough. |
| WIN-09 | **Self-update on Windows** uses the same signed manifest as every agent. The new program waits beside the old one as `whombat-agent.exe.new.exe` (Windows runs programs by their `.exe` ending) and must answer `version` first, run with Windows' own folders (`SystemRoot`, `WINDIR`, the temporary folders) in its environment and from the Windows folder. Windows can't overwrite a running program, so the agent renames itself aside (to `.prev`, kept for a rollback; a rollback sets the failed one aside as `.old`), puts the checked new one in its place and stops with a restart code; the service manager starts the new one, which removes what a rollback set aside. | The Linux agent replaces its file in place; on Windows a rename is the only safe swap. |
| WIN-10 | **The install line**: one line for PowerShell opened as administrator, made by the hosts service with every enrollment while it has a Windows build. It downloads `install.ps1` from the box's agents' address, checks it against the SHA-256 the line carries, and runs it with the address, the one-time code and the control level. The script refuses without administrator rights or on Windows before 10, picks the PC's build (amd64 or arm64), checks it against the SHA-256 it carries, installs the service, enrolls and prints one plain line (“Done: OFFICE-PC is in Whombat now.”). Run again, it updates the agent in place and keeps the PC's identity. The download skips the certificate check because the line pins the script and the script pins the agent; the agent then trusts only the box's own certificate authority. Windows PowerShell can switch the check off only for the whole session, so the line and the script switch it off for one download each and put the session's own check back in a `finally`, before the download is compared; a mismatch prints its line and runs nothing. | A person pastes one line and nothing else; Windows PowerShell 5.1 can't be given the box's own certificate authority for one download, but a hash in the line is as strong. |
| WIN-11 | **The agents' address takes TLS 1.2 too** (ECDHE-ECDSA with AES-GCM or ChaCha20 only), beside TLS 1.3. | Windows PowerShell 5.1 on Windows 10 can't speak TLS 1.3, and the installer downloads from that address. |
| WIN-12 | **Removing it**: `& "$env:ProgramFiles\Whombat\whombat-agent.exe" uninstall` in PowerShell as administrator stops and removes the service and the program and keeps the identity (as `install.sh --uninstall` does); the person then deletes the PC in Whombat, which turns the identity away. Add a server shows the line under the install line. | A PC that is added again reuses nothing the person didn't keep; the box decides who is accepted. |
| WIN-13 | **The binaries aren't Authenticode-signed (yet).** Their integrity is the SHA-256 in the line and the script, and the Ed25519 signature of the update manifest, as for every agent. Without a certificate Windows names no publisher in Services and a virus scanner may be more suspicious of a new build. With one: `sign-agents` signs each `.exe` with Authenticode before the manifest is made (the signature changes the file's hash), `install.ps1` also checks `Get-AuthenticodeSignature`, and nothing else changes. | A code-signing certificate is a purchase and a hardware key for John to decide on; the hashes already stop a changed file. |

## The build

| ID | Decision | Reason |
|---|---|---|
| WIN-14 | **Windows agents are built and shipped with the others**: the hosts Makefile's agent targets, the appliance's Nix package (which checks each `.exe`'s PE header and machine type), the hub's served files (the `.exe` files and `install.ps1`), the candidate's plan and `rackoon-sign`. A release whose signed manifest has no Windows entries yet still builds (the manifest check reports other bytes, as for any unsigned build), and the hub then makes no Windows line. The private `sign-agents` needs no change: it signs every `whombat-agent-*` file it finds. `make agent-windows-check` vets and builds the Windows agent on Linux in the hosts tests and `fast-test`. | One release flow; the first release with Windows code mustn't wait for a signature that only the release itself can make. |

## Whombat's side

| ID | Decision | Reason |
|---|---|---|
| WIN-15 | **The contract names a PC**: `HostServerPlatform` and `HostOsFamily` `windows` (appended), `HostServerDetail.windows` (`HostWindowsDetail`: product, version and build, maker and model, Windows Update's times, the protection with Defender and the antivirus list, BitLocker per drive) and `HostEnrollment.installCommandWindows` (absent while the box has no Windows build). The hub's Go zero times and empty names read as null. | Contracts first, and one odd field must not empty a page. |
| WIN-16 | **Older apps see a PC as a standard server.** An app below session protocol minor 22 (`WINDOWS_MINOR`) reads platforms and os families strictly, so the fleet, a server's page and the live server rows it gets show a PC as `standard` without an os family or its Windows facts. | An old phone must keep working; it shows the PC's figures and nothing it can't read. |
| WIN-17 | **A PC's page**: Summary, Storage and System on the web, the Summary alone on the phone (no tab row); the System line says its Windows (“Windows 11 Pro 24H2 (26100.2605)”); Technical details has **This PC**: the model, virus protection, the definitions' age and last quick scan (Defender's), when Windows Update looked and last installed, and BitLocker per drive. The ⋯ menu has no shell, and a switch turned off on the PC is allowed with its PowerShell line. | The PC's own facts where the other kinds keep theirs; nothing offered that the PC can't do. |
| WIN-18 | **Add a server has a third choice, Windows PC**: the same enrollment's PowerShell line for the level chosen above, how to open PowerShell as administrator, and how to remove it later; on a Whombat without a Windows build it says it can't add a PC yet. Sign in once stays Linux and Mac only, and the assistant's `server_add` tells the person to choose Windows PC. | OpenSSH is optional and off on most PCs; a line pasted as administrator works on every one. |
| WIN-19 | **A PC's mark is a PC tower** (`pc`, Lucide's `pc-case`), for Windows and Windows Server alike, never Microsoft's logo. | The logo is Microsoft's trademark; the mark only needs to say “a computer”. |
| WIN-20 | **The assistant on a PC**: `server_command` says its commands are PowerShell there; `server_update` and the care plan leave updates to the person (WIN-08); everything else (watching, restarting, the drive's space, the lists) works as on any server. | The tools are the same; only the shell and the updates differ. |
