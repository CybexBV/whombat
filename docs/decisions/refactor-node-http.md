# Shared Node HTTP-over-Unix-socket transport — 2026-10-20

Runtime refactoring, research opportunity 2 (IPC). No contract, permission, signing, pipeline, receipt, event,
lease or fencing changes. The pure vendored contracts stay untouched.

| # | Decision | Why |
|---|---|---|
| NH-01 | `@whombat/node-io/http` owns one raw Node HTTP request over a Unix socket, stream handoff, bounded body collection, cancellation and timer cleanup. It accepts every HTTP status and never parses JSON, authenticates or retries. Each request has its own connection (`agent: false`). | The manager, backup, hosts and runner sign-in clients repeated the same mechanics, including gaps in handling partial responses. Service policies belong to their adapters; mutations must never be retried by the transport. |
| NH-02 | Idle socket timeouts and total wall-clock deadlines are independent optional settings; a deadline may end at headers for a streaming caller. Manager and backup retain idle timeouts (backup defaults to one hour); hosts buffered calls retain total deadlines, while `open` only limits time to headers and hands the unread response and request to its caller. No new deadline is imposed on sign-in long polls, which retain caller-driven cancellation. | A checkpoint or destination setup can stay silent for minutes. A hosts response must finish within its per-call deadline, while an event stream can remain open indefinitely. |
| NH-03 | Buffered readers reject oversized, aborted and truncated responses, including valid JSON bytes in an incomplete HTTP message. Transport errors identify timeout, size, cancellation or incomplete response; native connection errors retain their codes. Pre-aborted signals reject before a request is created, and abort listeners and timers are removed on completion, failure or close. Streaming cancellation stays attached until the response ends or closes. | A partial answer is not a service result. Pending requests must settle on a broken response and successful polls must not accumulate abort listeners. |
| NH-04 | Adapters keep their existing paths, schemas, status handling and words. Manager rejects status ≥300 as `ManagerCallError` with its bounded error code; backup returns every status and maps empty or invalid JSON to null; hosts retains problem mapping and its single forced token refresh after a buffered 401 (`open` does not refresh); sign-in returns a `Response` and verifies the socket filesystem ownership before every request. Existing manager/backup/hosts body caps remain; sign-in gains a 16 MiB cap for its poll batches and small acknowledgement responses. | Extraction must not move authorization or service-specific behavior into a low-level package. Sign-in previously had an unbounded collector; 16 MiB leaves ample space for batched jobs and account lists without an unlimited allocation. |
| NH-05 | Transport and adapter regressions use real local Unix sockets in unit suites, without Postgres or new host services. Tests cover wire truncation, malformed chunks, oversized answers, early and mid-response abort, listener cleanup, idle and total deadlines, streaming handoff and status/JSON/token policy. | These are socket lifecycle and decoding behaviors; a database adds no evidence. Test deadlines are injected and socket progress is observed through events. |
