# Servers and Connections as places (SCP)

John, 2026-11-27, with a screenshot of the web sidebar's SERVERS / CONNECTIONS tabs and their row of logos: he didn't
like it in the menu and suggested Servers and Connections as menu items of their own, shown like Chat: a list, and the
page of the one picked on the right. My view: yes, with a status line per row, the worst mark on the menu item, the
`+` at the list's top, never an empty right side, Chat's behaviour on a narrow window, Overview kept as the full-width
dashboard (folding the list into Overview would squeeze its server table into cards), and a service page that fits the
narrower pane — its head on one line and a problem said once. He asked for a mockup
(`docs/design-handoff/servers-connections/index.html`), then: “Implement this fully, use the Council to review. Include
mobile apps.”

John, 2026-11-28: the phone's Places had Search and Usage too many (“Zoeken / Verbruik”), and the Overview felt like
too much now that Servers and Connections are in the menu. My view: agreed; only charts pinned to the Overview and its
arranged tiles had no other home, and on Home neither was used (no pin there, the layout as it came). He chose to remove
the Overview (SCP-18…SCP-23).

Supersedes `sidebar-tabs.md` SBT-03 and SBT-04 (the sidebar's tabs, and the other tab's problems carried under the open
one). Code: `packages/client/src/home/placeLists.ts` (the rows, their lines and order, the place's words, which place a
page is in, where a place opens), web `apps/web/src/app/shell/` (`assistantSidebarModel.ts`, `AssistantSidebar.tsx`),
`apps/web/src/features/things/places/` (the list beside a page, `/servers` and `/connected`), the service page's head
(`features/things/page/`); phone `apps/mobile/src/data/places.ts`, `ui/places.tsx` and the list screens. No contract,
schema or migration change.

| Id | Decision | Why |
| --- | --- | --- |
| SCP-01 | **Servers and Connections are places in the menu, right after the Inbox**: Chat · Inbox · Servers · Connections · Automations · Files · Vault on the web; Chat · Inbox · Servers · Connections · Automations · Files · Vault · Settings in the phone's Places sheet. Servers shows once there is a server or the hosts service runs; Connections always, since its list is where the first connection is added (first-day.md). The sidebar's SERVERS / CONNECTIONS tabs and the phone sheet's shortcuts to each server and connection are gone; the sidebar is the places and the conversations. | John's word; a row of logos under the menu is noise once each list has its own place. |
| SCP-02 | **A place is a list beside a page, Chat's shape**: the list column at Chat's width (392 px) with its heading (“Servers”, “Connections”), a line under it (`placeSummaryParts`: “5 servers · 1 not working · 1 needs a look”, the problems in red and amber), the `+` (“Add a server”, “Add a connection”, the same targets as before), then one row each: the logo, the name (in the list's sans face, as the mock draws it), at the end a server's processor now (“10 %”), and under the name how it is in a few words with its status mark when it isn't fine. The page on the right is the server's or connection's own page, unchanged in what it holds. | The same list in the same place as Chat's, so the app reads as one. |
| SCP-03 | **The rows say what Overview says, in Overview's order** (`serverPlaceRows`, `connectionPlaceRows`): servers from the hosts fleet, broken first then by name, a server that runs on another set in under it; a server's line is Whombat's reason when it isn't fine (else its pill's word), else the processor's word and what runs (“Quiet · 19 of 22 running”, a child's “Quiet · on pve-01”). A connection's line is its Overview tile's one line, worst first. Before the fleet or Overview is read, the rows of Home's things say their reason or status. A server's level is the fleet's live one, Home's only while the person keeps it quiet (`serverQuietWords`); a server Home knows that the fleet doesn't comes after the fleet's. | One set of words for one state across the app. |
| SCP-04 | **A problem never hides**: the menu item carries the worst mark of what it holds — the red ring for something not working or offline, the amber dot for something that needs a look (`placeTone`) — and its name says it (“Servers, something isn’t working”). Learning is not marked. On the web the mark is read from Home's things, which the shell already reads on every page; the list beside it reads the fleet live, so for a moment after a change the two can differ until Home catches up. The phone's sheet takes its mark from the rows it shows. | SBT-04's rule, kept now that there are no tabs to carry rows under. |
| SCP-05 | **Addresses**: Servers is `/servers`, Connections is `/connected` (`/connections?connection=…` holds the connections' own pages; without one it is the Overview's old address, SCP-20). A page stays at `/things/<id>`; the list shows beside it when the thing is in one of the two lists (`placeOfThing`), and the place's menu item is the selected one. A page neither lists (every guest of every server, a part of a server, a guest's page or a console opened over a server's address) keeps the whole width. | No old link changes meaning; a page has one address wherever it is opened from. |
| SCP-06 | **Never an empty right side**: on a wide window `/servers` and `/connected` open the one looked at last in that place (kept in the browser for each Whombat, `whombat.place.<burrow>.<place>`; the phone keeps it in the app the same way) when it is still listed, else the first row (`placeOpening`), only a row with a page of its own (an older account's row that leads to Settings is picked by hand); the phone waits until Home and the servers have answered. An empty list shows its words (“No servers yet.”, “Nothing connected yet.”) and the `+`; a list that couldn't be read says so with Retry (“Servers aren’t reachable right now.” when the hosts service is down). What the address carries for the shell (an approval, a thread) goes along to the page opened. | Opening a place shows something at once. |
| SCP-07 | **Narrow windows work like Chat**: below 1240 px on the web (Chat's split, `INBOX_SPLIT_MEDIA`) the place is its list alone, and a picked page is alone with “‹ Servers” or “‹ Connections” above it going back to the list. On the phone a place is a list screen that pushes the page; from 840 points wide (the app's two-page width) the list and the page sit side by side as Chat's do. | The way Chat already works on the same widths. |
| SCP-08 | **Right-click**: the Servers item's menu has Add a server, the Connections item's Add a connection; a list row's has Open and Rename, and F2 renames the row in focus, as the sidebar rows did (server-names.md). | Nothing the sidebar offered is lost. |
| SCP-09 | **A page's head is one line beside the list**: its logo, its name, its status word only when it isn't fine (“Needs a look”, not the reason), and its buttons; under it one quiet line of what it is. Where it runs, its address, Change and More detail are in the ⋯ menu. In a place there is no back link (the list is beside it); on a narrow window “‹ Servers” goes back to the list, and a page in neither list goes back to Servers or Connections. A server's page keeps its short condition word, the hub's own (“Running hot”, “Disk array failed”), which Worth a look may not repeat, and its sentence goes when Right now or Worth a look tells the problem (`serverHeadWords`). | Today's head wraps to three lines in the narrower pane. |
| SCP-10 | **A problem is told once on a page**: Worth a look tells it with its action; the head's pill says only the level, and a figure elsewhere is in amber with a short count (“1 offline”), not the sentence again. | UniFi said “AP Paardenstal is offline” four times. |
| SCP-11 | **Two columns in the narrower pane**: a service page's short cards sit side by side once the page itself is 700 px wide, so beside the list it isn't one long column. | The page measures itself, not the window. |
| SCP-12 | Superseded by SCP-18. | |
| SCP-13 | **On the phone a place is one list screen under two names** (`ServersPlace`, `ConnectionsPlace`; the app's `Connections` is Settings → Connections), opened from the Places sheet and from `/servers` and `/connected` links (also after a Whombat's name), and kept when the app is killed. A tap opens the page, a long press offers Open and Rename. | The same place on every device, without taking Settings' name. |
| SCP-14 | **From 840 points a place is the left page**: opening a place makes it the list, the picked page shows on the right, and on the first open the right side shows the one looked at last, else the first row. When the person closes that page the right side says “Pick a server to see it here.” (“Pick a connection …”) instead of opening it again; a link or a notice while a place is the list goes back to the tabs. Unfolding to two pages with a place opened higher in the stack makes it the list, what it opened beside it (`promotedList`); as the list its back names the tab under it. With Ask open beside a page on the web, the list steps aside as on a narrow window. | A page the person closed stays closed. |
| SCP-15 | **The phone's page head says the level too** (`headPillWord`): “Needs a look”, “Not working”, “Offline”; a thing down because of something else keeps its own words, which say what to look at. | The same head as the web's (SCP-09, SCP-10). |
| SCP-16 | **Search lists Servers and Connections as places** right after the Inbox (Connections always, Servers once it holds one), on the web as on the phone (“Your servers and how they are”, “What’s connected and how it is”), opening `/servers` and `/connected`. A thread opened from a place goes back to it (“‹ Servers”). | Every place in the menu can be found by its name. |
| SCP-17 | **The fact line runs under the whole head**, from the name's edge to the page's edge, not squeezed beside the buttons; a long name and its status word stay together on the line with the buttons. | Beside the list the buttons took half the line. |
| SCP-18 | **There is no Overview**: not on the web (no menu row, no page) and not on the phone (no tab; the bar is Chat · Inbox · Automations · Settings). What it showed is in other places: the servers and connections in their lists with their marks, what needs the person and the status line in the Inbox. Its arranged tiles and figures go with it; the layout stays in the database and its endpoints stay for older apps and the box's screen, which still reads them. | John, 2026-11-28: too much beside the two lists. |
| SCP-19 | **The phone's Places sheet no longer lists Search or Usage**: Search is the magnifier at the top, Usage is in Settings. | John, 2026-11-28. |
| SCP-20 | **The Overview's old addresses open a list**: `/connections` without a connection's page, `/dashboard` and `/things/servers` open Connections (`/connected`), or Servers (`/servers`) for Add a server (`?add=`), Point them here (`?repoint=1`) and the old Servers section (`?tab=servers`); the rest of the query (an approval, a thread) goes along, the old section and its anchor don't. The phone follows the same links to the same lists. | Links in older messages and notifications keep working. |
| SCP-21 | **Add a server and Point them here open over the Servers list** (`/servers?add=1…`, `?repoint=1`), which stays put under them; the list's `+` and the menu item's Add a server open it. A server that ran the install command and waits to be added is a card under Servers' rows with Review, which opens Add a server. Add a connection stays at `/connections?connection=add`, and the connections' pages go back to the Connections list (“← Connections”). | They were the Overview's; the Servers list is where they belong now. |
| SCP-22 | **A pinned chart goes on a page**: `pin_widget` puts it on the page it names, else on the page of what it reads (a server's for its metrics, the connection's or device's for its tool), and refuses when the person can see neither. Charts pinned to the Overview before stay in the database and on the box's screen, which still shows them. | With no Overview a pin needs a page to be seen on. |
| SCP-23 | **The Overview's code is gone, its words too** (web `features/home/HomeScreen` and the arranged tiles; phone `HomeScreen` and its cards; their words in both languages). The shared pieces the lists, the desk and the box's screen use stay (`home.overview`, `overviewTiles`, `serverPlaceRows`). | Nothing left that no one can reach. |
