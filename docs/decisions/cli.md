# Workstream: cli-embedded-pg (the `whombat` CLI and the embedded Postgres)

Plan phase 5 of `docs/decisions/archive/self-hosted.md`: S-03 (`WHOMBAT_HOME` layout), S-05 (embedded Postgres 17) and
S-06 (the `whombat` CLI). How to install and run it: `docs/install.md`. `auth-selfhost.md` (bootstrap,
login links), `github-gh.md` (gh), `selfhost-foundation.md` (paths) and `production.md` (C-16 env file,
production config) still apply.

## Layout

```
apps/cli (@whombat/cli, binary `whombat`)
  bin/whombat.mjs   shim for a PATH symlink (registers tsx, runs src/bin.ts)
  src/bin.ts        entry: `pnpm whombat …`, the shim and the systemd unit
  src/main.ts       argument parsing and printing only
  src/home.ts       WHOMBAT_HOME paths and layout
  src/config-file.ts config.env: build (defaults, secrets, idempotency), render, update in place, mode-600 write
  src/instance.ts   an installed instance: config.env + the server's own validation of it
  src/pg.ts         embedded Postgres: binaries, initdb, postmaster.pid, spawn / wait / stop, withPostgres
  src/process.ts    children as process-group leaders, line logging, group sweep
  src/supervisor.ts ordered steps, restart with backoff, reverse-order stop (pure over ChildHandle)
  src/start.ts      the steps of `whombat start`, child env, whombat.pid, signals
  src/init.ts  src/doctor.ts  src/service.ts  src/login-link.ts  src/web.ts  src/log.ts  src/which.ts
apps/server/src/host-api.ts   `@whombat/server/host`: what the CLI takes from the server
```

## Decisions

| # | Decision | Why |
|---|---|---|
| CLI-01 | **Runs from the checkout as TypeScript through tsx**: `pnpm whombat …` (root script `node --import tsx apps/cli/src/bin.ts`) or `apps/cli/bin/whombat.mjs` (registers tsx, symlink it onto PATH). No build step, as for server and runner (PR-09). Packaged distribution later (S-06). | One way to run everything; `pnpm install` is the only setup. |
| CLI-02 | **The CLI imports one server module, `@whombat/server/host`** (`apps/server/package.json` `exports`), an exception to "apps never import each other": config rules (`loadConfig`, `embeddedDatabaseUrl`), migrations, `bootstrapOwner` / `hostLoginLink` / `accountCount`, `withHostServices` (services open for one task, then closed; `runHostTask` now uses it) and `GhCliGitHub` for doctor. Server and runner themselves are always child processes, never imported. | Init, login-link and doctor must apply exactly the server's rules (production validation, the owner rules of AS-08, gh's account check); a second copy would drift. |
| CLI-03 | **Embedded Postgres = the `embedded-postgres` project's binary packages only**: `@embedded-postgres/linux-x64` / `linux-arm64` `17.10.0-beta.17`, pinned, as `optionalDependencies` (pnpm installs the host's one), their postinstall allowed in `pnpm-workspace.yaml` (it restores the libraries' symlinks). We drive `initdb` and `postgres` ourselves rather than use the package's `EmbeddedPostgres` class. | The class writes the initdb password to a world-readable file in `/tmp`, installs process-wide exit/signal hooks (`async-exit-hook`) that would stop Postgres before the server, detects readiness from English log text and has no stale-pid handling. |
| CLI-04 | **Cluster**: `initdb` once, role `whombat` (superuser) with a generated password, `scram-sha-256` for every connection (password through a mode-600 file next to `pgdata`, deleted straight after), UTF-8, data checksums, `lc_messages=C`, locale libc **`C.UTF-8`** (else `en_US.UTF-8`, else `C`). Runtime: `listen_addresses=127.0.0.1`, **no Unix socket** (`unix_socket_directories=''`), `max_connections=100`; the `whombat` database is created on first start. | The builtin provider's `C.UTF-8` was tried: full-text search then leaves `É` uppercase in tsvectors (“élodie” wouldn't find “Élodie”); libc `C.UTF-8` lowercases every script, like the dev and production databases (`en_US.utf8`), and its code-point collation doesn't change with glibc upgrades. No socket: nothing in `/tmp`, loopback TCP only. |
| CLI-05 | **Default ports**: server **4470** (`PORT`), embedded Postgres **55470** (`WHOMBAT_PG_PORT`), both on 127.0.0.1; `docs/install.md` suggests 4471 for the Tailscale sign-in listener. | Clear of dev (4400, 5180, 55432), our instance (4410, 55440) and each other, so a self-hosted install can sit next to a checkout used for development. |
| CLI-06 | **Server config: `DATABASE_URL` wins; else `WHOMBAT_PG_PASSWORD` selects the embedded Postgres** (`postgres://whombat:<pw>@127.0.0.1:<WHOMBAT_PG_PORT>/whombat`, `embeddedDatabaseUrl`), else the dev default. `Config.DATABASE_SOURCE` = `url` / `embedded` / `dev`; production refuses only `dev`. `WHOMBAT_PG_PASSWORD` is also a `_FILE` secret. | The server, host scripts (`pnpm login-link` with `WHOMBAT_ENV_FILE`) and the CLI read the same config.env; no process gets the password in its environment. Dev, tests and our instance keep `DATABASE_URL` (S-05). |
| CLI-07 | **config.env** (`$WHOMBAT_HOME/config.env`, mode 600, written atomically): `PUBLIC_URL`, `NODE_ENV=production`, `HOST`, `PORT`, `WHOMBAT_SERVER_URL` (the runner's; `http://127.0.0.1:<PORT>` — not `localhost`, which may resolve to `::1`), `WHOMBAT_AGENTS=live`, `WHOMBAT_GITHUB=gh`, `WHOMBAT_GH_BIN` (absolute, found on PATH or `~/.local/bin`), `WHOMBAT_WORKDIR_ROOTS=~`, `WHOMBAT_HOME`, `WHOMBAT_PG_PORT`, and the generated `WHOMBAT_MASTER_KEY` (32 bytes base64), `RUNNER_TOKEN` and `WHOMBAT_PG_PASSWORD` (32 bytes base64url). **Idempotency**: secrets are only ever added (a `*_FILE` counts as present; `--set` of an existing secret is refused and said so); settings passed explicitly replace the stored value; everything else — the owner's edits, comments, extra variables — stays, because an existing file is updated line by line. The result is validated with the server's `loadConfig` before anything is written. `init` makes a looser file private again; every other command refuses it (“chmod 600 …”). | S-03, S-06. Re-running init must never lock the owner out of their data (the master key encrypts every signing key; the database password is baked into `pgdata`). |
| CLI-08 | **The owner** is made by `bootstrapOwner` after the migrations, when the instance has no accounts (flags `--owner-email/--owner-name/--burrow`, or prompts). A re-run without `--owner-email` skips it and points at `whombat login-link`; with the owner's email it prints a fresh link; another email is refused (AS-08). `--json` prints the result (`generated`, `changed`, `owner`) for scripts and tests. With `--yes` (or no TTY) nothing is asked and missing answers are errors; `PUBLIC_URL` then defaults to `http://localhost:<port>`. | S-04, S-06. |
| CLI-09 | **`whombat start` = supervisor**: steps web build → `postgres` (ready = accepts connections; `whombat` database ensured) → migrations (in-process) → `server` (ready = `/api/v1/health` ok with the database up, 90 s) → `runner`. Each child leads its own process group and gets a **minimal environment** (PATH, HOME, USER, locale, TZ, XDG_*, proxy and CA variables, `GH_CONFIG_DIR`, plus `WHOMBAT_ENV_FILE` and `WHOMBAT_HOME`): everything else comes from config.env, so a terminal and systemd behave the same (an exported `PORT` or `GITHUB_TOKEN` in a shell changes nothing). Crash → restart after 1 s, doubling to 30 s, back to 1 s after 60 s up; a failure during startup stops what started and exits 1 (systemd restarts it). Stop (SIGTERM/SIGINT/SIGHUP): runner (SIGTERM, 60 s: it cancels turns and kills provider groups), server (SIGTERM, 30 s), Postgres (SIGINT = fast shutdown, 30 s, then SIGQUIT, SIGKILL); after each leader exits, whatever is left in its group gets SIGTERM, then SIGKILL. A second signal kills at once. `--db-only` runs just Postgres (restores, psql). | S-06's ordering and shutdown; systemd's `KillMode=mixed` covers what we can't. |
| CLI-10 | **Leftovers**: `$WHOMBAT_HOME/whombat.pid` holds the supervisor's pid and its children's; a second `whombat start` of the same home is refused while the first lives. After a supervisor that died without stopping (SIGKILL, OOM), the next start stops its server and runner (pid still running that entry point) and its postmaster (pid alive with its cwd = `pgdata`). A `postmaster.pid` whose pid is dead or is another program now is removed before Postgres starts. An exit hook SIGKILLs the children's groups if the supervisor exits without stopping them. | Stale pid handling (S-05) without trusting a pid that may have been recycled. |
| CLI-11 | **Logs**: `[source] line` on stdout (journald timestamps it) and with an ISO timestamp in `$WHOMBAT_HOME/logs/whombat.log`, mode 600, rotated past 20 MB (at startup and while running; one `whombat.log.1` kept). | One place to look (`tail -f`), bounded on disk. |
| CLI-12 | **Web build**: `start` builds `apps/web/dist` when it is missing or was built from another commit (stamp `dist/.whombat-build` = `git rev-parse HEAD`), with apps/web's own Vite in production mode (no pnpm needed on a systemd PATH; about two seconds). A `WHOMBAT_WEB_DIST` of the owner's is never built, only checked. | Upgrading is pull, install, restart; no step to forget. |
| CLI-13 | **doctor** = a list of checks over one context, each `ok / warn / fail / skip` with a fix; exit 1 on any fail. Node ≥ 24; config.env readable, mode 600, valid by the server's rules; Claude and Codex through the providers' own `available()` (installed and logged in; skipped for scripted agents); gh through `GhCliGitHub.whoami()` (logged in, `repo` and `workflow` scopes; a token without listed scopes is a warning); Postgres (running: version; stopped: started briefly to prove it runs); the server's local health (not running = warning); `PUBLIC_URL`'s `/api/v1/health` from this machine; the web build. **`EXTRA_CHECKS`** is the slot for the runner workstream's sandbox check (S-13). | S-06; a person should get one screen that says what to do next. |
| CLI-14 | **service**: `~/.config/systemd/user/whombat.service` (`--unit` for another name), `ExecStart=<node> --import <tsx URL> <checkout>/apps/cli/src/bin.ts start` with the real node binary (`process.execPath`, never a mise shim), `WorkingDirectory` the checkout, `Environment=WHOMBAT_HOME=…` and an explicit `PATH` = the directories of node, claude, codex, gh, git and bwrap as found at install, then the system ones; `Restart=on-failure`, `KillMode=mixed`, `TimeoutStopSec=120`, `UMask=0077`. No `NoNewPrivileges` (a setuid bubblewrap, the guarded Claude sandbox on some distros, would break). `install` = write, `daemon-reload`, `enable --now`; `uninstall` = `disable --now`, remove, reload (data untouched); `status` = `systemctl --user status`. Each prints the `loginctl enable-linger` hint unless linger is on. | S-06; systemd's PATH lacks `~/.local/bin`. Our instance's `whombat-*` units are unrelated and untouched. |
| CLI-15 | **login-link** works with Whombat running or stopped (it starts Postgres for the task, as init and doctor do: `withPostgres`). | Recovery from the host shell (S-04) when the service is down too. |
| CLI-16 | **Tests**: unit (`pnpm test`): config building and idempotency, env file rendering / in-place update / quoting, the supervisor with fake children (order, restart, backoff and its reset, startup failure, stop during a restart pause), process-group stops with real processes, unit rendering and the systemctl calls (fake runner), doctor output, pid files, logger rotation. `pnpm test:cli`: the real migrations on the embedded Postgres 17 with FTS (accented words), the append-only trigger and advisory locks, a stale `postmaster.pid`; and **init → start → health → the printed link signs in (once) → SIGTERM → exit 0, ordered stop, no process, ports free** in a temporary home on free ports, with scripted agents and `--github off` (production refuses the fake GitHub) and a stand-in web dist. Both skip only where the binaries can't run. | S-05, S-06 test asks. |

## Follow-ups

- The runner workstream adds its sandbox check to `EXTRA_CHECKS` (`apps/cli/src/doctor.ts`).
- ARCHITECTURE: the `apps/cli` row, the `@whombat/server/host` exception (CLI-02), “Local environment” / “Production” for
  self-hosting; DECISIONS: S-05/S-06 summary (orchestrator).
- The server logs every runner long-poll at `info` (about two lines a second): consider `logLevel: 'warn'` for
  `/internal/runner/claim` and `heartbeat`, for our instance too.
- The embedded binaries have no `pg_dump`: backups use a system `postgresql-client` ≥ 17 or the `postgres:17`
  image (`docs/install.md`); a `whombat backup` command (with retention, like `scripts/deploy/backup.sh`) would help.
- A temporary Postgres from `init` / `login-link` / `doctor` running at the moment `whombat start` begins is
  treated as a leftover and stopped (that command then fails once). Rare; a lock file could order them.
- Packaged distribution (S-06 “later”): a tarball with a built web app and a bundled CLI instead of a checkout.

## Workstream: cli-fixes (review findings on the CLI)

Fixes to the verified findings of the self-host code review (group 2, CLI lens), plus the runner sandbox check
in doctor. New modules: `src/errors.ts` (`CliError`, re-exported by `instance.ts`), `src/ports.ts`,
`src/pidfile.ts`, `src/child-env.ts`.

| # | Decision | Why |
|---|---|---|
| CLI-17 | **Port clashes are named as such.** Before our Postgres starts (`start`'s prepare, `withPostgres`) and before the server starts, the port is test-bound on its host; taken → `CliError` “Port N on H is already in use by another program …” with the fix (stop it, or `init --port/--pg-port`). `waitForPostgres` also counts an answer (success or 28P01) only once **our** postmaster holds the port: `postmaster.pid` names the child's pid and has its status line (line 8, written after the sockets are open), so another server's password refusal is never read as ours (for the race the pre-check can't close). `withPostgres` appends Postgres's FATAL/`could not` lines to its error for commands without a log. The server's health wait relies on the pre-check. | A second home on default ports was diagnosed as “config.env doesn't match pgdata”, sending people to swap their master key file. |
| CLI-18 | **Crash recovery has no deadline.** 57P03 (“starting up”, WAL replay) resets `waitForPostgres`'s timeout, with a “still starting” line about every 30 s; the timeout only counts time in which nothing answers. | Stopping recovery at 60 s restarts it from the same checkpoint: a slow disk would never come up. |
| CLI-19 | **`whombat.pid` records start times and the boot id** (`<pid> <start>`, `boot <id>`, `<child> <pid> <start>`; `/proc/<pid>/stat` field 22). A pid is refused as “already running” or stopped as a leftover only while it is the same process; a leftover child must also run this checkout's **absolute** entry point and have this home's `WHOMBAT_ENV_FILE` in its environment. Older files (bare pids) still parse; their entries are checked by liveness plus those two. No flock (Node has none built in). | A recycled pid after an unclean stop could SIGTERM another Whombat on the host (our production units run the same relative entry points) or block start for good. |
| CLI-20 | **After a crash, clean up before restarting**: `ServiceStep.cleanup` runs when a child exits unexpectedly (supervisor), sweeping its process group and the groups its descendants lead. Those are found by `/proc` every 2 s while the child runs (`trackDescendantGroups`): the runner's provider CLIs are group leaders of their own, re-parented once the runner dies. Orderly stops sweep them too after the runner exits. | A crashed runner left `claude` / `codex` running on a worktree with nobody reading them. A provider started less than 2 s before the crash can still escape; see follow-ups. |
| CLI-21 | **Short commands stop their Postgres on a signal**: while `withPostgres` runs its own postmaster, SIGINT/SIGTERM/SIGHUP stop it, then exit 128+n (a second signal exits at once; the exit hook SIGKILLs the group). | The postmaster leads its own group, so Ctrl-C never reached it, and Node's signal death skips `exit` hooks. |
| CLI-22 | **doctor checks with the service's environment** (`serviceEnv`): `whombat start`'s child environment (CLI-09), with the PATH of the unit `service install` wrote for this home (any `--unit` name; found by its header and `WHOMBAT_HOME`), plus what the child reads from config.env — the server all of it, the runner its provider keys (`RUNNER_PROVIDER_KEYS`, mirroring apps/runner's `RUNNER_ENV_KEYS`). Claude, Codex, gh and the sandbox checks use it; a failed line says when the unit's PATH was used. | A login exported only in the operator's shell showed “logged in” while the service could not authenticate. |
| CLI-23 | **`service install`**: refuses while a `whombat start` for the home runs outside the unit (a live pid from `whombat.pid` that isn't the unit's `MainPID`); then `daemon-reload`, `enable`, `reset-failed`, **`restart`** (applies a rewritten unit to a running service), and watches `ActiveState/SubState/NRestarts` for 8 s: failed, inactive, auto-restart or a restart → exit 1 with the unit's last 12 journal lines instead of “Started”. No `RestartPreventExitStatus` (a start refused as “already running” is caught by install; later, systemd's retries are harmless). | “Started” was printed for a unit that crash-looped into start-limit-hit; a re-install never applied the new PATH. |
| CLI-24 | **`PUBLIC_URL` behind a sign-in gate is a warning**: a redirect (301–308), 401 or 403 instead of the health JSON → `warn`, naming Cloudflare Access when the redirect goes to `*.cloudflareaccess.com` or `/cdn-cgi/access/`. Other non-Whombat answers (404, 502…) still fail. | install.md recommends Cloudflare Access; doctor then exited 1 on a correct setup. |
| CLI-25 | **`init --port` moves a generated `PUBLIC_URL`**: `http://localhost:<old>` (or 127.0.0.1) follows the new port; any other address stays and init prints to re-point the HTTPS front at 127.0.0.1:<new>. | The origin checks refused the new address after a port change. |
| CLI-26 | **No secrets on the command line in the docs**: SMTP goes into config.env (or `SMTP_URL_FILE`), an own database behind `DATABASE_URL_FILE`; `init` says so when a secret key (`SECRET_SETTINGS` = the server's `SECRET_FILE_KEYS`) still comes through `--set`. A unit test fails if install.md or the usage passes one with `--set`. | Shell history and `/proc/<pid>/cmdline`. |
| CLI-27 | **Sandbox checks in `EXTRA_CHECKS`** (`sandboxChecks()`, `sandboxAvailability()` from `@whombat/agent-runtime` with the runner's environment, asked once): `sandbox-claude` ok / **warn** when bubblewrap, socat or user namespaces are missing (guarded Claude falls back, RS-14), fix `sudo apt install bubblewrap socat` or `WHOMBAT_BWRAP=…` in config.env, or the namespaces hint; `sandbox-codex` ok / **fail** when Codex's bundled sandbox can't run (no fallback: guarded Codex can't run commands), skipped when Codex isn't installed (the Codex check reports that). Both skipped for scripted agents. | RS-19's “whombat doctor should print it”. |

### Follow-ups (cli-fixes)

- The runner could record its provider groups itself (or handle `uncaughtException` by killing them), closing
  CLI-20's 2-second window; it lives in apps/runner and agent-runtime.
- `SECRET_SETTINGS` and `RUNNER_PROVIDER_KEYS` copy server/runner lists; exporting `SECRET_FILE_KEYS` from
  `@whombat/server/host` would remove one copy.
- `ChildHandle.exited` settles on `close` (stdio closed): a grandchild that inherits a child's stdout delays
  crash detection until it exits. The runner's providers have pipes of their own, so it doesn't bite today.
- doctor's per-check 60 s limit still applies to a Postgres that recovers during `doctor`.
