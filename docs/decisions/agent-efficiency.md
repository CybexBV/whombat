it went:
- Run #2 rewrote `tests/feedback-browser.mjs` (16 desktop/mobile × light/dark scenarios) and spent ~4.5 min and 14
  calls making it pass (three 30 s Playwright timeouts); it proposed the same skill twice, 80 s apart.
- Its “independent review” was Codex's own `spawn_agent`: a copy of Banjo, 373 k input tokens that Whombat never
  counted (`CodexEventMapper` drops every notification of another thread), reported as an independent review although
  `requesting-code-review` says a reviewer teammate or the person.

  the change onto production's HTML instead of deploying a build (snapshot fetched twice, regex overlay, Cloudflare
  e-mail obfuscation chased for ~75 s), and the refreshed skill `how-whombat-website-deploys` now prescribes that.
- Every session's first call read nothing from the cache (~26 k × 6 = 42 % of the uncached input); the system prompt
  carries the turn's dispatch id in the pack-skill paths.
- Each request first costs a mention turn that reads a skill, starts the run and replies NO_REPLY (~83 k, 20–30 s);
  the deploy run then re-read what run #2 had read two minutes earlier, on a new branch (`gh pr diff | git apply`,
  `npm ci` again) although it was given `prNumber: 3`.

| AE-01 | **Sub-agents' usage is the turn's usage.** Codex: the usage of every thread the turn's thread spawns (a `collabAgentToolCall` from a thread of the turn names it in `receiverThreadIds`; transitively) counts into the turn's `inputTokens`, `cacheReadTokens`, `cacheWriteTokens` and `outputTokens`. | AE-02 | **A sub-agent's review is a self-check.** The sub-agent line and `requesting-code-review` say so: a sub-agent you start is you, its review never counts or is reported as an independent review. Independent review is a reviewer (or security) teammate; with none, the person who asked reviews the pull request — say it is ready for their review. Sub-agents stay allowed (RA-15). | The PR and the thread said “independent review passed” about Banjo reviewing himself. |
| AE-03 | **Checks match the change.** One “How you work” line: run the repository's own checks and the tests that cover what you changed, add or adjust a test for the behaviour you changed, and for a visible change look once (a preview or screenshot); don't build new test suites, harnesses or scenario matrices unless the task asks for them or the change is risky. | AE-04 | **A run starts first.** When a turn hands the work to a run (`start_run`), it starts the run before it reads skills or files: the run's turn reads what it needs. | The handoff turn read `systematic-debugging` only to start a run that read it again. |
| AE-05 | **A run on a pull request works on its branch.** `start_run` with the number of an open pull request of the repository runs on that pull request's branch, whatever `branch` says (the key is asked for that branch; the tool result names it). | AE-06 | **Earlier runs carry over.** A run's turn gets the burrow's earlier runs on the same pull request (else the same repository branch): number, title, status, the summary they finished with, their last run-log lines (≤ 3 runs, ≤ 12 lines each, each line ≤ 300 characters), newest first, in the turn's message (PE-02, not the stable prompt) — contracts 0.44.2 `DispatchContext.earlierRuns` (optional). | AE-07 | **A stable folder for a turn's pack skills.** Pack skills are materialized in a folder named by their content (a hash of the turn's skills: version ids, packs and names), reused by every turn with the same skills and removed once unused for a day — not one folder per dispatch. | AE-08 | **Codex shares no prompt cache across threads.** Measured 2026-10-04 with codex-cli 0.160.0: two identical fresh `codex exec` sessions 2 s apart, 11 466 input tokens each, 0 cached; run #2's sub-agent, whose first ~20 k tokens equalled its parent's, 0 cached. When the server serves content the repository lacks, don't layer the change onto the server's files: say what differs and bring it into the repository first (a pull request), unless a person says otherwise.
