# A dashboard for every connection

John, 2026-11-23: “When I click on a connection we sometimes get a dashboard (like Hetzner), but sometimes we get a
summary (like FindMy). I want (when possible) to have all connections show dashboards when we click on them by
default.” He had the connections researched (Fable 5.2, Muse Wonder Full and Opus), read the plan and said “Go” to
its first step: everything the server can do without a contract change or an app release. Then, the same day:
“Continue with step 2”, the pages for the accounts (Google, Microsoft 365, Email, GitHub, Website feedback), which
need a new session minor and an app release.

What the research found: 43 of 60 catalog entries already opened on a page in slots. The rest opened on Find My's
near-empty Summary, on the generic “How it answers” page (Notion, Airtable, Dropbox, the AI gateway, the report
tracker, Custom connections without a recipe, Proxmox and Unraid), on an empty page for the first sign-in (Todoist,
Mollie, Cloudflare with “Sign in with …”), or on Settings (the accounts).

| id | decision | why |
|---|---|---|
| CDB-01 | **A kind may name the tab its page opens on** (`KindView.lead`): that tab comes first, its other tabs after it, the Summary last, and the Summary gets no answer-time slots. Both apps open the first tab, so no app changes. An app below session minor 5 still opens on the Summary. | Find My's decision said its page opens on the map (FMC-03), but the server always put the Summary first, and that Summary only had answer times for a connection that sends nothing anywhere. |
| CDB-02 | **Find My opens on its map**, then the Timeline, then the Summary (what needs a look, Changes here, What Whombat may do). | The map and the people are the dashboard; nothing new is read. |
| CDB-03 | **The page of a connection Whombat can't see inside is “With Whombat”** (was “How it answers”): its answers and answer time as before, and when Whombat last used it (“3 h ago”, “Not yet”). A Custom connection without a page also offers “What’s inside” under Show more here, which asks the assistant to build its page. | Answer times alone said nothing a person cares about. What Whombat may do already lists the tools, so they aren't repeated. |
| CDB-04 | **No uses-per-day counter for that page.** | It needs a new counter and a migration for a page few connections reach once the kinds below exist; Last used says the same in one line. |
| CDB-05 | **A report tracker's page comes from what Whombat keeps of it**, no call to the tracker: Live “Fixes on their way” (pull request open, merged, on development; linked to the pull request), Inventory “Reports” (open with new this week, open bugs, open feature requests, fixed and out to customers in 30 days), Trend reports per day, People “Who reports most” by organization (two or more), and the installation the poller reads with when it last did. A tracker no automation listens to says so instead of showing noughts. Kept a minute. | The tracker is read only by its poller; the box's mirror already has everything a person asks first. |
| CDB-06 | **A generic AI gateway's page** (LiteLLM, a company's gateway): Inventory “Through the gateway” (Claude Code and ChatGPT on or off, turns today with how many failed and how many go now, its models from `GET /v1/models`), Trend turns per day from Whombat's own turns (each keeps the provider it went through the gateway for; a burrow has one gateway, so turns since it was connected count). Models kept 15 minutes and never read by the health pass. | A gateway has no management API Whombat knows; what Whombat sent through it is the useful part. |
| CDB-07 | **Every catalog entry opens on a dashboard or is named with where it opens instead**, checked by a test (`kinds/landing.test.ts`): Custom connections (their recipe), a device (its readings page), Whombat's servers (each server's page), and the accounts (Settings, until they get pages; superseded in part by CDB-80: the accounts have pages). | A new service can't ship with only the generic page by accident again. |
| CDB-08 | **One way to read a connection's MCP tools for a page** (`kinds/mcp-read.ts`): only tools the server marks read-only, with the kinds' deadline; recipes and kinds share it. | Kinds now read through “Sign in with …” connections too. |
| CDB-09 | **Dropbox's sign-in doesn't ask for `sharing.read`**: its page shows shared links only for a sign-in that already holds it. | One more permission for one count isn't worth asking every person for. |
| CDB-10 | **A kind's read kept longer than 15 minutes stays that long** (`cachedRead`'s keep follows its own time). | Airtable's, Cloudflare's and Tailscale's hour-long reads were dropped after 15 minutes and read again. |

## Reading through “Sign in with …”

| id | decision | why |
|---|---|---|
| CDB-20 | **Todoist, Mollie and Cloudflare connected with “Sign in with …” build their page from their own MCP server's tools that only read** (`kinds/mcp-read.ts`, helpers in `kinds/mcp-tools.ts`). The token path is unchanged. | The default sign-in gave an empty page. Whombat already knows from the server's list which tools only read. |
| CDB-21 | **Todoist reads `find-tasks-by-date`, `find-completed-tasks` and `find-projects`** (all `readOnlyHint: true`). They give today and overdue for everyone, as the API's `today \| overdue` does; the next 7 days; done today and in 14 days; and project names. Their tasks are turned into the API's shape, so the token's code builds the page. Source: https://github.com/Doist/todoist-ai (`src/tools/`, `@todoist/mcp-core` `getToolOutput`). | One page, two ways in. |
| CDB-22 | **No Done button when signed in with Todoist.** Done refuses on that sign-in. | A page never changes anything through MCP tools, and the token isn't for the API. |
| CDB-23 | **Per call: 40 tasks, 50 done tasks, 100 projects. At most 3 calls per list, then “+”.** | Whombat keeps 64 KiB of an answer, and one task with a description can take a kilobyte. |
| CDB-24 | **An answer is its structured content. Otherwise it is the first line of its text that is a JSON object.** A cut answer says “answered with more than Whombat reads”. | Todoist also sends its JSON as the first part of the text. A structured answer over 64 KiB is dropped. |
| CDB-25 | **The health pass reads only the shared main part:** Todoist's today and overdue, done today and projects (projects kept 15 minutes); Mollie's newest page of payments. Only an open page reads the week ahead, the done history, Mollie's older pages and the next payout. These are kept 5–10 minutes. | The 5-minute pass must stay cheap. |
| CDB-26 | **Mollie reads `ListPaymentsFromGivenIDOnwards` and `GetNextSettlement`.** The newest 25 payments every read, and up to 4 pages back to the month's start kept 5 minutes. Past that the month says “at least”. Tool names come from Claude's connector directory (https://claude.com/connectors/mollie) and two listings made from the live server (https://neuraltrust.ai/mcp-catalog/mollie, github.com/suverenai/suveren-gateway `content/integrations/mollie.json`). Mollie's own page (https://docs.mollie.com/docs/mollie-mcp-server) lists only what the server can do. | Mollie publishes tool names, but not their arguments or answers. |
| CDB-27 | **A Mollie tool gets only the arguments its own schema names.** That is a page size (`limit`, `pageSize`, `perPage`) and a payment to go on from (`from`, `fromId`, `startingAfter`). A tool that requires anything else is left out, with one line saying why. Answers are read as Mollie API v2's (https://docs.mollie.com/reference/list-payments, https://docs.mollie.com/reference/get-next-settlement). Any other shape leaves the part out. | The server's own schema, stored at connect, is the only sure source for arguments. Check this on a real Mollie sign-in. |
| CDB-28 | **Signed in with Mollie, there are no refunds or chargebacks, and the chargeback check counts as not seen.** | Its server has no tool for them; Mollie's page says refunds aren't supported. |
| CDB-29 | **When the server offers no read-only tool for the main part** (Todoist's tasks, Mollie's payments), the page keeps its line “This page needs … connected with an API token / key”. | The tools may not be synced yet, or the server changed. |
| CDB-30 | **Signed in with Cloudflare, the page reads nothing from Cloudflare.** Under the name it says “An API token shows its traffic and tunnels here.” The Worth a look hint stays and still starts off. Its MCP server (https://github.com/cloudflare/mcp, Code Mode at https://mcp.cloudflare.com/mcp) marks only `whoami` read-only; `search`, `execute` and `docs` aren't. | The hint starts off as advice about settings (watch-defaults), so the page said nothing before. |
| CDB-31 | **Fixture pages `con_todoist_mcp`, `con_mollie_mcp` and `con_cloudflare_mcp`** show each sign-in's page. | Fixture mode shows both sign-ins. |
