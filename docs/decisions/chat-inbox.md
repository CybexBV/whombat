# Chat as an inbox (2026-11-14)

John, 2026-11-14 (main checkout): it was hard to see which threads had unread messages, the room looked messy (a link
in a first message showed its preview in the list of threads), and he thinks of Chat's threads as a mail inbox he
likes to keep clean. He saw the mockup (Chat as a mail inbox: two-line rows, a blue dot, bold titles and a count,
filters, Settle from the row, Settle everything read) and said: “I like it. We should definitely have an auto-settle
option (configurable). For the rest I would like you to make the decisions for me. … when we type a lot (or paste a
lot), the chat input box should grow a bit so it's easier to read. Implement this fully.”

This file covers Chat and Feedback, the server and the shared client. The apps' own details are in
`docs/app/decisions/chat-inbox.md`. Builds on `chat-settle.md` (CHS) and `thread-unread.md` (TU).

| # | Decision | Why |
|---|---|---|
| CIB-01 | **Chat and Feedback list their threads like a mail inbox.** One row per open thread, the newest activity first; a new message brings its thread to the top. A row is two lines: the thread's title and the time, then the latest message (“Dusty: …”, “You: …”). Never a link preview, picture, file, card or button in the list: they show inside the thread. A link reads as plain text without `https://` and `www.`. The list comes from `chats.threads` (`state: open`), not the room's timeline. | A list you scan to see what's new and what's done; a whole first message with its preview made every row a different size. |
| CIB-02 | **A thread's title is the first line of its first message** (`threadTitle`), as it already was in Settled and Search. No title written by the assistant. | Instant and always right, it costs no model call, and people recognise their own question. |
| CIB-03 | Superseded in part by CIB-15 (the text is the plain start of the reply, not its first line). **`ChatThread.last`** (optional): the newest reply with words or files, `{authorId, text, at}`, `text` its plain first line (at most 200 characters; “A file”, “3 files” when it has only files). Absent before the first reply, and for a reply that is only a card: the row then shows the first message. The client keeps it current from new messages. | The row's second line, without loading every thread. |
| CIB-04 | **What's new stands out**: a thread with something new has a blue dot (`--chart1`), a bold title, its time in blue and a count of new messages; Chat's badge still counts such threads (TU-03). The open thread shows a “New” line above its first new message. In rows, “Waiting for you” keeps its words (`--warn-text`) without a dot, so the blue dot only ever means “new”. | The brown dot in the margin was easy to miss; mail's convention is known to everyone. |
| CIB-05 | **Superseded by CIB-20.** **Filters: All, Unread, Waiting**, over the open threads, with the number of unread and waiting threads. Settled stays its own list from the room's head. | The two questions people ask of an inbox: what's new, and what needs me. |
| CIB-06 | **Mark as unread** (`chats.markUnread`, `POST …/chats/threads/:rootId/unread`, no body): the person's marker in the thread moves back to just before the newest message someone else wrote in it, so that message counts as new again. The only way a marker moves back. A thread with nothing from someone else, or whose only such message is its first one already read in the room, stays as it is. It answers what is new in the thread and the room's badge (`ReadThreadResponse`) and publishes the badge like a read. Private, not signed (as TU-04). | Mail's “keep this in view, I'll come back to it”, without a new kind of state. |
| CIB-07 | Superseded by CIB-14. **Settle everything read** (`chats.settleFinished` with `onlyRead: true`): every open thread that could settle (CHS-03, pinned ones stay, CHS-S05) and has nothing new for the person. Without the flag it works as before. | Tidying what you've seen must not file away what you haven't. |
| CIB-08 | **Settling by itself waits until it's read.** The automatic round (CHS-06) leaves a thread with something new for the person open, for quiet days and merged pull requests alike. A thread the assistant settles because the problem went away (`resolved`) is unchanged. | An inbox that puts away unread mail loses messages. |
| CIB-09 | **The person chooses when threads settle by themselves**: never, after 1 day, after 3 days or after a week (`Preferences.chat.settleQuietDays` 1, 3, 7 or null; the contract already allows 1–90). Still 3 days unless changed. The merged pull request switch stays. Shown where the switch was (web Settings → You, the phone's Settled screen and Settings). The assistant changes it as any profile choice (`me.updatePreferences`). | John asked for it to be configurable; four choices cover a busy and a quiet week without a number field. |
| CIB-10 | **No “Later” in Chat.** | A new message already brings a settled thread back, and “remind me tomorrow” is a question the assistant answers; one button less on every row. |
| CIB-11 | **The message box grows with a long message**: up to about half the window on a computer and 40 % of the screen on a phone, then it scrolls inside. On a computer, once the text runs past one line, File, the model's mark, the mic and Send move under the text so it has the full width. Pasting a long text grows it at once. | Reading back a long message in a one-line strip beside four buttons is hard. |
| CIB-12 | **No contracts release, no session minor.** `ChatThread.last`, `onlyRead` and `chats.markUnread` are additions only this repository uses (TU-07). | Additions matter to other repositories only when they use them. |
| CIB-13 | **Clear chats settles what can settle.** Besides hiding the room's top level from the assistant's window (chat-clear.md), clearing Chat or Feedback settles every thread that may settle, as Settle finished threads does; what the assistant works on or what waits for the person stays in the list. The threads are in Settled and Search as before. | The room is the list of open threads now; a clear that left the list as it was would do nothing visible. |
| CIB-14 | **No Settle everything read, and a settled thread leaves the list at once.** The apps don't offer it; `chats.settleFinished`'s `onlyRead` stays for older apps. Settling sends the thread's first message again: a list of open threads that doesn't have it leaves it out, never starts it again at the top. | John, 2026-11-14: the button and the key hint were clutter, and a settled thread came back at the top. |
| CIB-15 | **A row's second line is the plain start of the newest reply** (`threadPreview`): its lines joined, Markdown marks dropped, a link as its words (`[PR 69](…)` reads “PR 69”), a bare address without `https://`, clipped at 200 characters, so a short first line goes on into the next. A reply with only files still says “A file” or “3 files”. The thread's title stays the first line of its first message (CIB-02). The server and the apps make it with the same function. Replaces CIB-03's “its plain first line”. | Two lines of room showed one short line (“Done.”) and links as markup. |
| CIB-16 | **A thread's repository** (`ChatThread.repo`: `fullName`, `name`, `iconUrl`) is the repository its automation runs work in (the recipe's, the GitHub triggers' and the steps' repositories), else the one repository of the work handed over from it (a T3 Code job's pull request, a run of the agent's own). One repository or none: when its runs, or else its jobs, name different repositories, or none, the row has none and `repo` is left out. A job is known by its repository once it opened a pull request. Two queries for a whole page of threads. | What John's threads are about (“Hunt for bugs · fusebox”) is a repository; an icon recognises it faster than words. Guessing between several is worse than a plain row. |
| CIB-17 | **A repository's icon is its own picture.** Whombat reads the default branch's file list once (one tree read) and downloads the best candidate (one download): by name first — `apple-touch-icon*.png`, then `android-chrome-`/`icon-` 192 or 512, then `app-icon*`, `icon` or `logo`, then `favicon*.png` — then the shorter path; other projects' and built folders (`node_modules`, `vendor`, `dist`, `build`, tests and fixtures) left out. Only PNG, JPEG or WebP by their bytes, at most 256 KiB; never SVG or ICO. Nothing that fits: no icon, and the apps show the name's first letter on a tile. | The phones draw raster pictures without help; a project's home-screen icon is made to be seen small. |
| CIB-18 | **The icon is kept, never waited for.** It is stored as a picture attachment of the burrow without a conversation, as a person's photo is, which anyone in that burrow may read (a private repository's too) and nobody else (`repo_icons`, migration 0004). What a look found, a picture or nothing, is kept a day; a look that failed (no connection, a rate limit, a timeout of 10 seconds) writes nothing and is tried again after half an hour. `chats.threads` answers with what is kept and starts the looks for repositories that are due in the background, one at a time and once each however many reads ask; the next read carries the icon. The same file a day later isn't downloaded again. | The list must open instantly, and GitHub's rate limit is shared with everything else Whombat does. |

## Where each thread stands (2026-11-28)

John, 2026-11-28, on Home: “I am unable to see in the chat thread list which threads are waiting for a reply, which
threads are working, and which threads are done.” He approved the mockup and asked for the phone apps too. The apps'
side: `docs/app/decisions/chat-inbox-web.md` AP-9391…AP-9397.

| # | Decision | Why |
|---|---|---|
| CIB-19 | **A thread says how its latest job ended** (`ChatThread.job`: `outcome` completed, failed or stopped, and `endedAt`): the newest T3 Code thread handed over from it (not a council's or a checklist's) once T3 Code said its run is over and it waits for nothing (no pull request's checks, no work it is still finishing), as long as the person hasn't written in the thread since. Optional and additive: an older app ignores it. | The live hand-overs list an ended job for half an hour (a week with its receipt); a row should still say Done after that, until the person asks something new. |
| CIB-20 | **Filters: All, Waiting, Working, Done, Unread**, over the open threads, each with its number. Waiting also counts a thread whose T3 Code job asks for the person's OK; Working counts the assistant's or T3 Code's work and a job waiting for checks; Done counts jobs that finished, didn't finish or were stopped. Settled stays its own list. | The three questions John asked of the list, beside what's new. |
