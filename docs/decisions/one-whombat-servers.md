# One Whombat — servers inside Whombat (stream SH, 2026-10-17)

Stream SH of `docs/implementation/one-whombat/assignment.md` §6.2, under `docs/decisions/one-whombat.md` (ONE-11…ONE-15)
and contracts 0.80.0 (CT-339, CT-342). The hosts service is Rackoon's hub run headless (`whombat-hosts`, contract
`hosts/docs/WHOMBAT.md`). Code: `apps/server/src/hosts/`.

| # | Decision | Why |
|---|---|---|
| ONE-DH01 | **The client is plain `node:http` over the unix socket** (`WHOMBAT_HOSTS_SOCKET`), one request per call, no new dependency. The bearer is the service token file's contents (`WHOMBAT_HOSTS_TOKEN_FILE`), read lazily, again when the file's mtime changed and once more after a 401 (the service rotates it by rename). `Accept-Encoding: identity`, 15 s default deadline (60 s for manage changes, 150 s for commands), answers over 16 MiB refused. Problems become `HostsError` with the service's `code`; a missing socket, refusal, missing token or timeout `HostsUnavailable`. | Same shape as computerd's client; the service may write its token after Whombat started (a fresh box), so nothing is read at boot. |
| ONE-DH02 | **The servers belong to this Whombat's oldest burrow.** Its `hosts.*` routes, the `hosts:<burrowId>` topic, the Servers connection and the Home sources exist only there; another burrow's `hosts.status` answers `present: false` with “Servers are watched in another burrow on this Whombat.” | One hosts service per box, one fleet; a box almost always has one burrow, and showing a second burrow another one's servers would leak them. |
| ONE-DH03 | **Superseded in part by one-person.md OP-S07**: a person's request goes as `admin` (no members); Whombat's own reads and tool calls go as before. **Who the service hears**: a person's request carries `X-Whombat-Actor: <principal id>\|<name>` and the role Whombat already allowed (owners `admin`, members `viewer`; a member's inspect views and manage reads `operator`, since Whombat lets members read them). Whombat's own cached reads go as `whombat\|Whombat` (viewer; `/agents` and `/hub` admin), the event stream as `whombat-server\|Whombat` admin. A Servers tool call goes as the Whombat's id and “Whombat for Mara”, with the role its route needs (reads viewer, power/config/snooze/checks operator, migrate and commands admin). The client address is passed when the request came over HTTP (a session has none). | The service's audit log and per-person limits then name the right person; the role is a second line behind Whombat's own rule. |
| ONE-DH04 | **Header text is sent as UTF-8 bytes**: controls and `\|` become spaces, names are cut to 120 bytes on a character boundary, ids are reduced to the service's `[A-Za-z0-9._:@-]`. | Node writes header strings as latin1; handing it the UTF-8 bytes makes Go read the name as written (“José”), within WHOMBAT.md's 128-byte limit. |
| ONE-DH05 | **Superseded by one-person.md OP-S07**: the person changes servers (no owners or members); Whombat still changes them only through the Servers tools under keys, tiers and approvals. **Who may change servers: the burrow's owners.** Members see everything (fleet, servers, guests, history, settings are owners'), may inspect views and read manage data, and may acknowledge or snooze alerts and take that back (attention, not a change to a server). Owners only: settings and switches, removing, host and guest power, snapshots, every manage change, maintenance windows, checks, consoles, enrollments. Whombat (the agents) changes servers only through the Servers connection's tools under keys, tiers and approvals. | The assignment's “owners change servers, members view”; a console is control, so it is the owners'. Heartbeat ping URLs (a check's credential) are blanked for members. |
| ONE-DH06 | **One event stream per process**, resumed with `Last-Event-ID`, reconnecting after 5 s doubling to a minute; `resync` (or coming back after a break) forgets the cache and sends `hosts.resync`. | The service keeps 4096 events and caps streams per actor; one stream is all Whombat needs. |
| ONE-DH07 | **Realtime frames on `hosts:<burrowId>`** are ephemeral bus frames (no outbox row): `hosts.guest`, `hosts.alert`, `hosts.task` (`action.finished` → `actionId`, `task.finished` → `taskId`) and `hosts.enrollment` as they come; `hosts.server` coalesced to one fleet read per 5 s for the servers that changed and only sent when the row changed (besides `lastSeen`); maintenance and check changes as `hosts.resync`. | Every server reports every 10 s: without coalescing a fleet of 8 would cost a fleet read per second, and on a managed box every frame lands in the session event log. |
| ONE-DH08 | **Mapping is lenient** (`map.ts`): main shapes field by field, rare nested parts by a snake→camel converter that keeps the keys of data maps (`values`, `options`, `series`, `summary`, `platforms`, `tags`, `unavailable`); a bare date becomes its midnight UTC, an unreadable time null, a missing list empty. Status: never reported → `pending`, offline, an open critical alert asking for attention → `bad`, the hub's warning or an open warning → `warn`, else `ok`. `cpu24h` is the last 48 points of `/fleet/series?range=24h`; a row's switches are `/agents`' hub switch AND agent flag, with the reason when off. | One odd field must not empty a server's page; the contract's status words need the alerts as well as the hub's three states. |
| ONE-DH09 | **A person's change runs on the service first, then is signed**: the route checks the owner rule, calls the service (an `externalEffect`, so a session command is pinned; every hosts write is `never` resent, CT-339), and on success commits `hosts.change` (kind System, “Restarted web on pve-02”) with the change for Done recently. A refusal signs nothing: the service audits refused attempts under the person's name. | Signing before would leave signed lines for changes that never happened (a digest mismatch, a switch that is off); the service's own audit already covers attempts. |
| ONE-DH10 | **Consoles are proxied** at `/api/v1/burrows/:burrow/hosts/consoles/:sessionId/ws`: `hosts.createConsole` opens the session on the service as the person and returns Whombat's own single-use token (30 s, same person, same session, kept in memory); the upgrade checks the sign-in (cookie from Whombat's origin or a bearer), the owner rule and the ticket, then opens the service's console over the unix socket (service token, the same actor, `rackoon.console.v1` + `rackoon.token.<token>`, no compression) and relays binary frames unchanged; a browser more than 4 MiB behind pauses the upstream. SPICE is refused (VNC covers Proxmox, ONE-13). | WHOMBAT.md §5; the service's token never reaches the browser. |
| ONE-DH11 | **Refusals in Whombat's words** (`errors.ts`): the service's code picks the contract error and a short sentence (“Changed meanwhile — review again.”, “pve-02 isn’t connected right now, so it can’t do that.”); field errors pass through for forms; the service's own sentence is kept only for the platform's message and argument refusals. An unreachable service is a 503 `conflict` with `details.code: hosts_unavailable`. | People and Whombat relay these; the contract has no `unavailable` REST code. |
| ONE-DH12 | **Undo** (ONE-08): power (start ↔ shut down or stop, pause ↔ resume; a restart, a snapshot and a command have none), configuration (the previous values, only while the keys still hold what the change set; masked secrets never restored), settings and switches (the previous ones), a snooze (taken back). The undoers are registered with the Home registry; recipes are sealed with the change. | The assignment's list; refusing when changed meanwhile keeps Undo from overwriting someone's later edit. |
| ONE-DH13 | **Superseded in part by one-person.md OP-S07**: the person undoes their own changes (no owner check); Whombat's changes are undone by Whombat as before. **Who runs the inverse**: a change Whombat made through a Servers tool is undone by the same Whombat as a new `connection_call` committed after the Undo commit (keys, tiers and approvals apply again; a sensitive inverse such as stopping a guest asks); a person's change is undone at once by the person who pressed Undo, if they are an owner. Taking back a snooze is every member's, on the service directly. The inverse records its own change with `undoes`, which marks the original undone. | ONE-08 and ONE-DW06 for Whombat's changes; a person's change has no Whombat to ask, and the owner rule applies to the inverse as to the change. |
| ONE-DH14 | **Callable builtins** (`connections/callable.ts`, shared with stream SD: `CALLABLE_BUILTINS` = `device`, `whombat_servers`; `isCallableEntry`): builtin entries whose connections the server makes and whose tools agents call through the same `connection_tools`/`connection_call` path — visible to agents, the Servers tools synced from the entry's tools, run by an adapter registered at startup (`registerBuiltinAdapter`) that also gets the call's agent, burrow, connection, conversation and person. | The catalog marks both `builtin` (never added by a person) but agents must call them like any connection; one predicate keeps the places that skipped builtins consistent. |
| ONE-DH15 | **The Servers connection is made by the server** in the servers' burrow when the service is configured (checked at start, every minute until there is a burrow — a fresh box has none — then every ten): shared, handle `servers` (`servers-2` if taken), label “Servers”, nobody connected it, unsigned like a migration. Without the service it stays and is marked `error`, so its tiers survive. Its tools start at the catalog's defaults (reads and changes Allowed, CX-20a); the sensitive rules make stopping, shutting down, rebooting, restoring or deleting snapshots, migrating and running a command always ask. | “Provisioned by the server, never addable” (CT-342); nobody's action to sign. |
| ONE-DH16 | **The Servers tools answer compact JSON** for the agent: rows without sparklines, details without the guest lists (`guests_list` has them), histories averaged to at most 60 points per series with average and peak, configurations with their digest; a server is named by id or host name (any case), a guest by id or a unique name; refusals as `{error, code, fields?}` in Whombat's words. `guest_power`'s stop/shutdown/reboot become the hub's `force_stop`/`shutdown`/`reboot` for VMs and `stop`/`stop`/`restart` for containers, with `confirm` (the approval already happened). `server_command` sends only the command (the reason is the person's, on the card and in the change); `guest_migrate` ignores `online` (the service moves running VMs live and containers with a restart). | Prompt size; the service refuses unknown fields. |
| ONE-DH17 | **Changes made through the tools are recorded by the tools** (`hosts.change` committed as the Whombat after the call, `forPersonId` its owner, in the call's conversation). | They know the server, the guest and the inverse; a generic “called guest_power” record can't undo anything. SW's generic recording of connection writes must skip `whombat_servers` (lead: check at merge). |
| ONE-DH18 | **Home sources** (`sources.ts`, registered as `hosts`): Needs you — critical alerts that ask for attention (“Look into it” · “Remind me tomorrow”, subject the server) and, for owners, servers waiting to be added (“<host> wants to be added”, Review → `/things/servers?add=1`); Your things — one thing per server (`server:<id>`, icon `server`, the hub's note or the status words, facts CPU · Memory · Hottest · Guests); Watch — every open alert (acknowledged and snoozed ones say so) and the hints. All from the cached fleet. | The mock's Needs you and Home; one fleet read per Home. |
| ONE-DH19 | **No migration** (`0105` unused): the connection and its tools use the existing tables, changes are SW's `changes`, console tickets and the cache are in memory. | Nothing of this needs to outlive a restart; a ticket lives 30 s. |
| ONE-DH20 | **The fake hosts service** (`hosts/testing/fake.ts`) serves the hand-off sample data on a unix socket with the hub's real shapes filled in, checks the bearer, records actor headers, streams events, follows actions with `action.finished`, keeps configurations with digests, answers diagnose/exec/migrate as WHOMBAT.md describes and serves echo consoles. Tests override single routes with `on(method, path, handler)`. | Tests and fixture worlds without Go; WT's web fixtures can reuse its JSON. |
| ONE-DH21 | **Servers calls in words** (`registerCallWords` in `connections/adapters/index.ts`, used by `call.ts` and the approval's copy): an approval for a Servers call is titled with what it does — “Restart web on pve-02?”, “Move web from pve-01 to pve-02?”, “Run “uptime” on basalt?” — instead of the action's generic “Use guest_power on servers”, and what Whombat posts after a yes is one sentence (“Restarting web on pve-02 now.”, “I couldn’t restart web on pve-02: pve-02 isn’t connected right now, so it can’t do that.”) instead of the tool's JSON. The words are written by the server from the call's own arguments (`ApprovalDraft.callWords`), never by the agent. | The mock's approval (“Restart arnica-prod-nest-01 on pve-02?”), and CLAUDE.md: tool names and JSON stay out of the chat. The action's copy in core is generic for every connection; a contract field for it is a 0.80.1 candidate. |
| ONE-DH22 | **No re-authentication step for owners.** Rackoon asked for a fresh sign-in before turning a switch on, a host shell or an admin manage op; the service token skips that (WHOMBAT.md §2). Whombat's own sign-in and the owner rule are the gate for people, the screens confirm destructive steps (the service's `confirm` / `confirmName` pass through), and Whombat's own calls ask a person through approvals. | Whombat has one sign-in (passkeys, enrolled devices on a box); a second, Rackoon-style password prompt doesn't exist here. |
| ONE-DH23 | **The Servers connection signs in with `none`** (`SERVERS_SIGN_IN` in `provision.ts`), like a device's connection, and `ensureServersConnection` sets a row the first version stored with `builtin` right (at start, then every ten minutes). `catalog_connections.sign_in` is typed `SignInKind`, so a value outside the contract no longer compiles. | `builtin` isn't a `SignInKind`: the server sent it in `connections.list` (unchecked in production), the app's tolerant decoding dropped the row and every box with servers showed “1 item needs a newer version of the app.” (John's DEV box, 2026-10-17). A builtin entry offers no sign-in, so `none` is what it is; no migration, the check that already runs repairs it. |

## A development server against the real hosts service

```sh
# In hosts/: the hub (the hosts service) and the simulator, built anywhere outside the checkout
go build -o ~/bin/whombat-hosts ./cmd/whombat-hosts && go build -o ~/bin/rackoon-sim ./cmd/rackoon-sim
D=~/scratch/hosts && mkdir -p $D/data
~/bin/whombat-hosts serve --headless --data $D/data --listen unix:$D/api.sock \
  --agent-listen 127.0.0.1:24428 --agent-url wss://127.0.0.1:24428 --service-token-file $D/token &
CA=$(curl -s --unix-socket $D/api.sock -H "Authorization: Bearer $(cat $D/token)" http://hosts/api/v1/hub | jq -r .ca_sha256)
~/bin/rackoon-sim --ui unix:$D/api.sock --service-token-file $D/token --agent-url wss://127.0.0.1:24428 \
  --ca-sha256 $CA --n 4 --interval 5s --offline-after 0 --allow-manage --state $D/sim &
# Whombat: the two settings, then start as usual
WHOMBAT_HOSTS_SOCKET=$D/api.sock WHOMBAT_HOSTS_TOKEN_FILE=$D/token pnpm --filter @whombat/server start
```

The servers show in the oldest burrow; owners switch consoles and power on per server (`PATCH …/hosts/servers/:id`).
`WHOMBAT_HOSTS_BIN` and `WHOMBAT_HOSTS_SIM` (the two binaries) turn on `hosts/real.int.test.ts`.
