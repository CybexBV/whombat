# The public README (RDM)

John, 2026-11-20: make the README the front door of the public repository, in the style of Fusebox's: a stranger
should want to try Whombat in the first screen, then learn how. Its facts follow the website (whombat.com: home,
download, pricing, open source, how it works) and assume the repository as it will be published, with the box's
system in `appliance/` and the server monitoring service in `hosts/`.

| # | Decision | Why |
|---|---|---|
| RDM-01 | **The README is for people who might run Whombat; developers get `docs/development.md`.** The README has the logo, one line and a three-line pitch, a large picture of Chat, eight reasons, the install steps with Easy and Expert side by side, a tour in pictures, what Whombat Link adds and what stays free, privacy and security in four points, a short build-from-source part, contributing and the licence. What the README held before (prerequisites, the community box's quick start, the layout, every script) moved whole to `docs/development.md`, which the README links. | A newcomer decides in the first screen; the long developer reference stays complete one click away. |
| RDM-02 | **Its pictures come only from the demo world**: the web app in fixture mode, never a real Whombat, so no real names, addresses or mail can appear in them. `pnpm readme:shots` (the `readme` Playwright project, `apps/web/readme/`) takes them all again into `docs/readme/`, with its own Vite server and the fixture worlds it needs (the one-Whombat shell, servers, services, automations, screens) and the visual suite's frozen clock. Each is taken light and dark and shown with `<picture>` by the reader's colour scheme; the desk screen is dark in both, so it has one picture. Nothing compares them: a changed screen needs the command run again, every picture looked at and the guard's picture scan before committing. | Pictures that remake themselves stay current with the app, and the demo world is already public. |
| RDM-03 | **Sizes for GitHub**: computer screens at 1440×900 (Chat at 1440×960, so the question and its approval fit) and the desk screen at 1280×800, drawn at their own size; phones at 390×844 drawn at twice the size, so they stay sharp when shown small. PNG, about 2 MB for all 15. | GitHub's column is about 900 px wide, so 1440 px is already sharper than needed; WebP would need a new tool for a small saving. |
| RDM-04 | **The phone pictures are the web app at phone size**, not the native app on a simulator. | The script must remake every picture on one machine without a Mac; the native app on a simulator can replace them later. |
| RDM-05 | **Badges: the licence, the newest build on the Beta channel (from the public update repository's releases), Download and the apps.** A “latest release” badge would show nothing: Production releases aren't published there as GitHub releases. | A badge that says “no releases” turns people away. |
| RDM-06 | **The README says what a newcomer would otherwise find out the hard way** (2026-11-21, after the launch review): Whombat is in beta; Whombat Link is sold in EU countries for now; the installer erases the disk and a self-installed Whombat doesn't encrypt it; what leaves the box (to the connected AI, and with Link the status and notification previews); the community box's limits (Linux, a scripted assistant until the real engine is installed, development passwords). A short “Questions” section answers the first questions: an account, why a whole system, why only HTTPS, building your own image, letting an AI act. The Beta badge sorts by version (`sort=semver`), because GitHub lists the update repository's releases out of order. | The first comments on a launch ask these; an honest answer up front builds more trust than a find. |
