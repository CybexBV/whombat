# Workstream: more connections — the server's catalog side (2026-10-19)

Decisions taken while building stream S of `connections-more.md` (CM-01…CM-30): the socket transport (TrueNAS,
ESPHome's Device Builder), the session sign-in (Pi-hole, Nginx Proxy Manager), reads by a query parameter (SABnzbd,
NZBHydra2), Plex's sign in once and the skills. Numbering CM-S01…; code in `apps/server/src/connections/socket/`,
`session.ts`, `provision/plex.ts`; migration 0120 (skills only).

## The socket (CM-13…CM-17)

| ID | Decision | Why |
| --- | --- | --- |
| CM-S01 | **One socket per call, opened by `openChannel`** (`socket/channel.ts`): `outboundConnectOptions` for the socket's `http(s)` URL (the policy's checked and pinned lookup, the pinned certificate's agent), then `ws:`/`wss:`; no redirects, no compression, `User-Agent: Whombat`, a 10 s connect deadline (DNS, TCP, TLS and the upgrade), the whole call `callDeadlineMs` (30 s, the Vault's test seam shortens it). A message is at most 4 MiB (the agent reads 64 KiB of it), at most 2 048 unread messages, anything that isn't a JSON object ends the socket. | CM-15. A TrueNAS `pool.query` or `disk.query` answer is one message larger than 64 KiB; reading it whole and cutting the text is the only way to give the agent the start of it. |
| CM-S02 | **Nothing secret goes on the handshake.** The sign-in is only the spec's `login` message, its templates filled from the secret and the fields (`fillLoginParams`); a template naming an empty value doesn't sign in (`needed`). ESPHome's `Authorization: Bearer` on the handshake and TrueNAS's other mechanisms are unused. | One way to sign in per dialect, the one CM-13 writes down; a header the server ignores could still be logged by a proxy in front. |
| CM-S03 | **JSON-RPC sign-in**: `true`, or a `response_type` of `SUCCESS`, signs in; `false` or another `response_type` is a refused key; an error (a method TrueNAS doesn't have, any other) is the protocol's problem, never a refused key. Calls carry ids 1, 2, …; notifications (no id) and other ids are skipped; `params` defaults to `[]`. JSON-RPC errors reach the agent as `{code, message, data: {error, errname, reason, extra}}`: the Python trace and `py_exception` are dropped. | A wrong mapping would mark a working connection `needs_reauth`. TrueNAS answers `false` for a revoked key, including one it turned off after it went over plain http (CM-05). The trace is long and says nothing an agent can act on. |
| CM-S04 | **ESPHome's greeting**: the first message within 10 s must be server info (`requires_auth` a boolean, `esphome_version` or `server_version` a string), else the socket isn't the Builder's (CM-07's too-old sentence). `auth/login` goes only when `requires_auth`; `rate_limited` means the Builder paused sign-ins — never retried, never `needs_reauth`; a Builder that asks while the connection has no password is a refused credential (“asks for a username and password”). The session token `auth/login` answers is kept only for the echo guard. | The Builder locks an address for 5 minutes after 10 failed logins; a second try would only make that worse. A Builder that gained a password since it was connected needs a person, as a refused token does. |
| CM-S05 | **Streams** collect their events' `data` as text (strings as they are, objects as JSON) and end with the terminal `event: "result"`, a `result` key, `seconds` (default 10, 1…25) or the socket closing (a log stream's output is its answer). A JSON-RPC method a spec lists as a stream is bounded the same way. | CM-14. `devices/logs` never ends by itself. |
| CM-S06 | **The answer's text**: compact JSON of the result; a stream's lines, each ending in a line break, then the result's JSON or “[still going after N s; Whombat stopped reading]”; an error as `{"error": …}` after any output, `isError` true. Cut at 64 KiB with `request`'s mark. Withheld whole (`CONNECTION_WITHHELD_TEXT`) when it holds a form of the secret or a token the sign-in gave (CM-12, VT-D22). | One shape for every socket answer, readable as JSON (`outputDocument` parses it for change records). |
| CM-S07 | **Failures in words** (`socketCallError`): a handshake answered 401/403 or a refused sign-in at call time is a failure with status 401, so `confirmRefusedCredential` runs the check and marks `needs_reauth` only when the check is refused too (CX-D31); no socket (404, a web page, no server info) is the entry's `missing` sentence; a closed socket is “The connection closed before it answered.”; the destination, a timeout or a certificate are the Vault's summaries. `failureOf` gives a `SocketCallError`'s own words. | The agent hears what happened in our words; one refused call doesn't take a connection down by itself. |
| CM-S08 | **The `call` tool** is stored with origin `socket`, after the typed and MCP tools; its definition (`socketToolDef`: the reads, the streams, `params` an array for JSON-RPC and an object for ESPHome, `seconds` only when the spec has streams) is hashed like any tool. `coversReads` (`request` and `call`) runs reads at Allowed unless the tool is Off; `connectionCallAccess` (`call-access.ts`) decides by the method for the call path, Look only, widgets and change records. A refused method, or the method Whombat signs in with, is `invalid_arguments` before anything is signed; so are unknown arguments and a `seconds` that isn't a whole number. A write's change record is “Changed something in TrueNAS”, as `request`'s. | CM-14, CM-16: only Whombat signs in, and calls that never end can't be answered. Until contracts 0.97.0 core's `callAccess` doesn't know `call`; the server's own function stays correct afterwards because it reads the spec it stores. |
| CM-S09 | **The socket check** (`socket/check.ts`): sign in, send the check's method and params, and say the version: the check's `version` path, else a string result, else `result.version`, else the greeting's; only the version number (“TrueNAS-25.10.1” → 25.10.1), the line “TrueNAS 25.10.1”. A check method's error naming `not_authenticated` or `EACCES` is a refused credential. An unverified certificate follows CX-D33 (Use this fingerprint). The http note says “the password crosses your network unencrypted” for socket and session entries, and isn't added when nothing secret is sent (ESPHome without a sign-in). `checkKindFor` answers `socket` for an entry with a socket check, whatever its sign-in. | CM-17. ESPHome without a sign-in would otherwise have been checked as an MCP server (`none` meant MCP until now). |

## The session sign-in (CM-10…CM-12)

| ID | Decision | Why |
| --- | --- | --- |
| CM-S10 | **Signing in** (`session.ts` `signInSession`): the login's JSON body with `{secret}` and the fields filled, `Content-Type` and `Accept` JSON. 400/401/403 is a refused password, 429 paused sign-ins, a 2xx without a token at `tokenJsonPath` “let Whombat in but gave it no session” with the two-step hint, anything else its status. The lifetime is the answer's seconds (a number or numeric string) or ISO time, else `ttlSeconds`, never past a day. | Pi-hole answers a wrong password 401, Nginx Proxy Manager 401 (400 for a malformed body); a user with two-step sign-in gets a challenge instead of a token (CM-08's sentence, generic enough for both). |
| CM-S11 | **Keeping it**: sealed in the access-token columns with its expiry, used while more than a minute is left (`REFRESH_MARGIN_MS`), else one sign-in per connection at a time outside any caller's command; the write is conditional on `credential_version` (a new password or address that lands meanwhile wins; the stale session is signed out). A refused password marks `needs_reauth` (`token_invalid`, “Needs a new password.”), which clears the session without signing it out (it expires). A 401 **or 403** is tried once more with a fresh session (`renewedOn`). | CM-11; as `client_credentials` (CS-D17). Nginx Proxy Manager answers an expired token 403. |
| CM-S12 | **Signing out** (`logout`, best effort, never throws) the session a new sign-in replaced, the one before a new password or address, and a removed connection's (`revokeConnectionTokens`). | Pi-hole keeps 16 seats; sessions Whombat no longer uses shouldn't hold them. |
| CM-S13 | **On the connect side** the check signs in (`CheckCredential.session`) and the connection keeps the session it got (create, sign in once, Replace token); an address change signs in with the stored password at the new address — the old address's session is never sent there — and replaces the session. `tokenCheckCredential` refuses a session sign-in whose body needs an empty field (`fields.username`). Echo forms are the password and the session. | CM-11: “The check signs in, then sends the entry's check request with the session.” A second sign-in right after the check would cost a seat for nothing. |

## Plex (CM-06)

| ID | Decision | Why |
| --- | --- | --- |
| CM-S14 | **plex.tv is a provisioner origin** (`PROVISION_ORIGINS`): sign in once may call it besides the server's own address, https only, under the destination policy, never with the server's pinned certificate. | The sign-in is at plex.tv; the Plex server itself is usually on the home network over http. |
| CM-S15 | **The sign-in**: `POST https://plex.tv/api/v2/users/signin`, form `login`, `password`, `rememberMe=true`, `verificationCode` with a code; headers `Accept: application/json`, `X-Plex-Product` and `X-Plex-Device-Name` “Whombat”, `X-Plex-Client-Identifier` `whombat-<32 characters>`, a MAC of the burrow under the master key (`provisionClientId`, the same for every sign-in from that burrow, so the account's Authorized Devices list one Whombat). 201 with `authToken` (`authenticationToken` read too); 401 mentioning the verification code asks for it (or refuses the one sent); any other 401 is a wrong login; 429 paused; anything else stops (CS-D30). The account's email (else username) is the connection's external name. | python-plexapi's sign-in, which Plex's own clients match; `rememberMe=true` is what they ask for the token that lasts. A random client id per sign-in would leave a new device in the account each time. |
