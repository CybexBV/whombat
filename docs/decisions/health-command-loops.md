# The same command failing the same way (HC-*)

Finding F5 of the DEV Whombat health review (2026-10-07), asked for by John directly. Measured on his box
(wb-k2rt-8pwn-5521), 2026-10-04…07: 121 of 616 shell commands failed (exit ≠ 0), 1 646 s in all. Run #5 (2026-10-04
12:33, whombat-app PR #1) had 46 failures costing 1 345 s of its 2 212 s and most of its 14.17 M input tokens:
`pnpm build:widget` failed 8 times, the Playwright visual suite 3 times, the typecheck twice — under the then 2 GiB
computer memory cap (since raised, memory-pool.md MP-01) — and `loader.ts` was edited 12 times between attempts. Run #8
had 20 failures. The pattern: the same command, unchanged, run again after it failed, up to eight times; nothing in the
prompt or the runner stopped it.

AE-03 (agent-efficiency.md, “Checks match the change”) decides which checks a turn runs; this decides when it stops
running one that keeps failing the same way. Both are “How you work” lines; the runner's backstop is new.

Measured before deciding: the pinned Claude Code 2.1.283, driven offline (fake Messages API, `CLAUDE_CODE_SHELL` a
logger; throwaway driver in `~/.cache/wb-tmp/hcl/drv/`), hands every Bash call to its shell as `source <snapshot>
2>/dev/null || true && shopt -u extglob 2>/dev/null || true && { \builtin unalias … } >/dev/null 2>&1 || true && eval
'<command>' < /dev/null && pwd -P >| <tmp>/claude-<4 hex>-cwd`, the last file named fresh for every call (2.1.292's
source: `Math.random()` per command) — two runs of one command never have the same text. Its tool result for a failure
is `Exit code N` and the merged output. Codex 0.160 runs `<login shell> -lc <command>` with the agent's command as written
(agent-computer.md spikes).

| # | Decision | Why |
|---|---|---|
| HC-01 | **The prompt says it.** “How you work” (`persona/work.ts`), right after AE-03's line: `- A command that failed twice the same way isn’t run a third time unchanged: change something (the command, the code, the environment) or say what is in the way.` Every turn with that section, with a computer or without. `pnpm prompt:size`, system prompt before → after: Pippa DM (Codex) 25 697 → 25 859 characters (6 424 → 6 465 ≈tok), Banjo run (Claude) 35 669 → 35 831 (8 917 → 8 958), Hazel personal 21 503 → 21 665 (5 376 → 5 416), Dusty scheduled 22 632 → 22 794 (5 658 → 5 699): +162 characters, ≈ +41 tokens a call; user turns unchanged. Tests: the runner's prompt snapshots (`prompt-turns`, `handoffs`, `prompt-capabilities`). | The model decides first; one line on every call costs less than one more failing build. It names the code and the environment as changes because the runner can't see those. |
| HC-02 | **What counts as the same failure.** The command the agent wrote — trimmed, Claude Code's wrapper taken off (`agentCommand`: the `eval` argument, unquoted; a wrapper it can't read loses only its `pwd -P >\| …` step) — in the same working directory (the request's `cwd`), ending with the same exit status (a signal as 128 + n). A success of it, or a failure with another status, starts it over; a changed command (text or directory) is another command. Not failures, and they start it over too: exit 1 that is an answer, of `grep`, `egrep`, `fgrep`, `rg`, `find`, `diff`, `cmp`, `test`, `[`, `git diff` or `git grep` as the last command of the line (Claude Code 2.1.292's own table, which tells the model “No matches found” or “Files differ” for them, plus `cmp`). Never counted: what Whombat didn't run (the guard's refusal or a person's no or silence, 126/125; a computer that couldn't start; a lost connection) and a command the client killed (its exit reaches nobody). Edits with the CLI's own file tools are no change to the runner: it can't see them, and run #5 edited `loader.ts` between its eight builds. | Without the wrapper taken off nothing would ever repeat for Claude. An answer isn't a failure, and Whombat's own no is a decision, not a try. |
| HC-03 | **Told at the second failure, not run at the fourth.** The second identical failure's output ends with `[whombat] This command failed the same way twice. Don't run it again unchanged: change something, or say what is in the way.`, the third's with `[whombat] This command failed the same way 3 times; unchanged, it won't run again. Change something, or say what is in the way.`; the fourth and every later identical command isn't run: exit 1 and `[whombat] Not run: this exact command already failed 3 times. Change it, or tell the person what is in the way.` Exit 1 as asked: 126 and 125 stay the guard's (`COMMAND_EXIT_CODES`: a key that is Off, a person's no, no answer in time). The lines go on stderr after the command's own output, right before its exit status (Claude Code merges both streams into the tool result, Codex aggregates them). One turn's record (a new turn starts empty): the last 64 failing commands (`REPEATS_KEPT`), keyed by a SHA-256 of directory and command, nothing of a command kept; a refused command stays refused until the turn ends or 64 newer failing commands push it out. | Two failures in a row with the same status are a pattern; a third try after a change of code or environment is fair, since the runner can't see such changes; a fourth unchanged is the loop run #5 was in. Against run #5: the build stops after 3 of its 8 failures, the Playwright suite (3) is warned on its second and third, the typecheck (2) is nudged once. The cost: a test command failing three times the same way while the code changes in between is refused once — a narrower or otherwise changed command runs, another exit status starts over, and the line says why. The third failure's line warns before the refusal, so the agent can change course without spending a call on it. |
| HC-04 | **Superseded in part by one-person.md OP-07, OP-S107**: repeats are still refused before a command runs, now by the turn's `TurnCommands`, which the launcher asks for every command. **In the exec service, first.** `ComputerSession` (`apps/runner/src/computer.ts`), the path every shell command of a computer turn takes for Claude and Codex (AC-02), keeps one `CommandRepeats` (`apps/runner/src/command-repeats.ts`, pure) per turn. The refusal is decided as soon as the request is read: before the computer is set up and before the guard, so a consequential command that kept failing isn't put to a person again. The verdict after a run comes from its exit frame, only while the client is still connected, and its line is written before the exit is passed on. Tests: `command-repeats.test.ts` (the wrapper strings as 2.1.283 sends them), `computer.test.ts` (the real wrapper against the exec service: the nudge on the second failure, the warning on the third, the refusal on the fourth, the start-over on a success, another status, a changed command or directory, Claude's calls counted together, answers, killed commands and the guard's no not counted). | One place sees every command of both providers before it runs. |
| HC-05 | **The Work view shows it as not run.** The exec service tells the turn before it answers (`onNotRun`), so the `ActivityRecorder` expects one refused command; its row is the provider's shell call (`Bash`, `shell`) whose result has `REPEAT_REFUSED_LINE` as a line: `failed`, `failure: 'blocked'`, kind `command` (Codex may have read the command as a read or a search), the command as object and evidence input. Both are needed: a command that prints the line itself stays an ordinary failure, and one refusal marks one row. The title comes from the server (`activityCopy`, `apps/server/src/runtime/activity-copy.ts`): a `command` row failed `blocked` with no key needed reads “Command not run” · “kept failing the same way”; core's `describeActivity` reads every blocked row as “Blocked”, and core is vendored, so no contracts change. A blocked row that names a key keeps core's “Blocked · needs …”. When contracts next change, this copy can move into core. Tests: runner `activity.test.ts`, server `activity-copy.test.ts`. | The one place a row reads output text (work-supervision.md: titles from facts), only to find which row was Whombat's own refusal, and only when there was one. |
| HC-06 | **Superseded by one-person.md OP-S107, OP-S115**: every command Hermes runs goes through the launcher, in development too, so the runner's backstop sees them all. **Turns without a computer are left alone.** Self-hosted guarded and trusted turns, the dev stack (computers off, AC-23) and Feedback assessments run Claude Code's own Bash or Codex's own shell; no exec service sees their commands, so there is no runner backstop there, only HC-01's line. | A backstop there would mean wrapping the CLIs' shells as computer turns do, on hosts whose owners watch their own machine; the measured loops were on the appliance. |
| HC-07 | **The journal says it.** The runner logs `command <first word> #<8 hex> failed the same way N times (exit S): told the agent` (info) and `…: not run` (warn), with the dispatch id; never the command itself (AC-DR21). | An operator sees it working without opening the Work view. |
