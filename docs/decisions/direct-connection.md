# The direct connection (DC-01…DC-20)

Step 4 of the Hermes rebuild, stream R2 (hermes-engine.md HE-49…HE-51, HE-S180…HE-S199): clients reach the box itself
over the local network or Tailscale with the same Noise session they use through the relay; the box serves its own page
to browsers there; it tells its clients those ways; owners switch Tailscale on from This Whombat; a developer's browser
gets into `pnpm dev` (`enroll.dev`). Code: `apps/server/src/managed/direct/`, `session/endpoint.ts` (`acceptDirect`),
`session/registry.ts` (the direct unenrolled class). Shapes: contracts 1.0.0 (CT-1250…CT-1257: `@whombat/protocol/direct`,
`Welcome.direct`, `TailscaleStatus` and `host.tailscale*`, the manager's `/v1/tailscale/*`, `enroll.dev`), mirrored in
`direct/protocol.ts` and `direct/tailscale.ts` until stream R1 vendors them; the ops in `direct/ops.ts` run once the
vendored allowlist names them.

| ID | Decision | Why |
| --- | --- | --- |
| DC-01 | **One session, three ways.** The direct listener carries exactly the relay's inner layers: Noise XX with the content identity (`secure.ts`, prologue `whombat-secure-session/2`, the client pins the box's PeerId) and session protocol frames, run by the same `SessionConnection`. Only the outer step differs: a WebSocket at `/v1/direct` (subprotocol `whombat-direct.v1`), the client's text `hello {v, class}`, the box's `welcome {heartbeatMs, maxMessage}`, then binary only — no ticket. | HE-50: one session, so one set of checks. |
| DC-02 | **One port, 4480** (`WHOMBAT_DIRECT_PORT`, `off` for none), bound on every address (`::`, IPv4 included; `0.0.0.0` without IPv6). Outside production `PORT + 80` on loopback (4400 → 4480), so two development servers don't collide. A port the box can't have leaves it on the relay, logged. | The image's firewall opens one port (HE-51); addresses change with DHCP and `tailscale0` appears at sign-in, so binding per address would need rebinding. |
| DC-03 | **Where it answers** (`WHOMBAT_DIRECT_INTERFACES`, default `lan,tailscale0`, `loopback` outside production), checked per connection before a byte is read: the interface the connection arrived on must be named — `lan` is the box's own network cards, never the computers' bridge (`wbc…`), container or VM bridges, tunnels — and the peer must be where that way comes from: private, link-local or on-link addresses for the local network, Tailscale's ranges (100.64.0.0/10, fd7a:115c:a1e0::/48) on `tailscale0`, loopback on loopback. | A public address on the LAN card is a router's port forward, not the local network; the agents' computers aren't clients. The firewall (N4) is the outer wall; this holds without it. |
| DC-04 | **Host and Origin.** `Host` must be the address the connection arrived at, the box's Tailscale names (MagicDNS name and short name, from tailscaled) or a configured name (`WHOMBAT_DIRECT_HOSTNAMES`), else 421. A WebSocket's `Origin` must be a page of this box on this port (any of those names or its own address), the hosted web app (`WHOMBAT_APP_URL`'s origin: it tries the box's `wss://` Tailscale route before the relay, contracts `directRoutesFor`), or absent (a native app), else close 4403; a box inside A3 (own-address.md) doesn't accept the hosted app's origin. On the own address (the relay's door) `:authority` or `Host` must be the box's own host, with port 443 implied, and `Origin` that address or absent. Development adds `localhost` and loopback pages (a Vite dev server). | DNS rebinding and other sites' pages: there is no cookie to steal, but a page elsewhere shouldn't use visitors' browsers against the box. |
| DC-05 | **Limits, per peer and overall** (`limits.ts`; a peer is an address, a local IPv6 one counted per /64): 64 sockets per peer, 512 overall; new WebSockets 30 at once then 1 a second; 4 Noise handshakes at once per peer, 16 overall, a budget apart from the relay's 8; 20 failures (a bad hello, a handshake that didn't finish, a key the box refused) in 10 minutes turn the peer away for 10 minutes (sockets closed at once). The outer hello within 10 s and ≤ 1 KiB; binary messages ≤ 256 KiB; no compression; pings every 20 s, two unanswered end it; HTTP headers within 10 s. At capacity 4429, while draining 4503 with `{"retryAfterMs":5000}`. | Nobody vouches for a direct peer, so what control's ticket and the relay bound per subject is bounded here; neither path can starve the other. |
| DC-06 | **Admission by the box, from the key the client proved, as through the relay** (contracts CT-1250): an enrolled endpoint gets the `app` channel, a revoked one the session's own `revoked` with its clear-cache notice, any other key the `enroll` channel. Unenrolled direct sessions have a class of their own (`MAX_UNENROLLED_DIRECT_SESSIONS`, 4; the relay's 4 are untouched), one per peer address at a time (another gets `too_many`), the same idle and lifetime limits, and one that ends without enrolling counts as a failure for its address (DC-05). | A page the box serves is its own origin with its own key (SC-12): it can only enrol over the connection it has, and the community edition has no relay. A class of its own keeps the local network from crowding out devices enrolling through the relay, and the reverse. The lead's first brief said enrolled keys only; the contract and the lead (2026-10-24) settled this. |
| DC-07 | **HTTPS and HTTP on the same port.** The first byte decides: a TLS record (0x16) gets HTTPS (TLS 1.2+) with the certificate for the requested name (SNI) when it is the box's Tailscale name and the tailnet has HTTPS; anything else plain HTTP. No certificate for a name: the TLS handshake fails. | `tailscale cert` is for the MagicDNS name only; one port for the firewall. |
| DC-08 | **The page for browsers** is the release's web build (`webDistDir`: `WHOMBAT_WEB_DIST`, else `WHOMBAT_APP_DIR/web`, else the checkout's `.whombat-app/web`), served by the listener itself: `index.html` never cached, `/assets/*` for a year, precompressed siblings, the app's routes answered with `index.html`, only GET and HEAD. Every answer: `nosniff`, `no-referrer`, `X-Frame-Options: DENY`, `frame-ancestors 'none'`, COOP/CORP same-origin. A plain GET of `/v1/direct` answers `{v: 1, appliance: <PeerId>}` so a page learns the key it pins. No web build: the page answers 404 and native clients are unaffected. | HE-50: a hosted https page can't open a socket to a LAN address. The old Fastify web serving is the HTTP clients' and goes with them (HE-48). The PeerId isn't secret: any handshake shows it. |
| DC-09 | **No HSTS** on the Tailscale page. | Certificates can be switched off for a tailnet; HSTS would lock browsers out of the box's name. |
| DC-10 | **A session knows how it came** (`SessionScope.transport`): the relay, or direct with the network (`lan`, `tailscale`, `loopback`, `door`: the own address), TLS or not, and the page's `Origin` and whether it is a secure context (https, or loopback in development); a native app has no page. | What a page can do depends on it (DC-11). |
| DC-11 | **What the plain HTTP page goes without** (`SECURE_CONTEXT_FEATURES`): passkeys (WebAuthn), notifications (service worker, Push, Notifications API), offline and installing (service worker), the async clipboard, camera and microphone (`getUserMedia`), the share sheet, and key protection (`crypto.subtle`: the device key is a software identity, SC-12). The Tailscale HTTPS page has all of them but passkeys (a passkey belongs to the hosted app's name). The own address's page (own-address.md) has all of them; its passkeys are box passkeys (`boxPasskey.*`, the box's host as RP ID), and the hosted app's passkey ceremonies are refused there like on the Tailscale page. The page knows its own context (`isSecureContext`) and says what isn't available there; the server answers honestly too: `passkey.register.begin`, `passkey.register` and `remoteHelp.confirmBegin` from a direct page whose origin isn't one of the passkeys' origins are refused (`forbidden`, `details.code: passkeys_unavailable_here`) before a ceremony starts. The session, its encryption, uploads, downloads and everything else work the same. | HE-50: what needs a secure context says it isn't available there. |
| DC-12 | **The ways in** the box tells an enrolled session (`Welcome.direct`, `DirectAddresses`, CT-1252; `routes.ts`): the direct port, its local-network addresses (IPv4 first, at most 8, link-local left out: a URL can't carry a zone) (superseded in part by open-speed.md OS-04: private addresses only), its Tailscale name while Tailscale is on and the listener answers on `tailscale0`, and the routes best first — each address (`ws://…:4480/v1/direct`, page `http://…:4480/`), then the name (`wss://`/`https://` with the name's certificate; `ws://`/`http://` while the tailnet has no HTTPS, so the Android app still connects). Null on the `enroll` channel; no routes on loopback. Read per session from the interfaces and the last Tailscale state. | HE-50: clients try direct first. Where the box sits on someone's network is for the people enrolled on it. |
| DC-13 | **The manager drives Tailscale** (CT-1255): the runtime calls `/v1/tailscale/state`, `on`, `off`, `sign-in` and `cert` on the manager's socket and never tailscaled itself. Owners' ops `host.tailscale`, `.on`, `.off {signOut?}`, `.signIn` (CT-1254, `direct/ops.ts`): no manager → `{tailscale: null, reason: 'not_managed'}`; the manager not answering → `reason: 'unavailable'` or `tailscale.unavailable`; a change running → `tailscale.busy`. The login link shown is only ever Tailscale's (`https://*.tailscale.com`); the box joins the tailnet of whoever signs in there. The runtime reads the state every 30 s and after each change (the names the listener answers to and the routes follow it). | HE-51: off until an owner signs it in, Tailscale's own login link, never an auth key in Whombat; the manager already does the box's host changes (Wi-Fi), the runtime holds no right over tailscaled. |
| DC-14 | **What the image and the manager give (N4):** tailscaled in the image, off by default; the manager as its only caller (its operator rights and the certificate permission are the manager's); the firewall opening 4480 on the LAN and `tailscale0` only. | The LocalAPI's own permission model, kept out of the runtime. |
| DC-15 | **Certificates** come from the manager (`/v1/tailscale/cert`: chain, key, `notAfter`) on the first TLS handshake for the name, are kept in memory only and asked for again daily and 14 days before they run out; a failed request is retried after a minute, the HTTPS page unavailable meanwhile. | tailscaled keeps and renews them; the runtime needs them in memory only. |
| DC-16 | **Tests use a stand-in** (`FakeTailscale` behind `FakeManager`): the login link, the sign-in completing, on and off, sign out, a certificate from a test-only pair. Never this machine's own tailscaled. | The brief. |
| DC-17 | **Development enrolment is `enroll.dev`** (CT-1257, HE-49): on the `enroll` channel, answered only by a development runtime and only on a direct session over loopback (`dev_only` anywhere else, the trust service refusing outside development whoever calls); the key of that session is bound to the account with `account.email`, created with `account.name` when new; while the Whombat has no owner that account becomes its owner and the Whombat is claimed (signed `appliance.claimed`, method `dev`). In development the runtime prints `http://localhost:<direct port>/` at start. `via: 'dev'` (recorded as `screen` until 1.0.0 is vendored). | `pnpm dev` has no relay, control or screen. | DC-18 | **Health:** the admin socket's session endpoint line names the direct listener (port, sessions); its counters (sockets, handshakes, refusals, failures, lockouts) carry no addresses. | Diagnostics without who. |
| DC-19 | *Superseded by DC-20 (whombat-link.md LNK-10): there is no plain-HTTP page any more.* **The plain-HTTP page: a software key only there, and said before it is used** (2026-11-05). `loadOrCreateEndpointKey` makes a non-extractable WebCrypto key wherever the page has WebCrypto, whatever the caller asks; a software key only when the page has no secure context **and** the caller allows it (`allowSoftware`: only the box's page and its screen mode); anywhere else it refuses (`EndpointKeyUnavailableError`). A stored key is held to the same rule: a software key is given back only where this page would make one; anywhere else it is refused as `weakKey` and kept until the person chooses “Forget this browser” (“Set up this browser again”), never used or quietly replaced. A browser whose WebCrypto lacks Ed25519 (or a stored WebCrypto key on a page without it) gets `unsupported` (“This browser can’t keep a device key safely”), never a blank page. On the plain-HTTP page, before anyone signs in or opens the app, `InsecurePageGate` says once per browser what the page can't protect and points to the Whombat app and the Tailscale page (“I trust this network”; remembered in that origin's `localStorage`, forgotten on sign-out); a browser left as a screen isn't stopped. The page stays: community boxes are set up there and tablets show the box's screen from it. | Closes the silent fallback (a hosted or Tailscale page never gets a readable key) and makes the remaining trade-off a choice the person makes knowingly. | DC-20 | **Pages only over HTTPS** (2026-11-18, whombat-link.md LNK-10, LNK-11, LNK-17). A browser that comes over plain HTTP, on the local network or a Tailscale address, gets one sentence (`text/plain`) naming the box's HTTPS addresses — its own address while it serves, then its Tailscale name — or how to get one, and no app code, so no page keeps a software device key. The identity GET of `/v1/direct`, the apps' Noise WebSocket and a council's picture uploads stay on plain HTTP: they carry their own trust. A tablet becomes a screen only from a page with a secure context (`enroll.display.request` refuses one without). | The plain-HTTP page was the one place a key could be copied; Link's own address and Tailscale give every box an HTTPS page. |

## Security review of the direct path (2026-10-24)

A fresh read of what changes when nothing stands between a client and the box: the relay and control are gone from the
path; the Noise session, the session protocol and the per-request checks are unchanged (MA-07, MA-08, the
secure-channel review in `appliance/docs/implementation/reviews/secure-channel-review.md`).

**Confidentiality and integrity without TLS.** The client pins the box's PeerId (learnt at enrolment, from control or
the box itself) and the library checks it inside the handshake, before message 3 (review §“Handshake”); a man in the
middle on the LAN or the tailnet sees ciphertext, as the relay does, and can't finish a handshake as the box without its
content key. Small-order and non-Ed25519 identities are refused before signature verification (review L-1, L-5, fixed
in the library). TLS adds nothing to that; on the Tailscale name it exists for the browser's secure context (DC-11), and
WireGuard already encrypts the tailnet hop.

**Replay.** Every connection runs fresh ephemeral keys; recorded traffic can't be fed into a new session, and transport
nonces stop reordering and duplication within one. The outer hello carries no secret and no state. Durable commands keep
their receipts (a resent request id never runs twice). The enrolment ceremonies keep their own one-use proofs (CPace
begins bound to both Noise keys, pairing codes, invite secrets, recovery statements bound to the new key).

**Denial of service.** Unauthenticated work is bounded at every layer (DC-05): accept (per peer and overall), the first
byte and the HTTP headers (10 s), the upgrade (a token bucket), the hello (1 KiB, 10 s), the Noise handshake (about
2–4 ms of CPU; 4 per peer and 16 at once, its own budget apart from the relay's), the admission lookup (one indexed read)
and failures (lockout). Unknown keys land in the direct unenrolled class (4 at once, one per address, the idle and
lifetime limits), never in the enrolled devices' or the relay's places. *Residual:* a LAN attacker holding many IPv4
addresses (ARP) can fill the overall budgets and slow the direct path for everyone; clients then use the relay, whose
budget is separate. The enrolment ceremonies' box-wide budgets (claim attempts 30 an hour outside the claim window,
screen sign-in requests 30 an hour, pending pairings) can be spent from one address in turn (keys are free; one session
at a time, 20 failures per 10 minutes): someone on the network can hold up sign-ins at the box's screen for an hour, or
make the claim wait for the claim button — as anyone on the same network with a cloud account could through the relay.
A per-address share of those budgets is the next step if it matters.

**Enumeration.** An unauthenticated peer learns that a Whombat answers on 4480, its PeerId (any Noise handshake shows it;
not a secret), the web build (public anyway), whether a key *it holds* is enrolled, and what the enroll channel tells
anyone who reaches it through the relay — the claim state, and whether an email has an account here
(`enroll.screen.request`, bounded by its limits). Nothing about devices, names or addresses (the ways in go to enrolled
sessions only, DC-12).
*Residual:* a Tailscale HTTPS certificate puts the box's MagicDNS name (machine and tailnet name) in public Certificate
Transparency logs, as Tailscale documents; the name is reachable only inside the tailnet. This Whombat should say so
before an owner relies on HTTPS (W4).

**Attackers on the local network.** Native apps are not affected: their code doesn't come from the box, and they pin its
PeerId. The box serves no page over plain HTTP (DC-20): a browser there reads one sentence and runs no code from it, so an
active LAN attacker (ARP, DHCP or DNS spoofing) can change that sentence but can't run code as a page of the box or read
a device key. Pages come from the own address or the Tailscale name, both HTTPS with authenticated code and a
non-extractable key.

**DNS rebinding and other sites.** No ambient authority (no cookie, no bearer token): every session proves a key held by
that page's own origin. The Host check (DC-04) still refuses rebound names, and the Origin check keeps other sites from
using visitors' browsers to open sockets to the box.

**Tailscale.** Tailnet peers reach the port as the tailnet's ACLs allow and are admitted like anyone else. Only owners
change Tailscale: whoever signs in decides which tailnet the box joins. The login link shown is only ever Tailscale's
(`https://*.tailscale.com`). Whombat holds no Tailscale secret and no right over tailscaled: the manager drives it
(DC-13, DC-14); the certificate's key reaches the runtime over the manager's socket and stays in memory. tailscaled's
state is the image's (not in Whombat's backups: a restored box signs in again). Changes aren't in the signed appliance
log yet: contracts would need a `tailscale.*` event type.

**Development.** Two independent checks keep `enroll.dev` to development (the op needs a direct loopback session; the
trust service refuses outside development), and the development listener binds loopback only. *Residual:* any process
or user on the developer's machine can enrol into a development Whombat, as they could read its database.

**What the tests show** (`direct.int.test.ts`, `direct/*.test.ts`): an enrolled key gets the same welcome and answers
directly as through the relay; an unknown key gets the enroll channel in the direct class, one per address, and counts
against its address when it leaves without enrolling; a revoked key hears `revoked` both ways; a client pinning another
box never gets a session; a page can't start a passkey ceremony where a native client can; `enroll.dev` only in
development on a direct loopback session, claiming for an owner's email; Tailscale's owners-only ops through the
manager, and HTTPS on the Tailscale name with the manager's certificate on the same port; the outer refusals (bad
hello, Host, Origin, rate, lockout, drain, capacity) and the page.
