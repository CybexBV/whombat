| UI-R17 | **`0049_hired_doing` and `0050_subscription_usage` keep the floors of `0048_capabilities`: `0047_delegation`** (2026-09-30, found shipping pve-20260929.5; supersedes UI-R01's and UI-R09's floors). An `expand` migration's floors are the oldest binary that can still read and write what it produces; for a data-only change or a new table that is the floor before it, not the schema before it. With floors climbing to `0049_hired_doing`, a box on `0048_capabilities` (every production box) taking 0049 and 0050 in one update would find that its current runtime could no longer write the migrated database, so its manager requires a verified backup checkpoint first (CT-134) and waits for ever without a backup destination: the DEV box did (`waiting: checkpoint`), and the upgrade gates 4 (rollback from pve-20260929.4) and 5 (`update-migration` from the 0047 runtime `2be6fc1`) failed on it.
