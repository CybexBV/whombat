# Backups you can trust: What's protected and restore tests (PRT)

Part of John's “look-after” build of 2026-11-28 (feature council: backups you can trust). Backups were set up one by
one, and nothing said whether all the data was covered, whether a copy sat on the same machine as the data, or whether a
backup would actually come back. Now one page answers “if a machine breaks, what would I lose?”, and Whombat can prove,
once a week, that a Proxmox machine's backup really starts.

Contracts (additive): `@whombat/core` `domain/protected.ts` (`ProtectedView`, `ProtectedRow`, `RestoreTestServer`,
`RestoreTestResult` and the shared words), `api.protected.get`, `api.restoreTests.set`, `api.restoreTests.run`,
`HostGuestDetail.restoreTest`, the care step `restore_test`, the server hint `restore_test.failed`, the assistant's
`whats_protected`. Session protocol minor 22 (`PROTECTED_MINOR`): an app shows the page's links only on a Whombat that
answers it. Migration `0048_restore_tests`. The hosts service restores a copy cut off from the start (`isolate` on
`backup.restore`, agents with the capability `restore_isolate`) and reads a backup's own settings without restoring it
(`backup.config` at `GET …/backups/config`, agents with the capability `backup_config`; `hosts/docs/MANAGE.md` 2.3),
which this release's signed agents bring.

## What the person sees

| # | Decision | Why |
|---|---|---|
| PRT-01 | **One page, “What’s protected”** (`/protected` on the web, `whombat://protected` on the phone), reached from a row at the end of the Servers list, beside Open to the internet and the same kind of row, and from This Whombat → Backups. One row for each thing that holds data: this Whombat, each server, each Proxmox, Incus and QEMU/KVM machine, and each connection that keeps data (Home Assistant, Immich, Paperless, Nextcloud, a NAS, the media and code services). A row links to its page. | The question is about everything at once; the answers were spread over a dozen pages. |
| PRT-02 | **Three groups, worst first inside each**: *Copied to another machine*, *Only on the same machine*, *Not backed up that Whombat can see*. A last backup that failed comes first, with the one before it. A copy older than eight days is amber. | The difference that matters when a machine dies is “is the copy somewhere else?”, not “is there a backup job?”. |
| PRT-03 | **Whombat says only what it saw.** *Copied* and *only on the same machine* are said only of a backup that worked, by where it is: a Proxmox machine's newest backup on its own backup list (the storage it is on, never a plan's storage), a NAS task whose run worked. A plan or task whose backups never worked is in the third group, “In a backup plan, but no backup has worked yet”; a last backup that failed with none before it, “… none has worked yet”. “Nothing backs it up” only where Whombat reads the backups and finds none; where it reads no backup facts (a server's own disks, a service without its own, a machine whose backup list wasn't read this time, a backup that worked but isn't on its list) the row says “Whombat can’t see its backups” and sits in the third group, never a guess. A kept fact from before this rule that says copied without a backup that worked reads as planned. Things Whombat couldn't read this time are named in one line. | Saying “copied” about a backup job that never worked, or “not backed up” about a backup Whombat can't see, would be false; hiding either would be worse. |
| PRT-04 | **A service without backup facts of its own takes its machine's**: Paperless on CT 131 is as safe as CT 131 (“With pve-02 · CT 131 · …”). One with its own facts (Home Assistant's backups and where they were uploaded, a Synology's Hyper Backup, a TrueNAS's replication and cloud sync) keeps the better of its own and its machine's. | Most services live inside a backed-up machine; the person shouldn't see them as unprotected. |
| PRT-05 | ***Ask {assistant} to set up backups*** on every row of the last two groups starts a chat in that thing's own thread (the server's, or the connection's) with a plain question that names it and what Whombat sees. The assistant proposes with the care plans and backup places it has. | One press from the worry to the fix, in the place that thing is talked about. |
| PRT-06 | **This Whombat's row is copied or same machine only once a backup worked at the place backups go now**: the backup service keeps its last backup when the place changes, so the row counts it only when it is newer than the moment backups started going to that place (the place Whombat set that changed the repository, a move of the same one to a new address not counting; when Whombat didn't set it, the service's word). Before that it is a plan, “In a backup plan, but no backup has worked yet”, with the failure while backups there fail. **It shows its off-site copy** from the copy's own status (“Off-site (Backblaze B2) · last copy 2 hours ago”): the storage's name, never its address; a last copy only once the bucket's own list showed a backup in it (“no copy yet” before); amber “copying there failed …” while copying there fails. Without a copy the row is as before. | A place chosen today holds no backup yet, whatever worked at the place before. The copy's own status is the one that knows; a copy the bucket doesn't show isn't one, and a copy that stopped is what the row must not hide. |
| PRT-07 | **Restore tests are a switch per Proxmox server**, “Test my backups”, off until the person (or a care plan's Go ahead) turns it on, with which machines (all, including new ones, until some are chosen), the last result, when the next test starts, and *Test one now*. | Proving a backup works is the step people never take by hand. |
| PRT-08 | **Once a week in the quiet hours** Whombat tests one machine: the one with a backup whose turn it is (never tested first, then the one tested longest ago), never sooner than seven days after the last test started (one that started late in the night moves the next a little later, at most a day). A test runs at most an hour: one whose copy wasn't asked to start by then (the restore still running) is skipped, “it took over an hour”, which raises no problem; one whose copy was asked to start gets the start's and the guest agent's own limits first, then fails as too long. A copy whose restore ends later is removed by the sweep. | One machine a week covers a home lab in a few weeks without loading the server. A slow restore says nothing about whether the backup comes back. |
| PRT-09 | **The result is a fact** on the machine's page (“Restore test: worked on Sunday (took 4 min)”) and on its row; a test that couldn't run says why (“there wasn’t enough free space”). | People trust what they can read next to the machine. |
| PRT-10 | **A failed test opens one problem for that machine** (“The backup of plex didn’t start when Whombat tried it”), which starts on in What Whombat watches (data is at risk and Whombat says which and why) but exists only while restore tests are on; it ends when a later test of that machine works, or when tests are switched off. A test that couldn't run (no space, no backup, the machine uses parts of the server) is no problem. | Data at risk is the bar for starting on; not being able to test isn't data at risk. |
| PRT-11 | **“Test my backups” is a line of a Proxmox server's care plan** (Go ahead turns the switch on), offered once the plan has its backups and the release the box would go back to after a failed update knows the step (schema `0048_restore_tests` or later, the automations' release gate). | One yes for looking after a server, as the care plan does already. The release before this one can't read a plan with the step. |
| PRT-12 | **The assistant reads it all with `whats_protected`** (personal chat only), optionally about one thing; it switches tests with the settings skill (`restoreTests.set`) and starts one with `restoreTests.run`. | “What would I lose if pve-01 died?” is a question people ask in Chat. |

## How a restore test runs (the real machine is never touched)

| # | Decision | Why |
|---|---|---|
| PRT-20 | **A copy, never the machine**: the newest backup is restored with the hosts service's restore route as a new guest in a range nobody picks (990000–990999), named `whombat-test-of-<name>` and tagged `whombat-restore-test` (where the cluster allows the tag). The real machine is only read. **Only a copy that is provably the test's own is touched**: the restore itself writes a mark only that test knows (`whombat-<test id>`) into the copy's notes, so the mark is there from the moment the copy exists, and nothing at a copy's number is changed, started, stopped or deleted unless its settings, read right before, carry that mark (a change also carries the settings' digest). A machine without the mark (a refused restore, a number someone took) is left alone and the test says so (“Whombat couldn’t be sure the copy was its own”). What remains: Proxmox takes no digest on a start, stop or delete, so a copy deleted and replaced at its number in the moment between the read and the call would be acted on; a delete also needs the copy's name. | Proxmox's restore can overwrite a guest; restoring to a fresh id in a reserved range never can. A person or Proxmox can make a machine at that number at any time, so the number alone proves nothing, and a finished restore task proves nothing about what is at the number later. Notes rather than a tag: a cluster can keep tags to a list, and the hosts service may always write notes. |
| PRT-21 | **It is cut off from the moment it exists**: the restore itself gives the copy its isolation (the hosts service reads the backup's settings and restores with every network card's `link_down=1` and a new MAC address, no start with the server, protection off, its name, mark and tag), so a reboot or a lost answer never leaves a copy on the network or starting with the server. A server whose helper can't do that gets no copy at all (“the server needs Whombat’s newer helper first”). Before it starts Whombat checks again: what didn't take is put on, each part in a change of its own (start with the server off first, then the cables, which never fail over a card model or bridge Whombat doesn't offer, then the name), and it starts nothing unless every card is down and it won't start with the server. A machine that uses parts of the server itself (passed-through devices, USB, host folders, memory shared with the server, the server's hardware random number generator, a hook script, raw QEMU arguments, a container that isn't unprivileged, which runs as the server's own root) is never tested: checked on the machine first, and again on the copy's own settings before it starts, which are the backup's and can differ from the machine's today (then the copy is deleted without starting). | A copy with the same MAC and addresses on the network would fight the real machine; a hook script runs on the server itself. Cut off by a later change, a copy lived with the backup's own settings until then. |
| PRT-22 | **It checks there is room first, for the backup as it was made**: the backup's own settings (read without restoring it) say its disks and memory, which can differ from the machine's today; a VM's disk left out of its backups isn't counted, since a restore leaves it out too. The storage the copy goes to must have those disks plus a margin and stay under 90 % full (three times the backup's size when a disk names no size); the server must have the memory free. When the backup's settings can't be read, or nothing says how big it is, there is no test (“the server needs Whombat’s newer helper first”, “there wasn’t enough free space”). | A test must never fill a disk or starve the real machines; a backup made before a big disk was removed still restores that disk. |
| PRT-23 | **Worked means it ran, and booted when it can tell**: running and, when the copy's own settings switch the QEMU guest agent on (and the real machine doesn't show it missing: running while its agent doesn't answer), its agent answering within 10 minutes; a container running for a minute; a VM without the agent running for two minutes. It stopped by itself, never started, or never finished starting up is a failure. | Running is the honest floor; the guest agent proves the system booted. The copy's own settings say whether it has one (a backup from before the agent was switched on hasn't), whatever the real machine answered at the time; an agent switched on but never installed would fail a good backup. |
| PRT-24 | **Then it is stopped and deleted** (a VM with a forced stop, a container with a stop, as the hosts service takes them), tried again for a while if Proxmox refuses. Every pass sweeps copies left behind by an interrupted test on servers with tests: a machine in the range carrying the mark of a test of that server and number (a copy whose restore answer was lost carries it too), never one only named or tagged like a copy; the sweep never starts one. | A restart or a crash mid-test must not leave a running copy behind. |
| PRT-25 | **Only on the cluster node Whombat talks to**, one test per server at a time; a machine on another node is skipped (“it runs on another server of the cluster”). | The hosts service restores on its own node. |
| PRT-26 | **Not now:** Incus and QEMU/KVM restore tests, files-level checks inside a copy, testing Proxmox Backup Server's own datastore, Docker containers' volumes on the page, an off-site copy of servers. | Proxmox first: it is where most people's machines are and the routes exist. |

## Server details

| # | Detail | Why |
|---|---|---|
| PRT-S01 | Migration `0048_restore_tests` (expand): `restore_test_servers` (per Whombat and server: on, chosen guests, when changed), `restore_tests` (one row per test with its step, copy id, task, outcome and reason; one unfinished test per server by a unique partial index), `catalog_connections.protection` (a service's own backup facts, written by the health pass from what its kind reads). | Every step is a commit, so a restart picks a test up where it was. |
| PRT-S02 | The runner (`backup-trust/runner.ts`) is a home job every minute: it advances running tests step by step (`restoreTest.step`, as the agent), starts a due weekly test, sweeps strays every ten minutes and gives the hosts service's hint list its problems. Passes never overlap. The person's switch and *Test one now* are `restoreTests.set` and `restoreTest.begin` through the pipeline. | All writes through the commit pipeline; reading Proxmox never holds the lock. |
| PRT-S03 | The page is built on the server (`backup-trust/view.ts`) from what Whombat already reads: Proxmox backup jobs (whether a plan covers a machine) and each machine's own backup list (where its newest backup is: on shared storage or a Backup Server it is a copy elsewhere), Incus snapshots and QEMU/KVM backups (same machine), the box's backup status, and connections' protection; kept for a minute. A machine's backup list is read at most 20 machines a build and kept until that machine's newest backup changes, so the next builds read the rest. | No new kinds of reads of the servers for a page view, and a big server isn't read whole on every visit. |
