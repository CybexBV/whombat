# Remote help (2026-10-21)

John, 2026-10-21: “We need to have some kind of debug mode that I can enable so you do have access to it … How can we
implement this in a way that customers can allow this also when they are in need of remote assistance, but still keep
it safe?” After the proposal: “We need a "Forever" option for dev environments (so only works on
https://dev.whombat.com). For the rest: Yes implement this fully”. Build brief: `docs/implementation/remote-help/assignment.md`.
Server details: RH-S*, web/Android: app `docs/decisions/remote-help.md` (AP-4440…), control CL-121…, appliance NX-411…,
MG-118…, CG-290…, contracts CT-930…

| Id | Decision | Why |
|---|---|---|
| RH-01 | **Remote help: an owner lets Whombat support into this Whombat for a limited time.** Off by default and off after every expiry; there is still no standing vendor login, key or account. Amends appliance NX-10 (“There is no vendor key or account that can log in”) to “none that works without an owner's grant” (appliance NX-411). | John needs to research his bare-metal DEV box (“Home”, the Z13) when he asks; customers need remote assistance. The promise that matters to owners stays: nobody gets in unless an owner says so, and they see and can stop it. |
| RH-02 | **Two levels.** *Look*: a fixed list of read-only commands (status, units, logs, boots, hardware, network, disks, memory, processes without arguments, updates, a full report), run as an unprivileged user; no shell, no forwarding. *Look and fix*: also a root command line, any command, restarts and connections to the box's own local ports and sockets. | The journal is content-free by design (appliance NX-16), so Look shows how the box is doing without chats, files or Vault. Fixing needs root; the card says plainly that it lets support see everything. |
| RH-03 | **How long: 1 hour, 1 day, 1 week, and Forever on test Whombats only.** Forever exists only on images whose `whombat.environment` isn't `prod` (John's DEV boxes are `local`; every box that runs on dev.whombat.com uses those images). The support service on the box is the only judge (`foreverAllowed` in its state); the runtime and the apps only show it. A prod image refuses `forever` with `forever_not_allowed` whatever a client sends. | John: “a "Forever" option for dev environments (so only works on https://dev.whombat.com)”. One judge on the box means a modified app or runtime can't get Forever on a customer box. |
| RH-04 | **Owners only, confirmed with a passkey when the owner has one.** Turning on (or changing the level/time) asks for a passkey assertion (new purpose `remote-help`, verified by the box like a passkey sign-in); an owner without a passkey confirms in a dialog. Stop never asks and is also on the desk screen without unlocking it. | A stolen unlocked phone shouldn't be enough to open the box to someone else; passkeys are optional today (an owner can have none), so requiring one would lock those owners out of help. Stopping only ever reduces access. |
| RH-05 | **The box decides who gets in: three checks.** (1) An OpenSSH user certificate signed by the Whombat support CA pinned in the image for its environment (DEV CA in non-prod images, prod CA in prod images), valid now, with this device's id as its principal; (2) an active grant, and the visit stays within its level; (3) on prod images, the help code the owner sees, as the SSH user name (5 wrong codes end the grant). Control can issue certificates but can't make a grant; the relay can neither. | Each party alone opens nothing: control/relay compromise, a leaked support key or a guessed code is not enough. DEV keys can never open a customer box. |
| RH-06 | **One way in: the box's own outgoing line through the relay, only while a grant is active.** A new root service on the box (`whombat-support`, appliance NX-412…) dials the relay as a worker for the device's **support route** (a second opaque route id control keeps per device), using an appliance ticket the manager fetches (device op `support.ticket`). Support people get a client ticket for that route plus their certificate from control's operator API. SSH runs end to end inside the relay's binary frames. No port listens on any network, no SSH daemon, no relay change. | Same outbound-only model as the app (NX-22); the relay already treats a route id as opaque, so a second route needs no relay release. The service is separate from the runtime so help still works when the runtime is what broke. |
| RH-07 | **A visit is one certificate.** It starts with the first connection made with a new certificate and ends when the certificate expires or after 15 minutes without a connection. The box records each step (Look command and its arguments, Fix command lines, command-line sessions' output, restarts, forwards with their target and bytes, refusals); typed input is not recorded. Records stay on the box (90 days, 500 MB) and only owners read them, in Settings. | Support tools open many short connections; one visit per certificate keeps “What support did” readable and the notifications to one per visit. Typed input can hold passwords. |
| RH-08 | **Superseded in part by one-person.md OP-S78**: the person is told of a visit and of five wrong help codes, never of their own grant; the signed appliance events hold. **And by RH-15**: a visit's message isn't repeated within 12 hours. **And by push-words.md PW-01**: the message is the notice and reaches the phone as a message; a security push only without a Chat. **Owners hear about it.** When a visit starts, every owner gets a security push and a short message from their assistant (“Claude from Whombat support is looking at this Whombat now. …”); when another owner turns it on, the others are told; when wrong help codes end it, all owners are told. Turning on, stopping, expiring and each visit are signed appliance events (`remote_help.on`, `remote_help.off`, `remote_help.visit`). | Visibility is the main safety net; the signed chain makes the history tamper-evident like the other appliance changes. |
| RH-09 | **Control sees metadata only.** `status.report.support` carries the state (`off`/`look`/`fix`), seconds left (none for Forever), how many are connected, whether a help code is needed and the service's SSH host public key (an id). Control audits every certificate it issues (operator audit, and the owner org's audit as “Whombat support”). | Keeps the §12 allowlist: enums, counters and ids. The host key lets support tools pin the box without trusting the relay. |
| RH-10 | **Customer boxes get the help code and the prod CA.** The prod support CA key is generated on the prod host at its next deploy (like the other control keys, HZ-05) and its public key pinned in `manifest/prod/support-ca.pub`; until then prod images report remote help as not available and the card says so. | Prod is paused and only deployed when John asks; a prod private key doesn't belong on The Titan. |
| RH-11 | **Terms: a new Appliance Terms version and updated Privacy Policy, Terms of Service and privacy notes**: “no standing vendor login … an owner can let Whombat support in for a limited time … the Whombat records what support does and the owner can stop it”. Existing owners aren't asked to accept again: turning remote help on, with the card's words, is the consent for that visit. | The published texts promise “no vendor login and no remote access”; they must describe what now exists. Acceptance is only checked at claim (CT-112). |
| RH-12 | **Where it lives:** Settings → This Whombat → About (web; Diagnostics is in Settings → Advanced), the phone's About screen, a small “Remote” chip in the desk's top row whose sheet has Stop (2026-10-22, John: the line was too big; appliance CG-295…CG-297), a line on the admin panel's device page. Not in Access, which is about agents' access. | Help and diagnostics belong together; owners look there when something is wrong. |
| RH-13 | **For agents on The Titan:** `~/Code/whombat-appliance/dev/support <name> …` (Look commands, `shell`, `port`, `sock`) through DEV control's operator API, named “Claude” on the box. Research with Look commands; use the command line only when the task is to fix something. | John: “so you do have access to it so I can reference to it and you can research when I ask”. |
| RH-14 | **Whombat connects as “Support”** (2026-10-22): DEV's `dev/support` names the visitor “Support” (was “Claude”), and the words let the name stand alone (contracts 0.121.1, CT-1050): “Support is connected now”, “Support is looking at this Whombat now through remote help. You can stop it in Settings → This Whombat → About.”, “Support is connected” on the desk; the steps say “Support connected”. A person who connects with `--as` reads as well (“Mara is connected now”). The fake support service's visitor is “Support” too. | John: when Whombat connects remotely, the owner reads “Support”, not “Claude” — and not “Support from Whombat support”. |
| RH-15 | **Superseded in part by push-words.md PW-01**: the security push no longer comes with every visit. **A visit is said in the Chat once per visitor per 12 hours** (2026-10-26): when a visit starts and the assistant said the same words (“Support is looking at this Whombat now …”) in the person's Chat in the last 12 hours, after any Clear chats, it says nothing new (`tellPerson`'s `unlessSaidWithinMs`). Every visit still sends the security push, is recorded step by step and is a signed `remote_help.visit` event; another visitor is always said. | John's Chat had eight of these lines in one day of DEV support work, each a thread of its own. The push and the records keep the safety net of RH-08. |
| RH-16 | **The passkey that works where the person is** (2026-11-22, John: remote help on iOS, Android and the web). The step-up of RH-04 asks for the person's passkeys that can run on the device in front of them: on the box's own address its box passkeys (the box's host as RP ID, checked like a box passkey sign-in), in the apps and wherever else the hosted app's passkeys work those, as before. Someone with none that works there confirms in the dialog, as someone without a passkey always has; `start` asks a passkey only of someone who has one that works there, and a begin is confirmed only by its own kind. | Since app.whombat.com opens a box at its own address, the web had no page left where the hosted step-up could run, and the phones can't use box passkeys (own-address.md OWA-17). A person whose passkeys are box passkeys can still turn it on from a phone; support still needs the help code, which only the owner's devices show, and stopping is always one tap. Replaces OWA-26. |
