# Workstream: delegation recovery

The delegation's independent GitHub verification and the lifetime of its completed T3 Code threads.

| Id | Decision | Why |
| --- | --- | --- |
| DLR-01 | **GitHub's explicit plan restriction means no active branch rules only when the branch independently says it is unprotected.** Accept only the specific 403 asking to upgrade to GitHub Pro or make the repository public, on the first rules page, with no reported required checks. Protected or ambiguous branches, ordinary permission errors, rate limits, missing endpoints and partial policy reads still block merging. | A private repository without branch protection returned this plan restriction even though its checks passed. Treating every 403 as unavailable blocked valid work; treating every 403 as no requirements would bypass real policy. |
| DLR-02 | **An unavailable independent verification preserves the completed review.** Keep the final task working, its answer, candidate, generation and passing evidence; put GitHub's bounded refusal on its row and wake the agent once per unchanged blocker. Retry the independent reads for that completed run with exponential backoff from fifteen seconds to fifteen minutes, also after a restart and after readiness is lost just before merging. No new review or test run is needed for a failed read. Changed inputs, heads or bases still invalidate the evidence, and failed checks still block certification. | A generic verification error caused a second full review and then an incomplete delivery, without changing the underlying access problem. |
| DLR-03 | **Superseded in part by DLG-68 ([delegate.md](delegate.md)): Whombat merges the checked candidate itself.** **A completed batch source thread can settle once its delegated work ends and T3 Code watches no pull request for it.** Its source pull request may stay open: the final thread owns the merge. Retain a watch without generic completion messages while T3 still watches a pull request. Ending a delegation quietly rechecks idle completed threads, deduplicated by their watches; the sweep repairs lists ended within the normal seven-day window. Re-read state, delegated work and pull-request watches before settling; an unreadable watch list waits for another read. Preserve failed, stopped, running or newly resumed work. Retry a refused settlement. | Source threads were retained for a merge that happened in another thread, and ended or kept-open lists had no cleanup path. |
| DLR-04 | **Implementation, merge and deployment have separate evidence.** An incomplete card's default status says some work is incomplete, including old cards refreshed during cleanup; a failed final row can show its unmerged state. Agent instructions require current GitHub evidence before reporting CI or merge status and the target's running revision before reporting deployment. A thread's completion text is not deployment evidence. | A card said “Done” after its final verification failed, while a later answer repeated an outdated CI blocker. |
| DLR-05 | **Superseded by FT-01 in [fast-testing.md](fast-testing.md): there are no repository rules a merge waits for.** **Policy scope superseded by RDL-01…RDL-03 in [archive/repository-delivery.md](archive/repository-delivery.md).** **A repository merge limit is a visible wait, not a failed review.** Keep the passing final row, its candidate, evidence and merge intent; name missing saved rules, person-only merging or unreadable rules on the card and wake the assistant once per unchanged blocker. A rule change immediately before sending a claimed merge restores the same waiting row instead of failing it. Current saved rules remain limits; resolving them resumes independent verification and merging without another review. | Adding a managed folder silently blocked a previously offered merge after a long successful review, leaving the person with no next step. |
| DLR-06 | **Passing-check retries superseded by RDL-06 in [archive/repository-delivery.md](archive/repository-delivery.md), itself superseded by [fast-testing.md](fast-testing.md): a retry of a passing final check keeps its evidence.** **Reopening clears the previous outcome note, and repeating the same choices preserves verification.** Invalidate for actual work, eligibility, rules or delivery-mode changes. Repeating already-set merge, pull-request and selection choices does not queue another combined check. An explicit retry still reruns the check. | The old incomplete summary survived reopening, and restating permission to merge discarded a passing review. |
| DLR-07 | **An external merge of the checked candidate reuses its review.** A mirror of that candidate's exact checked head preserves its final row while live GitHub reads independently confirm its delivered tree, checked base, current ancestry and checks. Only then record the final and its eligible sources as merged and wake the assistant to finish. Rules limiting automatic merges do not prevent recording a merge someone already made. Unchecked or changed external merges still need a fresh final check. | Manually merging a reviewed candidate otherwise restarted the full review, even though the delivered files were exactly those already tested. |
| DLR-08 | **The watcher's pass gives every working delegation its turn.** It moves on 20 working delegations per pass, by id, each pass going on after where the last one stopped and starting again after the last page (`workingPage`, a cursor kept in memory; after a restart it starts from the beginning). | It took the 20 oldest by `updatedAt`, and a pass that changes nothing leaves that age as it was, so beyond 20 such delegations the newer ones were never moved on. |

This refines the failure handling and settlement in `delegate.md` and `t3code.md`. The exact-revision merge guard,
branch-policy checks, completed-run probe and rules for preserving active pull-request watches still apply. Retry
bookkeeping lives in the watch's existing progress JSON; no schema migration or cross-process contract changes.
