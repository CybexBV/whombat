Asked for by John on 2026-09-27: a **Vault** where people keep logins and API keys for their agents. Not every agent
can use it: an agent needs a key to an entry. Every access is in the audit log. Example: give an agent Home
Assistant by saving its address and token in the Vault and giving that agent a key.

John's answers (2026-09-27), settled:

1. **Agents never see a secret.** They use entries through Whombat (a bridged MCP server or a brokered HTTP
   request); there is no way to reveal a value to an agent, not even with an approval.
2. **Entries are private to one person.** Nobody else sees them: not other members, not owners, not admins.
   There are no shared entries between people; the Vault is for agents. A person gives their own entries to agents.
3. **An entry at “Asks” asks once per turn** (per entry).
4. **Pack secrets move into the Vault.**

And the points he agreed to on the same day (the “a–h” list): only private entries exist (no team Vault); anyone
other than the owner who makes an agent use an entry always needs the owner's yes, once per turn; audit lines are
neutral for everyone but the owner; admins approve **home-network destinations**, never entries; the self-hosted
host's master key is the honest limit of “nobody”; a once-per-turn yes wakes the agent for a turn that holds the
pass; tools of an MCP entry are on/off; pack secrets become the private entries of the people who set them.

Spans four repos. Each records its own decisions in its usual file and cites VT-xx: contracts
`docs/decisions/contracts.md` (CT-97+, release 0.14.0), whombat-app `docs/decisions/app-managed.md` (AP-109+,
release 0.7.0), runtime here (VT-D01+ below) and `managed-runtime.md` (MR-68+), appliance
`docs/decisions/integration.md` (IN-58+, candidate 0.14.0).
