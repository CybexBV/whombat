# Full Proxmox support (2026-10-17)

John, 2026-10-17 (main checkout): “Implement full support for Proxmox (check Rackoon repo at 10.100.0.6 for more
information).” In Rackoon (The Falcon, `~/Code/rackoon`, identical to `whombat-hosts` at `beaea67`) he had asked the
same that morning — “full support for Proxmox … edit LXCs and VMs … what else would you add?” — and Rackoon got guest
editing, lifecycle, backups, firewall, HA, replication, tasks and bulk actions (`hosts/docs/MANAGE.md`). The
one-Whombat build (ONE-13) brought the agent and the hub over intact but only part of the screens and almost none of it
to Whombat's own tools. A gap review on 2026-10-17 (web, server and tools, Android) listed what is missing; this file
decides what “full” means here. The build brief is `docs/implementation/proxmox/assignment.md`.

| # | Decision | Why |
|---|---|---|
| PX-01 | **Everything Rackoon's web UI did for Proxmox, Whombat's web does**, restyled in Whombat's tokens and in English: hardware add and remove (disks, CD/DVD, cloud-init drive, network devices, EFI disk, TPM, mount points), unused disks (attach, delete), every option Rackoon edited, restricted keys shown locked (“Change this in Proxmox”), the full create dialog (Windows preset, static addresses, DNS, CPU type, VLAN), Convert to template, templates under the guest table, backups (protect, notes, delete, restore to a storage), firewall (options, edit, move, security groups), HA and replication, the fleet-wide guests list with tags and bulk actions, console tools (send keys, paste, full screen, the idle warning). | John asked for it twice; the agent and the hub already do all of it, so only the screens were missing. |
| PX-02 | **Whombat can do what a person can**, through the Servers connection's tools: create, clone, convert and delete guests, disks, backups and backup jobs, ISO images and container templates, tasks (follow, stop), firewall, HA, replication, pause and resume, host power, and it can list a guest's snapshots by name. Whatever destroys or moves something always asks (`HOST_MANAGE_DESTRUCTIVE_OPS`, host power, stopping a guest); the rest follows the tool's tier like any connection. | One Whombat is the front door (ONE-12); on the phone, asking Whombat is how people manage a server. |
| PX-03 | **Scheduled backup jobs** (beyond Rackoon): a server's Backups tab lists Proxmox's backup jobs and creates, edits, pauses, deletes and runs them; a guest without a job gets **Add to a backup job**. The agent changes jobs with `pvesh` as root after checking every argument (Proxmox wants `Sys.Modify` on `/` for jobs, which would let the token change node settings), reads them with the manage token and runs one with `vzdump` like Back up now. | The most common Proxmox hint is “no backup job”, and nothing could fix it. |
| PX-04 | **Control is switched on in two places, and Whombat says how.** The server's own `agent.toml` stays the first lock (a hijacked box can't grant itself control). `whombat-agent allow <switch>…` / `deny` / `policy` edit `[remote_control]` and reload the agent; where the server blocks a switch, the Agent card shows that one command to copy instead of “Switched off on the server itself.” | Rackoon's sentence sent people into a config file; one command is what a homelab owner can do. |
| PX-05 | **Long work reports back.** On the web every started task gets a toast with **Show progress** (the task's log) and its outcome when it ends; a task Whombat started through a tool ends with one short message from Whombat in that chat (“The backup of web on pve-02 is done.”), never the task id or log. Followed tasks are kept in memory for 24 hours (a restart forgets them; the task itself is unaffected). | A clone or restore that failed said nothing before; CLAUDE.md: plain words in the chat. |
| PX-06 | **The phone gets a guest screen** instead of the power-only sheet: Summary, Settings (read, plus the everyday edits: name, memory, cores, start at boot, protection, notes, tags, growing a disk, with the same review step), Snapshots, Backups, Tasks with their log, and Back up now, Clone, Delete. Adding hardware, the firewall rules, HA and replication stay on the web (AP-1367: they need room and a keyboard) and the screen says so with a link. The server screen gets Backups with its jobs. | Android is John's main device (2026-10-04); a power-only sheet isn't “full support”. |
| PX-07 | **Proxmox hints have a way out**: no backup job → Add to a backup job; backup old → Back up now; changes waiting → Restart to apply; old snapshot → Snapshots; guest agent down → the guest; storage overbooked → Storage. Shown on the server's Summary and the guest's page; Watch links to the guest. | A hint without an action is noise (ONE-07). |
| PX-08 | **Fixes found in the review**: restoring a backup over a guest also takes the request's `guestId` (it silently restored as a new guest); a manage request with a parameter Whombat doesn't pass is refused naming it instead of dropping it; listing snapshots needs power or manage on the service, not the console switch; `guest_migrate` takes `storage` (not `online`, which the service decides), `server_diagnose` takes `args`, `server_metrics` names the network series as they are; the guest agent option keeps its other settings; Rackoon names left in the service's docs. | Each was a wrong result without an error. |
| PX-09 | **Not now**: uploading an ISO from the browser (Download from URL covers it; a 5 GB upload through the box and the agent needs its own transport), Proxmox users and permissions, SDN, node network settings, Ceph, migration between clusters or standalone nodes, Rackoon's Screens wall (needs console thumbnails proxied), Incus backups. | Rare for a homelab, or a separate project. |
| PX-10 | **John's servers get control back as he had it in Rackoon** (ONE-23 left it to him; this request is his call): pve-02 everything, pve-01 guest editing (manage), in its `agent.toml` and in Whombat. The agents are reinstalled from the box first (DEV agents are unsigned, NX-152). | He asks for full support to use it; that was his own earlier choice per server. |
| PX-11 | **Delivery**: contracts 0.81.0, app 0.77.0, candidate 0.88.0 with the hosts pin, a host release for John's box (the hub is in the DEV image, NX-152). DEV only, one quick check per repo (ONE-21). | John's standing rules. |
