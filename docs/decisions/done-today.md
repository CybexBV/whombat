# Done today

The desk's *Done today* (“Dusty did 5 things today ›”), its list and *Welcome back*'s done rows say what the assistant
finished, in a few words it wrote itself: “Checked the status of pve-01”. Until now they listed Home's changes, the
records a tool leaves on the way (“Ran a command on the-falcon”), which say nothing about what was done. John asked for
it on 2026-10-27: a chat that is finished gets a very short summary of what the assistant did, and that is what the
screen shows. Contracts 3.3 (`report_done` in `@whombat/core` `mcp-changes.ts`, the `dnt_` id).

| # | Decision | Why |
|---|---|---|
| DN-01 | **The assistant says what it finished with a tool, `report_done {summary}`** (1–60 characters, past tense, plain words, no ids, commands or paths), once at the end of what was asked in a thread and again only after it did more there. It is the person's turns' tool (`personal`: their Chat, schedules and automations; no key), never an outsiders' turn's, never a search answer's (`toolFitsTurn`). Its rule is in the tool's description, not the prompt (hermes-engine.md HE-S37). Its activity row is bookkeeping (“Noted what I did”, `ROUTINE_WHOMBAT_TOOLS`). | The agent knows what it did; asking it at the end of its own turn costs one tool call in a warm context, where a separate summarising turn would cost a whole turn's prompt and show the assistant as busy. Small talk and plain answers stay out because the agent leaves them out. |
| DN-02 | **One row per thread** (`done_tasks`, migration 0011: burrow, agent, person, conversation, thread root or null for the top level, summary, the reporting dispatch, `reported_at`), written by the `report_done` command through the pipeline: a later report in the same thread replaces the words and the time. Rows older than 30 days go when the next report is made. The signed `task.done` event carries the row's and the conversation's ids, never the words. A deleted conversation or thread root takes its row with it. | In Chat each question is its own thread and its own task, so a thread is the unit that is “done”; the follow-up “and restart it” makes the task's words better instead of adding a second line. No sweep loop for a table this small. |
| DN-03 | **The desk reads finished tasks, not changes**: `buildFullGlance` takes the burrow's 50 newest (`recentDoneTasks`): today's (in the person's day) are the count and the three newest the list (`deskDone`), all of them *Welcome back*'s done rows. Settings' preview counts the same. A report sends `home.changed {working}` to the person, so the screen reads again within seconds. | One source for every place the screen says what was done. `working` because a task in one of the person's chats moved; apps refetch the whole overview for any part. |
| DN-04 | **Home's Done recently stays the changes**, with Undo and “Changes here” on a thing's page. | It is the record of what changed and the way back; *Done today* is the short story of the day. |
