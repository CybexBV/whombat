# Server asks: the server side

Decisions the server stream made building server-asks.md (SA-01…SA-09) on contracts 0.86.0. Migration 0107.

| Id | Decision | Why |
|---|---|---|
| SA-S01 | **“No row is `risky`” is superseded by server-asks.md SA-10: no row is `never`.** **`server_asks` keys a server by the hosts service's id in lower case** (primary key burrow + server id), with `asks_first` (`risky` or `never`, checked), `changed_by_id` and `changed_at`. Setting it back to Before risky actions keeps the row with `risky` (who changed it last stays); no row is `risky`. | The agents and the routes name servers in any case (`resolveServer` looks up ids and host names case-insensitively); one spelling per server keeps one row. |
| SA-S02 | **The server a call names comes from the fleet memory in `self.ts`** (`knownServer`: id or host name, any case → id, name, `hostsThisWhombat`), refreshed by every fleet read. Unknown: the fleet is read once (cached 5 s), still unknown → `risky` and no card button. The name is the host name when it is the id with its own capitals (“BlackBox”), else the id, as the Servers tools' messages say it. `callTier` stays pure: `planCall` resolves (`callServerOf`) and passes `{id, name, asksFirst, hostsThisWhombat}` in. | One lookup for the words and the decision; a call never fails because the fleet couldn't be read, it just asks. |
| SA-S03 | **On Never the whole sensitive check of the Servers catalog is skipped** (`isSensitiveCall`: the tools marked `sensitive`, `SERVERS_SENSITIVE` and the names that delete), except `serverAsksApply` (SA-03). The card's button (`params.server`) is set only when the call asks *only* for those rules (key and tool tiers would allow it, not Look only) and Never would let it run. The same applies to Undo's inverse calls (`hosts/undo.ts`), so an undo on a Never server runs without a card too. | SA-06's “only the sensitive mark changes”; offering the button where it wouldn't help would be a false promise. |
| SA-S04 | **Whombat's own built-in tools whose only change is their description keep their New mark as it was** (`mergeTools` `quietWording`, for `transport: 'builtin'` entries: same access, origin and input schema). 0.86.0 rewords the sensitive Servers tools; without this every box would show them New an hour after the update. No migration clears marks: the re-sync after the update would set them again, and New marks that earlier releases left on genuinely new tools stay. | Nobody asked for the rewording, so it is no news; a changed schema or wider access still is. |
| SA-S05 | **`hosts.updateServer` with only `asksFirst` sends no PATCH** to the hosts service, but reads the server's settings for the answer (`HostServerSettings` needs them; a 404 there says the server isn't there before anything changes). With more fields the PATCH runs as before (without `asksFirst`) and the asks change is a second commit in the same request. | SA-05; the read is no change on the service. |
| SA-S06 | **Undoing a yes that said “Don’t ask again” (`undo_approval`) puts the server back to Before risky actions** when it is still Never and the person may change servers (as RA-DS33 does for “Always allow”). Done recently also has the change's own Undo (`servers.asks`), refused when it was changed again since, owners only. | The same way back as the other “always” scope. |
| SA-S07 | **Realtime**: a change of the setting emits a local `server` change on the hosts service (`touched`), so the next `hosts.server` frame carries the row with its new `asksFirst` (the fleet rows always say `asksFirst`, `risky` or `never`). No new frame type. | Clients already refresh a row from `hosts.server`. |
| SA-S08 | **Words**: the signed line and Done recently's title are “Whombat stopped asking first on {server}” and “Whombat asks before risky actions on {server} again”; a shared Servers card that asks for the sensitive rules explains “Servers asks a person before this on {server}. If you approve, it runs once.” instead of “always asks”. | Plain words; “always” is no longer true. |
| SA-S09 | **No prompt in apps/server needed changing for SA-09**: nothing there tells the assistant that server commands always ask or suggests SSH keys; the Servers guide and tool descriptions come from the contracts (0.86.0 already says it), and `servers_overview` / `server_detail` now carry `asksFirst`. | Checked, nothing to align. |
