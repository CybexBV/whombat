# Workstream: runtime CI and test isolation (fixes from the 2026-11-10 audit)

| ID | Decision | Why |
|---|---|---|
| RTC-01 | The runtime check (`scripts/ci/check.py`) runs the CLI's database tests (`cli`: `apps/cli/vitest.int.config.ts`, `schema-check` and `migrate` on the job's Postgres) after the server suite, and the Hermes plugin's tests on the pinned Hermes (`hermes`: `packages/hermes-whombat/scripts/test.py --hermes pin`, a fresh install as `pnpm hermes:install` makes it) after the contracts. The check job keeps uv's and pip's caches in the CI server's cache, as `hermes-latest` does. | The appliance runs both CLI commands at every start, and the plugin runs in every turn; neither suite ran in CI. Locally on 2026-11-11: 3 CLI tests in 5 s, 151 plugin tests (1 skipped: no Chromium) in about 40 s with the install. |
| RTC-02 | Review-screenshot specs in `apps/web/e2e-managed/*-shots.spec.ts` that no longer reach their screens are deleted, not repaired: `an`, `bp`, `chat`, `console`, `si`, `sidebar-servers`, `step4`, `wb`, `wi`, `wq`, `wu`. `billing`, `bko` and `share` still run through and stay. | They were one-off visual checks for finished workstreams, skipped unless their variable is set, so nobody saw them break (Home's greeting, `/agents`, the sidebar's Servers and Dashboard, and words they wait for are gone). Each failed twice in a row on `main`. The screens they showed are covered by the visual baselines and the journeys. |
| RTC-03 | The tests that run the pinned Claude Code CLI on a credential home alone (`agent-runtime/src/providers/bundles.test.ts`) run it in `unshare -rnm` with an empty read-only `/etc/claude-code`, and skip only where such a namespace can't be made. | Claude Code's managed settings (`/etc/claude-code/managed-settings.json`) outrank every home, `CLAUDE_CONFIG_DIR` and `--settings`. The Falcon's sets `ANTHROPIC_AUTH_TOKEN` and `ANTHROPIC_BASE_URL` in `env`, so the CLI said an empty subscription home was signed in (`oauth_token`) there and nowhere else. Hiding it keeps the test whole on every machine; the host's file stays as it is. |
| RTC-04 | On a host without the image's tools, a commands' `PATH` entry that reaches the bound node install through a link (a version manager's `node/24` → `node/24.21.0`) is replaced by the install's own path. | The sandbox binds node's real install but not the link to it, so on The Falcon (node from mise) commands had no `node`: `commands-sandbox.test.ts`'s server kept between commands and Chromium in the commands' network never got their page, and a development box's commands couldn't run `node`. CI passes them: its node is reached without such a link. |
