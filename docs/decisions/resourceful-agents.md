# Resourceful agents (RA-01…RA-62)

John, 2026-10-03, in the main checkout: “I want the agents to work similarly as Hermes Agent … resourceful and get the
job done … learn who the user is and what their preferences are … I think that we have too many restrictions … Consider
if we should keep a computer per agent … consider what skills we need to give the agents … I want to make the agents
really capable.” After the write-up (`~/.cache/wb-tmp/research/2026-10-03-resourceful-agents/write-up.md`, compared with
an independent Codex run in its section 6): “Implement fully, I agree with LAN by default is fine.”

What the research found (verified in code, main `62bb7e43`): GF-01's “Getting it done” lines never reached the live
prompt (only the unused `persona/index.ts` builder has them) and about 40 live lines still say “stop”; no role holds
`memory.propose` or `skills.propose`, so hired agents can neither remember nor learn; there is no store about the person
at all; Claude turns are capped at 80 round trips and may not use sub-agents; agents can't schedule anything; a computer
loses its work folder when a turn ends and reaches no LAN; 57 keys are set per agent, per tool, and every key an agent
lacks is a place where it stops. Hermes Agent (`~/.cache/wb-tmp/hermes-agent`, 2026-10-03): one shell on a real computer,
approvals by risk only, a finish-the-job prompt, a user profile and notes the agent keeps itself, skills it writes and
fixes, schedules, sub-agents and background jobs that wake it.

Settled decisions this file amends are named in each row. Implementation decisions of the streams are `RA-D<stream><nn>`
(C contracts, S server, R runtime, K computer, A app, N appliance, P packs), recorded at the end of this file.
