# Working in public — decisions APC-nn

The appliance is public (AGPL-3.0-only) and its maintainers work in it directly (John, 2026-11-15). These rows were
written when it was a repository of its own; since the one repository it is the folder `appliance/` of
`github.com/CybexBV/whombat` (Whombat `docs/decisions/one-repo.md`), so “this repository” below is that folder, and
the rows that repository's move replaced say so. The policies they name (`CONTRIBUTING.md`, `SECURITY.md`,
`TRADEMARKS.md`, the contributor agreement) are the root's since OR-71. It follows Whombat's rules, PUB-01…PUB-16 (Whombat's
`docs/decisions/public-copy.md`). What differs here:

| # | Decision | Why |
|---|---|---|
| APC-01 | **Whombat's PUB rules hold here unchanged**: one public root commit whose tree is the cleaned private `main` (made with `commit-tree` by `Whombat <noreply@whombat.com>`), the private repository archived with the old history, private values kept out of the source and checked against the maintainers' private guard list, never rewritten. This replaces source-review.md SR-05's history-rewriting mirror. | One way of working in public for every repository. |
| APC-02 | **What moved to the maintainers' private whombat-ops**: their agents' maintainer guide, the `dev/` operator commands (shipping to Cybex's boxes, the DEV box, licences, Stripe, remote help; now its `bin/`, which run this repository's `harness/src/dev/` and `devbox/`), the remote-help client (`harness/src/support/`), the DEV instance's settings and units (`dev/instance/`), the runbooks about Cybex's own fleet (DEV instance, shipping, support, incidents, pilots, provisioning, replacement, RMA, release-signing custody, vulnerability response), the run records (`harness/reports/`, now git-ignored here; `release/out/`) and the production rollout plan and ledger. Deleted: `docs/archive/` and the old candidates' build reports that held private values; the archive keeps them. Everything else is here: the harness, the decisions, the implementation notes, the design references and the runbooks for building, installing, updating, backing up and recovering an image. | What helps someone work on the code is public; what only runs Cybex's fleet isn't. |
| APC-03 | **Every manifest candidate stays**: `manifest/candidates/` is the release record the flake and the candidate tool read and write (flake.nix's `runtime-pin` and `hosts-pin` read the pinned one). | A changelog of what each candidate pinned; nothing private in the ones that stay. |
| APC-04 | **Vendored is `vendor/` and `third_party/`**: a private value there is fixed by taking a release's own files, never by editing them. The contracts' Go vectors and the console's copy of the desk socket's contract come from the release whose only change was the made-up values (contracts 3.20.0), and say so in `VENDORED.md` and `PIN`. | Vendored files belong to their release. |
| APC-05 | **The notices are this repository's own**: `LICENSE`, `THIRD_PARTY_NOTICES.md` and every file of its own the notices name (`voice/NOTICES.md`, `nix/packages/hermes`, …) are here, and an image installs them. | There is no notices generator here. |
| APC-06 | **Public CI runs only on GitHub's runners** (`.github/workflows/public-ci.yml`): the Go tests, the harness's and the console's checks, the vendored contracts' checksums, the scanners' allowlist test and a secret scan of the new commits; pinned actions, a read-only token, no secrets. The NixOS builds and VM tests run in the maintainers' own CI from `ci/platform/`, never for a fork's pull request. | Whombat PUB-16; an image build needs far more than a hosted runner. |
| APC-07 | **The image holds no merge re-run setting** (nixos.md NX-524): the `self-installed-config` check reads back that no environment sets one. | The repository it would name is the tracker's, under the tracker's name (APC-13). |
| APC-08 | **Machine names in fixtures stay** (`the-falcon`, `blackbox`, `pve-02`: the mocks' seed world, as Whombat's PCV-06); the guard list refuses the addresses, logins and ids that tied them to the maintainers' machines, not the names. Comments name roles (“the build machine”). | The contracts' vectors carry these names too. |
| APC-09 | **Cybex BV holds the copyright** (John, 2026-11-15): `LICENSE`, the README, `THIRD_PARTY_NOTICES.md`, `TRADEMARKS.md` and the console page's notices name it. The vendored copies keep their release's own `LICENSE` until they are taken again from a Whombat release that names Cybex BV (APC-04). The console's sign-in fixtures' person is “John Doe”. | The holder is a company. |
| APC-10 | **Issues and pull requests are welcome**, under the contributor agreement (`CONTRIBUTING.md`, `docs/legal/contributor-agreement.md`); a pull request is merged here once `public-ci` and the maintainers' `guard` check pass. | John, 2026-11-15. |
| APC-11 | **Superseded by Whombat one-repo.md OR-16** (one public repository, `CybexBV/whombat`, with the appliance and the hosts service as folders). **The public repositories live under the GitHub organisation `CybexBV`**; the private ones become `CybexBV/<name>-archive`, archived. The account `CybexHQ` stays Cybex's and holds no repository: GitHub sends its old addresses on to the organisation (updates.md UP-X48). | John, 2026-11-15; the organisation, 2026-11-20. |
| APC-12 | **Superseded by Whombat one-repo.md OR-17 and OR-68** (the flake has no input for Whombat or the hosts service: it reads the folders beside it; the VM tests' old runtime comes from `vm-tests/common/migration-baseline.json`, which names none). **The flake's inputs are the public repositories**, at the commits it pins. | Anyone can build an image from public inputs. |
| APC-13 | **The first report tracker's name and its old marks never come back** (Whombat `report-trackers.md` TA-128): the guard list's “repository-wide” rules, checked with the rest of the list at every lint (`scripts/check-forbidden.sh`, `fast-test`'s `forbidden` step), at every commit and push by the maintainers' hooks, and by `release/build` in what it ships (`scripts/scan-artifacts.sh` on the runtime bundle, the manager and the console's page, archives unpacked; required for the maintainers' releases, `WHOMBAT_GUARDS_REQUIRED=1`). Without the list (contributors, public CI) the checks skip. | A guard at the commit, at the push and at the build. |
| APC-14 | **The console's vendored app is taken from the Whombat commit of the cut** (`console/ui/vendor/whombat-app/PIN`), and the vendor script copies the avatars' `elders.ts`, which their module imports. Its demo fixtures use a made-up tracker (“Acme Desk”). | The vendored brand held the old tracker's mark. |
| APC-15 | **The scanners' allowlists name the vendored contracts release, and a test says when they don't**: `.gitleaks.toml` and `.trufflehog-exclude.txt` name `harness/vendor/whombat-contracts/<version>/`'s two tarballs (their conformance vectors hold made-up JWTs and URLs with a password); `scripts/ci/test_scanner_allowlists.py` fails when a vendored tarball isn't allowed by both, and runs in public CI and in `fast-test` (`scanner-allowlists` step) when the allowlists or the vendored contracts change. | The move to contracts 4.0.0 left the allowlists on 3.21.0, and the scan stopped with nothing telling why. |
| APC-16 | **The texts say what is registered**, as Whombat PUB-17: the name “Whombat” is filed as an EU trade mark (pending); the logo, the mascot and the app icons are not registered. `docs/legal/name-and-marks.md` (version `2026-11-20`) and `TRADEMARKS.md` say so. | Only the word mark was filed. |
| APC-17 | **No real person, customer or real-looking domain**, as Whombat PUB-19: the console's demo address with an overlong name is on `harbour-street-studio.example`, and the decisions name a reporter by role, not by name. | A customer is private, and a domain on a real top-level domain could belong to someone. |
