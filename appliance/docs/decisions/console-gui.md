# A graphical installer and console — decisions CG-nn

Decided with John on 2026-09-27. Until now the ISO booted to a shell (`sudo whombat-install --disk /dev/sda
--yes-erase-disk`) and the installed box drew its recovery key and claim code as text on tty1 (`whombat-console`,
CC-08, NX-32, PI-04). John wants both to look and feel like Whombat: a full graphical installer where wombat avatars
guide you through the installation, then after the reboot a graphical screen with the claim code and wombats, and
once the box is claimed a calm screen with the burrow's name and random facts about wombats.

John agreed to the whole proposal (web kiosk, text fallback, burrow names in the console file, fact-checked facts,
mocks before code, minimal installer) and decided **no QR code on the claim screen** (since 2026-11-22 the graphical
console shows QR codes of the addresses to open, never of the letters: CG-418).

Component decisions refine this file: contracts CT-116+, Whombat runtime (managed-runtime.md) MR-78+, NixOS NX-78+.

## Console API (CG-06)

All responses `application/json`, `Cache-Control: no-store`. Static files at `/` need no token; everything under
`/api/` needs `Authorization: Bearer <token>`.

```
GET /api/state
{
  "mode": "console",
  "now": "2026-09-27T12:00:00Z",                  // server clock, for the backoff countdown
  "screen": "key" | "claim",
  "key": null | {
    "groups": ["cbdefghi", …],                     // 8 groups of 8 modhex letters; [] when broken
    "qr": ["#.#..##…", …],                         // QR modules, one string per row, '#' dark; [] when broken
    "hostEncrypted": true,
    "broken": false,
    "confirming": false,                            // a confirmation is with root
    "message": "" | "wrong" | "retry"              // WordKeyWrong / WordKeyRetry
  },
  "claim": null | {
    "state": "starting" | "waiting" | "claimable" | "backoff" | "claimed",
    "code": "KXQM",                                // claimable only
    "claimUrl": "app.whombat.com/claim",           // without scheme
    "appUrl": "app.whombat.com",                   // without scheme
    "retryAt": "2026-09-27T12:05:00Z",             // backoff only
    "burrows": { "first": "Banjo’s Burrow", "more": 2 }   // claimed only, when the runtime sent it
  },
  "footer": "Whombat appliance. There is no login on this console. …"
}

POST /api/confirm  {"group": "cbdefghi"}
  200 {"ok": true}          written to the confirm file, "confirming" until root decides
  422 {"message": "wrong"}  not the key's last group (checked locally, as the text console does)
  409                       not on the key screen, or already confirming
```
