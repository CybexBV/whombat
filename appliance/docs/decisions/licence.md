# Commercial protection: the signed appliance licence — decisions LC-nn

Decided by the orchestrator on 2026-09-26 (assignment: commercial protection + pre-publication security fixes). The
appliance software only runs its paid features with an active Whombat subscription or trial. The mechanism is a
short-lived licence token that control signs from the org's entitlement and the appliance verifies against a key set
pinned in its image. This record also settles self-installed boxes (A2), the appliance terms at claim (A3) and the
proprietary notices (A4).

Component decisions refine this file: contracts CT-76+, control CL-37+, runtime MR-55+, app AP-63+, manager
MG-34+, NixOS NX-38+, harness IN-39+.

**What it protects against, and what it doesn't.** The licence stops the ordinary ways of using the appliance
software without paying: an image copied onto other hardware, a box kept after its subscription ends, a
self-installed ISO nobody pays for, and a box cut off from control so it never learns that its subscription
ended. It is not DRM against its owner. The software is AGPL-3.0, so someone with root on their own hardware may
change it and take the check out; what they can't do is get Cybex's service (the relay, signed updates, remote help)
without paying, because control only serves claimed devices of paying orgs, and the Appliance Terms restrict the use
of that service, never the software. The
billing invariant `ENTITLEMENT_NEVER_AFFECTS = local_data, export, recovery, security_updates` still holds: no
licence state ever deletes, hides or locks data, or stops export, recovery or security updates.

## A1 — The licence token

| # | Decision | Reason |
|---|---|---|
| LC-01 | **Format: compact JWS, `alg: EdDSA` (Ed25519), header `{alg, kid, typ: 'whombat-licence+jwt'}`.** The claims are a strict object: `iss` (control's base URL), `aud` = `whombat-appliance:<env>`, `sub` = the device id, `org`, `plan` (`^[a-z0-9-]{1,32}$`), `state` (`EntitlementState`: `trialing \| active \| past_due \| grace \| cancelled`, which moves from control-contracts into `@whombat/protocol` and is re-exported), `limits {devices, members, agents, connectors}` (`devices` an integer; the other three an integer or `null` = unlimited), `iat`, `nbf`, `exp` (epoch seconds) and `jti` (≥ 128 bits, base64url). At most 4 KiB. Verification is the admission model (strict RFC 8032, small-order keys refused, same rules in TS and Go), in `@whombat/protocol` (`licence.ts`) and Go `protocol` (`licence.go`), with cross-language vectors `vectors/licence.json`. They cover valid tokens, tampered payloads and signatures, a wrong device, a wrong audience, an unknown `kid`, a key from another set (the admission key), a lifetime over 14 days, `nbf < iat`, a token from the future, and extra or missing claims. | Same shape and tooling as admission tickets, which already have TS/Go parity. A distinct `typ` and audience mean an admission ticket can never pass as a licence, and the reverse. |
| LC-02 | **Numbers.** Lifetime `exp − iat` = **14 days** (`LICENCE_LIFETIME_S` = 1,209,600, also the maximum). The manager renews **daily** (`renewAfterS` = 86,400 from control, ±10 % jitter). When the org's state is not `trialing`/`active`, control answers `renewAfterS` = 3,600, so a restored subscription shows up within an hour. Failed renewals back off from 60 s to 1 h. **Grace = 30 days after `exp`** (`LICENCE_GRACE_S` = 2,592,000). Clock skew 300 s. A box that can't reach control therefore keeps every feature for 14 days after its last renewal, shows the grace banner for the next 30, and lapses 44 days after its last renewal. | Daily renewal notices a cancelled subscription quickly. 44 days offline covers long outages, moves and holidays without a support call, and is short enough that an unpaid box is never useful for long. |
| LC-03 | **Keys.** The licence key is its own key, never an admission or assignment key (kid prefix `lic-`). Control holds it in a keyring file like the admission keys (`LICENCE_KEYS_FILE`, `current`/`next`/`retired`). **The appliance trusts only a key set pinned in its image:** `LicenceKeySet {v: 1, env, keys: [Ed25519 JWK, 1…8]}`, installed by the NixOS module `whombat.licence.keys` at `/etc/whombat/licence-keys.json` (0444). The runtime reads it from `WHOMBAT_LICENCE_KEYS_FILE` and the manager from `licence.keysFile`. `env` fixes the audience (`whombat-appliance:<env>`). **Rotation only through the signed update channel:** ship a release whose key set also carries the next key, switch control to it once that release is installed fleet-wide, then drop the old key in a later release. Nothing on the device fetches licence keys over the network. Control's `GET /v1/licence/keys` serves the public set for operators and the dev harness, which writes the dev image's file from it at provisioning time. Devices never call it. | A key fetched over HTTPS as a trust root would let whoever controls DNS or the endpoint mint licences. Pinning the key set in the TUF-verified image ties licence trust to release custody. |
| LC-04 | **Production has no licence key yet.** A prod image build without `whombat.licence.keys` fails an assertion, the same way the TUF root does (NX). The key belongs in the key-custody table (X-05). It is generated in the production key ceremony together with the other production keys, and not before. Dev and test use the dev keyring from control's `dev-init` (harness) and a fixed seed key in the VM tests, both labelled DEV and bound to audiences other than prod. | Assignment rule: no production keys. |

## A1 — Issuing and renewing (control, manager)

| # | Decision | Reason |
|---|---|---|
| LC-05 | **Device op `licence.renew {}` → `{token, expiresAt, renewAfterS, now}`**, signed like every device op. Control builds the claims from the org's entitlement (a missing row means the configured default, as elsewhere) and signs with the current licence key. `now` is control's clock. It **refuses** an unclaimed device (`device_unclaimed`) and a retired one (`device_revoked`, as every device op already does). It is rate-limited to 12 per hour per device (`rate_limited`) and audited: `licence.issued` with device, org, plan, state, `jti` and `exp`. Control keeps the last issued `jti`/`iat`/`exp`/state per device (`devices.licence_*`) for support. A cancelled org **still gets a token**, with `state: 'cancelled'`: the appliance should learn the truth at once, not after 44 days of silence. | The appliance gets a signed, dated statement of its entitlement. Refusing cancelled orgs would only delay the lapse and hide the reason. |
| LC-06 | **The manager renews and keeps the time high-water mark.** It starts once the runtime reports `claimed` in `GET /facts`, renews right after the claim, then every `renewAfterS`, and immediately when asked (LC-08). It verifies every token with the pinned key set (Go), requires `sub` = its device id and refuses a token whose `iat` is older than the one it holds (`stale`, kept out). It stores `{token, highWater}` in `/persist/manager/licence.json` (0600, atomic). **`highWater` = max(every accepted token's `iat`, control's `now` from every successful renewal)** and never goes down. It pushes `POST /licence {v, token, highWater}` to the runtime's admin socket whenever the token changes, at every runtime (re)start (`syncRuntime`, as for `/claim-lookup` and facts) and with the periodic facts re-send. `device_unclaimed`/`device_revoked` stop the loop until the runtime reports a claim again. | Rolling the clock back never gets earlier than the last time control or a signed token vouched for. |
| LC-07 | **The runtime also remembers the latest time it has seen itself.** Every hour, and at every licence push, it advances a persisted `clockMark = max(clockMark, local clock)`. The effective time is `max(local clock, highWater, clockMark)`. A renewed token **resets** `clockMark` to `highWater`, so control's time wins: a clock that once jumped forward heals at the next renewal, and a clock rolled back after a long offline stretch can't win back the time it already lived through. Tokens, `highWater` and `clockMark` live in `appliance_state` (`licence_token`, `licence_high_water`, `licence_clock_mark`). The runtime also refuses a pushed token whose `iat` is older than the stored one's (409 `stale`). | The manager's mark alone can't see time spent offline. Resetting at renewal keeps a wrong clock from causing a lasting lapse. |
| LC-08 | **Check now.** Owners and admins have `licence.refresh` (session op). The runtime asks the manager (`POST /v1/licence/renew` on the manager socket, answering `LicenceRenewResult {v, renewed, error?}` after the attempt, at most once per 60 s per caller, 429 `busy` otherwise). It then answers the new `LicenceStatusView`. Everyone else has `licence.status` (read). *Since IN-447 (2026-10-25; Whombat OP-01): one person; they have both.* | After paying, an owner shouldn't wait up to an hour. It also gives the dev instance a way to show a lapse and a restore without waiting. |

## A1 — Licence state and enforcement (runtime)

| # | Decision | Reason |
|---|---|---|
| LC-09 | **State.** The pure function `licenceStatus({claims, now, highWater, clockMark, claimedAt, graceS})` in `@whombat/protocol` (Go twin, vectors) returns `{state: 'licensed' \| 'grace' \| 'lapsed', reason, plan, limits, renewedAt, expiresAt, graceEndsAt}`. Effective time `t` = max(now, highWater, clockMark). With a valid token (signature, device, audience; the time checks use `t`): `cancelled` → **lapsed** (`cancelled`). Otherwise, while `t < exp`: `trialing` → licensed (`trial`), `active` → licensed (`active`), `past_due` → licensed (`past_due`, a note in Settings), `grace` → **grace** (`payment`). From `exp` to `exp + 30 d` → **grace** (`not_renewed`). After that → **lapsed** (`expired`). **Without a valid token** on a claimed box, the claim time counts as `exp`: grace (`no_licence`) for 30 days after the claim, then lapsed. An unclaimed box has no licence state (`null`). The runtime computes the state per call, caches it for 60 s, and writes a signed `licence.state_changed` appliance event on every transition. | One function and one set of vectors, so the manager, the runtime and the tests can never disagree. Claimed-without-token covers a box whose control is blocked from the start. |
| LC-10 | **Enforcement matrix.** Refusal codes: `licence.lapsed` and `licence.limit` (app error codes, `details.limit` = `members` \| `agents` \| `connectors`, `details.allowed` = n). **Grace** behaves like licensed, plus the banner. **Limits** apply in every state and only to adding: when a plan shrinks, nothing is removed. See the matrix below. *Since IN-447 (2026-10-25; Whombat OP-01, OP-11; control's licence limits `{devices, connectors}`): `details.limit` is `devices` \| `connectors`; no member or agent limit.* | The paid value is agents and growth. Human work and the data stay the customer's (the billing invariant). Blocking human writes would lock data in all but name. |
| LC-11 | **Limits count** people with an appliance account (not burrow memberships), team agents (`hire_agent` and pack-created agents; not each member's personal agent and not system agents) and connector connections (Google and similar; not AI provider sign-ins). `null` = unlimited. Limits come from the token, so an offline box keeps the last plan it was told. *Superseded by IN-447 (2026-10-25; Whombat OP-11): one person and one agent per Whombat, so only connector connections (and devices) count.* | Personal agents follow the member count. AI sign-ins are credentials, not connectors. |
| LC-12 | **Self-hosted mode has no licence.** The legacy self-hosted server (`Whombat` without managed mode) is out of scope. Licence code runs only in managed mode. | A different product line, and not a Whombat appliance. |

### Enforcement matrix (LC-10)

| Action | licensed | grace | lapsed |
|---|---|---|---|
| Sign in, open sessions, enroll a device of an existing account (pairing, re-enrollment, recovery kit) | yes | yes | yes |
| Read, search (plain), download, every export stream, audit CSV, diagnostics | yes | yes | yes |
| Human writes: messages without an agent, docs, canvases, files, reactions, burrow membership of existing accounts | yes | yes | yes |
| Device management (revoke, endpoints, push handles), owners (`admins.*`), recovery kit, backups, restore, quarantine reconciliation | yes | yes | yes |
| Updates (the manager, independently of the licence), security updates always | yes | yes | yes |
| AI provider sign-in and sign-out, removing members, agents, connectors, packs | yes | yes | yes |
| A turn already running, and executing an action approved within such a run | finishes | finishes | finishes |
| New agent turn: a message to or mentioning an agent, `start_run`, a run retry, AI search (`ask_search`) | yes | yes | **no**: `licence.lapsed`, the message isn't posted |
| Queued dispatches not yet handed to the runner | run | run | held (not dropped); they run once the box is licensed again |
| Automations, schedules, triggers and the GitHub poller | yes | yes | **no**: paused; schedules missed while lapsed are skipped, not caught up |
| New appliance member (`enroll.invite.create`, `enroll.invite.accept`) | up to `limits.members` (`licence.limit`) | same | **no**: `licence.lapsed` |
| New team agent (`hire_agent`, onboarding, pack agents) | up to `limits.agents` | same | **no** |
| New connector connection | up to `limits.connectors` | same | **no** |

## A2 — Self-installed boxes (the ISO)

| # | Decision | Reason |
|---|---|---|
| LC-15 | **A self-registered device (`origin: 'self'`, CC-10) can only be claimed by an org whose entitlement allows self-installed devices:** a new `selfInstall: boolean` in `Entitlement`, set per plan (trial and paid plans: true; the default follows `DEFAULT_SELF_INSTALL`, true in dev). | LC-16 | **`devicesAllowed` is enforced atomically.** Today the check runs before the claim transaction, and pending claims don't count. The app shows the refusal before the ceremony: “Your plan covers {n} Whombats.” | Two parallel claims can't slip past the limit, and a box over the limit can't run paid features. |

## Threats and residual risks

- **A person changing the software on their own box** (root on their own hardware): allowed by the AGPL-3.0. A changed
  box can still only use the service as a claimed device of a paying org, and it has to be changed again after every
  update.
- **A copied image**: runs only with tokens for its own device id, signed by control for a claimed device of a
  paying org. A second box with a cloned identity would share a device id. Control sees two boxes with one identity
  (status reports, relay routes), and the identity can be retired.
- **Control compromise**: can mint licences, which unlocks features but never data. The licence grants no access.
- **A lying or blocked control or DNS**: at worst the box lapses after 44 days. Data, export and recovery are
  unaffected by design.
- **Clock manipulation**: bounded by LC-06/LC-07. A clock set forward only harms the owner, and the next renewal
  heals it.
- **Forged or foreign tokens**: refused (pinned keys, `sub`, audience, `typ`), covered by vectors and a harness
  scenario.
