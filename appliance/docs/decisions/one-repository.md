# The appliance as a folder of the Whombat repository — decisions ORA-nn

2026-11-20. This repository is becoming the folder `appliance/` of the Whombat repository, and whombat-hosts its
folder `hosts/` (Whombat `docs/decisions/one-repo.md`). Until releases are built from there, Whombat holds an exact
copy of this repository's `main`, and changes still land here. These decisions make the release tools work in both
places, so the copy can be proven and old releases stay reachable afterwards.

| # | Decision | Why |
|---|---|---|
| ORA-01 | **Every release tool asks one resolver where a release's source is**: `release/lib/source.sh` for the tools in bash and `harness/src/lib/source.ts` for the harness, with the same cases tested for both (`release/source_test.go`, `harness/src/lib/source.test.ts`). It answers: which repository has a commit, where the appliance is in that commit, what its flake is called, and how to read a file of it. | Each tool found a release's source in its own way and assumed the appliance sits at the top of the checkout it runs from: `git -C "$root" cat-file`, `git+file://<checkout>?rev=`, `git show <rev>:<path>`. None of that holds for a commit of Whombat, or for an old commit that only an archive has. |
| ORA-02 | **A commit is looked for in the checkout the tool runs from, then in the archives** (`WB_ARCHIVE_GIT`: repositories separated by `:`, in order). Unset, the maintainers' two old checkouts are searched when they exist. | A release names the commit it was built from. After the move, a release from before it names a commit that only the old repository has, and its installer, the host comparison and the upgrade gates must still build from it. |
| ORA-03 | **The layout is read from the commit itself**: `appliance/flake.nix` means a folder of Whombat; `flake.nix` beside `nix/profiles` means a commit of the appliance's own repository. The flake is `git+file://<repository>?rev=<commit>`, with `&dir=appliance` for a folder. A working tree with uncommitted changes is `path:<folder>` at a repository's top and `git+file://<repository>?dir=appliance` inside Whombat. | One tool run meets both layouts (the candidate in one, the release before it in the other). A `path:` flake can't reach the folders beside it, and the merged flake will read Whombat and the hosts service from there. |
| ORA-04 | **At a repository's top the tools name the checkout exactly as before** (`git+file://<the folder as the caller named it>?rev=`), and a build's `source` stays `{repository: "whombat-appliance", rev, dirty}`. A build made from Whombat records `{repository: "whombat", rev, dir: "appliance", dirty}`. | The old release flow must not notice the change: it ships with these tools until the switch. |
| ORA-05 | **Changed to the resolver**: `release/build` (a build, `host-path` for both commits, `iso`), `release/upgrade-gates` and the flake's `upgradeGates` (each earlier release's flake by its commit, `flakes` in the arguments file), `release/sbom`, and in the harness `ship build` (the flake, the build script and the pins of the worktree it builds from), `ship validate` (the candidate file of the build's commit), the release notes, and the dev stack's `tufrepo`. The Hermes job and the dev stack override the flake's `whombat` input only while the flake has one. | These are the readers of a release's source. |
| ORA-06 | **Left for the new release flow**: the candidate (`harness/src/dev/candidate*.ts`), which still writes the two pins and assumes this repository, and `manifest/build`, whose clean clones name this repository as a component. | The candidate is rewritten for one repository, and the component list changes with it. Neither runs from the copy before that. |
| ORA-07 | **`scripts/ci/move-proof.sh` proves the move**: it evaluates the appliance's own commit and the same files under Whombat's `appliance/` and compares the derivation and output path of everything a release is made of (16 values). Evaluation only. | The same derivation is the same build, so nothing needs building twice. It proves the move alone; the new build has proofs of its own. |
| ORA-08 | **The scripts in `scripts/ci/` stay as they are.** They name the flake as `.#…` from the appliance's folder, which Nix resolves in both layouts. | Tried from the folder in Whombat: `nix-eval.sh` passes unchanged. |
